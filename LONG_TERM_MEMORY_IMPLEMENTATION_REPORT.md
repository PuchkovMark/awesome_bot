# Отчёт о реализации долговременной памяти

## Архитектура

Долговременная память добавлена рядом с существующей краткосрочной историей, а не вместо неё. `MemoryService` продолжает отвечать за недавнюю историю диалога. Новый `LongTermMemoryService` обслуживает извлечение, хранение, поиск, пользовательское управление и проверку доступа. Точка интеграции в обработчике VK добавляет только релевантные воспоминания к контексту ответа и запускает автоматическое извлечение после обычного ответа.

Личные записи привязаны к пользователю, общие — к беседе. Во время группового диалога в модель передаются только записи общей памяти этой беседы: личные факты участника не раскрываются остальным. Запрос личного списка из групповой беседы отправляет ответ в личные сообщения; если личная доставка недоступна, содержимое не публикуется в группе.

## Хранение и извлечение

- `LongTermMemory` хранит область действия, автора, категорию, текст, важность и уверенность, источник, отпечаток для дедупликации, embedding, связи с другими воспоминаниями, срок действия и состояние архива.
- `MemoryActionDraft` хранит краткоживущий контекст для уточнения неоднозначного запроса на удаление. Черновики и истёкшие факты очищаются/архивируются фоновой задачей.
- Автоматический сбор запускается только для сообщений, похожих на устойчивый факт, предпочтение, проект или явную договорённость. Модель классифицирует кандидаты, определяет область памяти, категорию, уверенность, важность, срок актуальности и связанные записи. Повторные факты дедуплицируются и могут обновить ранее сохранённую запись.
- Перед извлечением применяются локальные фильтры чувствительных данных, секретов, кратковременных инструкций и нерелевантного содержания. Автоматический сбор выполняется асинхронно и не задерживает обычный ответ бота.
- `MemoryEmbeddingProvider` отделяет поиск от конкретного embedding API. Реализация OpenAI получает векторы для семантического ранжирования; если ключ не настроен или embedding недоступен, сервис использует keyword relevance. Сохраняется имя модели, а устаревшие векторы пересоздаются при поиске.
- К контексту ответа добавляется не более шести наиболее подходящих воспоминаний. Переданный модели текст помечается как недоверенные данные, а не инструкции.

## Управление и границы доступа

Пользовательские запросы на добавление, просмотр, поиск, исправление, удаление и очистку обрабатываются обычными сообщениями, без отдельной команды. Автоматическое сохранение и использование памяти можно отключить независимо для пользователя и беседы.

Пользователь может управлять только собственной личной памятью. Общими настройками и полной очисткой памяти беседы управляют администраторы этой беседы; отдельное групповое воспоминание может удалить его автор либо администратор. При неоднозначном совпадении сервис запрашивает уточнение и ограничивает срок действия черновика.

В групповой памяти сохраняются только явно коллективные факты или договорённости. Личные факты участников, секреты и известные чувствительные категории исключаются из автоматического сохранения. Фильтрация является защитой по распознаваемым шаблонам и не гарантирует обнаружение каждой чувствительной формулировки.

## Настройка

- `MEMORY_EMBEDDING_API_KEY` — необязательный ключ OpenAI Embeddings; если он отсутствует, используется `OPENAI_API_KEY`.
- `MEMORY_EMBEDDING_MODEL` — embedding-модель, по умолчанию `text-embedding-3-small`.
- Без ключа OpenAI embeddings остается полнофункциональное хранение и поиск по словам, но семантическое ранжирование отключено.
- Факты для автоматического извлечения обрабатываются выбранным текстовым AI-провайдером. При включённых embeddings сохранённый текст отправляется в OpenAI для построения векторов.
- Миграция БД: `20261108030000_long_term_memory`.

## Проверки и ограничения

Автотесты используют mock AI и mock vectors: они проверяют сохранение/поиск, изоляцию личных и общих данных, отключение автосохранения и приватность уточнения удаления без реальных запросов к OpenAI или VK. Реальная доставка VK и live-вызовы провайдеров этими тестами не подтверждаются. Автоматическое извлечение зависит от эвристик-кандидатов и качества выбранной модели; неподдерживаемые формулировки могут не попасть в память либо потребовать явной просьбы «запомни».

Проверки реализации завершились успешно: `npm run build`, ESLint без автоисправлений, `prisma validate`, применение всех 13 миграций к чистой временной SQLite-БД и полный `npm test` (79 тестов).
