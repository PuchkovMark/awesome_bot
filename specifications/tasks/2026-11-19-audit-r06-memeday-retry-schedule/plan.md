## Текущий контракт и затронутые области

getMemeDaySchedule возвращает ключ только при точном HH:mm; markFailed выставляет nextAttemptAt через 10/20 минут, а claim больше не вызывается для этого выпуска.

## Принятые ограничения

scheduleKey, максимум трёх попыток и существующие 10/20 минут, стабильный randomId планового send, weekly-приоритет воскресенья и запрет повторять published/skipped.
Запрос пользователя относится к задачам и предложениям планов. Рекомендованный ниже вариант не считается согласованным. Не менять соседние функции, бюджеты, публичные schemas и сохранённые данные без отдельного решения.

## Открытые решения

| Решение | Что выбрать | Предложение и альтернатива | Зависимые шаги |
| --- | --- | --- | --- |
| R06-D1 | Срок жизни принятого выпуска. | Рекомендую продолжать его существующие три попытки с исходным scheduleKey, но явно согласовать допустимость после смены локального дня; альтернатива — терминально пропускать по границе дня. Числовой срок сверх текущих retry не выбран. | S1–S3 |
| R06-D2 | Простой в целевую минуту без публикации. | Рекомендую пока не догонять несуществующий выпуск, сохранив нынешнюю семантику создания; альтернатива — ограниченный catch-up, требующий отдельной границы и ключа. | S1 |
| R06-D3 | Настройки изменились между попытками. | Рекомендую отключение/новый запрет ночи отменяет ещё не начатую генерацию, а уже подтверждённый send не повторяется; альтернативу продолжения по первоначальным настройкам нужно выбрать явно. | S2–S3 |

Для каждого решения сейчас статус «ожидает ответа». Обсуждать по одному; выбранная в интерфейсе рекомендация, молчание или общий запрос на план не являются согласием.

## Предложенная последовательность

**S0.** Перед зависимыми изменениями разрешить перечисленные D*, если они есть, и сверить текущий baseline с источниками.

**S1.** Разделить discovery нового schedule и обход сохранённых retryable публикаций; после D1/D2 не выводить retry из нового HH:mm.
Владелец: [getMemeDaySchedule / startMemeDayJob](../../../src/jobs/memeDayJob.ts). Критерии: AC-1, AC-4.

**S2.** Повторно использовать условный claim по scheduleKey, nextAttemptAt, attempts и lock; после D3 проверить доступность чата/расписания.
Владелец: [claimScheduled / markFailed / listEnabledChats](../../../src/services/fun/memeDayService.ts). Критерии: AC-1, AC-2.

**S3.** Проверить окна генерация/upload/send/complete и устойчивость ключа отправки; не обещать exactly-once без доказанного протокола VK.
Владелец: [scheduledMemeDay / publishMemeDay](../../../src/services/vk/vkService.ts). Критерии: AC-3, AC-4.

**S4.** Проверить все AC по таблице, сохранить фактические ограничения проверки и только после реализации обновить перечисленные канонические документы в разрешённой области. Общую спецификацию сейчас не менять.

## Проверки и имеющиеся свидетельства

Прямых тестов MemeDayService/job нет. Проверки расписания возможны на фиксированном времени и подменённом publish.
Прямого существующего тестового файла для этой области не найдено; это ограничение свидетельств, а не разрешение пропустить AC.
При исполнении использовать существующие проверки `npm run check` и при необходимости `npm run build` внутри изолированного Node.js 22 согласно [operations](../../project/operations.md). Проверки специфичных сценариев из таблицы выполнить с подменёнными внешними вызовами/синтетическими данными; БД-гонки проверять на отдельной временной SQLite, а не на рабочем файле.
Новые и изменённые репозиторные тесты не требуются без явного запроса пользователя: недостающие сценарии допускается проверить временно вне `test/`. Наличие старого теста не подтверждает непроверенную ветвь. Во время текущего планирования runtime-проверки не выполнялись.

## Данные, совместимость и применение

Отбор retry использует существующие поля; миграция не ожидается. Если устойчивое хранение промежуточного изображения понадобится для выбранного D1/D3, согласовать его отдельно, не менять retention молча.
Развёртывание, обращения к живым VK/AI и применение миграций к operational DB не являются плановой проверкой и не авторизованы запросом на подготовку задач.
