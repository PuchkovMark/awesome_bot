# R05. Не терять напоминания при конфликте ожидающих согласий

**Приоритет:** P1. **Вид:** Исправление коллизии черновиков. **Дата:** 19.11.2026.
**Статус:** задача и план предложены; реализация не начата, выборы D* остаются открытыми.
**Основание:** [находка R05 аудита](../../../project-issues/specification-audit.md#r05-p1--несколько-запросов-согласия-могут-потерять-связь-с-напоминанием); [предложенный план](plan.md); [общий реестр](../../../project-issues/specification-audit-tasks.md).

## Проблема и проверенное текущее поведение

ReminderDraft уникален по creatorVkId/conversationId. handlePermanentFailure делает upsert с новым reminderId; прежнее напоминание остаётся processing/pending без своего черновика.

Канонические контракты: [reminderService.md#вход-и-диалоговые-черновики](../../project/src/services/reminders/reminderService.md#вход-и-диалоговые-черновики), [reminderService.md#очередь-и-доставка](../../project/src/services/reminders/reminderService.md#очередь-и-доставка), [models.md#reminderdraft](../../project/prisma/models.md#reminderdraft).
Релевантные участки текущего рабочего дерева проверены статически. Само наличие записи в аудите не означает воспроизведение инцидента; выполненные ранее тесты не считаются выполненными заново.

## Предлагаемый результат

Новый запрос не вытесняет незавершённое согласие без определённого перехода прежнего напоминания. У каждого ожидающего согласия есть путь ответа или истечения.

Для вопросов категории Q требуется сначала выбрать контракт; гипотеза не объявляется подтверждённым дефектом. Рекомендации плана не являются принятыми пользовательскими решениями.

## Область и ограничения

- [handlePermanentFailure / handleDeliveryConsent / processDueReminders / saveDraft](../../../src/services/reminders/reminderService.ts) — владелец затронутого исполнения/данных.
- [ReminderDraft / Reminder.fallbackState](../../../prisma/schema.prisma) — владелец затронутого исполнения/данных.

Запрос согласия не раскрывает содержание в группе; короткий ответ относится к определённому напоминанию; текущий срок 24 часа не меняется без согласования.

Новые пользовательские функции, команды и инструменты не добавляются. Сейчас разрешена подготовка задачи и предложения плана; изменение приложения, общей спецификации и запуск реализации этим документом не разрешены. Предыдущие незакоммиченные изменения сохраняются.

## Критерии приёмки предлагаемого результата

- **AC-1:** Две окончательные ошибки одного автора в одном peer не оставляют первое напоминание без достижимого ответа/истечения.
- **AC-2:** Согласие применяется только к связанным reminder и occurrence и выбранному в Q02 субъекту.
- **AC-3:** Коллизия с creating draft не теряет исходный текст и не подтверждает другое напоминание ответом на старый вопрос.
- **AC-4:** После рестарта и истечения срока все затронутые напоминания выходят из pending по определённому правилу.
