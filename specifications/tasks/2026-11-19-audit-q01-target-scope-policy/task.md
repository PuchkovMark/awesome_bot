**Статус:** задача и план предложены; реализация не начата, выборы D* остаются открытыми.
**Основание:** [находка Q01 аудита](../../../project-issues/specification-audit.md#q01-p1--не-установлена-единая-граница-допустимого-адресата-по-id-и-имени); [предложенный план](plan.md); [общий реестр](../../../project-issues/specification-audit-tasks.md).

## Проблема и проверенное текущее поведение

get_chat_info.member сначала разрешает текстовое имя по составу, но ID/reply может читать до подтверждения членства. ReminderService использует parsed.recipientVkId напрямую; send_vk_message уже требует текущего участника.

Канонические контракты: [tools.md#get_chat_info](../../project/src/services/ai/tools.md#get_chat_info), [reminderService.md#создание](../../project/src/services/reminders/reminderService.md#создание), [reminderParser.md#адресат-общая-область-и-очистка-текста](../../project/src/services/reminders/reminderParser.md#адресат-общая-область-и-очистка-текста), [tools.md#send_vk_message](../../project/src/services/ai/tools.md#send_vk_message).
Релевантные участки текущего рабочего дерева проверены статически. Само наличие записи в аудите не означает воспроизведение инцидента; выполненные ранее тесты не считаются выполненными заново.

## Предлагаемый результат

Для чтения VK и напоминаний существует явная политика target по функции и peer. Одинаковые ссылки на человека дают одинаковый результат.

Для вопросов категории Q требуется сначала выбрать контракт; гипотеза не объявляется подтверждённым дефектом. Рекомендации плана не являются принятыми пользовательскими решениями.

## Область и ограничения

- [createChatInfoTool / findMember / member branch](../../../src/services/ai/tools/chatInfoTool.ts) — владелец затронутого исполнения/данных.
- [handleMessage / recipient resolution](../../../src/services/reminders/reminderService.ts) — владелец затронутого исполнения/данных.
- [разбор recipientVkId / recipientReference](../../../src/services/reminders/reminderParser.ts) — владелец затронутого исполнения/данных.
- [строгий поиск адресата](../../../src/services/ai/tools/messageDeliveryTool.ts) — владелец затронутого исполнения/данных.
- [bound recipient resolvers](../../../src/services/vk/vkService.ts) — владелец затронутого исполнения/данных.

Модель не передаёт произвольный peer; actor задаётся сервером. Новый доступ к профилям/ЛС или новые типы адресатов не вводить по умолчанию. Отказ при неясности не угадывает пользователя.

Новые пользовательские функции, команды и инструменты не добавляются. Сейчас разрешена подготовка задачи и предложения плана; изменение приложения, общей спецификации и запуск реализации этим документом не разрешены. Предыдущие незакоммиченные изменения сохраняются.

## Критерии приёмки предлагаемого результата

- **AC-1:** Выбрана и записана отдельно для get_chat_info и reminders матрица собственного пользователя, текущего/бывшего участника и постороннего в ЛС и группе.
- **AC-2:** ID, имя, VK URL, mention и reply одного допустимого target проходят одну и ту же семантическую проверку.
- **AC-3:** Если политика запрещает адресата, отказ происходит до профильного API и создания напоминания; ошибка проверки членства не открывает доступ.
- **AC-4:** Разрешённые исходные сценарии, роли и строгая адресация send_vk_message сохранены.

## Решения и зависимости

Зависимостей от других находок аудита нет; ограничения текущих контрактов сохраняются.
