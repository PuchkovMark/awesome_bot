## Принятые ограничения

Модель не передаёт произвольный peer; actor задаётся сервером. Новый доступ к профилям/ЛС или новые типы адресатов не вводить по умолчанию. Отказ при неясности не угадывает пользователя.
Запрос пользователя относится к задачам и предложениям планов. Рекомендованный ниже вариант не считается согласованным. Не менять соседние функции, бюджеты, публичные schemas и сохранённые данные без отдельного решения.

## Открытые решения

| Решение | Что выбрать | Предложение и альтернатива | Зависимые шаги |

| Q01-D1 | Круг профилей get_chat_info в группе. | Принято пользователем 20.11.2026 при согласовании A01, ответ «2»: любой профиль, доступный VK API, включая пользователей вне беседы. Членство цели не обязательно; ограничение ЛС своим пользователем сохраняется. Права запрашивающего определяются отдельно в A01. | S1–S2 |
| Q01-D2 | Адресаты напоминаний. | Рекомендую текущий участник для запроса из группы и только автор в ЛС; альтернатива — сохранить явно разрешённую отправку внешнему ID с отдельным контрактом согласия. Решение get_chat_info не утверждает эту отдельную политику. | S1–S3 |
| Q01-D3 | Свежесть подтверждения членства. | Рекомендую live-проверка в защищённой точке и fail-closed при недоступном/неполном составе; альтернатива — документированная допустимая давность кэша. Давность не назначена автоматически. | S2–S3 |

## Предложенная последовательность

**S0.** Перед зависимыми изменениями разрешить перечисленные D*, если они есть, и сверить текущий baseline с источниками.

**S1.** Получить D1, затем отдельно D2/D3; составить таблицу actor/target/peer и ожидаемых ошибок для двух функций.
Владелец: [createChatInfoTool / findMember / member branch](../../../src/services/ai/tools/chatInfoTool.ts). Критерии: AC-1.

**S2.** По принятому D1 разрешать в группе профиль вне беседы, доступный VK API, без обязательного подтверждения членства цели. Сохранить серверную привязку peer, ограничение ЛС своим пользователем и отказ при неоднозначном имени. Выбор внешнего профиля не расширяет права actor; они согласуются в A01. Детали разрешения имени вне беседы не выбирать автоматически при подготовке реализации.
Владелец: [createChatInfoTool / findMember / member branch](../../../src/services/ai/tools/chatInfoTool.ts). Критерии: AC-2, AC-3.

**S3.** Провести parsed.recipientVkId через выбранную семантическую проверку так же, как имя; согласовать выдачу с A01 и согласие с Q02.
Владелец: [handleMessage / recipient resolution](../../../src/services/reminders/reminderService.ts). Критерии: AC-2, AC-3, AC-4.

**S4.** Проверить все AC по таблице, сохранить фактические ограничения проверки и только после реализации обновить перечисленные канонические документы в разрешённой области. Общую спецификацию сейчас не менять.

## Проверки и имеющиеся свидетельства

messageDelivery уже проверяет числовой ID текущего участника; chatInfo не покрывает member-target. Напоминания прямых тестов не имеют.
Существующие относящиеся файлы: [chatInfoTool.test.ts](../../../test/chatInfoTool.test.ts), [messageDelivery.test.ts](../../../test/messageDelivery.test.ts).
При исполнении использовать существующие проверки `npm run check` и при необходимости `npm run build` внутри изолированного Node.js 22 согласно [operations](../../project/operations.md). Проверки специфичных сценариев из таблицы выполнить с подменёнными внешними вызовами/синтетическими данными; БД-гонки проверять на отдельной временной SQLite, а не на рабочем файле.
Новые и изменённые репозиторные тесты не требуются без явного запроса пользователя: недостающие сценарии допускается проверить временно вне `test/`. Наличие старого теста не подтверждает непроверенную ветвь. Во время текущего планирования runtime-проверки не выполнялись.

## Данные, совместимость и применение

Проверки области не требуют миграции. Миграция/новое consent-хранение относятся к Q02, если будет выбран внешний адресат. Внешние контакты и новые команды не добавляются.
Развёртывание, обращения к живым VK/AI и применение миграций к operational DB не являются плановой проверкой и не авторизованы запросом на подготовку задач.
