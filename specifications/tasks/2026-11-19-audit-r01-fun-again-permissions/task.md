# R01. Повторно проверять доступ при нажатии «новый вариант»

**Приоритет:** P1. **Вид:** Исправление авторизации callback. **Дата:** 19.11.2026.
**Статус:** задача и план предложены; реализация не начата, выборы D* остаются открытыми.
**Основание:** [находка R01 аудита](../../../project-issues/specification-audit.md#r01-p1--кнопка-нового-варианта-обходит-актуальные-запреты-на-генерацию); [предложенный план](plan.md); [общий реестр](../../../project-issues/specification-audit-tasks.md).

## Проблема и проверенное текущее поведение

В message_event ветвь fun_again проверяет последний output пользователя, затем напрямую вызывает MemeService или FunService без актуальных mode/maintenance/imageAccess/rate-limit. Сами генераторы не являются слоем авторизации.

Канонические контракты: [commands.md#fun-feedback-and-fun-again](../../project/src/services/command/commands.md#fun-feedback-and-fun-again), [commands.md#command-meme](../../project/src/services/command/commands.md#command-meme), [funService.md#настройки-и-область-действия](../../project/src/services/fun/funService.md#настройки-и-область-действия).
Релевантные участки текущего рабочего дерева проверены статически. Само наличие записи в аудите не означает воспроизведение инцидента; выполненные ранее тесты не считаются выполненными заново.

## Предлагаемый результат

Кнопка повторяет разрешённую существующую генерацию с теми же актуальными ограничениями, что её исходный маршрут.

Для вопросов категории Q требуется сначала выбрать контракт; гипотеза не объявляется подтверждённым дефектом. Рекомендации плана не являются принятыми пользовательскими решениями.

## Область и ограничения

- [message_event fun_again / checkRateLimit](../../../src/services/vk/vkService.ts) — владелец затронутого исполнения/данных.
- [latestOutput / allowsPersonalJokes / generate](../../../src/services/fun/funService.ts) — владелец затронутого исполнения/данных.
- [MemeService.create](../../../src/services/fun/memeService.ts) — владелец затронутого исполнения/данных.

Связь output с пользователем и peer, отказ для старой кнопки, существующая клавиатура; запись fun_feedback не становится платной генерацией и не получает её запреты автоматически.

Новые пользовательские функции, команды и инструменты не добавляются. Сейчас разрешена подготовка задачи и предложения плана; изменение приложения, общей спецификации и запуск реализации этим документом не разрешены. Предыдущие незакоммиченные изменения сохраняются.

## Критерии приёмки предлагаемого результата

- **AC-1:** Maintenance, quiet, закрытый imageAccess и применимый rate limit блокируют fun_again до вызова генератора.
- **AC-2:** При повторе персонального вида применяется актуальное разрешение; нельзя использовать прошлый успешный output как бессрочную авторизацию.
- **AC-3:** Разрешённый callback создаёт один новый вариант и корректную клавиатуру; отказ не создаёт FunOutput или usage.
- **AC-4:** fun_feedback сохраняет собственные проверки области и не меняет поведение из-за запретов генерации.
