## Проверка критериев и инвариантов

| Критерий | Статическое свидетельство | Граница заключения |
| --- | --- | --- |
| AC-1 | Обе production точки вызывают один ImageQuotaService. Первое действие транзакции — INSERT OR IGNORE до seed; условный increment и создание попытки находятся в одной транзакции. Допуск возвращается после commit. Ошибка БД запрещает генерацию. Scope — автор/UTC-день, без peer. | Реальное поведение блокировок/таймаутов установленного Prisma/SQLite и двух процессов не воспроизводилось. |
| AC-2 | Квота изменяется отдельно от ApiUsage. Готовое изображение финализируется до VK; сбой finish оставляет занятый reserved и не отменяет доставку. В tool onImageSent вызывается до отдельно перехваченной ошибки статистики; production recordUsage сам перехватывает ошибку БД. | Сбои телеметрии/доставки проверены чтением пути исполнения и assertions, без запуска. |
| AC-3 | ImageNotExecutedError создаётся только на границах подготовки: получение клиента, downloadPhoto, Sharp/toFile. API-вызов и разбор ответа не входят в этот catch. Ошибки после API дают uncertain, готовый буфер — consumed. Только guarded reserved → released уменьшает used в той же транзакции; повтор/конфликт терминального исхода расход не меняет. | Сохранение состояний при аварийном завершении и ошибки engine не воспроизводились. |
| AC-4 | UTC-день и reservedAt вычисляются один раз до транзакции. Seed автора/двух image features использует полуоткрытый интервал дня и выполняется только при создании дневной строки. Новые image usage получают reservedAt. Миграция добавляет две таблицы без изменения старых usage; автосброса/очистки незавершённых попыток нет. | Fresh/upgrade, реальные Date bindings, рестарт и полночь требуют выполнения уже добавленных проверок. Переход требует завершить старые запросы и остановить всех старых writers. |

Проверены сохранение guards, публичной schema инструмента, выбора фото и адресата;
приоритет отсутствующего фото над лимитом соответствует согласованному изменению.
Квота не перенесена в общий генератор и не подключена к мемам/приключениям.
В транзакциях нет сетевых вызовов; operationId не объявлен дедупликацией VK-событий.
Схема и SQL статически согласованы по полям, defaults, составному PK/FK и индексу.

## Фактически выполненные проверки и ограничения

- Прочитаны diff/новые файлы и прослежены callers, порядок guards, reserve,
  генератора, finish, доставки и статистики.
- Сопоставлены реальные assertions тестов с изменённым контрактом; новые тесты
  не запрашивались, отсутствие покрытия не оформлялось как дефект.
- `git diff --check` — успешно.
- `problems` для пяти затронутых production-модулей и пяти тестовых/fixture файлов
  вернул отсутствие диагностик. Это не заменяет исполнение тестов.
- На предыдущем этапе этой сессии успешно выполнены генерация Prisma client,
  сборка TypeScript и focused ESLint через стадии Docker build. В рамках
  настоящего ревью эти команды не запускались повторно; прежний результат
  не выдаётся за новый прогон.
- Регрессионные тесты, общий npm run check, fresh/upgrade и проверка реального
  SQLite engine остаются невыполненными. Ранее запуск проверочного контейнера
  был отклонён; нового разрешения на такой запуск к моменту ревью не получено.
  Этот предел проверки отделён от подтверждённых дефектов.
- Бот, jobs, VK/OpenAI и миграции рабочей БД не запускались; секреты и рабочая БД
  не читались. Эксплуатационные условия переключения статически описаны,
  но на действующем окружении не подтверждены.
