# План исправления индикатора

Основание: [task.md](task.md). Пользователь запросил реализацию предложенного изменения `group_id`.

1. В [VkService.startActivity](../../../../src/services/vk/vkService.ts) убрать ограничение по диапазону `peerId` из условия передачи `group_id`. Остальной жизненный цикл сохранить.
2. Проверить реальные параметры группового и личного запроса, отсутствие `group_id` без ID сообщества и остановку на подменённом VK во временном сценарии; выполнить существующие проверки в Node.js 22 по [operations](../../../project/operations.md).
3. Пересобрать приложение и применить через `docker compose up -d --no-deps app`, без запуска миграций. Не вызывать VK/provider для проверки; отметить границу подтверждения в клиенте VK.

Соответствие: AC-1 → параметры `startActivity` → изменение условия → временная проверка; AC-2 → тот же метод → сохранение остального кода → проверка остановки и diff; AC-3 → Docker → сборка/перезапуск → состояние контейнера.

Миграции, новые зависимости и конфигурация не требуются. Для последующей отдельной синхронизации затронут контракт VkService. При новом существенном выборе сначала сообщить пользователю и согласовать зависимые изменения. После начала реализации планы не изменять без специального поручения пользователя.
