# Подробный план исправления индикатора

Готов к реализации. Основания: [task.md](task.md), [plan.md](plan.md). Рабочее дерево содержит посторонние изменения, в том числе в VkService; сохранять их.

1. S1, AC-1/AC-2: в [src/services/vk/vkService.ts](../../../../src/services/vk/vkService.ts), `startActivity`, заменить spread с `this.groupId && peerId > 0 && peerId < 2_000_000_000` на `...(this.groupId ? { group_id: this.groupId } : {})`. `peer_id`, `type`, интервал 4000 мс, `requestPending`, обработку ошибок и функцию остановки не менять. Изменение распространяется на все текущие вызовы общего метода, включая голос и фото.
2. S2 после S1: в изолированном Node.js 22 контейнере выполнить `npm run check`; временным сценарием извлечь фактический метод из исходника, подменить VK и таймеры и проверить параметры для ЛС/беседы, типы typing/photo/audiomessage, отсутствие ID и остановку. Сценарий не добавлять в репозиторий. Рабочую БД и секреты не подключать.
3. S3 после S2, AC-3: `docker compose build app`, затем `docker compose up -d --no-deps app` и `docker compose ps app`. Запуск здесь применяет исправление; отправку сообщений для проверки не выполнять. Сборка включает текущее рабочее дерево, как предписывает Dockerfile.

Условия завершения: правка и изолированные проверки выполнены, контейнер приложения обновлён; фактическое отображение индикатора остаётся проверкой в клиенте VK. Общую спецификацию VkService обновлять только отдельным запросом. Новых решений нет; при необходимости отклонения сначала согласовать его с пользователем. В ходе реализации планы доступны только для чтения, результаты сообщать в чате.
