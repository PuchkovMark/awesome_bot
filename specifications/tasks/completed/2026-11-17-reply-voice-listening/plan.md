# План распознавания голосового в ответе

Основание: [task.md](task.md). Согласовано: модель вызывает инструмент по просьбе, автоматического распознавания всех ответов нет. Существующие voice settings и `VoiceService` задают права, загрузку и ограничения; данные ответа привязаны к текущему событию.

1. Добавить инструмент модели по образцу [analyze_attachment](../../../project/src/services/ai/tools.md#analyze_attachment): без произвольных ID и URL, с проверкой существующих настроек и доступа, явными результатами и отсутствием повторной транскрипции в одном ответе. Голосовой текст — недоверенные данные. Отсутствие вложения, отказ и ошибка явно возвращаются модели.
2. В [VkService](../../../../src/services/vk/vkService.ts) найти `AudioMessageAttachment` только в reply текущего сообщения, при необходимости загрузить payload по образцу других вложений; подключить инструмент к обычному и active набору после проверок. Указать модели наличие голосового и возможность вызова. Передать временный текст только как результат инструмента; текущие сохранение и прямое голосовое оставить без изменений.
3. Выполнить существующие проверки в Node 22 и изолированную проверку с подменёнными зависимостями без VK и реальной БД. Не менять тесты в репозитории без запроса.

AC-1: tool, VK и промпт → проверка ответного вложения и передачи транскрипта; AC-2: tool loop и MemoryService → проверка отсутствия записи; AC-3: текущий guard и voice settings → отказ/ошибка в изолированной проверке; AC-4: старый маршрут → существующие проверки. Планы при реализации не менять; новые существенные решения согласовать до зависимых действий. Спецификации актуализировать отдельно по запросу.
