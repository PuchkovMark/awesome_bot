# Подробный план реализации пересказа истории

## Состояние и основание

**Статус: подробный план подготовлен.** Основание: [задание](task.md) и [план](plan.md) с последующими уточнениями пользователя, зафиксированными здесь. Код и тесты не изменялись, проверки не запускались. В рабочем дереве есть изменения инструкций и неотслеживаемые документы задачи; сохранять их без изменений. Пользователь разрешил подготовку этого документа, но не реализацию и не изменение других планов.

Последующее указание пользователя заменяет JSON из task.md обычным текстом, разбитым по темам; это относится к промежуточным выжимкам и результату для основной модели. Согласовано: существующий `run_subagent`, без отдельного инструмента; история текущей беседы за последние 24 часа, выбор по времени, промежутку либо количеству; один последовательный субагент, прямой результат основной модели без `DigestJob` для нового пути. Снимок фиксирует ID, а не содержимое. Остальные размеры, очистка, повторные попытки, отмена и покрытие заданы в [plan.md](plan.md). Произвольный выбор новых контрактов не делегирован.

## Согласованное решение: `run_subagent`

Сейчас [`createSubagentTool`](../../../../src/services/ai/tools/subagentTool.ts) принимает `task`, `format`, выборку и участников и всегда вызывает `startJob`; [`VkService`](../../../../src/services/vk/vkService.ts) затем отмечает отложенную доставку. Пользователь уточнил: инструмент запускает субагента и передаёт ему задание, пересказ — один из видов заданий, результат всех новых заданий возвращается напрямую основной модели. Отдельный инструмент и раздельный режим фонового запуска не нужны. Существующий фоновый путь для новых вызовов меняется; старые данные и общие процессы не удалять только ради этого изменения.

## Согласованное решение: суточный лимит запусков

[`SubagentService.startJob`](../../../../src/services/ai/subagentService.ts) проверяет `SUBAGENT_DAILY_LIMIT` по сохранённым `DigestJob` пользователя за последние 24 часа. Пользователь указал: суточного лимита запусков для нового прямого пути нет. Не создавать ради него счётчик в памяти или БД; другие согласованные ограничения и права сохраняются. Это решение уточняет план без его редактирования.

## Входной бюджет объединения

Пользователь уточнил, что уже согласованный предел запроса к субагенту составляет 60 000 оценочных токенов, то есть 180 000 Unicode code points при оценке один токен на три символа. Применять его и к каждому запросу объединения: текст выжимок и передаваемое обрамление входят в подсчёт. Это приблизительная оценка, а не гарантия реального числа токенов.

## Независимая детализация

### I-1. Хранение текста и цитат

В [`memoryService.ts`](../../../../src/services/memory/memoryService.ts) `MemoryService.addMessage` сейчас безусловно пишет `content`, `replyToText`, `attachments` и возвращает `StoredMessage`. Подготовить общую очистку emoji с сохранением обычного текста, применять к тексту и цитате до записи, не записывать сведения о вложениях, после очистки и trim пропускать пустые записи. Возвращаемый тип должен отражать пропуск; проверить всех вызывающих, особенно `persistedUserMessage.id` в [`vkService.ts`](../../../../src/services/vk/vkService.ts), чтобы не dereference отсутствующую запись и не потерять защиту от повторной записи.

В `VkService.messageStorageFields` и местах `addMessage` сохранить связи и автора, передавать только исходный набранный текст. В ветви голосового сообщения `text` сейчас перезаписывается результатом `voiceService.transcribe`; отдельно сохранить исходный текст до транскрипции для записи, не меняя обработку живого голоса. Цитаты очищать с учётом достоверного происхождения. Учитывать последствия для `getRecentChatContext`, `getHistoryPage`, разрешения участников, `/summary` и meme: им станет доступен очищенный текст, массового изменения старых строк не проводить.

### I-2. Снимок и подготовка

Не использовать для нового пути старые `loadHistoryMessages`, `formatTranscript` и `chunkMessages` без изменения их контрактов: [`chatDigestService.ts`](../../../../src/services/ai/chatDigestService.ts) обрезает сообщение до 1000, reply до 300 и делит по прежним настройкам. Реализовать изолированный поток чтения: scoped снимок ID по `conversationId`, выбору и эффективной дате `sentAt ?? createdAt`, стабильная сортировка с уникальным ID; затем читать только эти ID страницами, отдельно отмечая удалённые. Не фиксировать содержимое как неизменное и не включать новые сообщения.

В подготовленном тексте учитывать автора, идентификатор, дату, reply и пометку приблизительного времени; очищать старые записи на чтении без записи в БД. Соблюдать изоляцию при восстановлении reply. Длинное сообщение делить по абзацам, предложениям и Unicode code points с общим ID и номерами частей; размер полностью подготовленной порции, включая обрамление, не более 180 000 code points. Источник — сохранённая история, без предположений о полноте VK.

Текущий `messageWhere` фильтрует только `sentAt`, поэтому строки с `sentAt = null` сейчас выпадают из периодов даже при подходящем `createdAt`. Для нового пути включить обе ветви: непустой `sentAt` в периоде или null `sentAt` и `createdAt` в периоде. Использовать одинаковую эффективную дату для выбора и порядка. Границы периода применять совместно с `conversationId` и разрешёнными ролями/участниками; чтение по ID дополнительно ограничивать той же беседой.

### I-3. Обработка и объединение

Новый поток сжатия должен изолировать старый `buildChatDigest` и `/summary`: последовательные вызовы `AIProvider.send` через `SUMMARY_MODEL` с `maxOutputTokens: 8000`, нейтральная инструкция из плана, текст по темам со ссылками на ID, покрытие и ошибки формирует код. Старые `parseDigest`, `combineDigests` и `clampSummary` имеют лимиты и не подходят без отдельной проверки на усечение. Мягкая цель 4000 токенов не является причиной повторной генерации.

[`chatCompletion.ts`](../../../../src/services/ai/chatCompletion.ts) преобразует `finish_reason=length` в `AIOutputLimitError`: один повтор с требованием более сильного сжатия, затем деление входа пополам максимум на два уровня; исчерпание означает необработанную часть. Содержательно объединять соседние текстовые выжимки ограниченными по входу группами; при превышении полного текстового результата с обрамлением 60 000 code points выполнять до трёх раундов сжатия, затем возвращать явную ошибку. Не обрезать текст или сведения о покрытии.

### I-4. Таймаут и жизненный цикл

[`AIProvider.ts`](../../../../src/services/ai/AIProvider.ts) не содержит сигнала отмены, [`opencodeProvider.ts`](../../../../src/services/ai/opencodeProvider.ts) задаёт SDK timeout 90 секунд и `AI_MAX_RETRIES`, а старый `SubagentService.runPartWithTimeout` использует `Promise.race`, не отменяющий запрос. Передавать отмену до HTTP-вызова через тип опций и `sendChatCompletion`, учитывая transport retries внутри 90 секунд; общий deadline 10 минут останавливает новые запросы и отменяет текущий. Пригодный завершённый частичный результат возвращать с покрытием, незавершённый не считать готовым.

В [`bootstrap.ts`](../../../../src/bootstrap.ts) существующий shutdown вызывает `subagentService.stop()` перед отключением Prisma: подключить отмену операций нового пути к жизненному циклу и дождаться освобождения состояния там, где это необходимо. После рестарта новые операции не восстанавливаются; старые `DigestJob` и их обработку сохранять согласно принятому маршруту.

### I-5. Подключение и права

Изменить `SubagentRequest`, схему и `execute` в [`subagentTool.ts`](../../../../src/services/ai/tools/subagentTool.ts), подключение и `beginAction`/`commandResultDelivered` в [`vkService.ts`](../../../../src/services/vk/vkService.ts), а также описание в [`capabilityService.ts`](../../../../src/services/ai/capabilityService.ts) и подсказки [`localChatHistoryTool.ts`](../../../../src/services/ai/tools/localChatHistoryTool.ts). Передавать субагенту задание пользователя и возвращать результат непосредственно основной модели. Проверять доступ до чтения; не передавать другой peer или приватные сообщения в результат и логи. Для прямого пути не вызывать `acknowledge` и отдельную доставку, оставив основной модели обычную отправку ответа. Валидация времени и count ограничена последними 24 часами, fallback часового пояса сообщает о Москве.

Существующий [`locationService.ts`](../../../../src/services/settings/locationService.ts) выбирает `timeZone`, затем `locationTimeZone`, затем `DEFAULT_TIME_ZONE`, и отдельно определяет `timeZoneConfigured`; использовать этот установленный порядок для области беседы и передать в операцию признак fallback. Не считать московский пояс пользовательской настройкой, если сработало значение по умолчанию. До первого provider-вызова зафиксировать границу последних 24 часов, чтобы она не сдвигалась при обработке.

## Передача

Исполнитель следует `task.md`, `plan.md` и `implenent.md`. При новом выборе, устаревании плана или необходимости изменить согласованное сначала описывает проблему в чате и задаёт вопрос, ожидая ответа до зависимых правок; независимая работа может продолжаться. Во время реализации все планы доступны только для чтения: без специального указания нельзя менять даже статус, прогресс или результаты проверок. Согласие на решение или общее поручение реализации не разрешает правку планов; прогресс и результаты сообщаются в чате.
