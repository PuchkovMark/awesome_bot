# Пересказ текстовой истории беседы

## Статус

Основные решения согласованы. Пользователь принял рекомендованные варианты оставшихся вопросов сообщением «оставляем рекомендации». Этот документ сводит требования переписки в актуальную версию; ранние варианты с двумя агентами, порциями 80 000 символов и точным токенизатором заменены решениями ниже. Код ещё не изменён, реализация и проверки не выполнены.

## Проблема и проверенный baseline

Пользователь сообщил о некорректном пересказе большого количества сообщений. Конкретная причина исходной ошибки не подтверждена; задача определяет новый согласованный способ обработки.

[SubagentService](../../../project/src/services/ai/subagentService.md) сейчас загружает историю, делит её на одну/две части и сохраняет результат в [DigestJob](../../../project/prisma/models.md#digestjob); результат отправляет отдельный [сервис доставки](../../../project/src/services/ai/subagentResultDeliveryService.md). [chatDigestService](../../../project/src/services/ai/chatDigestService.md) делит по сообщениям/символам, ограничивает текст и содержимое дайджестов. Текущие defaults ограничения задачи — 3000 сообщений и 300 000 символов.

[MemoryService](../../../project/src/services/memory/memoryService.md) сохраняет переданный текст, reply и сведения о вложениях. В [VK-пути](../../../../src/services/vk/vkService.ts) голос может быть преобразован в текст до записи, поэтому непустой текст сам по себе не доказывает текстовое происхождение сообщения. Reply-ID и текст сохраняются при доступности, имя автора цитаты не всегда заполнено.

Текущий провайдер — OpenCode; базовая модель пересказа — Claude Haiku 5.5. Фактическая скорость и расход заранее не гарантируются.

## Согласованный результат

1. Пользователь просит пересказ текущей беседы за выбранный период до 24 часов. Основная модель вызывает инструмент, один субагент выполняет сжатие и возвращает результат напрямую основной модели.
2. Обработка запускается по запросу, без cron. Для нового пути не сохранять промежуточные/финальные выжимки в БД или файл и не использовать отдельную отложенную доставку. Состояние операции и промежуточные JSON находятся в памяти процесса.
3. Подсчёт приблизительный: символ — Unicode code point, оценочные токены — округлённое вверх число символов, делённое на 3. Порция подготовленной истории — до 60 000 оценочных токенов (180 000 символов). Финальный результат для основной модели — до 20 000 оценочных токенов (60 000 символов), включая JSON и передаваемое обрамление. Это не точный подсчёт токенизатора.
4. Выжимка одной порции — краткий законченный JSON с мягким ориентиром около 4000 токенов. Небольшое превышение не является ошибкой и не вызывает обрезания. Технический предел одного вызова — 8000 выходных токенов; он отделён от ориентиров длины и учитывает возможный reasoning.
5. Внутренняя выжимка нейтральная: темы, факты, решения, договорённости, открытые вопросы; значимые тезисы имеют ссылки на исходные сообщения. Персонаж применяется основной моделью к окончательному ответу без изменения фактов.
6. Выжимки объединяются содержательно, при необходимости несколькими ограниченными группами. Нет предела в пять порций. Предел 20 000 относится к результату для основной модели, а не к общему расходу всех генераций.
7. При остановке бота операция прекращается и состояние освобождается; после перезапуска незавершённый пересказ не восстанавливается.

## История и хранение

- Новые пользовательские и ботом сгенерированные записи истории очищаются от emoji; вложения и их служебные описания не сохраняются. Пустые после очистки и trim записи пропускаются.
- Самостоятельно написанный текст смешанного сообщения сохраняется; голос и расшифровка исключаются. Прямая обработка живых голосовых/медиа не отключается этим требованием.
- Цитаты/reply очищаются по тем же правилам; сохраняются ID, автор, время и принадлежность беседе. Голосовой текст не должен попадать в историю через цитаты, если происхождение достоверно известно.
- Старые записи массово не изменяются. При подготовке пересказа очищаются на чтении; старые голосовые исключаются, когда их происхождение можно достоверно установить. Нельзя обещать восстановление отсутствовавшей информации о происхождении.
- В начале операции фиксируется набор ID. Тексты читаются по этим ID в стабильном порядке; новые сообщения не включаются. Удалённые до чтения записи считаются пропуском обработки.
- Снимок ID фиксирует состав, но не неизменность текста при последующем редактировании. Более строгий снимок содержимого не выбран.
- Для сообщения без sentAt используется createdAt с указанием, что время приблизительное. Слишком длинное сообщение делится по абзацам, затем предложениям, затем границам Unicode-символов, с общим ID и нумерацией частей.
- Период интерпретируется в зоне беседы; при отсутствии настройки — Москва с предупреждением. Сохранённые сообщения считаются полным исходным источником: отсутствие активности не объявляется потерей истории.

## Ошибки и ресурсы

- Таймаут одного запроса — 90 секунд, всей операции — 10 минут. Это границы ожидания, не обещание успешного завершения за несколько минут на любом объёме.
- Если ответ оборвался по техническому лимиту: один повтор с требованием сжать сильнее, затем деление входа пополам; глубина такого деления ограничена двумя уровнями. Повторы не запускаются только из-за небольшого превышения мягких 4000.
- Если итог для основной модели больше 60 000 символов: до трёх раундов дополнительного содержательного сжатия, затем явная ошибка вместо обрезания или превышающего бюджет результата. Каждый запрос объединения имеет ограниченный вход.
- Ошибка/пропуск порции обозначается в частичном результате. При общем таймауте прекратить запуск новых запросов и вернуть доступный частичный результат, если он пригоден и укладывается в бюджет; незавершённая генерация не считается готовой.
- Существующие независимые ограничения провайдера и безопасность сохраняются. Старые искусственные ограничения количества сообщений/общих символов не должны отвергать историю вместо обработки порциями.
- Права и изоляция бесед/операций сохраняются; содержимое сообщений и секреты не попадают в логи.

## Критерии приёмки

- **AC-1:** Пересказ сохранённой истории текущей беседы за выбранный период до суток без молчаливой потери сообщений.
- **AC-2:** Основная модель вызывает инструмент сжатия без необходимости пользователю явно выбирать субагента.
- **AC-3:** Один агент последовательно обрабатывает все порции; второй не подключается.
- **AC-4:** Необработанные части обозначаются; исчерпание восстановления не выдаётся за полный успешный пересказ.
- **AC-5:** Зона беседы, московский fallback и предупреждение об отсутствии настройки работают согласованно.
- **AC-6:** Сохранённая история считается исходным источником; предупреждения относятся к обработке, известным пропускам ID и запасной дате, а не к предположениям о полноте VK.
- **AC-7:** Результат возвращается напрямую основной модели; пользовательский ответ формирует и отправляет она.
- **AC-8:** Соблюдаются согласованные таймауты, отмена при остановке и отсутствие восстановления незавершённой операции.
- **AC-9:** Граница входной порции — 180 000 Unicode code points полного подготовленного текста; прежние 300 сообщений/12 000 символов не дробят новый режим.
- **AC-10:** Новый путь не зависит от cron, сохранённого DigestJob или отдельной отложенной доставки.
- **AC-11:** Новые записи содержат очищенный текст без emoji/вложений/голосовой расшифровки; пустые записи пропускаются, включая ответы бота.
- **AC-12:** Reply-связи сохраняются, цитаты не обходят очистку; текст смешанного сообщения обрабатывается отдельно от аудио.
- **AC-13:** Краткость задаётся инструкцией, мягкие 4000 не обрезают завершённый ответ; технические 8000 и восстановление после обрыва обрабатываются отдельно.
- **AC-14:** Полный JSON-результат для основной модели не превышает 60 000 символов; иначе выполняется согласованное повторное сжатие либо возвращается явная ошибка.

## Границы и передача

Команду [/summary](../../../project/src/services/command/commands.md#command-summary) отдельно не перерабатывать. Новая очистка сохраняемой истории косвенно меняет доступные данные для всех потребителей Message; это нужно проверить и явно отразить. Обычное сохранение уже отправленного ответа основной модели остаётся.

Не удалять общие cron-процессы, поля схемы или старые записи только ради нового пути. Ревью и обновление общих спецификаций выполняются по отдельному запросу. Дальнейшие шаги и проверки — в [plan.md](plan.md). Ранее рекомендованные решения приняты; новые существенные вопросы, выявленные при реализации, разрешать по правилу передачи плана.
