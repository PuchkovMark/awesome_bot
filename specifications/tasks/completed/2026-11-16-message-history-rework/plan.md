# План пересказа текстовой истории беседы

## Статус и основание

Основные решения [задачи](task.md) согласованы; последующее решение пользователя заменяет предусмотренный в task.md JSON обычным текстом по темам. Пользователь принял рекомендованные варианты оставшихся вопросов сообщением «оставляем рекомендации». Ранние противоречащие варианты заменены этим планом. Реализация ещё не выполнена; проверки кода не запускались. Документ не является отчётом о готовом функционале.

## Проверенные исходные контракты

- [Инструменты истории](../../../project/src/services/ai/tools.md): run_subagent, get_subagent_status и ограничения доступа.
- [SubagentService](../../../project/src/services/ai/subagentService.md): загрузка истории, деление на одну/две части, сохранение результата и финализация.
- [chatDigestService](../../../project/src/services/ai/chatDigestService.md): символьные/поштучные чанки, JSON-дайджесты, обрезание текста, редукция и usage.
- [MemoryService](../../../project/src/services/memory/memoryService.md) и [Message/DigestJob](../../../project/prisma/models.md): сохранение текста/reply/вложений, история и фоновые результаты.
- [Доставка](../../../project/src/services/ai/subagentResultDeliveryService.md), [delivery job](../../../project/src/jobs/subagentDeliveryJob.md), [конфигурация](../../../project/src/config/README.md).
- Общие источники: [индекс проекта](../../../project/README.md), [реестр покрытия](../../../project/coverage.md), [карта тестов](../../../project/test/README.md), [operations](../../../project/operations.md).

Сейчас искусственные defaults ограничения задачи — 3000 сообщений/300 000 символов, порции — 300 сообщений/12 000 символов; загрузчик обрезает текст сообщения до 1000 символов. Новый путь должен перейти к согласованному разбиению без такого молчаливого усечения. Локальный выходной бюджет 3000/6000 и defaults 1200/2400 заменяются для нового пути согласованным техническим пределом 8000. Это не означает изменения всех существующих потребителей общих функций.

## Согласованные решения и причины

| Область | Решение |
| --- | --- |
| Исполнение | Один агент, последовательная обработка, запуск по запросу без cron. |
| Провайдер/модель | Существующий OpenCode provider; сжатие через SUMMARY_MODEL (по умолчанию Claude Haiku 5.5). |
| Вход | Сохранённая история текущей беседы за последние 24 часа; выбор по времени, промежутку или числу сообщений не выходит за эти сутки. До 60 000 оценочных токенов = 180 000 Unicode code points подготовленной истории на порцию; авторы, даты, reply и разделители входят в размер. |
| Оценка | ceil(число Unicode code points / 3); без отдельного API или токенизатора. Формула не гарантирует тарифную границу 100 000 реальных токенов. |
| Выжимка порции | Краткий законченный текст по темам, мягкий ориентир около 4000 токенов; небольшое превышение не обрезать и не считать ошибкой. |
| Предел генерации | 8000 выходных токенов на вызов, отдельно от мягкого ориентира и размера результата для основной модели; учитывать возможный reasoning. |
| Финальный результат | До 20 000 оценочных токенов = 60 000 символов всего текстового ответа инструмента с обрамлением. Это не предел общего расхода генераций. |
| Формат | Обычный текст по темам: факты, решения, договорённости, открытые вопросы; ID сообщений-источников для значимых тезисов. Границы/покрытие добавляет код. |
| Персонаж | Внутренние выжимки нейтральные; основная модель применяет персонажа только при финальном ответе, без изменения фактов. |
| Состояние | Локальное состояние операции в памяти процесса: ID/период беседы, снимок ID, позиция чтения, текстовые выжимки, покрытие и usage. |
| Возврат | Прямой ответ инструмента основной модели; финальную выжимку не сохранять в БД/файл, отдельную доставку не использовать. |
| Снимок | Зафиксировать ID в начале и читать текст страницами; новые ID исключены, удаление записи даёт явный пропуск. Снимок ID не фиксирует последующие правки текста. |
| Даты | sentAt, при отсутствии createdAt с пометкой о запасной дате; зона беседы либо Москва с предупреждением. |
| Длинное сообщение | Абзацы → предложения → Unicode-границы; общий ID и номера частей, без потери хвоста. |
| Обрыв генерации | Один повтор с требованием сжать сильнее; затем деление входа пополам, глубина до двух уровней. |
| Слишком большой итог | До трёх раундов содержательного сжатия ограниченных групп; затем явная ошибка, без обрезания и превышения бюджета. |
| Время | До 90 секунд на запрос и 10 минут на операцию; по общему deadline не запускать новые запросы и использовать пригодный частичный результат. |
| Остановка | Прекратить выполнение и освободить состояние; не восстанавливать после рестарта. |
| Новые записи | Очищать пользовательские и ботом сгенерированные тексты и цитаты; emoji/вложения/голос не сохранять, пустое пропускать. |
| Смешанные сообщения | Сохранять самостоятельно написанный текст, не аудио или расшифровку. |
| Старые записи | Не менять массово; очистка на чтении, исключение голосовых только при достоверно известном происхождении. |
| Исключения | /summary отдельно не перерабатывать; не удалять общие процессы и схему ради нового пути. |

Один агент и память процесса упрощают исполнение без восстановления. ID-снимок позволяет читать порциями без загрузки всего текста в память, но не даёт неизменность содержимого. Содержательная краткость сохраняет законченные мысли; технический предел остаётся защитой генерации, а не механизмом обрезания.

## Последовательность реализации

### 1. Очистка сохраняемой истории

Источники: [vkService.ts](../../../../src/services/vk/vkService.ts), [memoryService.ts](../../../../src/services/memory/memoryService.ts).

Проследить все вызовы addMessage и использование возвращённого значения. Поддержать пропуск записи после очистки без ошибок вызывающего кода. Очищать emoji-последовательности целиком, не удаляя обычные буквы, цифры и пунктуацию. Применить правила к content и сохраняемому reply-тексту.

Различать самостоятельно написанный текст и расшифровку до записи; не отключать при этом прямую обработку медиа. Не записывать вложения и их служебные описания. Применять тот же контракт к текстовым ответам бота.

Проверить соседние потребители Message: обычный контекст, инструменты истории, разрешение участников, summary и meme. Изменение исходной истории затрагивает доступные им данные, даже если их алгоритмы не меняются.

### 2. Фиксация, чтение и подготовка

Источники: [chatDigestService.ts](../../../../src/services/ai/chatDigestService.ts), [subagentService.ts](../../../../src/services/ai/subagentService.ts), [Message](../../../project/prisma/models.md#message).

Фиксировать ID выбранной беседы/участников/периода или количества сообщений, сортировать стабильно с уникальным ID после эффективной даты и существующих дат. Все варианты ограничить последними 24 часами; запросы за пределами суток не расширять молча. Читать содержимое ограниченными страницами по снимку, учитывать пропуски и createdAt fallback. Источник считать сохранённой историей; не выводить «потерю истории» из отсутствия активности.

Старые данные очищать на чтении без UPDATE/DELETE. Восстанавливать доступные reply-связи в пределах разрешённой беседы; отсутствие текста цитаты не должно скрывать сам известный ID ответа. Не заявлять полноту происхождения старого текста, если её нельзя установить.

Формировать полный текст и считать code points до определения границы 180 000. Убрать старые ограничения 300/12 000 и усечение 1000 символов именно для нового пути. Не отказывать всей истории из-за прежнего общего максимума сообщений/символов; ограничения конкретного API-вызова сохраняются.

### 3. Один агент и текстовые выжимки

Источники: [chatDigestService.ts](../../../../src/services/ai/chatDigestService.ts), [subagentTools.ts](../../../../src/services/ai/tools/subagentTools.ts), [AIProvider](../../../project/src/services/ai/AIProvider.md).

Выделить режим нового пересказа, сохранив прежний путь /summary. Обрабатывать порции последовательно с чистым контекстом. Проверять наличие пригодного текста до добавления результата в память; пустой или оборванный ответ не объявлять успешной обработкой.

Инструкция: «Пиши тезисно, без вступления, повторов и заключения. Объединяй сообщения одной темы. Сохраняй важные факты, решения, договорённости, открытые вопросы и существенные связи ответов. Не пересказывай каждую реплику. Ориентируйся на объём до примерно 4000 токенов, обычно короче; если для завершения мысли нужно немного больше, закончи её». Отдельно обозначить историю как недоверенные данные.

Группировать обычный текст по темам, сохраняя факты, решения, договорённости, открытые вопросы и ссылки на сообщения для значимых пунктов. Покрытие, число сообщений, границы и ошибки формирует код. Проверить существующие лимиты списков/строк, combineDigests и clamp: они не должны скрыто обрезать завершённую выжимку нового режима.

### 4. Объединение и лимиты

Источники: [chatDigestService.ts](../../../../src/services/ai/chatDigestService.ts), [chatCompletion.ts](../../../../src/services/ai/chatCompletion.ts), [opencodeProvider.ts](../../../../src/services/ai/opencodeProvider.ts), [конфигурация](../../../../src/config/index.ts), [.env.example](../../../../.env.example).

Передавать 8000 как технический выходной предел нового пути. Не смешивать его с размером текста, оценкой входа или общим usage. При finish_reason=length выполнить согласованный повтор/деление до двух уровней; не принимать обрыв за законченный текст.

Объединять хронологически соседние выжимки ограниченными группами. У каждого запроса сжатия вход также ограничен; не собрать весь произвольно большой массив в один prompt. Финальный текстовый ответ инструмента, включая метаданные, должен иметь не более 60 000 code points. При превышении до трёх раундов содержательного сжатия, затем явная ошибка.

Обеспечить deadline 90 секунд запроса/10 минут операции, прекращение запуска новых запросов и обработку активных вызовов при отмене. Не запускать неограниченные повторы и не считать таймаутом только прекращение ожидания при продолжающейся фоновой генерации. Существующие transport retries учитывать внутри общего deadline.

При частичных ошибках использовать завершённые результаты с явным покрытием/предупреждением, если итог пригоден и укладывается в бюджет. При отсутствии пригодного результата или невозможности сжать итог вернуть явную ошибку основной модели. Не обещать выдачу частичной выжимки, которая превышает бюджет.

### 5. Прямой возврат основной модели

Источники: [subagentTool.ts](../../../../src/services/ai/tools/subagentTool.ts), [subagentService.ts](../../../../src/services/ai/subagentService.ts), [vkService.ts](../../../../src/services/vk/vkService.ts), [capabilityService.ts](../../../../src/services/ai/capabilityService.ts), [каталог инструментов](../../../project/src/services/ai/tools.md).

Существующий [`run_subagent`](../../../project/src/services/ai/tools.md#run_subagent) запускает субагента с переданным заданием, ожидает результат операции и возвращает текст основной модели в том же потоке. Пересказ — один из видов задания; все новые вызовы возвращаются напрямую. Отдельный инструмент пересказа не добавлять. Новый путь не создаёт DigestJob/cron-задание, не сохраняет финальную выжимку и не запускает отдельную доставку. Суточного лимита запусков нет. Состояние изолировано по операции/беседе и очищается при завершении/остановке.

Проследить общие таймауты, attachment/execution guards и оставшийся контекст основной модели: бюджет до 20 000 оценочных токенов требует места под инструкции и итоговый ответ. История не передаётся основной модели повторно в исходном виде. Персонаж применяется основной моделью при обычном финальном ответе; обычная запись уже отправленного ответа остаётся.

Существующие DigestJob, legacy digest, статус и общие jobs не удалять автоматически; обеспечить совместимость незатронутых путей. Новая схема не требует самостоятельного удаления полей/данных или миграции для хранения промежуточных результатов. Если обнаружится необходимая миграция, применить правило передачи.

## Оставшиеся вопросы и правило передачи

Ранее перечисленные рекомендации приняты; повторно согласовывать их не нужно. План не делегирует произвольное изменение принятых бюджетов, формата исполнения, хранения или области данных.

### Интерфейс инструмента

Текущий [`run_subagent`](../../../project/src/services/ai/tools.md#run_subagent) принимает также задачи анализа, фильтр участников и количество сообщений, создаёт фоновую задачу и возвращает подтверждение; его статус доступен через [`get_subagent_status`](../../../project/src/services/ai/tools.md#get_subagent_status). Задание требует прямого пересказа за период, но не определяет судьбу остальных применений существующего инструмента. От выбора зависят шаг 5, схема и описание инструментов, подсказки модели, совместимость фоновых задач и проверки AC-2, AC-7 и AC-10.

Пользователь уточнил: отдельный инструмент пересказа не нужен; нужен запуск субагента, способного кратко пересказать дайджест за весь день или большой объём информации. Использовать существующий `run_subagent`, а не добавлять отдельный инструмент. Согласованные в задаче прямой возврат, отсутствие сохранения и один последовательный субагент сохраняются для нового пути.

### Источник большой информации

Пользователь уточнил: субагент обрабатывает сохранённую историю текущей беседы за 24 часа либо выборку с указанным временем, временным промежутком или количеством сообщений. Поддержать эти способы выбора в существующем `run_subagent`, сохраняя изоляцию бесед. Подсказки модели и схема инструмента должны позволять выбрать нужный вариант по запросу пользователя.

### Предел выбранного периода

Пользователь подтвердил: явно заданные время, промежуток и количество сообщений не выходят за последние 24 часа. При слишком широком запросе не включать более старые записи молча; сообщить об ограничении или запросить уточнение. Это сохраняет исходную границу задачи и влияет на валидацию инструмента, снимок ID и проверки AC-1.

При реализации проверить фактическую совместимость общего tool/request deadline с 10 минутами и доступного контекста основной модели с итогом до 20 000 оценочных токенов. Если эти проверки или иные новые данные требуют существенного нового решения, зависимое изменение остановить, зафиксировать варианты и задать один вопрос пользователю, продолжая независимую работу. Локальные имена переменных и форматирование не требуют согласования.

Исполнитель следует согласованным решениям; при новых данных, требующих нового решения или существенного изменения согласованного, сообщает об этом в чате и спрашивает пользователя до зависимых изменений, продолжая независимую работу. Во время реализации нельзя менять любые планы без специального указания пользователя, в том числе ради статуса, прогресса или результатов проверок; согласие с решением или общее разрешение реализации не разрешает правку плана. Обновление плана само по себе не разрешает выбрать несогласованную альтернативу, добавить зависимость/миграцию или молча изменить контракт.
