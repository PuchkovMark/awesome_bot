# План R11: удалить проверку доступа при получении истории

**Дата:** 20.11.2026. **Статус:** поведение, охват и удаление связанных тестов согласованы; подготовлен [подробный план реализации](implenent.md). Реализация не начата: сейчас код и тесты не менять.

**Основание:** [задача R11](task.md), [первый предложенный план](plan.md), обследование текущего рабочего дерева и последующие указания пользователя:

- «давай полностью уберем эту проверку из существующих методов»;
- «код пока не меняй»;
- «зафиксируй в плане удалить проверку из всех мест которые в табблице где она встречается»;
- «все связные тесты удалить запиши в план и запускай составление плана реализации».

Этот план заменяет прежнее предложение перенести/повторить проверку решением полностью удалить её из всех затронутых путей получения истории. [Первый план](plan.md) сохраняется как история предложения. Сейчас разрешено только зафиксировать решение в документах; изменение приложения этим запросом не разрешено.

## Согласованное решение и охват

**R11-N1 закрыто: удалить существующую проверку доступа во всех местах из таблицы, где она встречается.** Решение распространяется на обычное получение сообщений, поиск авторов и запуск/чтение истории субагентом, включая совместимую прежнюю ветвь его запуска. Ограничивать удаление только одним подключением в VkService нельзя.

Удаляемая проверка — checkReadToolAccess и аналогичный checkAccess у инструментов истории. Она запрещает вызов после начала доставки ответа, до положительного active-решения, при текущих quiet/maintenance, смене режима active-события либо ошибке получения роли/настроек. Удаление включает соответствующие callbacks в VK caller и фактические вызовы проверки внутри инструментов, а не только одну привязку или замену на callback, всегда возвращающий allowed=true.

Согласованное поведение: когда управление уже дошло до инструмента истории, получение сообщений и разрешение авторов не требуют этой дополнительной проверки. Входные ограничения обработки сообщения, правила отправки ответа и подключение tools остаются самостоятельными этапами.

В строках таблицы, где этой проверки нет, её не добавлять. Фильтры текущей беседы/пользователя, валидация, лимиты и прекращение завершённой/отменённой фоновой задачи сохраняются: это другие механизмы. Общий callback используется также инструментами вне таблицы; их поведение данным решением не изменяется.

## Проверенное текущее поведение

В [createLocalChatHistoryTool.execute](../../../../src/services/ai/tools/localChatHistoryTool.ts) порядок сейчас следующий:

валидация → поиск авторов при participants → возможный needs_clarification/not_found → проверки периода и бюджетов → checkAccess → getMessages.

[VkService](../../../../src/services/vk/vkService.ts) передаёт этому инструменту checkReadToolAccess, а getMessages связывает с [MemoryService.getHistoryPage](../../../../src/services/memory/memoryService.ts). Авторы определяются через resolveConversationParticipants в том же сервисе, только по сохранённым данным текущей беседы.

В [createSubagentTool.execute](../../../../src/services/ai/tools/subagentTool.ts) аналогичная проверка стоит до resolver и распространяется на прямую и прежнюю фоновую ветви запуска. VK caller передаёт отдельный callback с теми же условиями и общим checkToolAccess. Это отдельное место удаления, даже если оно не вызывает функцию с именем checkReadToolAccess.

Общий контракт исходного поведения: [get_local_chat_history](../../../project/src/services/ai/tools.md#get_local_chat_history), [run_subagent](../../../project/src/services/ai/tools.md#run_subagent), [VkService: AI-инструменты, действия и доставка](../../../project/src/services/vk/vkService.md#ai-инструменты-действия-и-доставка). Пока код не изменён, эти документы описывают исходный контракт; план фиксирует будущий переход.

## Удаление связанных тестов — согласованное решение R11-N2

Пользователь выбрал удаление тестов самой проверки доступа. В текущем дереве access-сценарии находятся внутри двух смешанных тест-кейсов:

| Файл | Где удалить сценарий проверки доступа | Очистка связанных fixtures |
| --- | --- | --- |
| [localChatHistoryTool.test.ts](../../../../test/localChatHistoryTool.test.ts) | В get_local_chat_history validates input and access удалить весь const denied и assertions denied.status/denied.message. Независимые проверки неверных аргументов сохранить; имя сократить до get_local_chat_history validates input. | Удалить type Access, options.access и checkAccess из makeTool. |
| [subagentTool.test.ts](../../../../test/subagentTool.test.ts) | В run_subagent validates input, period, and access удалить весь const denied и assertions denied.status/denied.message. Независимые проверки аргументов/периода сохранить; имя заменить на run_subagent validates input and period. | Удалить type Access, options.access и checkAccess из makeTool. |

Сохраняемый requests.length === 0 относится к основному экземпляру tool и проверяет, что неверные аргументы не вызвали чтение/запуск. Его не использовать как свидетельство работы удалённого guard.

Удалить все относящиеся к этому guard сценарии, моки и вспомогательные типы, если при реализации появятся дополнительные такие места. Связанные тесты не переписывать под фиктивный разрешающий guard и не заменять новыми тестами. Остальные сценарии этих файлов, тесты снимка и проверки других инструментов сохраняются. Сейчас удаление только запланировано.

## Сохраняемые условия

- Область данных задаёт caller: текущий peerId; для личного pager — также текущий senderId. Произвольную беседу модель не выбирает.
- Схемы инструментов, существующие статусы результатов и ошибок чтения, лимиты и пагинация сохраняются.
- Фильтр participants по-прежнему допускает 1–5 авторов, запрещён в ЛС, поддерживает прежние needs_clarification/not_found.
- Сохраняются периоды, TTL, формат снимка, бюджеты субагента и управление завершением/отменой его работы.
- Новые команды, настройки, таблицы и миграции не нужны.

## Проверки и ограничения

Обследование выполнено статически по текущему рабочему дереву с прежними незакоммиченными изменениями. На этапе подготовки документов проверки приложения, бот, VK, AI providers и рабочая БД не запускаются.

Решение о тестах принято явно: удалить R11-N2, а не адаптировать прежний отказ к новому поведению. Сохраняемые сценарии [localChatHistoryTool.test.ts](../../../../test/localChatHistoryTool.test.ts) проверяют пагинацию, бюджеты, строки сообщений, direct scope и participants. [subagentTool.test.ts](../../../../test/subagentTool.test.ts) проверяет преимущественно прежнюю ветвь без runDirect; её успешное прохождение не доказывает выполнение прямого субагента или реального SQL.

[subagentTools.test.ts](../../../../test/subagentTools.test.ts) и [vkMessageDeliveryIntegration.test.ts](../../../../test/vkMessageDeliveryIntegration.test.ts) относятся к сохраняемым снимку и окружающим active/delivery условиям; тестов удаляемого guard двух history tools в них не найдено. Проверки других guards из них не удалять. См. [карту проверок](../../../project/test/README.md).

После разрешения реализации выполнить статический поиск остаточных history guard и access-fixtures, затем npm run check в изолированном Node.js 22 по [operations](../../../project/operations.md). При необходимости диагностики использовать точные фокусные команды из [implenent.md](implenent.md). Отсутствие удалённого guard устанавливается по исходникам и типам; оставшиеся тесты подтверждают только собственные assertions. Дополнительные тесты на его отсутствие не создавать.

Миграции и изменения данных не нужны. Новые независимые сбои проверок не исправлять молча за пределами этой задачи.
