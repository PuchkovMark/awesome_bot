# Запуск и проверка

Проекту нужен Node.js 22.13 или новее. На целевом хосте Ubuntu 18 используется Docker: `Dockerfile` собирает приложение на `node:22-alpine`, а `docker-compose.yml` запускает отдельную миграцию перед приложением. Перед запуском нужен `.env` на основе `.env.example` с настройками VK и необходимых провайдеров. Подробности — в [README](../../README.md).

Compose монтирует `./prisma` и `./logs`; база по умолчанию находится в `prisma/dev.db`. Поэтому `docker compose up --build` выполняет миграции на настроенной базе и может влиять на работающего бота. Для проверки изменений используйте изолированные контейнер и базу, а не рабочую базу или боевые учётные данные.

Скрипты в `package.json`: `npm run build`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test` и объединяющий их `npm run check`. `npm run lint:fix` и `npm run format` изменяют файлы. `prisma:generate` генерирует клиент, а команды миграции изменяют состояние базы. Выбирайте проверки по задаче и запускайте Node.js-команды в подходящем контейнере. Пока новые тесты не требуются без отдельного запроса; существующие проверки можно запускать.

## Переключение на атомарную квоту изображений R09

Перед миграцией [image_daily_quota](../../prisma/migrations/20261120000000_image_daily_quota/migration.sql)
завершить все старые image-запросы и остановить все экземпляры старой версии,
записывающие ApiUsage. Затем применить миграцию и запустить новую версию.
Смешанная работа версий и откат на старый writer не поддерживаются: поздний старый usage
может не попасть в уже инициализированный счётчик. Принудительно оборванный запрос
с неизвестным исходом требует отдельного решения до переключения; отсутствие usage
не доказывает отсутствие генерации. Эти действия относятся к развёртыванию,
а не к проверке на рабочей базе.

Миграция добавляет таблицы без переписывания ApiUsage. Начальный расход автора/UTC-дня
переносится один раз внутри первой резервации, независимо от беседы.
Новые image usage получают createdAt времени резервации, поэтому завершение после
UTC-полуночи не попадает повторно в seed следующего дня.
После рестарта reserved остаётся занятым; TTL-release/cleanup/retry не предусмотрены.
Подробности — в [контракте квоты](src/services/image/imageQuotaService.md).

Регрессионные тесты R09 используют mkdtemp, синтетическую SQLite и подменённые VK/AI.
Проверки миграций выполняются только на отдельной базе. Сборка не запускает бота.
