# vkEvents

## События VK

В групповой беседе VK-обработчик распознаёт `chat_invite_user`, `chat_invite_user_by_link`, `chat_invite_user_by_message_request` и `chat_kick_user`. Для вступления по ссылке или заявке при отсутствии ID участника используется положительный ID отправителя. При наличии ID события `recordEvent` сохраняет `MembershipEvent` с типом `join` или `leave`, источником, автором и временем; положительный ID участника означает `user`, отрицательный — `community`. Уникальное ограничение `conversationId,eventId` отбрасывает повтор как `false`.

Для положительного ID вступившего `memberService.recordJoin` создаёт или обновляет `ConversationMember`, устанавливает `isPresent` и время вступления. По `lastJoinIntroductionEventId` условным обновлением резервируется обработка представления/анкеты для данного события. При включённом анкетировании сервис получает профиль: если он отсутствует, назначается приглашение с формой; при наличии ответы могут использоваться для представления. Приветствие определяется отдельной настройкой `welcomeEnabled`; повторное вступление получает отдельный текст приветствия. Повторная отправка приветствия как таковая этой проверкой не гарантированно исключается.

При `chat_kick_user` положительный пользователь помечается отсутствующим с `leftAt`; вызываются обработчики выхода обычных игр и мафии. Ошибки записи статистики и обработки вступления/выхода журналируются отдельно. Затем обработчик передаёт событие дальше через `next()` и не попадает в обычную обработку сообщения. Полная синхронизация списка участников больше не запускается; актуальная численность для статистики запрашивается у VK отдельно в [MembershipService.getStats](membershipService.md#статистика). Инкрементально сверено 20.11.2026 по membership-event ветке [vkService.ts](../../../../../src/services/vk/vkService.ts).
