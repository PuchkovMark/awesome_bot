# membershipService

**Тип:** сервис статистики и синхронизации состава. **Источник:** [membershipService.ts](../../../../../src/services/membership/membershipService.ts), `MembershipService`, `recordEvent`, `syncIfStale`, `getStats`, `formatMembershipStats`.

## Синхронизация состава

`syncIfStale` использует `syncLocks` внутри процесса и ограничивает синхронизацию одним местным днём на беседу. Зона выбирается из часового пояса беседы, зоны её местоположения или `Europe/Moscow`. Условное обновление `membershipLastSyncDay` происходит **до** загрузки участников из VK; при ошибке загрузки значение в показанном методе не откатывается, поэтому в этот же местный день повторная синхронизация не заявлена.

`fetchMemberIds` загружает страницы по 200, сохраняет положительные числовые ID и отклоняет пустой или неполный ответ, если VK сообщает ненулевое общее число. `updatePresentMembers` пакетами по 100 создаёт или обновляет присутствующих, а ранее отмеченных присутствующими, но отсутствующих в полученном наборе, помечает вышедшими. Синхронизация не создаёт `MembershipEvent`, поэтому история входов/выходов не восстанавливается задним числом.

## Статистика

`getStats` строит период `[now - days × 24h, now]` в UTC instant; `timeZone` нужен для форматирования даты начала. Параллельно считает `join` и `leave` события и группирует `join` по `memberId`. `uniqueMembers` — число групп; `returningMembers` — число ID с более чем одним входом; `repeatJoins = joined - uniqueMembers`; `net = joined - left`. Текущее число сначала запрашивается у VK (`count: 1`); невалидное значение, отсутствие API или ошибка приводят к fallback на `ConversationMember.isPresent=true` и `currentSource='db'`. Если начало периода раньше `membershipTrackingSince`, выставляется `partial`; пользовательский отчёт сообщает дату начала учёта и предупреждает о возможной неполноте данных базы. Публичная команда `/membership [дней]` ограничена администраторами бота и групповой беседой, допустимо 1–3650 дней, по умолчанию 30; эти ограничения находятся в command layer, сам `getStats` входные дни не валидирует.

`recordEvent` пишет сырое событие с уникальностью `conversationId,eventId`; дубликат Prisma P2002 возвращает `false`, остальные ошибки выбрасываются. Caller из `VkService` отправляет в историю join/leave для положительных пользователей и отрицательных community IDs; анкеты/приветствие применяются только к положительным пользовательским ID. Ошибка записи события журналируется отдельно и не прерывает обработку вступления/выхода.

Синхронизация состава не создаёт событий статистики. `fetchMemberIds` сохраняет только положительные безопасные целые `member_id`; если VK объявил непустой список, но вернул пустые или неполные страницы, выбрасывается ошибка до обновления локального состава. Успешные ID upsert-ятся транзакциями максимум по 100 операций; транзакция охватывает одну партию, не все страницы/партии вместе. Затем ранее присутствующие локальные ID, отсутствующие в выборке VK, пакетно помечаются вышедшими. Изменение `membershipLastSyncDay` предшествует сетевому запросу: ошибка после claim остаётся залогированной, но не освобождает сегодняшний слот.

Данные текущего состава и события статистики имеют разные источники и могут расходиться: membership event dedup применяется по `(conversationId,eventId)`, но синхронизация присутствия не backfill-ит историю. Внутренний `syncLocks` только process-local; условная запись дня является общей для БД. `getStats` делает три независимых агрегатных запроса, а текущий count получает отдельно; единой транзакционной snapshot границы нет.

Тестовые свидетельства: [`membershipService.test.ts`](../../../../../test/membershipService.test.ts) проверяет только форматирование результата, русские формы дней, признаки partial/db fallback и отрицательный net. [`membershipCommand.test.ts`](../../../../../test/membershipCommand.test.ts) проверяет aliases, доступность только bot admin/group, диапазон дней и передачу форматированных агрегатов с подменённым сервисом. Сами Prisma filters, event uniqueness, VK pages, batch writes, sync locks и API fallbacks тестами не покрыты; тесты не запускались.
