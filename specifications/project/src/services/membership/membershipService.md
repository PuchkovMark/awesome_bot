# membershipService

**Тип:** сервис событий участия и статистики. **Источник:** [membershipService.ts](../../../../../src/services/membership/membershipService.ts), `MembershipService`, `setApi`, `recordEvent`, `getStats`, `formatMembershipStats`. Инкрементально сверен 20.11.2026 по реализации R07 в рабочем дереве.

## Синхронизация состава

Полная ежедневная синхронизация удалена в R07: `syncIfStale`, pagination, batch writers и process-local lock отсутствуют. Membership event в [VkService](../vk/vkService.md) больше не запускает загрузку полного списка. Этот заголовок сохранён для существующих входящих ссылок.

`ConversationMember` остаётся у [MemberService](../member/memberService.md) для event-driven вступлений/выходов, анкет, представлений и модерации; `MembershipService` эту модель больше не читает и не изменяет. Поле [`ChatSettings.membershipLastSyncDay`](../../../prisma/models.md#chatsettings) сохранено как неиспользуемое legacy-поле; миграция и очистка прежних значений не выполнялись. Пропущенные события входа/выхода не восстанавливаются задним числом.

## Статистика

`getStats` строит период `[now - days × 24h, now]` в UTC instant; `timeZone` нужен для форматирования даты начала. Зона выбирается из `ChatSettings.timeZone`, затем `locationTimeZone`, иначе `Europe/Moscow`. Параллельно считает `join` и `leave` события данной беседы и группирует `join` по `memberId`. `uniqueMembers` — число групп; `returningMembers` — число ID с более чем одним входом; `repeatJoins = joined - uniqueMembers`; `net = joined - left`. Если начало периода раньше `membershipTrackingSince`, выставляется `partial`; это неполнота периода учёта, а не признак свежести состава. Публичная [команда `/membership [дней]`](../command/commands.md#command-membership) ограничена администраторами бота и групповой беседой, допустимо 1–3650 дней, по умолчанию 30; эти ограничения находятся в command layer, сам `getStats` входные дни и права не валидирует.

Текущая численность запрашивается только через `messages.getConversationMembers({ peer_id: Number(conversationId), count: 1 })`. Используется API из аргумента либо API, зарегистрированный `VkService.start()` через `setApi`. При safe integer `count >= 0` возвращаются `current=count`, `currentSource='vk'`, включая корректный ноль. При отсутствии API, исключении или невалидном count возвращаются `current=null`, `currentSource='unavailable'`; ошибки вызова/ответа логируются предупреждением. Локальный состав не читается, retries и кэш отсутствуют. Ошибки чтения настроек или агрегатов БД не преобразуются в этот результат и выходят из `getStats`.

`formatMembershipStats` при `current=null` выводит «Сейчас: недоступно», при `unavailable` добавляет «VK недоступен, поэтому текущее число участников определить не удалось». Остальные агрегаты сохраняются. Тип `MembershipStats.currentSource` и formatter по-прежнему допускают legacy `db` и прежнее предупреждение о данных бота, но production `getStats` больше не производит этот источник. При `partial` показывается дата начала учёта; при нулевых join/leave — сообщение об отсутствии событий. [`get_chat_info`, action `membership`](../ai/tools.md#get_chat_info) передаёт `current`/`current_source` модели без подстановки нуля или DB fallback.

`recordEvent` пишет сырое событие с уникальностью `conversationId,eventId`; дубликат Prisma P2002 возвращает `false`, остальные ошибки выбрасываются. Caller из `VkService` отправляет в историю join/leave для положительных пользователей и отрицательных community IDs; анкеты/приветствие применяются только к положительным пользовательским ID. Ошибка записи события журналируется отдельно и не прерывает обработку вступления/выхода.

## Данные и границы проверки

События `MembershipEvent` и текущий count VK имеют разные источники и могут расходиться. `getStats` делает три независимых агрегатных запроса, а текущий count получает отдельно; единой транзакционной snapshot границы нет. Этот сервис не содержит `$transaction` и не создаёт служебных lease/снимков. События хранятся без найденной retention job, в scope `conversationId`; персональные списки событий команда и tool не возвращают.

Тестовые свидетельства: четыре сценария [`membershipService.test.ts`](../../../../../test/membershipService.test.ts) проверяют форматирование, русские формы дней, partial/legacy `db` и отрицательный net, но не новый `null/unavailable`. Пять сценариев [`membershipCommand.test.ts`](../../../../../test/membershipCommand.test.ts) проверяют aliases, bot admin/group, период и форматированные агрегаты с подменённым сервисом. Восемь сценариев [`chatInfoTool.test.ts`](../../../../../test/chatInfoTool.test.ts) включают mock membership aggregates и guards. Согласно [ревью R07](../../../../tasks/completed/2026-11-19-audit-r07-membership-sync-recovery/review.md), ранее выполненный совместный прогон дал 17/17; при этой синхронизации тесты не перезапускались. Фактические Prisma filters, event uniqueness, VK count/ошибки и `null/unavailable` этими тестами не воспроизводятся; текущий error path сверен статически.
