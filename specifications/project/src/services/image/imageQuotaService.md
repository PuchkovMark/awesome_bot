# ImageQuotaService

**Источник:** [imageQuotaService.ts](../../../../../src/services/image/imageQuotaService.ts).
Общий устойчивый допуск `/image`, `/edit` и `generate_image`, независимо от беседы
и процесса. Использует общий Prisma client; конструктор допускает отдельный клиент
и часы без I/O. Лимит — `IMAGE_MAX_PER_USER_PER_DAY`, день — UTC.
Генерации мемов и приключений не используют эту квоту.

## Данные и операции

[ImageDailyQuota](../../../prisma/models.md#imagedailyquota) хранит расход автора/дня;
[ImageQuotaAttempt](../../../prisma/models.md#imagequotaattempt) — попытку с UUID.
Инвариант: `used = legacyUsed + count(status != released)`.
Prompt, фото, peer и стоимость в этих таблицах не сохраняются.

`reserve({ operationId, vkUserId, feature })`, где feature —
`image_generate | image_edit`, фиксирует время один раз. Первая операция короткой
interactive transaction — параметризованный `INSERT OR IGNORE` дневной строки,
чтобы получить writer lock до чтения старой статистики. Новая строка инициализируется
count существующих `ApiUsage` автора с этими features за `[dayStart, dayEnd)`;
значение не обрезается лимитом. Commit строки служит маркером завершённого seed.
Для существующего дня статистика повторно не прибавляется.

Затем проверяется operationId. Известный ID возвращает `already_processed`,
даже если попытка осталась `reserved` или ID повторён на следующий день.
Другой автор/feature с тем же ID — ошибка. Это защита внутреннего вызова,
а не дедупликация входящих событий VK.
Условный `updateMany(used < limit)` увеличивает расход; в той же транзакции
создаётся `reserved` попытка. Ошибка создания откатывает increment и seed.
Допуск возвращается только после commit:
`reserved` с operationId/utcDay/reservedAt либо `limit_reached`.
Ошибка/блокировка БД запрещает генератор; автоматических повторов нет.

`finish(operationId, consumed | uncertain | released)` выполняет guarded переход
только из `reserved`. Только успешный переход в `released` уменьшает расход
соответствующего дня в той же транзакции. Повтор/конфликт терминального исхода
не меняет расход. Неизвестный ID — ошибка. При release decrement разрешён только
если used > legacyUsed; отсутствие такого остатка откатывает переход попытки
как нарушение счётчика, без обрезания значения через max(0).
При сбое финализации исходный резерв продолжает занимать место.

## Границы исполнения и хранения

Резерв создаётся после проверки ввода, прав, конфигурации и фото, до генератора.
Только [ImageNotExecutedError](imageError.md) доказывает отказ подготовки до Images API
и разрешает release. Ошибки после обращения к API, moderation, timeout и пустой ответ
дают `uncertain`; SDK сохраняет собственные настроенные retries.
Готовый буфер даёт `consumed` до отправки в VK. Сбой finish логируется и не отменяет
доставку. Сбой upload/send/ACK не возвращает место и не повторяет генерацию.

Рестарт, возраст записи и UTC-полночь не освобождают резерв. Очистки, фонового
восстановления и команд управления нет. Незавершённая попытка учитывается постоянно
в исходном дне. `ApiUsage` остаётся статистикой после подтверждённой отправки,
со временем `reservedAt`; ошибка этой записи не влияет на квоту.
Перед переключением версии обязательна остановка старых writers после завершения
их запросов: [operations](../../../operations.md#переключение-на-атомарную-квоту-изображений-r09).

## Проверки

[imageQuotaService.test.ts](../../../../../test/imageQuotaService.test.ts) использует
синтетическую SQLite, реальные миграции, независимые клиенты и два процесса с IPC-барьером;
проверяет seed, rollback, release, терминальные состояния, рестарт и UTC-полночь,
fresh/upgrade и сохранность стоимости. Worker может завершиться после commit без finish.
[imageTool.test.ts](../../../../../test/imageTool.test.ts) проверяет адаптер инструмента;
[VK integration](../../../../../test/vkMessageDeliveryIntegration.test.ts) — обе production
точки допуска и конкуренцию команды/tool из разных бесед с отдельной SQLite.
Внешние VK/AI подменены; это не проверка живых сервисов или рабочей БД.

20.11.2026 исходники повторно сверены с [ревью R09](../../../../tasks/completed/2026-11-19-audit-r09-image-quota-atomicity/review.md).
Описанные тесты и fresh/upgrade пока не выполнялись; наличие assertions не
подтверждает успешный runtime. Эта синхронизация ограничена статическим чтением.
