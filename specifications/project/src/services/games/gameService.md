# `GameService`

**Тип:** раундовые игры, кроме мафии. **Символы:** singleton `gameService`; `start`, `handleNaturalMessage`, `shouldHandleMessage`, `handleCommand`, `handleTimeouts`, `expireDifficultyVotes`, `handleParticipantLeave`. **Источник:** [gameService.ts](../../../../../src/services/games/gameService.ts); определения и parsers — [gameEngine](gameEngine.md), очередь — [gameSessionLock](gameSessionLock.md). `/games` описан в [каталоге команд](../command/commands.md#command-games), игра мафия имеет отдельный [сервис](mafiaService.md).

## Состояние и запуск

Состояние v1 сериализуется в `GameSession.data`: вид/создатель/сложность/настройки, участники с именами и счётом, номер раунда и задание, deadline/remaining time, попытки, hints, использованные prompts и результаты, состояние ассоциаций/истории/правды, текущий отвечающий/команда, голоса, голосование сложности и `statsRecorded`. `getActiveSession` выбирает самую недавно обновлённую сессию текущей беседы со статусом `waiting|active|paused|round_complete`, кроме `mafia`. Невалидный JSON бросает ошибку; legacy-формат конвертируется в v1 с одним вопросом и пустым составом.

Все route calls, обрабатывающие состояние конкретной беседы, обёрнуты в процессный `serializeGameConversation`. `start` направляет mafia в `MafiaService`; остальные виды отвергают неизвестный ID, активную обычную игру и любое другое активное игровое приключение. Создаётся `Conversation` с `isGroup` по numeric peer ID, затем нормализуются настройки. В групповом `team` режиме создаётся `waiting`-сессия с ведущим и капитаном команды 1; первый второй участник запускает раунд. В остальных случаях первый раунд готовится сразу, а сессия сохраняется `active`. Ведущий случайно задаёт стартовое слово ассоциаций; игрок автоматически входит в состояние создателя.

Командный состав ограничен `maxParticipants`; новые игроки при team mode направляются в меньшую команду, при равенстве — в команду 1, первый участник команды становится капитаном. Уже присутствующему игроку обновляется имя, а не создаётся дубль.

## Подготовка раунда и AI

Каждый новый раунд очищает попытки, hints, голоса и голосование сложности; выбирает очередного игрока по кругу, команду по чётности раунда, ставит deadline из `timeLimitSeconds` (или без срока при нуле) и сбрасывает answering player/truth stage. `association` создаёт prompt с предыдущим словом, `story` просит одно предложение после последнего, `truth` адресует выбор текущему игроку. Остальные вопросы генерирует текстовая модель: вопрос+валидатор проходят максимум две пары попыток; загадка использует отдельный parser и тоже максимум две попытки. История последних до 15 заданий запрещает повтор. Если обе попытки не проходят структуру/валидацию, `prepareRound` бросает исключение.

Системные prompts маркируют category, задание, ответы и историю как данные, а не инструкции. Валидатор проверяет однозначность, сложность и то, что ответ не указан в вопросе/подсказках. В `quiz` с choices требуется ровно один верный вариант. Сбой AI checker трактуется как invalid/false. Подробные JSON bounds — в [gameEngine](gameEngine.md) и [riddleGeneration](riddleGeneration.md).

## Действия

`handleNaturalMessage` сначала распознаёт естественный запуск, иначе загружает активную сессию, отклоняет повторный `GameEvent`, разбирает действие и передаёт его в `handleAction`. Если текст не является действием, только `active` сессия принимает участника/ответ. Для обычного ответа неизвестный свободный текст обрабатывается только как reply-to-bot; `shouldHandleMessage` заранее выбирает явное действие, reply, правильный нормализованный ответ, команду голосования `who`, выбор/подтверждение `truth`, prefix `ассоциация:` или `продолжение:`. Natural game start регулируется `allowNaturalStart`.

| Действие | Контракт |
| --- | --- |
| `join` | Добавляет/обновляет игрока; если сессия `waiting` и игроков уже 2+, готовит первый раунд. В иных статусах также сохраняет присоединение, пока не достигнут cap. |
| `score` | Показывает счёт; сама ветвь не требует участия. |
| `repeat` | Через `renderSavedResult` читает сохранённый итог последнего раунда и текущий prompt либо финальный итог. Не вызывает commit, не создаёт GameEvent и не меняет updatedAt, очки или статистику; проверку участия не добавляет. |
| `hint` | Использует следующую заранее сгенерированную подсказку, ограниченную `hintsPerRound`; при исчерпании/отсутствии сообщает об этом. Каждая успешная выдача сохраняет state/event. |
| `pause` / `resume` | Только создатель, администратор бота или администратор беседы. Пауза сохраняет остаток deadline и снимает deadline; resume возвращает его относительно текущего времени. |
| `stop` | Те же полномочия; завершает игру досрочно и сохраняет статистику. |
| `pass` | Требует `active` и участника. В команде передать ответ может капитан текущей команды и переключает команду. В индивидуальной игре текущий отвечающий передаёт право следующему; если право ещё не было закреплено, передать может любой участник. |
| `skip` | Только `active`, при `allowSkip=true`; завершает раунд без победителя. |
| `next` | Требует `round_complete`, готовит следующий раунд без дополнительной проверки роли. |
| `team`, `captain` | Меняют состав/капитана только ведущий или администратор. ID вычищается до цифр; целевой участник должен существовать, team — 1/2. При переводе действующего капитана сервис назначает замену в старой команде, если есть подходящий игрок. |
| `change-difficulty` | Создатель/администратор применяет новый уровень со следующего задания. Обычный групповой участник запускает 30-секундное majority vote; собственный голос засчитывается сразу, для успеха/отказа нужно `ceil(participants/2)`. |
| `vote-difficulty` | Голосует только при активном голосовании; список участников/голосующих может расшириться до cap. Повторный голос в ту же сторону не удваивается; противоположная сторона не удаляет прежний голос. |

Ответы нормализуются NFKC/lowercase, `ё→е`, удаляются punctuation и повторные пробелы; допустим номер или A–E из choices. Командная игра принимает ответы только текущей команды; закреплённый отвечающий ограничивает individual mode. Неправильный reply длиннее двух символов проходит AI-сверку. Неуспешный ответ увеличивает personal attempts и `answers`; после `attemptsPerPlayer` сообщает об исчерпании попыток, но другой игрок всё ещё может ответить. Текст вне reply и не распознанный как ответ игнорируется. Персонажный вопрос `?` в reply использует отдельный AI checker, считает попытку и не раскрывает имя.

## Режимы вопросов и подсчёт

- `answer` (quiz/riddle/character/word/songfilm): первый правильный ответ закрывает раунд. Участник получает base points сложности, speed bonus за долю оставшегося времени и штраф за hints/ошибки; формула и bounds — в [`pointsForCorrectAnswer`](gameEngine.md).
- `truth`: только выбранный текущий игрок отвечает `правда` или `действие`; модель генерирует короткое задание до двух попыток, затем denylist блокирует опасные темы. `готово`, `сделал`, `сделала`, `выполнено`, `дальше` закрывают ход и начисляют базовые очки без speed bonus.
- `association`: нужен reply либо `ассоциация:`; после очистки слово должно иметь не менее двух букв/цифр и не встречаться раньше. AI checker оценивает связь с предыдущим словом и категорией; при успехе участник получает очки и завершает текущий раунд. Цепочка переходит к следующему вопросу, пока не достигнут лимит раундов.
- `story`: нужен reply либо `продолжение:` и 4–300 символов. Предложение добавляется к общей истории, игрок получает очки; последний раунд возвращает всю историю.
- `who`: голоса `за <имя|ID>` принимаются в reply либо префиксом; каждый голосующий выбирает существующего участника один раз. При завершении (все проголосовали или timeout) каждый лидер получает число полученных голосов как очки; tie даёт нескольких winners.

Если раунд не последний, `completeRound` сначала сохраняет `round_complete` и score delta, затем при `autoAdvance` готовит новый prompt. Ошибка подготовки не откатывает счёт и оставляет раунд завершённым, чтобы ведущий мог вызвать next. При последнем раунде `finishGame` фиксирует `statsRecorded`, выбирает победителей по score либо сумме очков команды, добавляет 3 очка каждому игроку победившей команды и транзакционно обновляет статистику/сессию. Ничья учитывает всех лидеров; при нулевом результате победителя нет.

`recordStats` обновляет `GamePlayerStats` отдельно для global и conversation scopes каждому участнику, включая `gamesPlayed`, wins, answers, accuracy source counts, best score, win streaks; признак `excludedFromGlobal` не мешает записи, но исключает игрока из global leaderboard. Победители получают `first-win`; пять global wins — `five-wins`. `/games privacy` меняет лишь этот фильтр отображения.

## Транзакции, таймауты и уход участника

`commit` в одной транзакции записывает optional `GameEvent`, положительные `GameScore` deltas и сериализованный `GameSession`. Unique conflict event ID (`P2002`) трактуется как повтор и не коммитит изменения. Без `eventId` дедупликации нет. Подготовка вопроса и часть прямых `gameSession.update` происходят вне этой транзакции; внутренняя сериализация действует только в одном процессе.

`handleTimeouts` выбирает `active` сессии раундовых игр с просроченным deadline. В `who` завершает подсчёт голосов; в остальных открытых играх закрывает раунд, для quiz/riddle/character/word/songfilm показывает первый правильный ответ. Затем запускает закрытие истёкших difficulty votes. Job вызывает методы каждые 10 секунд; обёртка и доставка сообщений описаны в [gameTimeoutJob](../../jobs/gameTimeoutJob.md).

`handleParticipantLeave` удаляет игрока/его голос, передаёт капитанство первому участнику команды и заменяет создателя первым оставшимся участником. Если уходит current player, его раунд завершается как пропущенный; пустая сессия помечается `finished` и `statsRecorded`, без обычного подсчёта статистики. Этот leave hook также сериализован локально.

## Команды и свидетельства

Прямой `handleCommand` для `repeat|повторить` выбирает текущую сессию, иначе `getLatestFinishedSession`: только раундовые виды игр текущей беседы, `state=finished`, `updatedAt DESC`. Новая текущая игра имеет приоритет над старым финалом. Без сохранённой сессии возвращается «Сейчас нет сохранённой игры.». Natural-action repeat по-прежнему работает через текущую сессию; изменяющие действия не получают доступ к finished.

`renderSavedResult` показывает ожидание и состав/счёт для waiting; последний `roundResults[].summary` и текущее задание для active/paused, с отметкой паузы; для round_complete — итог и предложение начать следующий раунд, без выдачи старого вопроса за новый. Для finished возвращает завершение, победителей и scoreboard. При восстановлении командных победителей учитывает уже начисленный бонус 3 очка при statsRecorded, не меняя сохранённых сумм; это сохраняет ничью при разном размере команд. Недостающий итог раунда или задание обозначаются явно. Чтение не вызывает AI, переход или повторное начисление; публичный результат доступен любому допущенному роутером автору в этой беседе, включая зрителя, а в ЛС выборка остаётся в текущем диалоге.

`handleCommand` делегирует mafia раньше других игровых действий; поддерживает список/help, local/global top, stats, privacy, start/options, join, difficulty, harder/easier, score, team/captain, pause/resume/stop, hint, skip, repeat, next, pass и запуск по alias вида игры. Неизвестный вход возвращает перечень доступных действий. Полный текст команд приведён в [каталоге](../command/commands.md#command-games).

В `test/` нет прямых игровых тестов `GameService`, `gameEngine` или round transitions. При закрытии R08 временный внешний стенд проверил 36 комбинаций timeout-переходов, повторное чтение и restart; полный существующий check прошёл 165/165. Эти проверки не стали постоянными тестами. Перечень и ограничения — в [карте проверок](../../../test/README.md#инкрементальная-сверка-r08--20112026).
