# MemeService

**Тип:** генератор изображений с мем-подписью и генератор мем-концепций из истории беседы. **Символы:** `MemeService.create`, `createFromContext`, `parseContextMemePlan`; singleton `memeService`. **Источник:** [memeService.ts](../../../../../src/services/fun/memeService.ts).

## Ручной мем `create`

`create(request, userId, conversationId, isChat, sourceImage?, imageDescription?)` сначала получает системную инструкцию выбранного персонажа. Идея обрезается до 1000 символов, нейтральное описание изображения — до 1200. Текстовый `AIProvider` должен вернуть JSON с `scene` и `caption`; код берёт первое regex-совпадение greedy `{[\s\S]*}`, разбирает JSON и проверяет обязательные строковые поля. Дополнительные ключи разрешены. После trim `scene` и `caption` должны быть непустыми, максимум 700 и 80 символов соответственно.

Prompt запрещает опасные/оскорбительные идеи, текст внутри изображения, идентификацию людей и выполнение инструкций из идеи/описания фото. При malformed JSON, ошибке парсинга или нарушении длин генерация завершается исключением без fallback-повтора.

`renderPlan` использует `ImageGenerationService.editBuffer` при наличии фото, иначе `generate` с требованием иллюстрации без текста/логотипов. Sharp читает размеры (fallback 1024×1024), разбивает подпись по словам примерно по `width/30` знаков и берёт максимум три строки, вычисляет размер шрифта в диапазоне 22–48px, добавляет полупрозрачную тёмную панель снизу и текст. XML escaping заменяет `&`, `<`, `>`; результат принудительно JPEG quality 90.

Сначала создаётся `FunOutput(kind=meme)` и удаляются более старые, чем последние 30 мемов данной беседы. Затем best-effort создаётся `ApiUsage(provider=openai, feature=meme)`; ошибка usage только журналируется. Возвращается JPEG buffer, ID и исходная подпись. Ошибка prune после create может оставить output, хотя метод завершится ошибкой.

## Мем из истории `createFromContext`

`createFromContext(conversationId, requesterId, kind, targetUserId?, isChat=true)` берёт настройки `MemeDayService`. Для weekly использует семь дней и до 100 записей; остальные виды используют сутки и до 50. Выбираются только `role=user` сообщения этой беседы с непустым `userId`, от новых к старым, затем список разворачивается в хронологический порядок.

Regex исключает сообщения с распознанными просьбами не использовать их для шутки/цитаты/публикации, упоминанием личного/конфиденциального, паролей, паспортов, здоровья, врача, больницы, телефонного номера или домашнего адреса. Извлекаются авторы и личные `FunPreference`; malformed JSON, не-объект, либо присутствующее `personalMemes !== true` считается opt-out. Отсутствующее поле трактуется как разрешение.

Для `kind=user` обязательны `targetUserId`, включённая настройка `allowParticipantMemes`, отсутствие ID в `excludedUserIds`, отсутствие opt-out и хотя бы одно подходящее сообщение целевого автора; иначе выбрасывается ошибка или возвращается `null` (нет сообщений). Отображаемое имя берётся из последнего сообщения автора с fallback «участник беседы». Для остальных видов исключаются opt-out сообщения; записи без связанной строки user остаются в общей выборке.

Если после фильтра нет минимум трёх сообщений — возвращается `null`. В модель попадают последние 30 подходящих сообщений по времени, каждое сначала очищается от email, URL и телефонов, whitespace сворачивается, строка обрезается до 500 символов; персональный вид подписывает только сообщения цели именем, остальные авторы обобщаются как «Участник».

К prompt добавляются до десяти последних опубликованных мемов этой беседы (темы, подписи, виды) и агрегаты их голосов. Цитировать сообщения дословно модель может только при `allowQuotes=true` и `kind=quote`; иначе prompt требует обобщённую тему. Для `kind=user` prompt разрешает только нейтральные темы сообщений выбранного пользователя. Контекст, темы и подписи помечены как недоверенные данные.

Ответ разбирает `parseContextMemePlan`, который ищет сбалансированный JSON-объект с поддержкой вложенных braces/escaped strings и принимает `{skip:true}` либо `skip:false, topic, scene, caption`; лимиты: topic 120, scene 700, caption 80, все непустые. При первом некорректном JSON делается один повтор с исправленной инструкцией; второй невалидный результат выбрасывает ошибку, `skip` возвращает `null`. Валидный план передаётся тому же renderer, сохраняет `FunOutput` и возвращается с `topic/kind`.

## Связанный процесс и проверки

`VkService` выбирает scheduled kind и проверяет членство/opt-out до персонального мемa; при отсутствии безопасной персональной идеи дневной выпуск повторяется как общий. `MemeDayJob` резервирует публикацию, проверяет недавнюю активность и управляет retry status. `publishMemeDay` отправляет JPEG, опциональную voting keyboard и stable `randomId` для планового schedule key, затем сохраняет publication; при исключении удаляет `FunOutput` и повторно выбрасывает ошибку. Подробности статусов/настроек — в [MemeDayService](memeDayService.md), маршруты — в [`/meme` и `/memeday`](../command/commands.md#command-meme).

Тестов `MemeService` или разбора `parseContextMemePlan` в `test/` нет; выбор контекста, privacy regex, opt-out, JSON retry и rendering описаны source-level, но не подтверждены автоматическими сценариями.
