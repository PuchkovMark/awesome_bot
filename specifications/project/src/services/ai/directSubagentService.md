# DirectSubagentService

[Реализация](../../../../../src/services/ai/directSubagentService.ts): `run(provider, request)` вызывается из [`VkService`](../vk/vkService.md) через [`run_subagent`](tools.md#run_subagent); `stop()` вызывается при [shutdown](../../bootstrap.md). Вызывает `SUMMARY_MODEL` через переданный `AIProvider`, без инструментов и внешней доставки. Задание, формат, период, выбор участников, текущая беседа и timezone поступают от caller. Дополнительная проверка доступа к истории отсутствует в вызывающем инструменте, сервисе и чтении снимка; область данных задаётся текущим `conversationId` из VK caller и сохраняется в запросах [historySnapshot](historySnapshot.md). Входной VK-маршрут и доставка ответа имеют собственные условия. Состояние, выжимки и снимок ID существуют в памяти процесса, `DigestJob` не создаётся.

## Обработка

[`createHistorySnapshot`](historySnapshot.md) фиксирует отсортированные ID, затем сервис читает страницы по 100 записей. Каждый фрагмент содержит время в зоне беседы, ID, автора и метаданные ответа; цитата и собственный текст разбиваются отдельно и подписываются. Отсутствующий `sentAt` заменяется `createdAt` и помечается приблизительным. Пропущенные при чтении ID и ошибки страниц отражаются в уведомлениях. Если timezone не настроена, caller передаёт московский fallback, а результат содержит предупреждение.

Системная инструкция требует нейтральный краткий текст по темам со ссылками на значимые сообщения, а также трактует историю как недоверенные данные. Один запрос, включая инструкцию, ограничен 180000 Unicode code points; часть лимита резервируется под служебные строки. Приближение в три символа на токен не является настоящим токенизатором. Длинные фрагменты делятся по абзацам, предложениям или code points с сохранением идентичности; детали — [historyTranscript](historyTranscript.md). `maxOutputTokens=8000` установлен явно независимо от `AI_MAX_OUTPUT_TOKENS`, мягкий ориентир ответа — около 4000 токенов. Внутри одной операции запросы последовательны.

При `AIOutputLimitError` выполняется один повтор с требованием сжать сильнее; при повторном обрыве вход делится по границам записей или, для одной записи, по тексту с повторением заголовка и номера подчасти. Рекурсивное деление ограничено двумя уровнями. Обычные ошибки дают сведения о пропущенных частях и сохраняют успешные выжимки; частично обработанное сообщение не считается полностью обработанным. До трёх раундов объединения с тем же входным ограничением уменьшают результат; при ошибке объединения пригодные исходные выжимки могут вернуться с предупреждением, если укладываются в бюджет. Результат с уведомлениями ограничен минимумом из 60000 code points и `maxOutputChars`; превышение после сжатия возвращает явную ошибку, не усечение.

## Ресурсы и ограничения

Для каждой беседы в процессе разрешена одна операция; отдельный отменяемый семафор ограничивает число одновременных запросов провайдера значением `SUBAGENT_PROVIDER_CONCURRENCY`. Таймаут операции — 10 минут, ожидания каждого запроса, включая очередь, — не более 90 секунд и оставшегося времени операции. Общая отмена при таймауте или остановке возвращает ошибку; готовый частичный результат при этом не гарантирован. `stop()` отменяет активные операции и ожидает их завершения; после перезапуска состояние не восстанавливается. Дневной лимит, старые ограничения размеров выборки и фоновые jobs к этому пути не применяются.

Пустая выборка, отсутствие пригодного результата, превышение бюджета и ошибка чтения обрабатываются отдельно. Это статический контракт; прямого теста в `test/` нет. Частные синтетические проверки ошибок, деления и метаданных перечислены в [ревью задачи](../../../../tasks/completed/2026-11-16-message-history-rework/review.md); реальный VK и внешняя модель там не вызывались.
