# Исполнение инструментов модели

Снимок: 2026-11-16, `2dbb190` с незакоммиченными изменениями рабочего дерева. Этот файл — канонический каталог секций инструментов; проверенные контракты раскрываются ниже, а состояние сверки и оставшиеся пробелы ведутся в [реестре покрытия](../../../coverage.md).

## Контракт и цикл

[AIProvider.ts](../../../../../src/services/ai/AIProvider.ts) определяет `AITool`: имя, описание, JSON Schema `parameters` и асинхронный `execute(args: unknown): Promise<string>`. [providerFactory.ts](../../../../../src/services/ai/providerFactory.ts) создаёт `OpenCodeProvider` для текстовой модели.

[chatCompletion.ts](../../../../../src/services/ai/chatCompletion.ts) проверяет уникальность имён доступных инструментов и передаёт их как функции OpenAI-совместимому API. При вызове модели разбирает JSON аргументов, находит инструмент по имени, вызывает `execute` и добавляет результат в историю с `tool_call_id`. Неизвестный инструмент, некорректный JSON, неподдерживаемый тип вызова и превышение лимита вызывают ошибку; результат с `finish_reason=length`, блокировка контент-фильтром и пустой ответ также обрабатываются как ошибки. Счётчик вызовов общий для ответа; значение по умолчанию — 10, если вызывающий код не задал другое.

## Где инструменты доступны

В финальном вызове [vkService.ts](../../../../../src/services/vk/vkService.ts) сценарий `questionnaireOnly` передаёт только `save_questionnaire`. В обычный набор входят инструменты времени, погоды, доставки, справки и исполнения команд, игр, локальной истории, субагентов, информации о беседе, местоположения, изображения, вложений, напоминаний и памяти. `decide_chat_response` добавляется, когда требуется решение для активного режима; `save_questionnaire` добавляется также в явно адресованной групповой беседе. Фактические контексты сведены в матрицу; каждый найденный публичный контракт описан ниже. `get_vk_info` отдельно описан как определённая, но не подключённая фабрика.

`subagentService.runPart` создаёт отдельный набор через [subagentTools.ts](../../../../../src/services/ai/tools/subagentTools.ts): `get_local_chat_history`, `search_history`, `summarize_history` и `get_current_datetime`. Инструменты истории работают по SQL-снимку; инструмент времени обращается к внешнему сервису. Субагент возвращает внутренний отчёт; для финальной генерации в другом вызове передаётся `tools: []`. Наличие factory-файла само по себе не означает, что инструмент доступен модели: `get_vk_info` определён, но не входит в provider tool arrays и рассмотрен отдельно ниже. Веб-поиск выполняется отдельной автоматической веткой до `provider.send`.

После ответа основной модели `commandResultDelivered` или `messageDeliveryGuard.hasAttempted` подавляет обычную отправку, чтобы избежать повторного ответа. При `questionnaireOnly` без попытки вызова анкеты ответ не отправляется; при требуемом решении активного режима без `true` сообщение обрабатывается как фоновое. Затем повторно проверяются настройки режима и обслуживания. Точные guards и callback side effects приведены в [VkService](../vk/vkService.md) и в каждом контракте ниже.

## Provider tool arrays и call sites

Статический поиск по `src/` обнаружил 12 выражений `AIProvider.send`; пять явно задают `tools` (три callable arrays и два вызова с пустым массивом), а семь остальных не передают `tools` и проходят без функций. Основная VK-обработка и часть субагента — единственные call sites с доступными модели инструментами. `getAIProvider()` сейчас создаёт `OpenCodeProvider` для каждого вызова, поэтому заданные arrays проходят через один `sendChatCompletion` tool loop.

Общие helpers в исходном каталоге инструментов имеют собственные спецификации в [индексе `tools/`](tools/README.md). В частности, строки `before`/`from`/`to`, разбираемые `parseIsoDateTime`, должны соответствовать точной грамматике из [dateTime.md](tools/dateTime.md); формулировка «ISO 8601 с часовым поясом» в отдельных tool-разделах является кратким обозначением этого ограничения.

## analyze_attachment

**Источник и доступность:** `createAttachmentTool` в [`attachmentTool.ts`](../../../../../src/services/ai/tools/attachmentTool.ts); подключается в обычном и active основном tool наборе, не передаётся в questionnaire-only и субагенту. `vkService` связывает его с `ImageAnalysisService`, `DocumentAnalysisService`, текущим VK event, `imageAccess` и текущими автором/беседой.

### Аргумент, выбор вложения и доступ

Принимает ровно `{ "prompt": string }`: ключ обязателен, `trim()` не должен быть пустым, длина исходной строки — не более 4000 символов, дополнительные поля запрещены. Пример: `{"prompt":"Опиши содержимое документа и выдели сроки"}`. `prompt` передаётся в выбранный анализатор после trim; модель не передаёт URL, user ID, peer ID или тип файла.

Сначала проверяется `getActionError` (active-mode decision, уже начатое/отправленное действие или полученные сведения VK), затем актуальный общий доступ (admin, режим, maintenance). В группе для не-администратора бота дополнительно требуется `imageAccess === 'all'`; admin беседы сам по себе этот барьер не обходит. В ЛС применяется общий доступ и scope текущего диалога. Отказ возвращает `not_allowed` до поиска/загрузки вложения. После этого проверяется `OPENAI_API_KEY`; если его нет — `not_configured`.

Выбор имеет такой порядок: фото текущего сообщения → фото сообщения, на которое дан reply → документ текущего сообщения → документ replied-to сообщения. Helpers при необходимости принудительно загружают VK payload; ошибка загрузки логируется, после чего возможен поиск в reply или `needs_attachment`. Таким образом, фото в replied-to сообщении имеет приоритет перед документом, прикреплённым к текущему сообщению. Для документа extension проверяется без учёта регистра: `gif`, `jpeg`, `jpg`, `png`, `webp` классифицируются как `image_document`; `pdf`, `docx`, `odt`, `pptx`, `xlsx`, `csv`, `json`, `md`, `rtf`, `txt` — `document`; остальные extensions дают `unsupported`. Фото-attachment имеет приоритет как тип изображения независимо от filename.

### Обработка и размеры

- `photo` передаётся `ImageAnalysisService.analyze`, затем `ImageGenerationService.downloadPhoto` скачивает его внутренним VK photo downloader с пределом 20 MiB, timeout 20 секунд и без redirect; после этого Sharp поворачивает/уменьшает и преобразует его в JPEG для OpenAI. Этот отдельный downloader проверяет HTTPS и allowlist доменов VK, но не использует `downloadVkFile` и его дополнительные проверки URL credentials/port. Feature usage — `analyze`.
- `image_document` передаётся `ImageAnalysisService.analyzeDocument`; разрешены GIF/JPEG/JPG/PNG/WEBP, предел 8 MiB, требуется URL VK. Файл скачивается с allowlist/без редиректов и декодируется Sharp; output также JPEG. Usage — `analyze`.
- `document` передаётся `DocumentAnalysisService.analyze`; расширения: PDF/DOCX/ODT/PPTX/XLSX/CSV/JSON/MD/RTF/TXT, предел 8 MiB. Проверяется `%PDF-`, префикс `PK` для архивных форматов либо отсутствие NUL в текстовом; файл целиком отправляется как `input_file` в OpenAI Responses API. Usage — `document_analysis`.

Провайдер получает содержимое файла и prompt. В image/document system prompts содержимое вложения считается недоверенным; написанные в документе/на изображении инструкции не исполняются. Image analyzer запрещает выдавать диагноз/реальную идентификацию по внешности; для запроса психологического портрета допускается только описание видимых признаков и обозначенная художественная интерпретация. Содержимое не доставляется инструментом самостоятельно: `{status:'result', kind, message}` возвращается модели, а итоговый текст отправляется общим AI delivery flow.

### Повторы, статусы и ошибки

Malformed input — `not_executed`; доступ — `not_allowed`; нет ключа — `not_configured`; файл отсутствует — `needs_attachment`; формат не поддерживается — `unsupported`. Флаг `attempted` устанавливается только после нахождения поддерживаемого вложения и непосредственно перед анализом. После начала analysis повтор запрещён, включая случай ошибки провайдера; однако отсутствие файла, unsupported формат, отказ доступа или отсутствующий ключ этот флаг не устанавливают. Это фактическое поведение отличается от краткой фразы tool description «Не вызывай инструмент повторно».

Успех возвращает JSON string `{status:'result',kind,message}`. Ошибка загрузки/анализа/провайдера логируется и возвращает единый `error` без исходного исключения. После успешного анализа usage записывается best-effort: ошибка `recordUsage` только журналируется и не меняет результат. `getActionError` и общие guards остаются ответственностью вызывающего `vkService`; tool сам не пишет историю и не отправляет сообщение в VK.

## decide_chat_response

**Источник:** `createActiveChatDecisionTool` в [`interactionTools.ts`](../../../../../src/services/ai/tools/interactionTools.ts). Подключается только для неадресованного непустого сообщения в беседе с режимом `active`, если нет ожидающего выбора памяти. В `normal`, ЛС, addressed request и `questionnaireOnly` инструмент отсутствует.

Schema — ровно `{ "respond": boolean }`; поле обязательно, дополнительные ключи запрещены. Некорректный ввод возвращает JSON `not_executed` с инструкцией передать true/false. Экземпляр принимает только одно валидное решение; повтор возвращает `not_executed`. При валидном вызове callback записывает решение в состояние текущей очередной обработки и возвращает `result`: true разрешает ответ и последующие действия, false оставляет сообщение без ответа.

Отказ от ответа не отменяет сохранение текста: handler сохраняет его как фоновое сообщение, может анализировать долгосрочную память и запускать разрешённую авто-реакцию. При true ответ проходит обычный AI flow. Решение не является авторизацией: остальные инструменты дополнительно проверяют режим, maintenance и права. Основной интеграционный сценарий решения и последовательности действий находится в [`vkMessageDeliveryIntegration.test.ts`](../../../../../test/vkMessageDeliveryIntegration.test.ts); отдельного unit-теста фабрики не обнаружено.

## execute_bot_command

**Источник и доступность:** [`createCommandExecutionTool`](../../../../../src/services/ai/tools/commandExecutionTool.ts); создаётся `vkService` для обычного и active-mode контекстов основного агента, отсутствует в `questionnaireOnly` и субагенте.

### Аргументы и разрешённые имена

Schema требует только строки `command` и `arguments`, `additionalProperties: false`; длина команды отдельно не задана, аргументы ограничены `MAX_INPUT_CHARS`. `command` после trim может иметь один ведущий `/` или `!`, затем сырой остаток должен соответствовать `^[\\p{L}\\d]+$`. Имя приводится через NFKC + `toLocaleLowerCase('ru-RU')` и таблицу псевдонимов. Допускаются канонические ключи `commandAliases` плюс специальные `анкета`, `удалить`, `подтвердить`. Наличие алиаса в нормализаторе не всегда означает доступность: например, псевдоним с `_` отвергается raw regex до нормализации.

Примеры: `{"command":"помощь","arguments":""}`; `{"command":"games","arguments":"adventure"}`. Текст с пробелом внутри `command`, неизвестное имя или чрезмерно длинные аргументы возвращают `invalid`. Команда и её аргументы передаются раздельно; несколько команд одним вызовом не поддерживаются.

### Выполнение и права

Каждый экземпляр инструмента принимает не более одной валидной попытки; флаг устанавливается до проверки роли/выполнения. Следующий вызов возвращает `not_executed`. Роль вычисляется на сервере по реальному `senderId` через `settingsService.isAdmin`; модель не передаёт идентификатор пользователя, peer или роль. Если проверить роль не удалось, вызов закрывается по умолчанию и возвращает `denied`.

Для команды из `isBotAdminCommand` требуются права администратора бота. Сейчас этот набор включает `model`, `effort`, `mode`, `maintenance`, `imageaccess`, `users`, `logs`, `admin`, `broadcast`, `membership` после нормализации имени. `подтвердить` всегда отклоняется инструментом: пользователь должен самостоятельно вызвать `/подтвердить удаление профиля`. `broadcast confirm ...` тоже запрещён, пользователь должен отдельно подтвердить рассылку. Для остальных команд инструмент не заменяет доменные проверки: `executeCommand` в `vkService` повторно проверяет maintenance, актуальный режим беседы, active-mode consent и затем передаёт команду в `runBotCommand`/`CommandService`, где выполняются дополнительные права и проверки состояния (например, беседные admin-команды). В тихом режиме обычным участникам доступны только специально разрешённые сценарии профиля участника.

### Результат и побочные эффекты

Инструмент возвращает JSON string со статусом `invalid`, `not_executed`, `denied` либо результатом, который вернул callback исполнения (`result`, `denied`, `not_executed`). Отказ отправляется в VK через `reportDenial`, если отправку не блокирует более раннее действие/active-mode guard; ошибка этой доставки только логируется, JSON-отказ всё равно возвращается. Успешная команда может прямо отправить сообщение или изменить состояние, используя текущего отправителя и беседу. При direct delivery `commandResultDelivered` подавляет обычный ответ модели. Для действий с отдельными подтверждениями код не обходит командный слой.

В `vkService` перед выполнением ещё раз проверяются `ChatSettings` и maintenance; если чтение этих данных не удалось, команда запрещается. Если ранее началось другое действие или доставка, возвращается `not_executed`. Для image aliases запрос дополнительно разбирается как image command, с теми же проверками доступа к медиа.

## generate_image

**Источник и доступность:** фабрика `createImageTool` в [`imageTool.ts`](../../../../../src/services/ai/tools/imageTool.ts); [`VkService`](../vk/vkService.md) создаёт её на основном пути модели и передаёт в обычный и active-mode tool set. В `questionnaireOnly` и инструментам фонового субагента она не передаётся. Системная инструкция просит использовать инструмент для новой картинки и правки присланного фото. Сервис изображений — [`ImageGenerationService`](../image/imageGenerationService.md), фактическая отправка идёт через `senderService.sendPhoto` в текущий `peerId`.

### Аргументы и валидация

Принимает ровно объект следующей формы; дополнительные свойства запрещены и схемой, и исполнителем:

| Поле | Тип | Обязательно | Ограничения |
| --- | --- | --- | --- |
| `action` | string | да | Точное значение `generate` или `edit`. |
| `prompt` | string | да | После trim не пустая строка; исходная длина не более 4000 символов. Исполнителю передаётся значение после trim. |

Примеры аргументов: `{"action":"generate","prompt":"Лесной пейзаж на рассвете"}` создаёт изображение; `{"action":"edit","prompt":"Преобразуй в акварель"}` редактирует выбранное фото. Фото не передаётся в аргументах: источник ограничен текущим событием VK.

Некорректная структура, неизвестное поле, неподдерживаемое действие, пустое после trim или слишком длинное описание возвращают JSON со статусом `not_executed`; исключение не выбрасывается. При этом схема декларирует `minLength: 1`, но проверку whitespace выполняет только runtime-валидатор.

### Права и последовательность проверок

1. Вызывается общий `checkToolAccess` из [`VkService`](../vk/vkService.md): заново читаются роль глобального администратора бота, настройки текущей беседы и maintenance. Ошибка чтения прав/настроек запрещает действие; maintenance запрещает его не-администратору; в группе не-администратору запрещён quiet mode; active event требует, чтобы текущий режим всё ещё был `active`.
2. Если отправитель не глобальный администратор бота, дополнительно требуется `imageAccess === 'all'`. Роль администратора самой беседы эту проверку не заменяет. При отказе возвращается `not_allowed` (общий отказ `checkToolAccess` возвращается как `not_executed`).
3. Если в runtime нет `OPENAI_API_KEY`, возвращается `not_configured`.
4. Считаются строки [`ApiUsage`](../../../prisma/models.md#apiusage) этого `vkUserId` за текущие UTC-сутки с feature `image_generate` или `image_edit`, без фильтра по беседе. При достижении `IMAGE_MAX_PER_USER_PER_DAY` вызов возвращает `limit_reached` до чтения фото или вызова провайдера. В [`.env.example`](../../../../../.env.example) и конфигурации [`IMAGE_MAX_PER_USER_PER_DAY`](../../../../../src/config/index.ts) значение по умолчанию — 20.
5. Для `edit` вызывается `getPhotoAttachment`: сначала фото текущего сообщения, затем фото сообщения, на которое оно отвечает; если attachment payload ещё не загружен, VK payload загружается принудительно. Документы и произвольные URL не подходят. При отсутствии фото возвращается `needs_photo`.
6. После проверок запускается activity типа `photo`. Генерация/редактирование, отправка и учёт использования выполняются внутри `try/finally`; activity останавливается в `finally`.

`checkToolAccess` не вызывает общий `getActionError`/`beginAction`: этот tool не проверяет `actionExecutionStarted`, `vkInfoReturned` и `messageDeliveryGuard` до обращения к генератору. Это отличается от ряда инструментов с явной блокировкой конфликтующего действия. Успешная отправка выставляет `commandResultDelivered`, поэтому `VkService` подавляет последующий обычный текстовый ответ модели; отдельный `beginAction` при этом не вызывается.

### Внешние вызовы, отправка и побочные эффекты

Для `generate` `ImageGenerationService` вызывает OpenAI Images API с `OPENAI_IMAGE_MODEL`, `quality=high`, `size=1024x1024`, `n=1`; SDK настроен на timeout 120 секунд и `AI_MAX_RETRIES`. Для `edit` сервис получает URL большого, затем среднего размера VK-фото; если URL отсутствует, загружает payload. Разрешены HTTPS URL хостов VK/userapi/vkuserphoto, без redirect, с timeout 20 секунд, размером до 20 МиБ и MIME JPEG/PNG/WebP. Sharp поворачивает фото по метаданным, вписывает в предел 2048×2048 без увеличения и кодирует JPEG quality 90; затем Images API получает файл и тот же размер/качество результата, что и при генерации. Сервис возвращает непустой PNG buffer.

Готовое изображение немедленно отправляется фото в текущую беседу с подписью, различающей генерацию и редактирование. Только после успешного `sendPhoto` вызывается запись `ApiUsage` с автором, текущей беседой, provider `openai` и feature `image_generate` либо `image_edit`; ошибки записи Usage логируются и не пробрасываются. После этого помечается факт отправки для подавления второго ответа. Tool возвращает JSON `{ "status": "result", "action": "generate" | "edit", "message": "Изображение отправлено в текущий диалог." }`, а не изображение или ссылку. Повторная генерация моделью не нужна.

### Результаты и ошибки

| `status` | Условие и поведение |
| --- | --- |
| `not_executed` | Неверные аргументы либо общий отказ проверки доступа/настроек. Содержит понятное модели сообщение. |
| `not_allowed` | Отправитель не глобальный администратор и `imageAccess` не равен `all`. |
| `not_configured` | Отсутствует `OPENAI_API_KEY`. |
| `limit_reached` | Достигнут дневной лимит; предлагается повторить завтра. |
| `needs_photo` | `action=edit`, но фото в текущем сообщении или reply не найдено. |
| `result` | Изображение уже отправлено; содержит `action` и подтверждающее сообщение. |
| `error` | Генерация, скачивание, преобразование или VK-отправка завершилась ошибкой. `moderation_blocked` получает отдельное сообщение о необходимости изменить описание; код VK `917` — сообщение об отсутствии доступа сообщества к беседе; прочие ошибки сообщают модель `OPENAI_IMAGE_MODEL`. |

Ошибки внутри генерации/отправки преобразуются через [`getSafeImageErrorDetails`](../image/imageError.md) и логируются с peer, sender, provider и моделью; moderation отказ логируется как warning, остальные ошибки как error. При ошибке до успешной отправки Usage не записывается и флаг подавления ответа не выставляется. Пользовательский prompt и содержимое изображения не добавляются в объект этих логов самим tool. Ошибка подсчёта дневного лимита происходит до `try/catch` инструмента и не преобразуется в один из перечисленных JSON-статусов. Между подсчётом и записью Usage нет атомарной резервации; следствие этого порядка — конкурентные вызовы могут одновременно пройти одну и ту же проверку лимита.

### Тестовые свидетельства и ограничения

Тесты используют внедрённый mock-сервис. ## get_bot_commands

**Источник и доступность:** [`createBotCommandsTool`](../../../../../src/services/ai/tools/botCommandsTool.ts); включён в обычный основной tool set и active-mode set; отсутствует в `questionnaireOnly` и субагенте.

Принимает только `{}` (`type: object`, пустой `properties`, `additionalProperties: false`). Исполнитель дополнительно требует, чтобы аргумент был объектом, не `null`/массивом и без ключей; иначе выбрасывает исключение `get_bot_commands does not accept arguments`, которое обрабатывает общий tool loop.

Каждый вызов асинхронно получает свежий `CommandToolContext` из текущего события: роль администратора, доступ к изображениям, режим беседы, выбранный персонаж, список доступных в текущем scope персонажей, `isChat`, provider label `opencode`, настройку голоса и `commandService.getCommandReference()`. Возвращает обычный текст, собранный из трёх частей: `buildBotCapabilities(context)`, перечень режимов игр (`id` и заголовок из `gameModes`) и command reference. Он только сообщает возможности и не выполняет команды/действия.

Capabilities отражают текущую настройку персонажа, normal/active/quiet, доступность поиска, времени, местоположения, голоса, медиа и заявленные правила доступа. Справка команд строится из help/admin pages и локализуется; сам tool не фильтрует справочную строку по роли и объединяет admin pages в ответ для любого контекста. Это расхождение между видимостью справки и доступом: наличие команды в справочном тексте не разрешает выполнение. `execute_bot_command` и доменные обработчики всё равно проверяют роль и доступ; capabilities не являются источником авторизации. Тестов фабрики/результата `get_bot_commands` не обнаружено; тесты в этом проходе не запускались.

## get_chat_info

**Источник и доступность:** `createChatInfoTool` в [`chatInfoTool.ts`](../../../../../src/services/ai/tools/chatInfoTool.ts), использует общие VK user-information helpers из [`vkUserInfo.ts`](../../../../../src/services/ai/tools/vkUserInfo.ts) и парсеры участников из `vkInfoTool.ts`. Контракт первого — [отдельная спецификация helper](tools/vkUserInfo.md); обработка участников для `get_chat_info` описана ниже в этом разделе. Tool подключается в основном и active-mode запросах, но отсутствует в `questionnaireOnly` и субагенте. Вызов требует общий `checkAccess` из `vkService` (maintenance, режим и решение active mode). Участники группы могут запрашивать сведения беседы/профили; статистика membership дополнительно только для администратора бота.

### Аргументы и несовпадения схемы с проверками

Обязательное `action`: `overview | members | member | birthdays | membership`; допустимы только поля `action`, `target`, `offset`, `count`, `days`, `sections`, `profile_fields`, `album_id`, `post_filter`. Неизвестные свойства отклоняются как `not_executed`.

| Поле | Ограничение реализации |
| --- | --- |
| `target` | До 200 символов, только для `member`; пустая строка эквивалентна self. `me`, `self`, `я` также выбирают автора; `reply` использует автора цитаты. Поддерживаемые VK ID/упоминания/ссылки разбираются `participantId`; иначе в беседе выполняется lookup по участникам. |
| `offset` | Только `members`, safe integer 0…`MAX_USER_INFO_OFFSET` (2,147,483,627). Для `member` отвергается, хотя schema description допускает списки разделов. |
| `count` | Safe integer 1–50. Проверка запрещает его для `membership`, но принимает также для `overview` (там он игнорируется) и `member`. Для `members`/`birthdays` это размер страницы/лимит; для `member` он применяется к коллекциям, если выбран соответствующий раздел. Schema description не перечисляет `member`. |
| `days` | Только `birthdays` (1–366) или `membership` (1–3650); по умолчанию 30. |
| `sections` | Только `member`, непустые уникальные значения: `profile`, `posts`, `friends`, `groups`, `albums`, `photos`. По умолчанию только `profile`. |
| `profile_fields` | Только `member`, непустой уникальный поднабор `PROFILE_FIELDS`; требует, чтобы `sections` включал `profile`. Если поле не передано, фабрика подставляет полный список `PROFILE_FIELDS`, а не список default полей низкоуровневого parser. |
| `album_id` | Только `member` с разделом `photos`; допустимы `profile`, `wall` или положительный/отрицательный числовой owner ID в установленном regex формате. |
| `post_filter` | Только `member` с `posts`; `all | owner | others`, default `all`. |

`sections`/`profile_fields` с неверным типом, пустым массивом, дублями или неизвестным значением, а также несочетаемые `album_id`/`post_filter` проходят в `parseUserInfoOptions`, который возвращает undefined; фабрика превращает это в `error` с общим сообщением о недоступности сведений, а не в `not_executed`. Это отличается от явных проверок `target`, `offset`, `count` и `days`, которые возвращают `not_executed`.

### Действия и scope

- `overview`: в группе вызывает `messages.getConversationsById` только для текущего `peerId`; требует ровно одну беседу с тем же ID и объект `chat_settings`. Возвращает ограниченный набор title, owner, member_count, state и флаги канала/исчезающих сообщений. В ЛС возвращает только `scope=direct`, текущие `peer_id` и `user_id`, без вызова VK conversation API.
- `members`: доступно только в группе; запрашивает страницу до 50 участников через `messages.getConversationMembers` и возвращает `total`, `offset`, `members`, `has_more`, `next_offset`. Каждая страница ограничена кэшем 10 минут по ключу peer/offset/count; профили участников кэшируются по ID на 60 минут. Список содержит пользователей и сообщества; участникам добавляются значения профиля и `hidden_fields` для не вернувшихся полей. В ЛС — `not_applicable`.
- `member`: без `target` возвращает профиль автора; `target=reply` — автора цитаты; явная строка может разрешаться как ID либо через поиск среди участников беседы. В ЛС чужой target запрещён. Возвращает user profile, разделы, и для совпавшего group member дополнительную `participant` запись (роль/join info). Пример: `{"action":"member","target":"reply","sections":["profile","posts"],"count":10,"post_filter":"owner"}`.
- `birthdays`: сканирует участников беседы либо только профиль автора в ЛС. Разбирает VK `bdate` форматов `d.m`/`d.m.yyyy`, но год рождения не раскрывает в выдаче; неподдерживаемые/приватные значения входят в `hidden_birthdays`. Часовой пояс берётся из контекста, иначе `Europe/Moscow`; рассчитывается ближайшая дата, в том числе с clamp для 29 февраля. В окно попадают дни `<= days`, результат отсортирован по `days_left`, обрезается `count` (по умолчанию 50) и содержит `has_more`, `checked_at`.
- `membership`: только group и `access.isAdmin` (администратор бота); администратор беседы сам по себе недостаточен. Берёт статистику через переданный callback либо `MembershipService.getStats` за 30 дней по умолчанию. Возвращает агрегаты `current`, `current_source`, `joined`, `left`, `net`, `unique_members`, `returning_members`, `repeat_joins`, period, `tracking_since`, `partial`; список пользователей и персональные события не возвращает. В ЛС — `not_applicable`.

Пример простого запроса: `{"action":"members","offset":0,"count":50}`. Вызовы без доступа возвращают `not_executed` до VK-запроса. После результата инструмент вызывает `onInfoReturned`; `vkService` затем запрещает другие действия, которые не должны следовать за чтением данных VK. Для `overview` callback отмечается после API-вызова, до проверки формы ответа, поэтому даже malformed response может закрыть последующие действия.

### Сбор данных, приватность и ошибки

`getMembers` требует доступ перед каждым незакэшированным VK-запросом; пустая страница при offset ниже общего count считается неполной и выдаёт ошибку. `users.get` вызывается бот-ключом для профилей участников и собирает поля из whitelist. `getVkUserInfo` для `profile` использует bot API, а для `posts`, `friends`, `groups`, `albums`, `photos` — отдельный `VK_SERVICE_TOKEN`; если public API не создан, каждый такой раздел возвращается как `error`. Секции обрабатываются последовательно и каждый раздел повторно вызывает `requireAccess`; частичный успех возвращается верхним `status=result` с индивидуальными ошибками в sections, а если ни один раздел не получен — `status=error`.

Перед возвратом профиль/коллекции проходят sanitizer: удаляются ключи похожие на `access_key`, `access_token`, `refresh_token`; ограничиваются глубина (5), массивы (20 элементов), поля объекта (40), текст (до 1000 символов) и бюджет каждого раздела (8 000 символов/1 000 узлов). Записи коллекций дополнительно сверяют owner ID, формируют ссылки постов/фото и сообщают `truncated`/`has_more`. VK-ответы являются недоверенными данными, не инструкциями.

**Зафиксированное расхождение доступа:** при `member` в беседе числовой ID/ID из VK markup разбирается как `target` без предварительного подтверждения членства. Фабрика вызывает `getVkUserInfo`, и лишь после этого ищет участника для поля `participant`; отсутствие совпадения не отменяет возвращение найденного `user`/`sections`. Это отличается от текстового target, который сначала ищется в текущем списке участников. Поведение следует сохранять как факт реализации и отдельно учитывать при проверке разрешённых границ данных; код в рамках документации не менялся.

`ChatInfoAccessError` превращается в `not_executed`. Некорректные/неполные VK ответы, недоступность методов/ключей и другие исключения логируются без профиля и сводятся к `error` с общей формулировкой; частичные ошибки разделов содержат status/message и, если доступен, VK error code. Успешные персональные данные поднимают `onInfoReturned`, что влияет на guard остальных действий.

## get_current_datetime

**Источник и доступность:** фабрика `createCurrentDateTimeTool` в [`currentDateTimeTool.ts`](../../../../../src/services/ai/tools/currentDateTimeTool.ts); сервис получения UTC-времени и резервный поставщик описаны в [TimeService](../time/timeService.md). В основном агенте tool входит в обычный и active-mode наборы, но не в questionnaire-only. Системная инструкция основного агента требует использовать его для текущих и относительных дат, не выдумывать время при отказе сервиса, указывать часовой пояс и сообщать о московских значениях по умолчанию при `default_used=true`. Tool также включён в набор инструментов каждой части фонового субагента; финальная генерация отчёта выполняется с `tools: []`.

### Аргументы и выбор часового пояса

Принимает объект с необязательным `time_zone` (string, максимум 128 символов), другие свойства запрещены. Если поле передано, оно должно быть непустым после trim; валидность проверяется `Intl.DateTimeFormat` до сетевого запроса. Некорректный тип, пустая/длинная строка, лишний ключ или невалидная зона дают `not_executed`. Даже сохранённая, но невалидная зона не заменяется автоматически значением по умолчанию.

Пример: `{"time_zone":"Asia/Kolkata"}`. Приоритет: `time_zone` из аргумента → часовой пояс выбранного scope → `Europe/Moscow`. В основном запросе scope выбирается по событию: в группе берутся только настройки беседы (`timeZone ?? locationTimeZone`), в личном диалоге — только настройки пользователя; настройки другого scope не используются. `VkService` передаёт динамический `getTimeZone` callback, поэтому после успешного `manage_location` тот же модельный цикл видит обновлённую зону. Инструмент не сверяет явно переданный `time_zone` с текстом текущего сообщения: любой валидный аргумент от модели используется как requested.

В субагенте зона считывается перед обработкой фонового задания из настроек текущей беседы либо автора и передаётся инструментам его частей; callback обновления не передан. Сам tool в субагенте использует `checkAccess`, всегда возвращающий allowed, потому что его вызов ограничен внутренним набором инструментов фоновой задачи. Он не читает историю и не проверяет состояние активности задачи.

Основной запрос проходит `checkReadToolAccess`: до внешнего вызова проверяется, не начата ли уже доставка сообщения, разрешено ли отвечать в active mode, а также актуальные maintenance и режим беседы. В группе quiet mode запрещает вызов не-администратору бота; для active event проверяется, что режим не изменился. Отказ возвращается как `not_executed` и не вызывает TimeService. Tool только запрашивает данные и возвращает результат модели; он не отправляет сообщение напрямую, не сохраняет результат и не меняет location settings. Общий access guard основного пути читает настройки через `SettingsService`, чьи getter-ы используют upsert.

### Результат и ошибки

Для валидного instant результат `result` содержит `source` (`timeapi.io` или `utctime.app`), `utc_datetime` в ISO UTC, `time_zone`, `time_zone_source` (`requested`, `chat`, `user` или `default_moscow`), `settings_configured`, `default_used`, локальные `date` (`YYYY-MM-DD`), `time` (`HH:mm:ss`), локализованный русский `weekday` и `utc_offset`. Форматирование выполняется через `Intl.DateTimeFormat('ru-RU')` с учётом DST и дробных смещений. `settings_configured` описывает сохранённую зону scope, а не наличие аргумента: валидная явно запрошенная зона при незаданных настройках даёт `settings_configured=false`, `default_used=false`, `time_zone_source=requested`. Если ни аргумент, ни контекстная зона не заданы, результат использует Москву и включает текстовое `note`, требующее сообщить пользователю о fallback.

Если оба источника времени отказали или вернули невалидные данные, `AggregateError` преобразуется в `error` с сообщением о двух недоступных источниках; другая ошибка запроса даёт общий `error`. Ошибка преобразования/форматирования даты также возвращает `error` без полей времени. В этих случаях tool не подставляет системные часы. Детали ошибки логируются только с её именем.

### Тестовые свидетельства и ограничения

В [`currentDateTime.test.ts`](../../../../../test/currentDateTime.test.ts) 14 тестов проверяют оба внешних источника и fallback, валидацию timestamp, выбор scope chat/user, явную зону, переход DST, московский default, аргументы/зоны, запрет запроса при отказе доступа, сообщения об ошибке и передачу tool result обратно модели через общий completion loop. Они используют mock-сервисы или локальный HTTP server; реальные time API не вызываются. Отдельный путь временного инструмента субагента проверяется наличием инструмента в [`subagentTools.test.ts`](../../../../../test/subagentTools.test.ts), но его конкретное форматирование и политика доступа отдельно не тестируются. Тесты в этом проходе не запускались.

## get_local_chat_history

Одно публичное имя имеет две реализации: основная модель читает локальные строки БД, а субагент — неизменяемый снимок своей части фоновой задачи. Схемы, результаты, лимиты и доступ различаются; не переносите аргументы или поля ответа из одного контекста в другой.

### Основная модель: локальная SQL-история

**Источник и привязка:** `createLocalChatHistoryTool` в [`localChatHistoryTool.ts`](../../../../../src/services/ai/tools/localChatHistoryTool.ts), создаётся `VkService` для текущего peer. Доступен в обычном и active-mode наборе, отсутствует в questionnaire-only и наборе субагента. В групповой беседе читает общую историю этого `conversationId`; в ЛС к нему добавляется ограничение текущим `senderId`. Используются `MemoryService.getHistoryPage` и `resolveConversationParticipants` ([контракт сервиса](../memory/memoryService.md)). Это локальная SQL-выборка, не запрос истории VK и не скачивание вложений.

**Аргументы:** принимает объект только со следующими необязательными полями (`additionalProperties: false`):

| Поле | Тип, предел и смысл |
| --- | --- |
| `before` | ISO 8601 с `Z` или смещением зоны; включительная верхняя граница по `createdAt`. Будущее значение отклоняется. По умолчанию используется время самого старого сообщения в текущем prompt-контексте; если якоря нет — текущее время. Уже показанные сообщения при обычной выборке исключаются. |
| `from` | ISO 8601 с `Z` или смещением; включительная нижняя граница по `createdAt`. Не может быть в будущем и должна быть раньше эффективного `before`. |
| `limit` | Целое безопасное число 1–50, по умолчанию 20. |
| `participants` | Только в беседе: массив из 1–5 непустых строк до 120 символов. Принимает имена, полные имена и поддерживаемые формы VK ID. Повторяющиеся после trim строки удаляются. |

Пример: `{"limit":20}`. Фильтр авторов разрешён только для бесед; в ЛС возвращается история текущего пользователя без возможности запросить другого автора. Парсер распознаёт URL/`screenName` VK, но resolver сопоставляет разобранное имя с сохранёнными именами авторов, а не запрашивает соответствие у VK.

**Выбор участников и проверка доступа:** авторы разрешаются по пользователям, для которых в этой беседе уже сохранены пользовательские сообщения; текущий состав VK не запрашивается. Используется отображаемое имя, последнее сохранённое имя автора или VK ID; имя сравнивается точно, затем применяется сопоставление падежной формы. `Пенёк`, `пенек`, `пенечек`, `бот`, `bot` и текущее имя персонажа разрешаются как бот. Однозначно неизвестный автор возвращает `not_found`; неоднозначный — `needs_clarification` с кандидатами, их именами/VK ID, найденными участниками и списком отсутствующих ссылок. При совпадении имени бота и пользователя также требуется уточнение. Общий resolver описан в [MemoryService](../memory/memoryService.md).

При успешном разрешении вызывается `checkReadToolAccess`: он проверяет запрет после попытки `AiMessageDeliveryGuard`, необходимость положительного active-mode решения, затем актуальные права/режим и maintenance. Только после разрешения доступа вызывается `getHistoryPage`. **Порядок имеет значение:** разрешение участников и формирование ответов `needs_clarification`/`not_found` происходят до access guard; эти ветви могут вернуть список кандидатов без вызова `checkAccess`. Тесты инструмента не проверяют этот порядок и его достижимость через все верхние ветви VK-маршрута. Tool не вызывает `beginAction`, не изменяет данные и не отправляет сообщение в VK.

**Границы SQL-выборки:** без фильтра участников выбираются роли `user` и `assistant`; в режиме участников выбираются только соответствующие `user` ID и, если указан бот, `assistant`. В ЛС выбор дополнительно ограничен внутренним ID автора. `getHistoryPage` сортирует строки по `createdAt DESC, id DESC`, берёт `limit + 1` для `hasMore` и возвращает полученную страницу в хронологическом порядке. История не имеет дополнительного временного TTL внутри этого запроса: читаются сохранившиеся строки, соответствующие периоду и scope; доступность старых сообщений зависит от очистки истории (см. [задания очистки](../../jobs/README.md)).

Обычная выборка начинается от `defaultBefore` и исключает ID уже включённых в prompt сообщений, а также ID, возвращённые предыдущими вызовами инструмента. В режиме `participants` начальная граница по умолчанию — текущее время, а исключаются только сообщения, уже возвращённые этим инструментом: подходящие сообщения, которые уже были в контексте, могут снова появиться с `in_context: true`. Курсор `next_before` равен времени самого старого возвращённого сообщения; `before` включителен, а исключение уже выданных ID предотвращает повтор страницы. `oldest_available` ищется по базовому scope/фильтру авторов и не ограничивается `from`, `before` или выданными ID.

**Ответ и ограничения:** каждое сообщение содержит `time` (ISO по `createdAt`), `speaker`, `role`, `text`; возможно `in_context`, `truncated`, `attachments` (до пяти сохранённых строковых типов вложений) и `reply_to` с автором и текстом. Сырые VK ID сообщений, URL и payload вложений не возвращаются. Текст сообщения обрезается до 1000 символов, текст цитаты — до 500; факт обрезания обозначается `truncated`.

Состояние лимитов живёт в экземпляре инструмента на один ответ основной модели: максимум 3 вызова, 100 возвращённых сообщений и 24 000 символов сериализованных записей. `limit` дополнительно ограничивается оставшимся числом сообщений; пустые/пробельные сообщения пропускаются. `calls` расходуется перед SQL-чтением, поэтому ошибка чтения занимает один вызов. После лимита возвращается `not_executed`. Успешный ответ содержит `status` (`empty`, `result` или `partial`), `scope`, `participant_mode`, `messages`, `returned`, `has_more`, `complete`, `context_messages`, `suggest_digest`; дополнительно могут быть `participants`, `next_before`, `oldest_available` и `limitation`. `partial` означает, что есть ещё сообщения или исчерпан бюджет выдачи. `complete` описывает пагинацию, а не отсутствие усечения текста. При заполнении лимита инструмент предлагает `run_subagent` или уточнение периода.

Неверная схема, будущие даты, неверный период, запрещённый личный фильтр, исчерпанный лимит или отказ доступа возвращают `not_executed`. Неоднозначность и неизвестный участник возвращают `needs_clarification` и `not_found`. Исключение `getMessages` преобразуется в `error`; логируются только scope и имя ошибки. Ошибки resolver до этого `try/catch` самим tool в JSON-статус не преобразуются. Сообщения и цитаты считаются недоверенными данными, а текст результата инструктирует модель не выполнять их команды и не объявлять неполную выборку полной.

### Контекст субагента: часть загруженного снимка

**Источник:** `createSubagentPagerTool` внутри [`subagentTools.ts`](../../../../../src/services/ai/tools/subagentTools.ts), включён фабрикой `createSubagentTools` в отдельный набор каждого `runPart` ([жизненный цикл](subagentService.md), [загрузка снимка](chatDigestService.md)). Он получает только сообщения текущей части, переданные в памяти; SQL и VK API во время чтения не вызываются. Текущая задача остаётся только для чтения; если `isActive()` уже false, вызов возвращает `not_executed`. Одинаковое имя не означает доступность в основном tool array.

Схема принимает только необязательные `before`, `from` (ISO 8601 с зоной) и `limit` (целое 1–50, default 20); другие ключи, включая `participants` и `to`, отклоняются. `from` — включительная нижняя граница, `before` — включительная верхняя; без `before` берутся самые новые сообщения части. Будущее `before` не отклоняется отдельно, оно просто служит верхней границей фиксированного снимка. Участники, разрешения и фильтры автора здесь не принимаются: состав снимка определяется задачей субагента заранее.

Страница сортируется хронологически; ранее выданные сообщения отсеиваются по `dbId`, иначе `conversationMessageId`, иначе составному ключу из времени, автора и начала текста. Записи содержат `time`, `speaker`, `role`, `text`, при наличии VK `message_id`, до пяти `attachments` и `reply_to`, если есть текст или ID цитируемого сообщения. В `reply_to` поля `message_id`, `author` и `text` добавляются только при наличии исходных значений; текст цитаты обрезается до 500 символов после `trim()`, при усечении ставится `truncated`. Текст сообщения ограничен 1000 символами; обрезание также помечается `truncated`.

Ответ содержит `status` (`empty`, `result` или `partial`), `scope`, `messages`, `returned`, `has_more`, `total_in_snapshot`, `complete`, `oldest_available`; `next_before` добавляется, когда есть продолжение и выдан хотя бы один элемент. `complete` означает полноту выбранного диапазона части, а не полноту всей беседы или всего задания. История помечается как недоверенная.

Пределы — до 3 вызовов, 100 сообщений и 24 000 символов сериализованных записей. Экземпляр pager создаётся заново на каждую часть в `runPart`, так что эти пределы применяются к каждому контексту части отдельно. Бюджет уменьшает только реально добавленная запись; при нехватке символов страница возвращает `partial`. Ошибочная схема/дата, неактивная задача и исчерпанные лимиты дают `not_executed`; пустая выборка — `empty`. Отдельный SQL error branch отсутствует, так как чтение идёт из массива в памяти.

### Тестовые свидетельства и пробелы

[`localChatHistoryTool.test.ts`](../../../../../test/localChatHistoryTool.test.ts) содержит 12 тестов основной реализации: якорь/курсор и неповторение, лимиты вызовов/сообщений/символов, обрезание, пустой результат, аргументы/доступ, direct scope, participant filter/`in_context`, запрет фильтра в ЛС и ambiguous/not-found. Store, resolver и access guard заменены mock-ами; реальные Prisma-условия и порядок participant lookup относительно доступа ими не проверяются.

В [`subagentTools.test.ts`](../../../../../test/subagentTools.test.ts) pager затрагивают три сценария: страницы и `next_before`, ID сообщений и reply target (вместе с поиском), состав read-only набора инструментов. Они работают с фиксированным массивом; раздельный тест budgets, `isActive` для pager и SQL-загрузка каждого чанка не обнаружен. Тесты не запускались.

## get_subagent_status

**Источник и доступность:** фабрика `createSubagentStatusTool` в [`subagentStatusTool.ts`](../../../../../src/services/ai/tools/subagentStatusTool.ts). Инструмент входит в обычный и active-mode набор основной модели; отсутствует в `questionnaireOnly` и отдельном наборе субагента. `VkService` привязывает его к `peerId` текущего диалога и передаёт `checkReadToolAccess` и `subagentService.getLatestStatus`. Результат задачи хранится в БД и не добавляется в обычную историю сообщений; продолжить разговор по нему можно, запросив этот инструмент.

### Аргументы и область статуса

Принимает только пустой объект `{}`; `additionalProperties: false`. Любой ключ, `null`, массив или иной не-объект возвращает `not_executed` с сообщением, что аргументы не принимаются. Пример: `{}`.

Сервис выбирает запись [`DigestJob`](../../../prisma/models.md#digestjob) с максимальным `createdAt` для `conversationId` текущего peer. Запрос не фильтрует по `userId` или `kind`: в групповой беседе отображается последняя задача беседы вне зависимости от автора. Текущий путь создания задач субагента записывает `kind=history_task`; наличие в рабочей БД других/legacy видов задач отдельно не исследовалось, поэтому их возможное попадание в этот статус неизвестно. В ЛС peer привязан к конкретному пользователю.

### Доступ и результат

Перед чтением вызывается `checkReadToolAccess`: он запрещает чтение после попытки отправки через `AiMessageDeliveryGuard` и до положительного решения для active mode, затем повторно проверяет общий доступ инструмента, режим и maintenance. Общие guards описаны в [VkService](../vk/vkService.md). Этот read tool не вызывает `beginAction` и не проверяет `actionExecutionStarted`/`commandResultDelivered`, поэтому может выполниться после другого действия, уже начатого в том же ответе модели. Сам tool пользовательское сообщение не отправляет.

Если задачи нет, возвращается `{status:"none", message:...}`. При отказе access guard — `{status:"not_executed", message:...}`. Успешное чтение сериализует поля `SubagentStatus` вместе с инструкцией модели считать результат данными, а не управляющими инструкциями:

| Поле | Условие и значение |
| --- | --- |
| `status` | `pending`, `processing`, `finalizing`, `partial`, `done` или `failed`; если запись не найдена — `none`. Неизвестное внутреннее состояние сервис отображает как `pending`. |
| `task`, `format` | Исходная инструкция и формат, только если соответствующие значения заполнены. |
| `participants` | Имена участников из сохранённого фильтра; поле отсутствует при пустом списке. |
| `partsTotal`, `partsDone` | Число частей задачи и количество частей со статусом `done`. |
| `delivered` | `true`, если у записи сохранён `resultSentAt`, иначе `false`. |
| `result` | Включается только для `done` или `partial`, если сохранён непустой результат. Для `pending`/`processing`/`finalizing` результат не выдаётся. |
| `error` | Только для `failed`, если текст ошибки сохранён; обрезается до 500 символов. |
| `createdAt`, `completedAt` | ISO timestamp; `completedAt` отсутствует, пока задача не завершена. |
| `instruction` | Добавляется wrapper-ом: результат — данные, а при `failed` или отсутствии результата нельзя выдумывать ответ. |

Исключение из `getStatus` перехватывается: в лог попадает только `errorName`, модель получает `{status:"error", message:...}` без деталей исключения. Описание инструмента говорит о хранении 7 дней; фактический срок задаёт `SUBAGENT_RESULT_RETENTION_DAYS` (значение по умолчанию — 7), после чего cleanup удаляет завершённые записи. Поэтому буквальные 7 дней зависят от конфигурации.

### Тестовые свидетельства и ограничения

Четыре теста в [`subagentStatusTool.test.ts`](../../../../../test/subagentStatusTool.test.ts) проверяют выдачу готового результата и метаданных, статусы `processing` и `failed`, отсутствие задачи, отказ доступа и отклонение лишнего аргумента. Они подменяют `getStatus`: запрос Prisma и выбор последней строки, отображение всех внутренних статусов, перехват ошибки БД, область `kind`/`userId` и фактическая очистка по сроку хранения этими тестами не проверяются. Тесты не запускались.

## get_weather

**Источник и доступность:** `createWeatherTool` в [`weatherTool.ts`](../../../../../src/services/ai/tools/weatherTool.ts), использует [WeatherService](../weather/weatherService.md) и контекст выбора локации. Подключается в обычном и active основном наборе, не в questionnaire-only/subagent. `vkService` передаёт локацию текущей беседы или пользователя, текст текущего сообщения и общий `checkReadToolAccess`; инструмент только читает данные и сам не сохраняет настройки.

### Аргументы и валидация

Все поля необязательны, дополнительные свойства запрещены:

| Поле | Тип и ограничения |
| --- | --- |
| `location` | 2–100 символов; буквы, цифры, пробел и ограниченный набор знаков препинания. Это имя населённого пункта, не адрес. |
| `region` | 2–100 символов и тот же набор символов; требует `location` или координаты. |
| `country_code` | Ровно две латинские буквы; требует `location` или координаты, приводится к upper case. Код страны не проверяется по фактическому ISO справочнику. |
| `latitude`, `longitude` | Должны идти парой; валидные конечные числа в диапазонах −90…90 и −180…180. |
| `time_zone` | Валидная IANA зона, строка максимум 128 символов; допускается только при переданной широте (валидатор координат требует также долготу). |
| `geocoding_source` | `geonames` или `openstreetmap`; допускается только при координатах. Служит attribution для уже выбранной точки, не переключает поиск города. |
| `forecast_days` | Целое 1–7, default 1. Поскольку период отсчитывается от текущего времени, прогноз «на завтра» требует как минимум 2 суток. |

Невалидная комбинация, неизвестный ключ, запятая в `location` вместе с отдельным `region`, непарные координаты, `region/country_code` без места или недопустимая строка возвращают JSON `not_executed` без внешнего запроса. Пример прямого места: `{"location":"Воронеж","region":"Воронежская область","country_code":"RU","forecast_days":2}`. Пример уже выбранной координаты: `{"latitude":55.75,"longitude":37.62,"time_zone":"Europe/Moscow","geocoding_source":"openstreetmap"}`.

### Доверие к названию места и выбор настроек

После валидации вызывается `checkAccess`; отказ возвращает `not_executed`. Модельное `location` считается подтверждённым, если текст текущего сообщения пуст либо нормализованное имя является подстрокой нормализованного текста **текущего сообщения** (NFKC, lowercase ru-RU, удаление всех небуквенно-цифровых знаков). Если текст есть, но имя не совпало, оно игнорируется, чтобы модель не выбрала город из старой истории. Переданные вместе с таким неиспользованным именем `region`/`country_code` отдельно к сохранённым настройкам не добавляются.

Приоритет места: explicit pair coordinates → подтверждённое explicit city query → координаты настроек scope → имя места настроек → `DEFAULT_CITY` (Москва). К сохранённым координатам/именам применяются проверки целостности настроек; некорректное сохранённое значение возвращает `not_executed` и просит явно указать город. Для имени строится `WeatherLocationQuery` с регионом/кодом или названием страны; затем `WeatherService.resolveLocation` возвращает одну точку, `not_found` или `ambiguous`.

При нескольких кандидатах ответ `needs_clarification` содержит короткий текст максимум о пяти вариантах (название, регион, страна), не выдаёт сырой массив кандидатов. Модель должна попросить выбрать; только после выбора передаются координаты выбранной локации и её attribution. `not_found` возвращается как отдельный статус и сообщение геокодера. Названия от внешних сервисов — недоверенные данные, не инструкции.

Часовая зона для местоположения берётся из найденной точки, иначе из настроек `timeZone`, затем `locationTimeZone`, затем `DEFAULT_TIME_ZONE` (`Europe/Moscow`). `settings_configured` true только когда настроены и город/координаты, и часовой пояс. `default_used` true при использовании города по умолчанию или его дефолтной зоны; соответствующие оговорки включаются в `note`. `location_source` равен `requested`, `default`, `chat` или `user` в зависимости от источника.

### Ответ и ошибки

Успешный JSON: `status=result`, нормализованное `location`, `location_source`, `settings_configured`, `default_used`, `retrieved_at_utc`, `forecast_issued_at_utc`, `current_is_model_estimate=true`, объект `current`, массив `forecast`, `forecast_days`, `note`. Точка содержит `time_utc`, `time_local`, `temperature_c`, `feels_like_c`, `humidity_percent`, `wind_speed_m_s`, `condition`, `condition_code`, периоды осадков и вероятность. Недоступные optional значения опускаются. Перед форматированием инструмент разрешает найденную, настроенную или дефолтную IANA-зону, поэтому успешный результат содержит локальное время. В первых 24 часах forecast points почасовые, дальше примерно раз в шесть часов; это отдельные значения, не дневные min/max.

`GeocodingUnavailableError` превращается в `error` о недоступности обоих геокодеров; `WeatherUnavailableError` — в `error` о недоступности/невалидности основного и резервного поставщиков. Прочие исключения — общий `error`. Поставщик/attribution передаются через callback, но не добавляются в JSON ответа инструменту; `vkService` сейчас использует callback без пользовательского текста. Сервисная политика кэширования, fallback, таймаутов и очередей описана в [WeatherService](../weather/weatherService.md).

## get_vk_info

**Статус регистрации:** [`createVkInfoTool`](../../../../../src/services/ai/tools/vkInfoTool.ts) возвращает `AITool` с именем `get_vk_info`, но вызовов фабрики в `src/` не найдено. Инструмент отсутствует в основном tool array `VkService` и отдельном наборе `SubagentService.runPart`; финальная генерация субагента явно использует `tools: []`. Поэтому описанный ниже контракт определён кодом, но сейчас недоступен модели.

Фабрика получает bound `VkInfoContext`: `api`, необязательный `publicApi`, текущие `peerId` и `senderId`, признак группы, необязательный `replySenderId`, `checkAccess()` с признаком admin и callback `onInfoReturned()`. Произвольный peer или sender в аргументах не принимаются; контекст беседы задаётся вызывающим слоем. Фабрика не отправляет сообщения и не пишет данные в БД. Нормализация опций и контракт общих VK-запросов вынесены в спецификацию [vkUserInfo](tools/vkUserInfo.md), поскольку тот же helper используется `get_chat_info`.

### Аргументы и семантическая валидация

Обязателен `kind`: `conversation`, `members` или `user`. Дополнительные поля запрещены. Поля схемы:

| Поле | Тип / ограничения | Допустимый scope |
| --- | --- | --- |
| `kind` | enum string | всегда обязательно |
| `target` | string, до 200 символов | только `user`; текущий автор по умолчанию, `me`/`self`/`я` — также текущий автор, `reply` — автор reply; иначе ID, упоминание, имя или короткий адрес |
| `offset` | integer от 0 до `MAX_USER_INFO_OFFSET` (`2_147_483_627`) | `members` или списки `user`; одинаковый offset применяется к каждому выбранному списку |
| `sections` | уникальный непустой массив enum, от 1 до 6 элементов | только `user`; default `profile` |
| `profile_fields` | уникальный непустой массив из enum ниже | только `user` с секцией `profile`; default: `screen_name`, `domain`, `sex`, `bdate`, `city`, `country`, `home_town`, `occupation`, `status`, `about`, `activities`, `interests`, `music`, `movies`, `books`, `online`, `last_seen`, `verified` |
| `count` | integer 1–20 | только списки `user`; default 10. Для `members` размер страницы фиксирован — 100 |
| `album_id` | `profile`, `wall` или числовой ID альбома `-?[1-9]\d{0,14}` | только если выбран `photos`; default `profile` |
| `post_filter` | `all`, `owner`, `others` | только если выбрана секция `posts`; default `all` |

Допустимые значения полей `sections` и `profile_fields`, их defaults и проверки `parseUserInfoOptions` описаны в [спецификации общего helper](tools/vkUserInfo.md#опции-выборки-и-валидация). Исполнитель дополнительно проверяет принадлежность параметров `kind` и согласованность текущего peer: group ID должен быть больше `2_000_000_000`; в ЛС `peerId === senderId`. Некорректные аргументы логируют только peer/sender и возвращают `not_executed`.

Пример для профиля: `{"kind":"user","target":"reply","sections":["profile"],"profile_fields":["city","bdate","screen_name"]}`. Пример страницы участников: `{"kind":"members","offset":100}`.

### Доступ и разрешение пользователя

`requiresAdmin = context.isChat || kind !== 'user'`: в группе любой `kind`, включая запрос профиля пользователя, требует положительного `checkAccess()` и `isAdmin`; отказ возвращается как `not_executed`. Так как фабрика не связана с caller, неизвестно, какие внешние роли callback относит к `isAdmin`; строка `description` инструмента сама по себе это не подтверждает. В прямом диалоге доступен только `kind=user` о текущем авторе; ID другого пользователя отвергается. Для short name в ЛС фабрика дополнительно запрашивает через `users.get` собственные `screen_name` и `domain` и допускает запрос только при точном нормализованном совпадении.

В группе целевой пользователь находится только в текущем списке участников. Числовой ID/ссылка разбираются через [`participantId`](../../../../../src/services/ai/tools/vkInfoTool.ts) и [`parseVkUserReference`](../../../../../src/services/vk/vkMention.ts); имя или screen name сопоставляется после NFKC-нормализации, lowercase `ru-RU` и свёртки пробелов с `screen_name`, полным именем или `first_name`. Список загружается страницами по 500, максимум 60 страниц. Несколько текстовых совпадений, неполный обход или отсутствие участника возвращают `not_executed`; функция не делает произвольный `users.get` для чужого ID.

Если выбранный участник — сообщество, разрешается вернуть только сам объект `participant`; сочетание сообщества с `sections`/`profile_fields` отклоняется. В `participantPage` тип ID > 0 означает user, ID < 0 — community; результат включает имя/screen name, `is_admin`, `is_owner`, `joined_at` (из Unix seconds в ISO), `invited_by` и VK profile object. Для community ID берётся из `groups` в ответе VK. Ветка `members` возвращает переданный VK profile object без рекурсивного sanitizer и общего лимита размера; запрос ограничивает fields `screen_name`/`domain`, но точный состав ответа зависит от VK API.

### VK-вызовы и результат

- `conversation`: `messages.getConversationsById({ peer_ids: [peerId] })`; принимается ровно одна запись с совпадающим peer и `chat_settings`. JSON содержит `conversation` с `id`, title, owner, member count, state и flags.
- `members`: `messages.getConversationMembers({ peer_id, offset, count: 100, extended: 1, fields: ['screen_name','domain'] })`. Результат содержит `total`, `offset`, массив `members`, `has_more`, а при продолжении — `next_offset`; если следующий offset за пределом API — `offset_limit_reached`.
- `user`: использует общий [`getVkUserInfo`](tools/vkUserInfo.md#получение-профиля-и-коллекций) для `users.get` и запросов коллекций. Здесь `get_vk_info` отвечает за выбор/проверку пользователя, права и внешнюю форму результата; API-поля, пагинация, принадлежность элементов владельцу и локальные ошибки секций описаны в спецификации helper.

В результате публичный инструмент помещает профиль, если он был получен, в `user`, а статусы профиля/коллекций — в `sections`; правила проекции и усечения определены общим helper и не дублируются здесь.

Для непрофильных секций нужен `publicApi` (при отсутствии helper сообщает о ненастроенном `VK_SERVICE_TOKEN`). Если он не задан, соответствующая секция получает `status=error`, но остальные выбранные секции продолжают выполняться. VK privacy/API errors также записываются в статус конкретной секции с ограниченным сообщением и `vk_error_code`, если он есть. Общий status `result`, если успешно получена хотя бы одна секция; иначе `error`. На общем успехе возвращается `source=vk` и инструкция считать VK-контент недоверенным. `checkAccess()` повторяется перед отдельными user-section вызовами и после загрузки; затем вызывается `onInfoReturned()`. Этот callback должен блокировать последующие model-действия, но его реальное связывание не найдено.

Пример формы ответа: `{"status":"result","source":"vk","user_id":123,"user":{"id":123,"first_name":"…"},"sections":{"profile":{"status":"result","requested_fields":["city"],"not_returned_fields":[]}},"instruction":"…"}`. Исключение вне guard логируется с peer/sender, error name и необязательным VK code, пользователю модели возвращается общий `error`. Tool не реализует собственные timeout/retry; отдельная отправка пользователю или изменение состояния отсутствуют.

### Общие helpers и тестовые свидетельства

Фабрика `get_vk_info` не вызывается в текущем source tree, однако модуль [`vkInfoTool.ts`](../../../../../src/services/ai/tools/vkInfoTool.ts) активен через shared helpers: `participantPage`, `participantId` и `matchesParticipant` используются `get_chat_info` и `send_vk_message`; их контракты разобраны в этих разделах. Публичный `getVkUserInfo` и нормализация его опций описаны отдельно в [vkUserInfo.md](tools/vkUserInfo.md), где зафиксировано также использование helper активным `get_chat_info`.

Отдельного `get_vk_info` тестового файла/прямого вызова в тестах нет. [`messageDelivery.test.ts`](../../../../../test/messageDelivery.test.ts) косвенно проверяет shared participant parsing/matching через поиск адресата `send_vk_message`; [`chatInfoTool.test.ts`](../../../../../test/chatInfoTool.test.ts) проверяет отдельные сценарии `get_chat_info` с mocked VK callbacks, но не валидирует реальные VK API вызовы или санитайзер. Схема, сборка ответа, доступ, `publicApi`, ошибки приватности и callback `onInfoReturned` для самой фабрики тестами не подтверждены. Тесты не запускались.

## manage_location

**Источник и доступность:** `createLocationTool` в [`locationTool.ts`](../../../../../src/services/ai/tools/locationTool.ts), использует [`LocationService`](../settings/locationService.md). Подключается в обычный и active-mode запросы основной модели; отсутствует в questionnaire-only и субагенте. `VkService` связывает tool с текущим событием: scope `chat` и ID беседы для группы, scope `user` и ID автора для личного диалога. Возможности также объявлены в [`capabilityService`](capabilityService.md); близкие команды `/city` и `/timezone` описаны в [каталоге команд](../command/commands.md#command-city) и его секции [`/timezone`](../command/commands.md#command-timezone).

### Аргументы и проверка

Схема требует только `action`; дополнительные ключи вне таблицы запрещены. Все перечисленные поля optional в JSON Schema, а необходимые для конкретного действия проверяет исполнитель:

| Поле | Тип и допустимые значения | Проверка |
| --- | --- | --- |
| `action` | string: `show`, `set_city`, `set_timezone`, `clear` | Обязательно; иначе `not_executed`. |
| `city` | string | Для `set_city` обязательно; от 2 до 100 исходных символов, после trim минимум 2; разрешены буквы, цифры, пробел, точка, запятая, апострофы, круглые скобки и варианты дефиса. В сервис передаётся trim-значение. |
| `region` | string | Необязательно; те же текстовые ограничения, что и `city`. |
| `country_code` | string | Необязательно; ровно две ASCII-буквы `[A-Za-z]{2}`, перед сохранением переводится в uppercase. |
| `time_zone` | string | Для `set_timezone` обязательно; исходная длина максимум 128 символов, после trim не пусто. IANA-валидность дополнительно проверяет сервис. |
| `target` | string: `city`, `timezone`, `all` | Используется для `clear`; если отсутствует, применяется `all`. |

Примеры: `{"action":"show"}`, `{"action":"set_city","city":"Казань","country_code":"RU"}`, `{"action":"set_timezone","time_zone":"Asia/Yekaterinburg"}`, `{"action":"clear","target":"timezone"}`. Известное, но не относящееся к действию optional-поле не отклоняется: например, `city` при `show` будет проверено по формату, но проигнорировано. `set_city` передаёт в LocationService только `name`, необязательные `region` и `countryCode`; поля региона и кода страны могут уточнить геокодирование.

### Права, привязка к scope и порядок

Перед любым действием, включая `show`, вызывается `checkReadToolAccess`: отказ после уже начатой отправки или при неразрешённом решении active mode возвращается как `not_executed`; затем повторно проверяются maintenance и режим. В группе обычному пользователю quiet mode запрещает tool; глобальному администратору бота разрешён. Личные настройки привязаны к `senderId`, групповые — к текущему `peerId`; модель не может передать чужой ID.

Для `show` дополнительная проверка администратора беседы не нужна. Перед `set_city`, `set_timezone` и `clear` в группе нужен `canManage`: глобальный администратор/создатель бота либо VK участник с `is_admin` или `is_owner` в текущей беседе. Ошибка VK API при проверке членства логируется и трактуется как отсутствие прав. В личном диалоге изменение относится только к настройкам автора.

Есть различие во времени проверки глобальной роли: общий `checkReadToolAccess` повторно получает роль, но `canManage` использует `currentIsAdmin`, считанный `VkService` в начале обработки события; при этом VK роль администратора/владельца беседы запрашивается в момент изменения. Поэтому изменение глобальной роли между началом обработки и вызовом инструмента не обязательно отражается в `canManage` этого же запроса. `checkReadToolAccess` также не вызывает общий `beginAction` и не блокирует tool по `actionExecutionStarted`/`commandResultDelivered`; это ограничение последовательности действий модели.

### Поведение действий и запись настроек

| Действие | Поведение и результат |
| --- | --- |
| `show` | `LocationService.getLocationSummary` возвращает `city`, `time_zone`, `city_configured`, `time_zone_configured`, `default_city`, `default_time_zone`, `settings_configured`. Если города нет — отображается Москва; часовой пояс берётся в порядке `timeZone` (явный override) → `locationTimeZone` (из места) → `Europe/Moscow`. Флаг `settings_configured` равен AND двух признаков configured. |
| `set_city` | Для слова «Москва» без уточнений сервис использует встроенные координаты без геокодирования; иначе вызывает `WeatherService.resolveLocation`. Не найденный город возвращает `not_found`; ошибка поставщика/сохранения — `error`; неоднозначность преобразуется в `needs_clarification` со строкой до пяти вариантов `name — region, country`, без сырого массива кандидатов. Координаты сохраняются, но tool возвращает только имя, регион, страну, производный часовой пояс и обновлённую публичную сводку. Сохраняются название, координаты, страна, регион и `locationTimeZone`; отдельный явный `timeZone` не перезаписывается. |
| `set_timezone` | Сервис проверяет IANA-зону через `Intl.DateTimeFormat`. Неверное значение возвращает `invalid`, ошибка записи — `error`; успех сохраняет явный `timeZone`, который при отображении и потреблении имеет приоритет над зоной города. |
| `clear` | `target=city` удаляет город, координаты, страну, регион и `locationTimeZone`, но оставляет явный `timeZone`; `target=timezone` очищает `timeZone` и также `locationTimeZone`, сохраняя город; `all` выполняет обе очистки. Успех возвращает сводку после сброса. |

Сохранённое место/часовой пояс используется `get_weather` и `get_current_datetime` для текущей области (`chat` либо `user`); fallback на настройки другого scope не выполняется. После успешного изменения `VkService` обновляет переданный в tool объект настроек, чтобы другие инструменты той же обработки видели новое значение. `getLocationSummary` читает через `SettingsService` методы с `upsert`: даже `show` может создать отсутствующие `User`/`UserSettings` либо `Conversation`/`ChatSettings`. Сам tool не перехватывает исключение чтения сводки; основной цикл tool-вызовов обработает выброшенную ошибку.

### Статусы и свидетельства тестов

Помимо `result`, tool возвращает `not_executed` для неверной структуры/обязательных полей или отказа общего access guard; `not_allowed` для попытки изменения групповой настройки без требуемых прав; `needs_clarification` для неоднозначного города; `not_found` и `error` для соответствующих результатов `set_city`; `invalid`/`error` для часового пояса и `error` при сбросе. Изменение вызывает `onChanged` только после успешной записи и перезагрузки сводки.

## play_game

[`play_game`](../../../../../src/services/ai/tools/interactionTools.ts), созданный `createGameTool`, принимает обязательные `game`, `action`, `value`, иных ключей не допускает. `game`: `current | standard | mafia | adventure | battle`; `action`: `inspect | start | answer | join | leave | hint | repeat | pause | resume | stop | skip | next | score | pass | vote | difficulty | status | command`; `value` — строка до `MAX_INPUT_CHARS`, пустая допустима на уровне tool, но downstream требует её для `answer`, `vote`, `command`.

Примеры: `{"game":"current","action":"inspect","value":""}` и `{"game":"standard","action":"start","value":"riddle"}`. Некорректная схема возвращает `not_executed`. Только действия кроме `inspect` занимают единственную попытку `play_game` этого ответа; повторный `inspect` допустим.

`vkService` проверяет общий action guard и повторно получает admin/режим/maintenance. Если действие требует прав администратора беседы, проверка делегируется VK API. Для любых действий кроме `inspect` вызывается `beginAction`, который блокирует конкурирующие действия и delivery. Беседа/автор, display name, ID события и resolver имён задаёт приложение.

Далее `GameInteractionService` читает активные сессии только текущей беседы. `inspect` сообщает активные игры и возможный личный ночной ход мафии. Для `current` неоднозначный набор требует уточнения. В ЛС `current`/`mafia` ответ, голос или команда сначала могут быть маршрутизированы в ожидающий private action мафии; если одновременно есть личная игра, нужен выбор.

`start` направляется в соответствующий движок: `standard` разбирает обычный ID через `parseGameKind`, `mafia` запускает мафию, `adventure` принимает жанр из `adventureGenres` либо `random`, `battle` передаёт команду баттлу. `current` для запуска недостаточно конкретен. Остальные действия преобразуются в команды `GameService`, `MafiaService`, `AdventureService` или battle; неподдерживаемая комбинация получает `not_executed`, а standard difficulty допускает только 1–4. Для adventure/battle при наличии event ID создаётся `GameEvent`; нарушение уникальности отклоняет повтор. Возврат `null` от движка преобразуется в `uncertain`, не безопасен для автоматического повтора.

Результат `result` отправляется напрямую в VK (при `adventureResult` используется отдельная доставка приключения); `info`, `not_executed`, `uncertain` возвращаются модели. После прямой отправки `commandResultDelivered` подавляет итоговый ответ. Подробности — в [GameInteractionService](../games/gameInteractionService.md) и спецификациях движков. Интеграционный сценарий инструмента есть в `vkMessageDeliveryIntegration.test.ts`; тесты не запускались.

## run_subagent

**Назначение и регистрация:** [`createSubagentTool`](../../../../../src/services/ai/tools/subagentTool.ts) подключается в обычный и active-наборы в [`VkService`](../../../../../src/services/vk/vkService.ts); отсутствует в questionnaire-only и наборе самого субагента. Инструмент оценивает локальную историю, сохраняет фоновую задачу и возвращает быстрый ответ. Результат позже формирует [`SubagentService`](subagentService.md) и доставляет отдельный job. Сам анализ ограничен сохранённой SQL-историей; инструмент времени субагента отдельно обращается к источнику времени.

### Аргументы и проверка выборки

Обязателен `task`: строка после `trim()` длиной не менее 10 символов, исходная строка не длиннее 2000. Разрешены только объявленные поля (`additionalProperties: false`). Для истории надо выбрать **один** режим:

- `count`: положительное safe integer; с `from`/`to` несовместим.
- `from` и `to`: обе даты обязательны вместе, ISO 8601 с часовым поясом, `from < to`, `to` не в будущем.

Другие поля необязательны:

| Поле | Контракт | Значение по умолчанию |
| --- | --- | --- |
| `format` | `summary`, `timeline`, `list`, `answer` | `summary` |
| `max_output_chars` | целое от 500 до `min(3500, SUBAGENT_MAX_OUTPUT_CHARS)` | это же верхнее значение |
| `participants` | 1–5 непустых строк длиной до 120 символов; только group context | все авторы в scope |

Пример аргументов: `{"task":"Составь хронологию решений","count":200,"format":"timeline"}`. `count` вместе с датами, непарные даты, неверная зона, будущий конец периода, неподходящий формат и лишние поля возвращают `not_executed`. Фильтр участников отклоняется в ЛС; ссылки/имена разрешаются по авторам сообщений, сохранённым в беседе, а не по текущему составу VK. Одинаковые после `trim()` значения дедуплицируются.

При разрешении участников возможны `needs_clarification` с кандидатами и `not_found`; разрешение выполняется **до** `context.checkAccess()`, поэтому эти ответы могут содержать найденные локальные имена до access guard. После разрешения проверяются message-delivery guard, active decision и общий доступ/режим/maintenance. Это порядок реализации; тесты tool фабрики не доказывают его безопасность для каждого входного VK-маршрута.

Дальше выполняется предварительная оценка SQL-истории. Значения конфигурации по умолчанию в [`config/index.ts`](../../../../../src/config/index.ts): минимум 100 и максимум 3000 сообщений, максимум 300 000 символов, 25 чанков и 90 000 приблизительно оценённых входных токенов. Инструмент отклоняет пустой/слишком короткий объём, превышение каждого бюджета и ошибку оценки (`error`). Оценка чанков — максимум из расчёта по числу сообщений и символам, не менее одного.

### Запуск, хранение, права и side effects

Непосредственно перед сохранением callback ещё раз применяет `beginAction()`. `SubagentService.startJob` отвергает запуск при остановке процесса, ограничивает незавершённую задачу одной на беседу через уникальный `activeKey=conversationId`, помечает задачу просроченной при отсутствии обновлений дольше `SUBAGENT_TIMEOUT_MINUTES` (30 минут по умолчанию) и ограничивает инициатора десятью задачами за последние 24 часа. Конфликт уникального ключа обрабатывается как `already_running`.

Успешная постановка создаёт [`DigestJob`](../../../prisma/models.md#digestjob) со `status=pending`, `kind=history_task`, пользователем, peer, запросом, фильтром участников и исходными ID сообщения. Задача ставится во внутреннюю очередь; подтверждение отправляется пользователю в текущий peer. Сбой отправки подтверждения логируется, но не отменяет уже принятую задачу; callback `onStarted` всё равно отмечает прямую доставку, чтобы итоговый ответ модели не продублировал подтверждение. Отправка итогового результата проходит отдельно через [`subagentDeliveryJob`](../../jobs/subagentDeliveryJob.md) и [`SubagentResultDeliveryService`](subagentResultDeliveryService.md).

Результаты фабрики включают `accepted` с job ID, оценкой объёма и предварительным числом частей; `already_running`; `not_executed` (права, ограничения, остановка или дневной лимит); `needs_clarification`; `not_found`; `error` (сбой оценки/создания). `parts` определяется автоматически: меньше `SUBAGENT_SECOND_PART_MIN_MESSAGES` — 1, иначе до 2 с учётом `SUBAGENT_MAX_PARTS`. Параметр `parts` не принимается от модели. Preflight считает доступные сообщения; сервис сначала сохраняет число по `count`, а после загрузки пересчитывает по фактическому snapshot, поэтому ответ может отличаться от окончательного `DigestJob.parts`. Пример результата (схематичный): `{"status":"accepted","job_id":"…","available_count":200,"parts":1}`.

### Тестовые свидетельства и ограничения

[`subagentTool.test.ts`](../../../../../test/subagentTool.test.ts) содержит 12 сценариев: малый объём, сообщение/символьные ограничения, короткая выборка при большом `count`, формат/лимит результата, автоматический порог частей для малого и большого объёма, существующая задача, участники (включая неоднозначность и запрет ЛС), валидация периода и проверка доступа. Проверки используют подменённые estimate/startJob и не подтверждают реальный SQL, транзакционную конкуренцию Prisma, daily-limit подсчёт или фактическую доставку результата. Тесты не запускались.

## search_history

`createSubagentSearchTool` из [`subagentTools.ts`](../../../../../src/services/ai/tools/subagentTools.ts) подключён только в `SubagentService.runPart`; читает in-memory snapshot уже выбранной SQL-истории и не выполняет новых запросов к БД или VK.

### Аргументы и алгоритм

Обязателен `query` — строка длиной 2–200 символов после `trim()`; дополнительные свойства запрещены. `from` и `to` необязательны независимо друг от друга, но если заданы, должны быть ISO 8601 с часовым поясом; `from` включается, `to` исключается. `limit` — целое от 1 до `SUBAGENT_MAX_SEARCH_RESULTS`, по умолчанию тот же максимум (50). Пример: `{"query":"решение","from":"2026-01-01T00:00:00Z","limit":10}`.

Сравнение выполняется как поиск подстроки в `message.text`, без учёта регистра с локалью `ru-RU`; автор, роль, reply и вложения не участвуют в совпадении. Совпадения сортируются от новых к старым и обрезаются до `limit`. Текст каждого совпадения ограничен 500 символами; для длинного текста выставляется `truncated`. Запись содержит доступный `message_id`, ISO-время, `speaker`, `role`, цитату и необязательный `reply_to` с условными полями, указанными в описании pager выше.

Результат — JSON со статусом `result` или `empty`, исходным trimmed `query`, `matches`, количеством всех совпадений (`total_matches`), фактически возвращённых (`returned`) и `has_more`. Ошибка/неверные поля возвращают `not_executed`; выполнение после отмены/завершения задачи возвращает такой же статус. Инструкция результата помечает совпадения как недоверенные данные, а не команды.

## send_vk_message

**Источник и фабрика:** [`createMessageDeliveryTool`](../../../../../src/services/ai/tools/messageDeliveryTool.ts). Tool доступен в обычном основном запросе и активном режиме после создания для текущих `peerId`, `senderId`; в `questionnaireOnly` отсутствует; субагенту не передаётся. Текущий адресат задаётся приложением, модель не может передать произвольный peer ID.

### Аргументы

`mode` и `text` обязательны; допустимы только `mode`, `text`, `recipient` (`additionalProperties: false`):

| Поле | Тип/ограничения | Значение |
| --- | --- | --- |
| `mode` | enum string | `reply_to_current`, `reply_to_quoted`, `reply_to_member`, `mention_member`, `send` |
| `text` | string, после trim непустой, максимум `MAX_VK_MESSAGE_LENGTH` (4000); не должен содержать VK-ссылку-упоминание `[id…|…]`/`[club…|…]`/`[public…|…]` или `@screen_name` | Готовый окончательный текст. Приложение формирует VK mention само для режимов участника. |
| `recipient` | string до 200 символов, после trim непустой | Обязателен только для `reply_to_member` и `mention_member`; запрещён для остальных режимов. Принимает имя в именительном падеже, полное имя, числовой ID или поддерживаемую VK-ссылку. |

Иллюстративный корректный вызов: `{"mode":"reply_to_current","text":"Хорошо, проверю."}`. Неизвестные поля, режим, слишком длинный/пустой текст, встроенное упоминание или несовместимый `recipient` возвращают `not_executed` без исключения и пишут предупреждение.

### Привязка диалога, права и единственность действия

Перед обращением к VK проверяются положительные безопасные целые `senderId` и `peerId`, а также согласованность scope: для беседы peer должен быть больше `2_000_000_000`; для личного диалога `peerId === senderId`. Несовпадение возвращает `not_executed`. Затем проверяется `attempted` самого инструмента и флаг `ambiguousMember`; после lookup эти флаги не допускают повторной попытки/угадывания адресата в том же экземпляре.

`context.checkAccess()` выполняется перед lookup/ответом о проблеме адресата и повторно непосредственно перед отправкой. Конкретная политика приложения передана из `vkService`: она учитывает решение active mode, запрет действия после чтения сведений VK, уже начатое действие, прямую отправку команды и ранее начатую доставку. После финальной проверки вызывается `context.beginAction()`; отказ возвращается как `not_executed`. Tool устанавливает локальный `attempted` до `deliver()`, чтобы ошибка или неопределённый результат отправки не провоцировали второй вызов.

### Режимы доставки

- `reply_to_current`: ответ на входящее сообщение текущего события. Если отсутствуют оба положительных ID (`conversationMessageId` и `replyTo`), возвращается `not_executed`.
- `reply_to_quoted`: ответ на процитированное сообщение только если его `peerId` совпадает с текущей беседой и доступен валидный ID. Чужая/недоступная цитата не используется.
- `send`: отдельное сообщение в текущий peer без reply options.
- `mention_member`: разрешён только в беседе. Участник находится только среди текущих участников; успешный ID форматируется приложением как `[idN|Имя]`, после чего текст отправляется отдельным сообщением.
- `reply_to_member`: сначала выполняется тот же строгий поиск участника. Затем проверяется до 20 ближайших `conversation_message_id` перед anchor текущего сообщения. Выбирается наиболее новый видимый текст участника, не старше 30 минут и не более чем на минуту из будущего. Если найден — ответ привязывается к нему; если сообщений нет — режим становится `mention_member` и отправляет отдельное упоминание с текстом.

Поиск участника постраничный (`LOOKUP_PAGE_SIZE`, `MAX_LOOKUP_PAGES` из `vkInfoTool.ts`; shared parsing описан в [разделе `get_vk_info`](#get_vk_info)). Учитываются пользователи, не сообщества. Числовой ID должен соответствовать текущему участнику. Имя сначала сопоставляется точно, затем допускается существующая функция падежного сопоставления. Несколько точных или неоднозначных совпадений, неполные страницы, изменившееся число участников, дубликаты/некорректные строки VK либо участники без профилей при поиске по имени приводят к отказу, а не к выбору приблизительного получателя. При ошибке API отправка адресату запрещена; инструмент пытается сообщить проблему в текущий диалог и помечает instance как ambiguous.

Если VK не позволяет проверить недавние сообщения, `reply_to_member` безопасно понижает режим до `mention_member`; результат включает limitation, что использовано упоминание. В lookup-error/ambiguous/not-found случаях адресат не угадывается: возвращается `clarification_requested` либо `error`, если объяснение удалось доставить; при неопределённой доставке возвращается `uncertain`.

### Результат, ошибки и доставка

Результат сериализуется JSON-строкой с `status`, `message`, при успешной/неопределённой доставке также фактическим `delivery`; возможны статусы `result`, `uncertain`, `not_executed`, `clarification_requested`, `error`. `uncertain` означает, что VK вызов мог выполниться, но подтверждение потеряно; не повторять отправку. При запросе уточнения/ошибке разрешения адресата tool сам доставляет один короткий текст через `context.deliver` в текущий диалог. При обычной отправке тот же callback передаёт окончательный текст и reply options.

`AiMessageDeliveryGuard` на стороне приложения отмечает попытку до вызова отправителя, запрещает вторую попытку и сохраняет состояние даже при exception. После возврата модели `vkService` видит `hasAttempted` и подавляет обычный ответ модели; это также подавляет fallback после исключения, поскольку сообщение уже могло уйти. Инструмент не пишет запись истории сам; обычное сообщение, отправленное инструментом, не должно дублироваться как стандартный ответ ассистента.

## summarize_history

`createSubagentSummarizeTool` из [`subagentTools.ts`](../../../../../src/services/ai/tools/subagentTools.ts) доступен только активной части фонового субагента. Вызывает `summarizeHistorySnapshot` на выбранных сообщениях in-memory snapshot; это дополнительный вызов AI provider и учитывается в общей concurrency/usage budget субагента. Для точных цитат предназначены `get_local_chat_history` и `search_history`.

### Аргументы и выполнение

Все поля необязательны, дополнительные запрещены: `focus` — строка до 1000 символов; `from` и `to` — независимые границы ISO 8601 с часовым поясом (`from` включительно, `to` исключительно); `max_chars` — целое от 2000 до `SUMMARY_MAX_DIGEST_CHARS` (по умолчанию значение конфигурации, 8000). Пример: `{"focus":"решения по поездке","from":"2026-02-01T00:00:00Z","max_chars":4000}`. Пустой `focus` после `trim()` заменяется исходной задачей субагента.

Неверные типы/диапазон/лимит возвращают `not_executed`. Пустой выбранный диапазон возвращает `empty` без расходования лимита вызовов. После проверки активности вызывается `summarizeHistorySnapshot` с часовым поясом, focus, лимитами и usage/concurrency callback; лимит вызовов по умолчанию равен одному и увеличивается до запроса provider. При исключении возвращается общий `error`, детали логируются только типом ошибки и количеством сообщений.

Успех возвращает JSON `status=result`, количество использованных сообщений, `text`, `complete` и предупреждение о недоверенности данных. `complete` вычисляется только как равенство размера выбранного диапазона размеру всего snapshot; это не подтверждение полноты исходной SQL-истории или requested date range. Текст обрезается до `max_chars`, если требуется. Сводка не меняет историю и не отправляется пользователю непосредственно; её включает в общий итог `SubagentService`.
