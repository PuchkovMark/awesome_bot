# chatDigestService

**Тип сущности:** сервис чтения истории сообщений и построения структурированных/пользовательских дайджестов.
**Runtime identity:** функции `loadHistoryMessages`, `countHistoryMessages`, `estimateHistoryMessages`, `summarizeHistorySnapshot`, `finalizeChatDigest`, `buildChatDigest`; типы `ChatDigestRequest`, `ChatDigestChunk`, `HistoryMessage`, `HistoryLoadInput`, `ChatDigestMeta`, `HistoryEstimate`, `UsageSnapshot`, `UsageBudget`.
**Источник:** [`src/services/ai/chatDigestService.ts`](../../../../../src/services/ai/chatDigestService.ts).
**Связанные сущности:** [контракт AIProvider](AIProvider.md), [сервис субагентов](subagentService.md), [каталог инструментов истории](tools.md), модели [`Message`](../../../prisma/models.md#message) и [`User`](../../../prisma/models.md#user).

## Входные данные и границы выборки

`ChatDigestRequest` допускает `count`, `from`, `to`. `HistoryLoadInput` добавляет обязательный `conversationId`, необязательные `participantUserIds` и `includeBot`. Условия запроса всегда ограничены `conversationId`; даты образуют полуоткрытый интервал `sentAt >= from` и `sentAt < to`. Если даты заданы, сообщения без подходящего `sentAt` не проходят условие.

Фильтр авторов строится так:

- без ID участников и без `includeBot` выбираются роли `user` и `assistant`;
- с ID участников выбираются только `user` этих пользователей;
- с `includeBot` выбираются `assistant`, а при наличии ID также сообщения `user` этих участников;
- `includeBot` без списка участников означает только `assistant`.

Отбор и загрузка используют Prisma `Message`. Загрузка сортирует по `sentAt DESC`, затем `createdAt DESC`, ограничивает `take` при truthy `request.count`, после чего разворачивает порядок для хронологической обработки. Пустой после `trim()` текст отбрасывается. Текст сообщения и текст reply ограничиваются 1000 символами. JSON-вложения разбираются безопасно: некорректное значение даёт пустой список, сохраняются только строки и максимум 10 элементов. Автор берётся из `authorName`, затем `displayName`, иначе отображается `Пенёк` для assistant или `Участник` для user.

Если у загруженных сообщений есть `conversationMessageId`, недостающий текст ответа восстанавливается из того же выбранного набора по `replyToConversationMessageId`. Восстановление не делает дополнительный запрос и потому не найдёт сообщение-цель, отсутствующее в текущей выборке.

## Публичные операции

| Функция | Поведение и результат |
| --- | --- |
| `loadHistoryMessages(input)` | Возвращает `{ messages, source: 'db' }` из локальной БД. |
| `countHistoryMessages(input)` | Считает строки с теми же условиями; при наличии `request.count` возвращает `min(total, count)`. |
| `estimateHistoryMessages(input)` | Возвращает `{ count, chars, capped }`. При нуле — нулевые значения; если число превышает `SUBAGENT_MAX_MESSAGES`, не загружает тексты и возвращает `capped: true`, `chars: 0`. Иначе оценивает объём по содержимому, вложениям и фиксированным 40 символам на строку. |
| `summarizeHistorySnapshot(provider, messages, options)` | Разбивает переданный снимок, параллельно суммирует части, сводит дайджесты к лимиту символов и возвращает дайджесты, исходное число сообщений, текстовый формат и, если передан бюджет, usage. Пустой вход возвращает пустой результат без вызова модели. |
| `buildChatDigest(provider, input)` | Загружает сообщения из БД, суммирует с часовым поясом и лимитом `maxDigestChars`; возвращает структурированные дайджесты, количество и источник `db`. |
| `finalizeChatDigest(provider, request, digests, maxChars, timeZone, meta?)` | Просит провайдера сформировать краткий русский пересказ только по переданным дайджестам и ограничивает итоговую строку `maxChars`. При `meta` в prompt указывается фактически обработанное число и источник. |
| `formatTranscript(messages, timeZone?)` / `formatDigestText(digests)` | Форматируют сообщение с временем, участником, ответом и вложениями либо объединённый дайджест в читаемый текст. В транскрипте ID цитируемого сообщения добавляется как `#<id>` только если есть `replyToText`; имя автора цитаты необязательно, её текст обрезается до 300 символов. |

Сервис не отправляет сообщения в VK и не создаёт/сохраняет дайджест в БД. Вызвавший код отвечает за выбор участников, права, лимиты конкретной задачи, передачу результата и обработку ошибок. `buildChatDigest` не передаёт `participantUserIds` или `includeBot` сам по себе: они должны прийти во входном `input`.

## Формат дайджеста и обработка модели

Каждый `ChatDigestChunk` имеет `from`, `to`, `message_count`, массивы `topics`, `decisions`, `questions`, `agreements`, `facts`, `participants`. Для отдельного фрагмента парсер допускает до 4 тем/решений/вопросов/договорённостей, по 160 символов на пункт; до 6 фактов по 240 символов; до 8 участников по 60 символов. Значения обрезаются и дедуплицируются. Некорректные даты заменяются границами фрагмента или текущим временем, неверный `message_count` — числом сообщений.

Промпт помечает транскрипт как недоверенный, запрещает исполнять содержащиеся в нём инструкции и требует не выдумывать сведения. Для фокусной задачи инструкция просит извлекать относящиеся к ней сведения и сохранять автора/время/короткую цитату, если они известны. Это инструкция модели; сервис не проверяет фактическую достоверность извлечённых тезисов.

Сообщения группируются по `SUMMARY_CHUNK_MESSAGES` и `SUMMARY_CHUNK_CHARS` (минимум 1 сообщение и 1000 символов для соответствующих размеров). Каждый текст предварительно обрезан до 1000 символов на этапе загрузки из БД; для уже переданного снимка такого ограничения `summarizeHistorySnapshot` не накладывает. Чанки суммируются с `SUMMARY_MODEL`, без инструментов, с последовательно пробуемыми уникальными положительными лимитами `SUMMARY_CHUNK_OUTPUT_TOKENS` и `_MAX`. При `AIOutputLimitError` единственный слишком длинный фрагмент рекурсивно делится пополам, максимум на один уровень; дальше ошибка оборачивается с номером/размером части. Некорректный JSON не считается ошибкой: содержимое становится одним усечённым фактом (800 символов), а даты и участники берутся из сообщений.

При нескольких дайджестах редукция сначала делает до трёх раундов AI-объединения групп, размер которых ограничен бюджетом от `maxDigestChars`; запросы объединения могут проходить через переданный `limiter`. Если модель достигает лимита вывода при объединении, используется детерминированное объединение. Если итог всё ещё превышает лимит, пары объединяются локально до тех пор, пока размер JSON не укладывается или не остаётся один элемент. Комбинированные списки ограничены 6 темами/решениями/вопросами/договорённостями, 8 фактами и 12 участниками; локальная комбинация сохраняет первое значение каждого списка и не делает модельного резюме.

Финальный пересказ — отдельный запрос без инструментов и с лимитом вывода `max(1200, ceil(maxChars * 1.2))`. `clampSummary` обрезает превышение по последней точке/восклицательному/вопросительному знаку после 55% лимита, иначе по символам с многоточием. Ошибки провайдера, кроме специально обработанного превышения лимита в чанковом/merge-запросе, передаются вызывающему коду.

## Usage budget и конкурентность

`UsageBudget` суммирует только `inputTokens` и `outputTokens` ответа (отсутствующие значения считаются нулём). Пределы нормализуются минимум к 1. Превышение — строго `>` лимита, после чего `ensureWithinLimits()` выбрасывает `UsageLimitError` со снимком фактических и допустимых счётчиков. Бюджет проверяется до начала и после каждого успешного суммаризирующего запроса. Финальная функция `finalizeChatDigest` не принимает этот бюджет и не добавляет свои токены.

`summarizeHistorySnapshot` использует `options.concurrency` или `SUBAGENT_SUMMARIZE_CONCURRENCY`, минимум 1; опциональный `limiter` оборачивает каждый чанк и merge-запрос, но не ограничивает сам `provider.send` в финальном пересказе. Ошибка одного worker отклоняет `Promise.all`, а уже начатые запросы не отменяются.

## Тесты и ограничения

В [`test/chatDigestService.test.ts`](../../../../../test/chatDigestService.test.ts) 12 сценариев: загрузка локальных SQL-сообщений и пустой результат; ограничение count; оценка capped и объёма; отказ по usage budget; итоговый пересказ с обрезанием и фактическим числом сообщений; повтор чанка с большим лимитом; деление чанка после двух лимитов; детерминированный merge fallback; наличие полей снимка для субагента. Prisma и provider подменены. Прямые assertions на фильтр участников, границы времени, восстановление/форматирование reply, fallback парсинга некорректного JSON и обычный успешный многораундовый merge в файле отсутствуют. Тесты в этом проходе не запускались.
