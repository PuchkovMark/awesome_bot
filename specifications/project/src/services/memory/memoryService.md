# memoryService

## Сохранение и выборка истории

`addMessage` при необходимости создаёт или обновляет пользователя по VK ID и создаёт `Conversation` по ID диалога. Сохраняются роль, очищенный текст, токены, VK-идентификаторы, имя автора и сведения об ответе; вложения не записываются. `cleanHistoryText` удаляет emoji и пробелы по краям; пустой результат даёт `null` без записи. Текст цитаты очищается так же; при отсутствии числа токенов оценка — `ceil(длина текста / 4)`, минимум один. `Message` имеет уникальный индекс по `conversationId,conversationMessageId`; обработку конфликтов вызывающей стороной следует проверять по конкретному пути.

`getContextForUser` выбирает записи текущего пользователя и разговора за TTL, не более `MAX_HISTORY_MESSAGES`, вначале от новых к старым; затем прекращает добавление при превышении `MAX_HISTORY_TOKENS` и возвращает выбранные сообщения в хронологическом порядке. `getRecentChatContext` выбирает общие `user` и `assistant` сообщения конкретной беседы за TTL, ограничивает количество и возвращает их по возрастанию времени. TTL конструктора ограничен диапазоном 1–24 часа.

`resolveConversationParticipants(conversationId, references, botNames)` находит только пользователей с сохранёнными `role=user` сообщениями в этой беседе. Для кандидатов берётся display name, последняя сохранённая `authorName` или VK ID. Числовые ID сопоставляются напрямую; имена нормализуются без учёта регистра, затем проверяется падежное совпадение. Бот определяется по alias `Пенёк`, `пенек`, `пенечек`, `бот`, `bot` и переданному текущему имени персонажа. Неоднозначные совпадения и неизвестные ссылки возвращаются отдельно; VK API и актуальный состав беседы не запрашиваются. Синтаксис VK screenName/URL распознаётся парсером, но значение затем сравнивается с сохранёнными именами, а не разрешается по профилю VK. После trim повторные ссылки удаляются; максимум обрабатываются `MAX_PARTICIPANTS` ссылок.

`getHistoryPage` работает по `conversationId`, необязательно ограничивает данные пользователем, периодом `from`/`before`, списком авторов и уже возвращёнными ID; предел страницы — 50. Даты сравниваются с `Message.createdAt`, обе границы включительные; строки выбираются в порядке `createdAt DESC, id DESC`, а страница возвращается в хронологическом порядке. При выборе участников пользовательские сообщения фильтруются по их внутренним ID, сообщения бота — по `role=assistant`. Возвращает страницу, `hasMore` и время самой старой записи по базовому фильтру, без применения периода и исключённых ID. Сам метод не устанавливает TTL; очистка сообщений выполняется отдельно.

В [MemoryService](../../../../../src/services/memory/memoryService.ts) у `getHistoryPage` и `resolveConversationParticipants` нет проверки роли, режима или maintenance. [VK caller](../vk/vkService.md#ai-инструменты-действия-и-доставка) задаёт текущий `conversationId`, для личного pager — также текущий `senderId` через `vkUserId`. Основной [`get_local_chat_history`](../ai/tools.md#get_local_chat_history) проверяет аргументы и бюджеты без дополнительного `checkAccess`; у [`run_subagent`](../ai/tools.md#run_subagent) такой проверки также нет. Контроль активности прежней фоновой задачи относится к её жизненному циклу и сохраняется. Тестов `MemoryService.getHistoryPage`/`resolveConversationParticipants` в текущем `test/` не обнаружено.

Очистка по TTL и семидневный режим недельного мема описаны в [jobs.md](../../jobs/README.md). `clearUserHistory(vkUserId, conversationId?)` удаляет сообщения конкретного пользователя в одной беседе или без ограничения беседой.
