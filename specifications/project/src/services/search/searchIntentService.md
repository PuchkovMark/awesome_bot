# findWebSearchQuery

**Тип:** функция определения намерения. **Источник:** [searchIntentService.ts](../../../../../src/services/search/searchIntentService.ts), `findWebSearchQuery(provider, userMessage)`. Делает отдельный `provider.send` с системной инструкцией и сообщением пользователя, возвращает `{ query?, response }`, сохраняя полный ответ для учёта токенов. Инструкция рассматривает сообщение пользователя как недоверенные данные.

Из текста ответа берётся совпадение от первой `{` до последней `}` и разбирается JSON. Строковое `search_query` обрезается по краям и принимается при длине 2–500; невалидный JSON, другое значение и некорректная длина дают `query: undefined`. Ошибка самого провайдера распространяется вызывающему коду.

В [VKService](../../../../../src/services/vk/vkService.ts) этап включён, когда провайдер поиска не `none` и задан хотя бы один поисковый ключ. При валидном запросе вызывается [SearchService](searchService.md), результаты добавляются в системное сообщение как недоверенные данные, описание каждого ограничивается 1200 символами; инструкция просит модель не выводить ссылки. Пустой результат или ошибка поиска сопровождаются инструкцией не утверждать, что актуальные сведения проверены. Ошибка классификации логируется и основной ответ продолжается. Успешные стадии учитываются как `search_intent` и `search`.

Права проверяются вызывающим маршрутом, сервис сам их не проверяет; сообщение пользователя передаётся модели. Отдельного теста функции в текущем `test/` не обнаружено. Полный контекст порядка ветвей VK остаётся предметом дальнейшего исследования.
