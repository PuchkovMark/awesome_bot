# MemberService

**Тип:** сервис членства и анкет участников. **Runtime identity:** `MemberService`, singleton `memberService`; format/parser exports `formatProfileIntroduction`, `parseQuestionnaireQuestions`, `parseStoredQuestionnaireQuestions`. **Источник:** [memberService.ts](../../../../../src/services/member/memberService.ts). Данные принадлежат паре `(conversationId, vkUserId)` в `ConversationMember`; JSON профиля и промежуточных ответов хранится в строковых колонках.

## Вступление и выход

`recordJoin(conversationId, vkUserId, eventId)` отклоняет пустой event ID, получает настройки беседы и существующую отметку `lastJoinIntroductionEventId`, затем upsert-ит присутствие и даты вступления. Условный `updateMany` резервирует новый event ID только если предыдущая отметка всё ещё совпадает; повторное событие не запускает второй раз интро/приглашение анкеты. Сверка и upsert не объединены в транзакцию. При включённом `questionnaireEnabled` и успешном claim читается заполненный профиль: он возвращается для приветствия; без него сервис выставляет `questionnaireInviteSentAt` и флаг приглашения. `welcomeEnabled`/`welcomeText` возвращаются caller-у и сами по себе не управляют состоянием анкеты.

`recordLeave` получает настройки и upsert-ит `isPresent=false`, `leftAt=now`; неизвестный ранее участник создаётся как отсутствующий. VK caller дополнительно завершает игровые участия. Ошибки метода логируются на уровне VK membership handler. При кике строка не удаляется, а профиль остаётся.

## Два режима анкеты

Поля `questionnaireQuestions`, `questionnaireAnswers`, `questionnaireIndex` составляют черновик; `null` означает, что активной анкеты нет. `questionnaireIndex=-1` означает заполнение всего шаблона одним сообщением; `0..N-1` — пошаговый ответ на текущий вопрос. `startQuestionnaire` читает сохранённые вопросы из `ChatSettings` и проверяет их каждый раз: JSON-массив из 1–32 непустых строк, каждая до 200 символов. `parseQuestionnaireQuestions` для нового значения разбивает аргумент по `|`, trim-ит элементы и выполняет те же лимиты.

`startQuestionnaire`:

- если уже активен пошаговый режим или `replaceExisting=false`, бросает ошибку с просьбой ответить либо отправить `/profile cancel`;
- при активном шаблонном режиме и `replaceExisting=true` возвращает сохранённый шаблон с предыдущими ответами; отсутствующие/повреждённые поля приводят к ошибке восстановления;
- заполненный профиль без `replaceExisting` отклоняется;
- иначе сохраняет snapshot списка вопросов и существующие ответы (при редактировании), ставит `questionnaireIndex=-1` и возвращает шаблон.

Создание анкеты выполняется командой `/profile` или `/анкета` (последняя без аргумента преобразуется в `profile edit`). Подробные синтаксис и права — [каталог команд](../command/commands.md#command-profile). Команда доступна в групповых беседах; сервис сам не авторизует инициатора.

## Разбор шаблона и пошаговый ответ

`shouldHandleQuestionnaireAnswer` проверяет сохранённый черновик. Для индекса `0..N-1` достаточно активной анкеты. Для `-1` текст должен содержать хотя бы один распознанный заголовок вопроса; если сообщение является reply на форму, разрешается нумерованный ответ без повторения текста вопроса. Повреждённый JSON вопросов бросает ошибку.

В шаблоне понимаются строки вида `1. Вопрос`, `№ 1) Вопрос`, нумерация с `.`/`)`/`-`/`:` либо пробелом, а также заголовок с `Ответ:` (распознаются варианты `отвт`, `отв`, `отве[дт]`, ограниченные разделители). Заголовок с текстом сверяется с сохранённым вопросом после NFKC/lowercase/удаления знаков: используется расстояние Левенштейна, порог similarity ≥ 0.72 и допуск редактирования max(2, ceil(20% длины вопроса)). При совпадении ответом становятся последующие строки до следующего заголовка; повторный номер возвращает ошибку. Строки с командами анкеты и инструкциями шаблона пропускаются. Ответ `—` очищает сохранённый ответ, пустой ответ сохраняет старый, непустые значения перезаписывают его. Обнаруженные ответы ограничены 500 символами каждый; всё входное сообщение ограничено 3500 символами.

Для пошагового режима непустой trim-ответ до 500 символов сохраняется вместе с индексом следующего вопроса и возвращает следующий вопрос. Последний ответ переносит JSON ответов в `profile`, устанавливает `profileCompleted`, даты создания/обновления, сбрасывает отметку запроса удаления и очищает поля черновика. Шаблонный режим после успешной валидации выполняет те же переходы за один вызов. Ошибки повреждённого JSON промежуточных ответов и недопустимого индекса бросаются; пустые/слишком длинные пользовательские значения возвращаются как prompt без сохранения.

VK обрабатывает заполнение через `save_questionnaire`: это единственный tool для обычного пользователя, когда в беседе `quiet`, у него есть активная анкета и сообщение явно адресовано боту. В другом режиме тот же tool доступен только в обычном конечном наборе и повторно требует group, explicit addressing, действительный активный шаблон/вопрос и общий `VkService` access guard. Tool отправляет продолжение/ошибку напрямую и подавляет второй ответ модели. Незапрошенная анкета не сохраняется; при неудачной попытке в `questionnaireOnly` ответ модели не отправляется. См. [маршрутизацию VK](../vk/vkService.md) и [контракт инструмента](../ai/tools.md#save_questionnaire).

## Просмотр, правка, отмена и удаление

- `getProfileDetails` возвращает только `profileCompleted=true`; `getProfile` форматирует ответы по сохранённым ключам-вопросам и дату последнего обновления.
- `listProfiles` принимает только целую страницу ≥ 1, выбирает завершённые анкеты текущей беседы по `profileUpdatedAt DESC`, по 10 записей; за пределом количества страниц возвращает пустой список и метаданные.
- `updateProfileAnswer` требует непустой ответ ≤ 500 символов и положительный целый номер в пределах числа сохранённых ответов; меняет значение по порядку ключей JSON и timestamp.
- `clearProfileAnswer` требует существующий завершённый профиль и номер в диапазоне. Удаляет ключ; если ответов не осталось, сбрасывает `profileCompleted` и обе даты, иначе сохраняет обновлённую дату.
- `cancelQuestionnaire` условно очищает только поля черновика и возвращает, была ли строка обновлена. Профиль и членство сохраняются.
- `requestProfileDeletion` ставит timestamp только для завершённого профиля. `confirmProfileDeletion` принимает запрос до 5 минут по умолчанию, затем вызывает `deleteProfile`. `deleteProfile` чистит профиль, черновик и запрос удаления, но сохраняет строку участника и присутствие. Эти методы не проверяют роли; command layer ограничивает команду удаления только своей анкетой и подтверждением.

Команды администратора бота могут читать, изменять ответ или удалять профиль указанного участника; `/profile get` пишет AdminLog только при `isAdmin`; удаление и изменение также журналируются. Групповой VK caller отправляет результат административной правки инициатору в ЛС, а в беседу — уведомление. Разбор ссылок/упоминаний и локализация пользовательского имени выполняются до сервиса. Подробные ветви — [профиль и анкеты](../command/commands.md#command-profile).

## Ограничения и тестовые свидетельства

Публичные методы получают conversation/user IDs от caller-а и не проверяют актуальное членство в VK, срок действия профиля или административную роль. JSON profile parser при некорректном значении использует пустой объект; списки настроек вопросов валидируются строго. Изменения анкеты, claim вступления и отправка сообщения VK не находятся в общей транзакции: сбой VK после записи не откатывает состояние базы. Конкурирующие `answerQuestionnaire` могут прочитать одинаковый индекс и перезаписать черновик; compare-and-swap для этого перехода нет.

В `test/` нет прямых тестов `MemberService`, парсера шаблона, command profile routes или membership event handler. [`membershipCommand.test.ts`](../../../../../test/membershipCommand.test.ts) тестирует только `/membership`; [`membershipService.test.ts`](../../../../../test/membershipService.test.ts) проверяет форматирование статистики, не анкеты. В [`vkMessageDeliveryIntegration.test.ts`](../../../../../test/vkMessageDeliveryIntegration.test.ts) эта часть не тестируется. Тесты не запускались.
