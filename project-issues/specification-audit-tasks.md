## Проверки и ограничения подготовки

- Статически сверены затронутые функции VK, tools, напоминаний, игр, участников, голоса, истории и схемы; прочитаны относящиеся канонические контракты и существующие тестовые assertions для используемых свидетельств.
- В каждом плане есть сопоставление AC → контракт/исходный владелец → шаг изменения → сценарий проверки, а также миграционные последствия и правила передачи исполнителю.
- Новые/изменённые репозиторные тесты не назначены обязательными: существующие проверки и временные изолированные сценарии используются в пределах выбранной задачи. Для задач документации достаточно статической сверки.
- Миграции, точные новые lease/retention-бюджеты и существенные интерфейсы остаются предложениями до выбора D*. Рабочая БД, секреты, VK и AI API не использовались.
- Подробные документы исполнения и review не создавались заранее. Переход к подробной детализации и реализации выполняется по правилам [workflow](../specifications/tasks/README.md) после разрешения необходимых решений и соответствующего поручения.

Правила передачи: исполнитель не меняет планы во время реализации без специального указания, даже для статуса или результатов. Новое существенное решение обсуждается до зависимого кода; отдельное согласие на решение не означает разрешения редактировать существующие планы.
