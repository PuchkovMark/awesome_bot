# Awesome Bot

Новый собеседник и помощник VK. Сейчас реализуется F1.1: технический скелет без запуска бота, подключения VK, LLM и БД.

## Среда и команды

Проверяемая среда: Ubuntu 22.04.5 LTS, Node.js 26.13.1, npm 11.20.0. Версия Node.js закреплена в `.nvmrc`; при использовании nvm выполните `nvm use`. Основной путь разработки — локальный, Docker необязателен.

```sh
npm ci
npm run lint
npm run typecheck
npm run build
npm test
```

Тесты загрузки ESM требуют предварительной сборки. `build` выполняет линтинг, проверку типов и выпуск JavaScript в `dist`; тесты запускаются отдельно. После установки зависимостей проверки не обращаются к VK и LLM и не требуют секретов.

## Слои

| Каталог | Назначение |
| --- | --- |
| `src/core` | Ядро: будущие роутер, очередь, контекст и агентный цикл |
| `src/channels` | Будущие адаптеры платформ |
| `src/tools` | Будущие инструменты модели |
| `src/storage` | Будущий доступ к данным |
| `src/llm` | Будущий клиент модели |

Слои пока содержат только пустые ESM-модули. Требования и статусы — в [проекте](docs/project.md) и [дорожной карте](docs/roadmap.md).

## Границы платформ

Локальное правило ESLint запрещает прямые платформенные импорты во вложенных исходниках `src/core` и `src/tools`. Список `platformPackages` в [конфигурации](eslint.config.mjs) содержит `vk-io` и дополняется при подключении новых платформенных библиотек. Запрет охватывает подмодули, импорты типов, реэкспорты, TypeScript import-type/import-equals, `import()` и `require()`; вычисляемые имена загрузки в этих слоях отклоняются. Платформенные импорты разрешены в адаптерах `src/channels`.

Нарушение останавливает `npm run build` на линтинге. Правило проверяет прямые импорты исходников; транзитивный граф сторонних зависимостей не анализируется. Независимость ядра также проверяется при ревью.

## Проверки скелета

Vitest проверяет реальную конфигурацию ESLint, расширение списка платформенных пакетов, загрузку выпущенных модулей самим Node.js и запуск сборки на временных копиях проекта. Негативные примеры не записываются в основные исходники. Для дочерних процессов используется тот же Node.js и npm; запускайте тесты командой `npm test`.

После `npm ci` тесты работают без сетевой установки и внешних API. Каталоги `dist`, `node_modules`, отчёты покрытия и локальные файлы окружения исключены из Git. Отсутствие сборки перед ESM-тестом считается ошибкой.

Проверенный набор инструментов закреплён в [манифесте](package.json) и lock-файле: TypeScript 6.0.3, ESLint 10.15.0, typescript-eslint 8.73.0, Vitest 5.1.1. TypeScript 6 выбран в пределах поддерживаемого typescript-eslint диапазона; обновление зависимостей требует повторного прогона проверок.
