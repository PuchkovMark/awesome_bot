# VK AI-бот

Бот для личных сообщений и бесед ВКонтакте. Получает сообщения от имени сообщества, передаёт их языковой модели, сохраняет историю в SQLite и отправляет ответ обратно в VK.

## Возможности

- Отвечает на личные сообщения сообщества.
- В беседах отвечает реплаем, если в сообщении как отдельное слово встречается «Пенёк», «Пенек», «Пенёчек» или «Пенечек»; слово «Бот» и значение `BOT_NAME` для обращения не распознаются. Также отвечает на настоящее VK-упоминание (`@club<ID>`) и на ответ через функцию VK «Ответить» на сообщение сообщества. Команды с `/` выполняются без обращения к боту и без выбора команды моделью; для большинства команд с `!` обращение по-прежнему необходимо. Режим беседы и проверки прав сохраняются.
- Поддерживает русские названия команд как основные, английские — как псевдонимы; команды можно вызывать с префиксами `/` и `!`.
- `/пересказ` (английский псевдоним `/summary`) сразу показывает пересказ за последние 2 часа. Кнопки под пересказом переключают период на 2 или 6 часов, редактируя исходное сообщение.
- Генерирует картинки по команде `/изображение <описание>` и преобразует приложенное изображение по команде `/преобразить <описание>`; естественную просьбу к Пеньку может обработать модель через инструмент.
- В групповых беседах администраторы могут включить приветствия новых участников и анкету-знакомство; бот запоминает вступления и выходы, чтобы отличать новых участников от возвращающихся.
- Участники могут создавать и редактировать профиль беседы; доступны просмотр профилей, список анкет и подтверждаемое удаление. Новичкам бот предлагает анкету, если она включена.
- Поддерживает шесть персонажей общения. Личный персонаж и персонаж беседы настраиваются отдельно; выбранный стиль не ограничивает доступные функции.
- Сохраняет историю отдельно по пользователям и беседам; в группах ИИ получает только общий контекст беседы. Обычная история удаляется не позднее 24 часов; если администратор включил недельные мемы, общие сообщения беседы хранятся до 7 дней только для подготовки мема недели.
- Поддерживает режимы беседы `active`, `normal` и `quiet`, игровые сессии, перевод, подключаемый поиск и голосовые сообщения.
- Создаёт личные и общие напоминания по обращениям к боту или ответам на его сообщения, задаёт уточняющие вопросы и поддерживает расписания с повторением.
- Хранит историю сообщений в SQLite с помощью Prisma; контекст ограничен временем жизни и лимитом токенов.
- Обрабатывает запросы каждого пользователя последовательно.
- В беседе ответ отправляется одним сообщением (до 4000 кодовых единиц UTF-16); если текст не помещается, он сокращается с предупреждением. При включённой озвучке голос длинного ответа прикрепляется к тому же сообщению. В личных сообщениях длинный ответ отправляется полностью несколькими сообщениями по порядку, без ограничения числа частей.
- Во время генерации ответа в беседе показывает статус «печатает» через токен сообщества.
- Использует Gemini 4 Argon через OpenCode для текстовых запросов; уровень рассуждения задаёт администратор.
- Периодически удаляет сообщения, срок хранения которых истёк.

## Требования

- Node.js 22 или новее и npm.
- Токен доступа сообщества VK с разрешением на сообщения.
- ID сообщества VK.
- API-ключ OpenCode для текстового ИИ; для медиа и голоса также нужен ключ OpenAI.

В настройках сообщества VK включите сообщения и Long Poll, чтобы бот получал новые события.
Для переключения периода пересказа также включите событие `message_event` в настройках Long Poll сообщества, иначе VK не передаст боту нажатия callback-кнопок.

## Установка и запуск

Скопируйте пример конфигурации:

```bash
cp .env.example .env
```

Заполните `.env` (описание переменных — ниже), затем выполните:

```bash
npm ci
npx prisma generate
npx prisma migrate deploy
npm run dev
```

Для запуска собранной версии:

```bash
npm run build
npm start
```

## Настройка

### VK

```env
VK_TOKEN=токен_сообщества
VK_GROUP_ID=числовой_ID_сообщества
VK_SERVICE_TOKEN=
```

- `VK_TOKEN` — токен сообщества, которым бот получает и отправляет сообщения.
- `VK_GROUP_ID` — числовой ID сообщества без префикса `club`.
- `VK_SERVICE_TOKEN` — необязательный сервисный ключ приложения VK для доступных записей, друзей, сообществ и фотоальбомов пользователя. Получите его в настройках приложения по [документации VK](https://dev.vk.ru/ru/api/service-token/client-cred-flow), сохраните только на сервере в `.env` и перезапустите бота. Не отправляйте ключ в переписку. Без него профиль работает, а дополнительные разделы сообщают о недоступности.

### Текстовый ИИ

```env
OPENCODE_API_KEY=ключ_OpenCode_Console
AI_EFFORT=low
AI_MAX_OUTPUT_TOKENS=32768
OPENCODE_BASE_URL=https://opencode.ai/inference/go/openai/v1
OPENAI_API_KEY=ключ_OpenAI
OPENAI_MODEL=gpt-4.1-mini
```

Единственная текстовая модель — `gemini-4-argon` через OpenCode. Администратор бота или создатель меняет уровень её рассуждения командой `/усилие low|medium|high` (также `/effort`); без аргумента команда показывает текущий уровень. По умолчанию используется `low`, сохранённое командой значение действует глобально и не меняет модель. Старые `AI_PROVIDER`, `AI_THINKING_MODE` и сохранённые настройки провайдера/режима больше не выбирают модель или уровень. `OPENAI_MODEL` по-прежнему используется отдельно для анализа медиа. Ключи остаются в `.env`, не в базе данных: создайте ключ OpenCode в [OpenCode Console](https://opencode.ai/console), а ключ для медиа и голоса — в [OpenAI API dashboard](https://platform.openai.com/api-keys).

`AI_MAX_OUTPUT_TOKENS` ограничивает суммарное число токенов рассуждения, вызовов инструментов и ответа в каждом запросе к модели; по умолчанию 32768, максимум 32768. Уменьшение лимита снижает возможный расход, но может привести к неполному ответу, который бот сообщает как ошибку. Повышение effort также может увеличить расход и задержку. OpenCode Go предназначен для запросов кодирующих агентов, поэтому доступ для VK-бота зависит от правил OpenCode и настроек подписки.

OpenAI SDK автоматически повторяет временные ошибки с ограниченным числом повторов; `AI_MAX_RETRIES`, `MAX_HISTORY_MESSAGES` и `MAX_HISTORY_TOKENS` задают соответственно лимит повторов и контекста.

Встроенные системные инструкции не содержат справку о командах и сроки хранения контекста. При необходимости модель запрашивает актуальный справочник через `get_bot_commands` и выполняет действия через `execute_bot_command`. Заполненная анкета передаётся модели ответом на сообщение бота, с обращением по имени или упоминанием перед шаблоном; `save_questionnaire` сохраняет исходный текст анкеты только от имени её автора. `play_game` запускает игры и передаёт действия нужному игровому движку, а `manage_reminder` и `manage_memory` используют существующие сервисы напоминаний и памяти. Инструменты привязаны к реальному отправителю и беседе, проверяют права и не раскрывают личную память в группе. Результаты действий отправляются пользователю напрямую; за один ответ ИИ начинает не более одного действия. Для подтверждения рассылки и удаления своей анкеты пользователь должен самостоятельно отправить команду подтверждения. Инструменты доступны Gemini 4 Argon через OpenCode.

Реализации инструментов находятся в [`src/services/ai/tools/`](./src/services/ai/tools/).

Модель может использовать `send_vk_message`, чтобы ответить на текущее или процитированное сообщение либо отправить отдельное сообщение в текущий диалог. При обращении к боту по имени или ответом на его сообщение обычный ответ остаётся ответом на обращение; результат инструмента не отправляется повторно как итоговый текст модели. В активном режиме решение отвечать по-прежнему принимается до отправки, в остальных режимах сохраняются прежние ограничения.

По просьбе передать слова участнику инструмент проверяет его членство в текущей беседе по имени или VK-упоминанию. Он отвечает на последнее сообщение этого участника среди 20 предыдущих сообщений, если оно не старше 30 минут; иначе отправляет отдельное сообщение с упоминанием, не отвечая на исходную просьбу. Если участников с таким именем несколько или VK не позволяет однозначно их проверить, бот просит уточнение. Для поиска приложение получает список участников и ограниченную выборку сообщений из VK; содержимое этой выборки не передаётся модели и не сохраняется. Отправка в другую беседу или личные сообщения другого участника недоступна. После чтения полной истории или сведений VK в том же ответе действие, как и другие действия, недоступно. Длинные ответы используют обычные настройки озвучивания; если доставка не подтверждена, бот предупреждает об этом и автоматически не повторяет отправку.

Для текущей даты и времени модель может вызвать `get_current_datetime`. Инструмент запрашивает UTC у TimeAPI.io, а при ошибке, тайм-ауте или некорректном ответе использует резервный UTCtime.app; если оба недоступны, сообщает об ошибке. По указанной зоне IANA время переводится с учётом правил часового пояса. Без неё используются настройки беседы в группе или пользователя в личном диалоге; если зона не задана, результат явно указывается в UTC. Ключи и настройка веб-поиска не нужны, текст сообщений и VK ID внешним сервисам времени не передаются.

Для погоды модель использует `get_weather`: текущую модельную оценку и прогноз на ближайшие 1–7 суток предоставляет [Open-Meteo](https://open-meteo.com/), а при его недоступности или некорректных данных — [MET Norway](https://api.met.no/). Населённые пункты ищутся через Open-Meteo/GeoNames и резервный [Photon](https://photon.komoot.io/); неоднозначное название бот уточняет. Если место не указано и не сохранено в настройках текущей беседы или личного диалога, бот спросит город. Личное место участника не используется в группе. Если часовой пояс места неизвестен, время указывается в UTC. Ключи и веб-поиск не нужны; внешним сервисам передаются только название и уточнения места или его координаты, но не история сообщений и VK ID. В ответ добавляется указание источников и лицензий.

Бесплатный Open-Meteo предназначен для [некоммерческого использования](https://open-meteo.com/en/terms). Публичный Photon — демонстрационный сервис с ограниченной доступностью и [условиями разумной нагрузки](https://github.com/komoot/photon#demo-server); для больших нагрузок рекомендуется собственный экземпляр. Результаты поиска и прогнозы кэшируются в памяти; запросы к MET Norway ограничиваются и для одинаковых координат повторяются не чаще одного раза в три часа и не ранее заголовка `Expires`. Для нескольких одновременно работающих экземпляров необходимо обеспечить общие ограничения и кэш в соответствии с [правилами MET Norway](https://docs.api.met.no/doc/TermsOfService).

Когда контекста недостаточно, модель может запросить дополнительные сохранённые сообщения текущей беседы или личного диалога через `get_local_chat_history`. В группе возвращается общая история беседы, в личном диалоге — только сообщения текущего пользователя. Инструмент отдаёт дословные сообщения старше уже показанных, до 50 за вызов и до 100 за ответ, но не более 24 000 символов и трёх вызовов; для продолжения используется `next_before`, период можно ограничить через `before`/`from`. Чтение локальной истории не блокирует отправку ответа или другие действия. Доступны только сообщения, которые ещё хранятся в SQL: обычно до 24 часов, для бесед с недельными мемами — до 7 дней.

Если нужного периода нет в локальной истории, модель может запросить сообщения текущей групповой беседы напрямую из VK за выбранный период. VK возвращает только доступные сообществу сообщения. За один вызов инструмент проверяет до 500 идентификаторов пакетами по 100; за ответ возможны три вызова и не более 50 сообщений с учётом `MAX_HISTORY_MESSAGES` и `MAX_HISTORY_TOKENS`. Старый период может определяться выборочно по идентификаторам, поэтому полнота не гарантируется; неполная выборка отмечается. Инструмент не записывает загруженные сообщения в базу или журналы, а ответ, использующий эту историю, не сохраняется в локальном контексте. Полученные данные передаются OpenCode для ответа; хранение на стороне провайдера зависит от его правил. Команды `/сброс` и `/забыть` очищают локальную историю, но не удаляют сообщения в VK, поэтому доступные старые сообщения могут быть запрошены снова. В личных диалогах VK-история недоступна.

Для пересказа большого фрагмента модель запускает `get_chat_digest`: в группах сообщения берутся из SQL с добором из VK, в личных диалогах — только из SQL. Для фрагмента до 20 сообщений инструмент перенаправляет в `get_local_chat_history`. Обработка идёт в фоне: бот сразу подтверждает запрос, а пересказ присылает позже ответом на исходное сообщение. В пересказе указывается фактическое число обработанных сообщений и источник. Результат digest не записывается в локальный контекст.

Инструмент `get_chat_info` по необходимости получает сведения о беседе и её участниках: обзор беседы, список участников по 50 за вызов, профиль участника, ближайшие дни рождения и статистику входов и выходов. Действие `membership` доступно только администраторам бота и возвращает агрегаты: текущее число участников, вошло, вышло, прирост, уникальные и повторные входы. В личных сообщениях доступны только собственный профиль и собственный день рождения; список участников, статистика и чужие профили недоступны. Отсутствующие из-за приватности VK поля возвращаются в `hidden_fields`.

Статистика входов и выходов собирается с момента миграции: история событий хранится в `MembershipEvent` бессрочно, а агрегаты считаются при каждом запросе. Текущий состав обновляется после входа или выхода, но не чаще одного раза в календарный день беседы; синхронизация не создаёт фиктивных событий. Если бот был выключен во время входа или выхода, это событие не восстанавливается.

Доступны поля профиля, записи на стене (владельца или других авторов), друзья, сообщества, список альбомов и фотографии конкретного альбома (`profile`, `wall` или ID альбома). Фото возвращаются как ссылки, подписи и метаданные, без анализа изображения. Списки пользователя выдаются страницами до 20 элементов, участники беседы — до 100. Профиль запрашивается ключом сообщества; для остальных разделов нужен `VK_SERVICE_TOKEN`. VK может не вернуть отдельные поля или запретить раздел из-за типа ключа, настроек приватности и других ограничений; ошибки и сокращение данных отмечаются отдельно. Сервисный ключ не обходит настройки приватности.

Полученные сведения передаются OpenCode; при включённой озвучке длинный ответ также передаётся OpenAI. Инструмент не сохраняет сведения, а ответ на их основе не записывается в локальный контекст. После получения сведений действия в том же ответе блокируются. Итоговый ответ отправляется в исходный диалог и в беседе виден её участникам; хранение данных у внешних провайдеров зависит от их правил.

### Напоминания

Создавайте и управляйте напоминаниями обычными сообщениями: «Пенёк, напомни завтра в 10:00 позвонить мастеру», «Пенёк, напоминай каждый будний день в 9 утра поливать цветы» или «Пенёк, покажи мои напоминания». В беседе также можно ответить на сообщение бота. Если не хватает времени, даты, часового пояса или получателя, бот задаст уточняющий вопрос и не сохранит неполное напоминание.

По умолчанию напоминание личное: в беседе его содержимое и подтверждение отправляются автору в личные сообщения, а не участникам чата. Просьба «напомни всем» создаёт общее напоминание в исходной беседе. Указанного участника можно выбрать через VK ID/ссылку или уникальное имя участника беседы. Если личная доставка не удалась, бот попросит явное согласие, прежде чем отправить напоминание в беседу.

Поддерживаются ежедневные, еженедельные, будничные, выходные, ежемесячные и ежегодные расписания, интервалы вроде «каждые три дня», перенос, удаление, пауза и возобновление. Время хранится с часовым поясом: используются сохранённые личные или групповые настройки, а если часовой пояс не задан — московское время (`Europe/Moscow`). Указывать зону при создании напоминания не требуется. Напоминания и попытки доставки хранятся в SQLite и сохраняются после перезапуска; временные ошибки отправки повторяются ограниченное число раз.

### Долговременная память

Бот автоматически сохраняет полезные факты, предпочтения, проекты и договорённости, если они прямо сообщены и проходят проверку. Личная память привязана к VK ID; общая память беседы отделена от неё. В групповых ответах используются только общие воспоминания — личная память участника туда не передаётся.

Управляйте памятью обычными сообщениями: «Пенёк, что ты обо мне помнишь?», «Пенёк, запомни, что я люблю научную фантастику», «Пенёк, забудь, что я использую Node.js», «Пенёк, отключи запоминание» или «Пенёк, очисти всю мою память». Для общей памяти используйте формулировки «Покажи память этой беседы», «Запомни в общей памяти беседы…»; очистить её и менять настройки может администратор беседы. Личный список из группового чата отправляется только автору в личные сообщения.

Автоматический сбор можно отключить отдельно от использования ранее сохранённых данных. Пароли, ключи, сведения о здоровье, политических и религиозных взглядах и другие распознаваемые чувствительные данные автоматически не сохраняются. Система использует OpenAI Embeddings для семантического поиска, когда задан `MEMORY_EMBEDDING_API_KEY` или `OPENAI_API_KEY`; без ключа остаётся поиск по словам. Модель эмбеддингов задаётся через `MEMORY_EMBEDDING_MODEL`. Текстовые факты для извлечения обрабатываются выбранным AI-провайдером; при включённых эмбеддингах сохранённые факты также отправляются в OpenAI для построения векторов.

### Генерация и редактирование изображений

```env
OPENAI_API_KEY=ключ_OpenAI
OPENAI_IMAGE_MODEL=gpt-image-2.6-flare
```

Для генерации и редактирования используется OpenAI Images API с моделью `gpt-image-2.6-flare` и качеством `high`. Модель можно изменить через `OPENAI_IMAGE_MODEL`; доступ к GPT Image может потребовать верификации организации OpenAI.

Генерация изображений ограничена администраторами по умолчанию. Настройте `VK_ADMIN_IDS` как список числовых VK ID через запятую. Администратор может выдать доступ в беседе через `/доступккартинкам all` (английский псевдоним `/imageaccess`).

### Голос и веб-поиск

```env
VOICE_ENABLED=false
OPENAI_TRANSCRIPTION_MODEL=gpt-transcribe
OPENAI_TTS_MODEL=gpt-4o-mini-tts
WEB_SEARCH_PROVIDER=serper
SERPER_API_KEY=
TAVILY_API_KEY=
```

Для голосового ввода/ответов задайте `VOICE_ENABLED=true` и настройте `OPENAI_API_KEY`. Команда `/голос on` включает автоматическую озвучку ответов ИИ длиннее 500 символов; короткие ответы остаются текстовыми. В беседе озвучивается текст единственного сообщения, а в личных сообщениях ответы длиннее 4096 кодовых единиц UTF-16 озвучиваются несколькими голосовыми сообщениями и запросами OpenAI. Голос выбирается через `/голос <voice>`. Команда `/озвучить <текст>` работает независимо от автоматического режима и принимает до 4096 кодовых единиц UTF-16; в беседе можно ответить `/озвучить` на текстовое сообщение. `/голос off` отключает автоматическую озвучку ответов. Английские псевдонимы этих команд — `/voice` (также `/voise`) и `/say`.

Попросите бота найти информацию обычным сообщением, например: «Пенёк, найди прогноз погоды в Москве». Модель определяет, нужен ли поиск, и использует найденные сведения для ответа. Поиск по умолчанию использует Serper; при ошибке или пустом результате автоматически пробует Tavily, и наоборот, если `WEB_SEARCH_PROVIDER=tavily`. Настройте `SERPER_API_KEY` и `TAVILY_API_KEY` для резервирования; `WEB_SEARCH_PROVIDER=none` отключает поиск.

### Пользовательские настройки и беседы

В таблице раздела «Команды» приведены все английские псевдонимы для основных русских названий.

- `/развлечения` показывает меню развлечений: `/случайнаяшутка [тема]`, `/мем [идея]`, `/шутка [all|VK ID]`, `/подкол`, `/предсказание [тема]`, `/реакция [стиль]` (или ответ на сообщение с `/реакция`), `/рейтинг`, `/история [длина]` и `/баттл`. Текстовые варианты учитывают выбранного персонажа и последние ответы, предлагают оценки и кнопку нового варианта. Мемы создаются с короткой подписью, наложенной отдельно; исходная фотография не перезаписывается. Для мемов действуют настройки доступа к изображениям и OpenAI Images API.
- `/мемдня on|off` включает или отключает ежедневный мем в групповой беседе (по умолчанию выключено). `/мемдня now`, `user [@имя]` и `all` запускают мем вручную; `history`, `top`, `week` и `random` показывают архив, рейтинг, еженедельный и случайный мем. После публикации голосуйте кнопками 😂, 🔥, 😐 и 👎; повторный голос заменяет предыдущий. Настройки `/мемдня settings` доступны администраторам беседы и бота; время по умолчанию 20:00, недельный выпуск — по воскресеньям. Используется только общий контекст этой беседы; личные сообщения не используются, участники могут запретить мемы о себе через `/настройкиюмора memes off`. Часовой пояс по умолчанию задаёт `MEMEDAY_TIMEZONE` (UTC); беседа может выбрать свою зону IANA. Для генерации требуется текстовый ИИ и настроенный провайдер изображений.
- `/приключение start [жанр|random]` запускает интерактивное приключение; доступны `detective`, `survival`, `fantasy`, `horror`, `scifi`, `pirates`, `time` и `comedy`. В групповой игре используйте `/приключение join`; участники могут свободно описывать действия или применять `/осмотреть`, `/изучить`, `/поговорить`, `/использовать`. Команды `/инвентарь`, `/статус`, `/журналприключения`, `/карта`, `/подсказка` и `/голосовать <номер>` показывают состояние или управляют ходом. Ведущий управляет игрой командами `/приключение pause|resume|end|abort|restart`: `/приключение end` сохраняет журнал, а `/приключение abort` сразу удаляет текущее приключение без сохранения. Настройки сложности, режима решений, длительности и иллюстраций доступны через `/приключение settings`. Состояние, журнал, предметы и голосование сохраняются в базе; иллюстрации создаются настроенным провайдером изображений и при повторном посещении переиспользуются. Старые команды `/игры adventure` и `/игры detective` запускают новый модуль.
- `/настройкиюмора jokes off|on` запрещает или разрешает персональные шутки про текущего пользователя, а `/настройкиюмора memes off|on` — мемы про него в этой беседе. Настройки `intensity`, `sarcasm`, `absurdity` и `emojis` доступны пользователю отдельно; администратор бота задаёт общие настройки беседы через `/настройкиюмора chat <параметр> <значение>`. Он же может включить автоматические реакции командой `/настройкиюмора auto on`, задать вероятность `/настройкиюмора probability 1-30` и интервал `/настройкиюмора interval 60-3600`; по умолчанию они выключены. Автоматические реакции используют только контекст этой беседы и ограничиваются общей паузой.
- `/баттл start [1-5]`, `/баттл join`, `/баттл submit <шутка>`, `/баттл score` и `/баттл stop` управляют юмористическим баттлом в групповой беседе. Участники присоединяются самостоятельно; ИИ выбирает победителя раунда как развлекательный вердикт.
- По умолчанию выбран Чипсик. Одна команда `/персонаж` открывает меню шести персонажей и выбирает личность с учётом контекста: в личных сообщениях — для пользователя, в групповой беседе — общую для беседы. Доступны `/персонаж info`, `list`, `default`, `settings` и `reset` (сброс доступен только в личных сообщениях); `/персонаж settings humor=70 sarcasm=30` меняет настройки стиля. Личные настройки хранятся отдельно для пользователя и персонажа, а настройки беседы общие для всех её участников и доступны администраторам беседы/бота.
- В беседе администраторы могут разрешить или запретить смену персонажа участниками командами `/персонаж allow` и `/персонаж deny`; по умолчанию смена доступна только администраторам.
- Администратор бота может управлять профилями командами `/персонаж add id|имя|описание|пример|инструкция`, `/персонаж edit id|name|значение`, `/персонаж prompt id|инструкция`, `defaults id|humor=70|influence.sarcasm=80`, `enable`, `disable`, `availability`, `exclusive` и `access`; `default <id>` назначает профиль по умолчанию, `rollback id|версия` восстанавливает снимок, `stats [id]` показывает успешные ответы. Системные инструкции не показываются публичными командами.
- `/инструкция` действует в текущем диалоге: в личных сообщениях показывает, задаёт (`/инструкция <текст>`) или удаляет (`/инструкция clear`) личную инструкцию пользователя; в групповой беседе те же варианты управляют общей инструкцией беседы, доступной для просмотра и изменения только администраторам беседы или бота.
- В групповой беседе администратор задаёт режим командой `/режим active|normal|quiet`. Обычный режим отвечает на упоминания, команды и ответы боту; в активном модель также рассматривает неадресованные сообщения и решает, нужно ли ответить на вопрос или просьбу. Это увеличивает число запросов к модели. В тихом режиме обычным участникам доступны команды анкет.
- Команды `/приветствие on|off` и `/приветствие set <текст>` управляют приветствием в текущей беседе (подстановка `{name}` — имя участника). По умолчанию приветствия выключены. `/опрос on|off` управляет автоматическим знакомством при вступлении: если профиль есть в этой беседе, бот публикует краткую презентацию из заполненных ответов; если профиля нет — предлагает заполнить анкету. По умолчанию функция выключена. `/опрос set <вопрос 1> | <вопрос 2>` задаёт от 1 до 8 вопросов. Администратор беседы, администратор бота или создатель могут управлять этими настройками.
- При вступлении бот знакомит участников только в рамках текущей беседы. Если анкеты нет, он предлагает заполнить её через `/анкета`; если анкета есть, публикует только сохранённые непустые ответы, без VK ID. Любой участник может заполнить или изменить свою анкету через `/анкета` или `/профиль create`; `/профиль edit` обновляет анкету, `/профиль show` показывает её, `/профиль cancel` отменяет заполнение. Заполнение анкеты не зависит от настройки `/опрос`. Оно необязательно; ответы видны участникам беседы. Участники могут получить список анкет командой `/анкеты [страница]` и просмотреть профиль по упоминанию; администраторы бота могут изменить чужой ответ `/профиль edit <VK ID> <номер ответа> <текст>` или удалить анкету `/профиль delete <VK ID>`. Результаты администраторских команд отправляются в личные сообщения администратора.
- Обычный TTL ограничен 24 часами; включённые недельные мемы продлевают хранение общих сообщений соответствующей беседы максимум до 7 дней. `/сброс` очищает историю пользователя в текущем разговоре, `/забыть` — личную историю пользователя во всех беседах. Смена персонажа не очищает историю.
- Восемь быстрых игр — викторина, загадки, персонаж, слово, правда или действие, «кто вероятнее всего», песня/фильм и ассоциации — запускаются командами `/игры начать <игра>` или естественной просьбой (например, «Пенёк, давай викторину про историю»). В беседе доступны также командные режимы и общая интерактивная история. Для игровых действий участники отвечают на сообщение бота или обращаются к нему; модель передаёт действия игровому инструменту. Игровые состояния и результаты сохраняются отдельно для каждой беседы, а повторные события VK не начисляют очки повторно.
- При запуске можно настроить уровень 1–4, число раундов, категорию, лимит игроков, режим `team`, время ответа, подсказки, попытки и ручной/автоматический переход. Например: `/игры начать викторина сложность экспертная раундов 5 team`. Изменить уровень можно и в ходе игры, обратившись к боту: «Пенёк, сделай игру сложнее» или «Пенёк, переключи на лёгкий уровень»; в группах уровень меняется голосованием, результаты завершённых раундов и счёт сохраняются.
- Игровые действия можно описать обычным текстом, обратившись к боту или ответив на его сообщение: например, попросить подсказку или присоединиться. В командном режиме участники автоматически распределяются между командами; ведущий/администратор может назначить состав и капитанов командами `/игры команда <VK ID> <1|2>` и `/игры капитан <VK ID>`. Таймеры продолжаются после перезапуска, а выход участника из беседы обрабатывается для активной игры.
- `/игры рейтинг` показывает рейтинг беседы, `/игры top` — общий рейтинг, `/игры статистика` — личные результаты и достижения. Команда `/игры приватность выключить` исключает пользователя из общего рейтинга; локальная статистика бесед остаётся отдельной. ИИ используется для генерации и проверки игровых заданий и подсказок, а очки, таймеры, голосования и состояние сессии управляются программно.
- «Мафия» запускается командой `/игры мафия` или обычной просьбой. Игроки записываются фразой «я играю»; организатор начинает партию командой `/игры мафия начать`, а ходы ночью отправляются боту в личные сообщения. Роли выдаются только после проверки доступности личных сообщений всех игроков; при неудаче доставки партия отменяется, секретные роли в беседу не отправляются. Используйте `/игры мафия настройки сложность 3`, `/игры мафия настройки ночь 60 секунд` или естественную просьбу для изменения параметров; сложности 1–4 задают сбалансированный состав ролей. В ходе партии безопасные настройки применяются к следующим фазам, а состав ролей сохраняется для будущей партии. Доступны команды «пауза», «продолжай игру», «заверши игру» и «результаты»; ночные действия, дневные голосования, роли, таймеры и статистика обрабатываются программно, а состояние восстанавливается после перезапуска.
- Административные команды проверяют VK ID: `/админка`, `/пользователи`, `/журнал`, `/усилие`, `/обслуживание`, `/рассылка`.
- Роль «Создатель» выше роли «Администратор» и закреплена за Mark Puchkov (VK ID `388581097`). Создатель автоматически имеет права администратора; только он может назначать и снимать администраторов. Остальных администраторов задают через `VK_ADMIN_IDS` или команду `/админка add|remove`.

### Прочие параметры

```env
DATABASE_URL=file:./dev.db
PORT=3000
LOG_LEVEL=info
BOT_NAME=awesome_bot
CONTEXT_TTL_HOURS=24
MAX_HISTORY_TOKENS=4000
MAX_HISTORY_MESSAGES=30
MAX_INPUT_CHARS=12000
MAX_REQUESTS_PER_MINUTE=10
MEMEDAY_TIMEZONE=UTC
```

- `DATABASE_URL` — адрес базы данных; по умолчанию используется локальная SQLite.
- `PORT` — порт приложения.
- `LOG_LEVEL` — уровень логирования.
- `BOT_NAME` — имя экземпляра бота для журналов запуска; для обращения в беседе используются только «Пенёк/Пенек» и «Пенёчек/Пенечек».
- `CONTEXT_TTL_HOURS` — сколько часов хранить сообщения в контексте.
- `MAX_HISTORY_TOKENS` — приблизительный лимит истории, передаваемой модели.
- В групповой беседе вопросы об авторе предложения (например, «кто это предложил?») дополнительно сверяются с недавними сообщениями за период `CONTEXT_TTL_HOURS`; если подходящее сообщение не найдено, бот не должен угадывать.
- `MEMEDAY_TIMEZONE` — временная зона IANA по умолчанию для расписания «Мема дня»; беседа может установить свою.

Анкета автоматически предлагается новому участнику только если она включена в беседе. Профили привязаны к беседе; просмотр отдельного профиля и списка доступен участникам, а администраторы бота могут просматривать, изменять и удалять чужие анкеты через команды `/профиль get|edit|delete`. Английские названия команд продолжают работать как псевдонимы.

Если город и часовой пояс не настроены, бот использует Москву и `Europe/Moscow` по умолчанию и сообщает об этом в ответах о погоде и текущем времени.

## Пересказ большой истории

Для больших объёмов истории бот использует фоновую обработку: быстрая модель делает структурированные выжимки по фрагментам, а основная модель составляет итоговый пересказ. Запрос можно сформулировать обычной фразой, например «перескажи последние 6000 сообщений». Бот сразу подтверждает запрос и присылает результат ответом на исходное сообщение. Повторный запрос во время обработки сообщает, что задача уже выполняется.

## Docker

Для запуска через Compose подготовьте `.env`, затем выполните:

```bash
docker compose up --build -d
```

Compose сначала применяет миграции Prisma отдельным сервисом `migrate`, затем запускает приложение. Если база уже существует, неприменённые миграции будут применены автоматически.

## Размещение в облаке

Приложение использует одну SQLite-базу, указанную в `DATABASE_URL`. Для размещения на VM или контейнерной платформе подключите постоянный диск, например задав `DATABASE_URL=file:/data/bot.db` и смонтировав диск в `/data`: без постоянного хранилища история будет потеряна при пересоздании контейнера. Используйте один экземпляр бота, чтобы все процессы работали с одной базой.
