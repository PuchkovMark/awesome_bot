# Проверка OpenCode Go и DeepSeek — F2.9

- Дата проверки: 2026-11-21.
- Статус: документальная часть выполнена; пригодность сервиса, доступ аккаунта и натурные проверки не подтверждены. F2.9 не завершена.
- Связанные документы: [задача 011](../tasks/011-go-model-validation.md), [дорожная карта](../roadmap.md#веха-2-ядро-без-платформы), [клиент F2.1](../tasks/completed/010-llm-client.md), [privacy](../specs/privacy.md).
- Область: официальная документация и один публичный GET каталога без авторизации. Запросов генерации, чтения ключей/.env, расходов и изменений аккаунта не было.

## Итог

Подтверждены публичное описание модели и маршрут. Допуск разговорного бота через Go не установлен; есть прямые ограничения опубликованных условий, требующие разрешения вопроса человеком. Найден отдельный риск продолжения вызовов инструментов из-за reasoning_content. Качество русского, рабочий контекст, устойчивость и права аккаунта не измерены. Завершать F2.2 на основании этой проверки нельзя.

## Условия использования

[Go: Where can I use it](https://opencode.ai/docs/console/go/#where-can-i-use-it) ориентирует подписку на coding-agent трафик, требует собственной идентификации и стабильной сессии. Наше обычное общение участников не становится coding-трафиком из-за наличия инструментов. Это вывод о несоответствии подтверждённого назначения, а не автоматический выбор другого тарифа.

[Terms of Use](https://opencode.ai/legal/terms-of-service) в разделе What are the basics of using OpenCode ограничивают использование собственными внутренними нуждами и исключают работу в интересах третьих лиц. Раздел Are there restrictions in how I can use the Services также содержит ограничения автоматического извлечения Output и автоответчиков. Сочетание этих пунктов с документированным inference API требует разъяснения применительно к боту сообщества. Условия прочитаны, но юридическое толкование и применимость решает человек. Подтверждение провайдера не получено; агент в поддержку не обращался.

[Inference API](https://opencode.ai/docs/console/api/inference/) описывает JSON POST и Bearer-ключ. Клиент F2.1 соответствует этой форме; это не доказательство допуска аккаунта.

Публичный [GET каталога Go](https://opencode.ai/inference/go/v1/models) вернул модель без авторизации. Выборка существенных полей на дату проверки:

## Инструменты: риск продолжения диалога

[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/#tool-calls) указывает, что thinking включён по умолчанию и при наличии tools предыдущий reasoning_content должен полностью возвращаться в последующих запросах; при его отсутствии описан HTTP 400. Это требование upstream API, не измеренное поведение шлюза Go. Публичный каталог Go при этом объявляет reasoning_content как поле совместимости, что делает проверку существенной.

Текущие [типы клиента](../../src/llm/types.ts) не содержат reasoning_content, а [нормализация](../../src/llm/opencode.ts) его не возвращает. Поэтому наличие транспортных форм инструментов ещё не доказывает рабочую последовательность «запрос вызова → синтетический результат → продолжение». Это не опровергает результат F2.1: её согласованный объём проверялся подменами и не обещал готового живого цикла.

До интеграции требуется выяснить, нужен ли этот возврат именно через Go и поддерживается ли согласуемый режим работы. Любое необходимое изменение контракта либо настроек клиента выносится отдельно; в этом исследовании код и утверждённые ограничения не меняются. Рассуждения не становятся текстом ответа участникам и не копируются в отчёт или логи.

## Русский, контекст и устойчивость

[Документация DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) также заявляет инструменты и большой контекст для собственной модели, но не доказывает эти свойства через Go для нашего трафика. Для русского и устойчивости нет измерений этого проекта.

Нужны отдельно согласованные синтетические проверки: ответ по-русски с соблюдением инструкции; нахождение заранее известных фактов в рабочем объёме и признание отсутствия ответа; продолжение после результата инструмента; повторяемость и длительность без выдачи неполного ответа за полный. Порог успеха и размер выборки пока не выбраны. Рекламный максимум контекста и 482 теста клиента не заменяют эти измерения. Стресс-прогон с намеренным исчерпанием подписки не предлагается.

## Доступ, расходы и передача данных

[Go](https://opencode.ai/docs/console/go/#usage-limits) описывает общую квоту моделей с окнами 5 часов, неделя и оплаченный месяц. Extra Usage может переключить расход на баланс; DeepSeek требует разрешения Global в настройках privacy. Реальные подписка, тип ключа, регионы, остатки и Extra Usage владельца не проверены и не изменялись.

Там же в разделе Privacy для DeepSeek заявлен ZDR с примечанием: соглашение продлевается ежемесячно, текущий срок — до 2026-11-30. Поэтому значение zdr=true нельзя превращать в бессрочное обещание нулевого хранения. [Политика сервиса](https://opencode.ai/legal/privacy-policy) и конкретные получатели требуют проверки человеком для нашего сценария. Сроки локальных бэкапов из этого не следуют.

Перед реальными текстами остаётся согласовать состав передачи и указание внешнего провайдера в согласии и служебном сообщении добавления. Синтетический прогон не решает этот юридический вопрос. Его данные, число запросов, токены, время и расходы должны быть явно согласованы до запуска; постоянные лимиты проекта этим отчётом не назначаются.
