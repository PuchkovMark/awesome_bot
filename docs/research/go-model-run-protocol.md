# F2.9 — протокол оставшегося прогона Go

**Для владельца.** Протокол утверждён 2026-11-23. Владелец подтвердил отключённый Extra Usage перед запуском. [Фактический результат](go-model-validation.md#натурная-проверка-2026-11-23) В зачёт идут проверенные в F3.5 ответы `deepseek-v4.1-flash` через Go в личке, на обращение и на reply в тестовой беседе. Оставшийся прогон проверяет продолжение после результата инструмента и работу на синтетическом контексте. [Фактическая приёмка F3.5](../tasks/completed/024-vk-manual-acceptance.md#текущая-приёмка)

## Допуск и пределы

- **$0 сверх действующей подписки Go.** Перед прогоном владелец проверяет, что Extra Usage выключен, ключ покрыт подпиской, у аккаунта открыт доступ к DeepSeek и есть остаток в пятитичасовом, недельном и месячном окнах. Проверку провести по Go Console; те же счётчики доступны через официальный API. Для DeepSeek документация указывает настройку Global. При недоступности ключа, модели, региона или квоты прогон останавливается у соответствующей проверки. [OpenCode Go, квоты и Extra Usage](https://opencode.ai/docs/console/go/#usage-limits) · [Доступ к моделям](https://opencode.ai/docs/console/go/#enable-restricted-models) · [Счётчики Go](https://opencode.ai/docs/console/go/#usage)
- **До 5 запросов генерации, последовательно.** Две цепочки по два POST и один условный диагностический POST на весь прогон. До 16 КиБ UTF-8 на сериализованное тело каждого запроса, включая поля продолжения. `max_tokens=1024` на вызов, до 5 120 запрошенных выходных токенов. До 60 секунд на запрос и до 6 минут на запуск целиком. Тайм-аут, `401`, `403`, `429`, серверная ошибка или неподтверждённый лимит останавливают прогон. Автоматические повторы выключены. Реальную квоту специально не исчерпывают.
- **Данные полностью синтетические.** Маршрут `https://opencode.ai/inference/go/openai/v1/chat/completions`, модель `deepseek-v4.1-flash`, штатный User-Agent бота и отдельная стабильная сессия на каждую цепочку. До вызовов владелец согласует допуск этого теста, данные и пределы. Go описывает назначение для coding-agent трафика, общие условия ограничивают использование в интересах третьих лиц. Применимость к боевым беседам проверяется отдельно по этим условиям. [Маршрут Go](https://opencode.ai/docs/console/harnesses#base-urls) · [Назначение Go](https://opencode.ai/docs/console/go/#where-can-i-use-it) · [Условия OpenCode](https://opencode.ai/legal/terms-of-service)

## Что проверить

1. **Короткая цепочка.** Объявить одну функцию `lookup_test_batch` с обязательным строковым аргументом `id`. В системной инструкции задать русский язык, префикс `ПРОВЕРКА:` и требование отмечать отсутствующие факты. Попросить проверить партию `B-17` и её срок. Успех первого запроса — один `tool_calls` для этой функции, правильный аргумент и непустой идентификатор вызова. Во второй запрос вернуть сообщение роли `assistant` с исходным вызовом. После проверки имени и аргумента локально подставить константу `{"status":"готова","code":"K7-M2"}` в сообщение роли `tool` с тем же `tool_call_id`. Оба запроса передают тот же список инструментов. Основной прогон использует форму текущего клиента без `reasoning_content` в продолжении. Успех продолжения — законченный русский ответ с префиксом `ПРОВЕРКА:`, статусом и кодом из результата и сообщением, что срок неизвестен. Второй вызов инструмента, обрезанный, пустой или отказной ответ считаются непрохождением.
2. **Рабочий контекст.** После успешной короткой цепочки повторить обмен с синтетической историей, доведённой до 6 500–7 500 единиц локальной оценки входа при штатном бюджете F2.5 в 8 000. В первой трети истории указать зал «Север», остальные реплики заполнить фактами о других партиях. Попросить включить зал в тот же финальный ответ. Успех — предыдущие критерии и правильный зал. Фактические `prompt_tokens` и `completion_tokens` записать отдельно, если Go их вернул. Две цепочки проверяют повторяемость на этих примерах. [Конфигурация F2.5](../../src/core/context/config.ts) · [Локальная оценка входа](../../src/core/context/budget.ts)
3. **Условный контроль `reasoning_content`.** Если исходное продолжение получило HTTP 400 и первый ответ содержал это поле, повторить только продолжение, добавив точное значение поля в предыдущее сообщение роли `assistant`. Сохранить прежние сообщения, идентификатор инструмента, параметры и ту же сессию. Добавление поля — единственное изменение. Поле хранить только в памяти тестовой сессии. Результат контроля классифицировать отдельно. Успех только с полем означает, что текущий контракт клиента не проходит этот сценарий и требуется отдельное решение. Неудачный контроль оставляет причину отказа открытой. Документация DeepSeek описывает этот случай для upstream API; итог теста относится к маршруту Go. [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/#tool-calls) · [Контракт клиента](../../src/llm/types.ts)

### Остановка после HTTP 400

- Если короткая цепочка прошла только с `reasoning_content`, завершить прогон после третьего запроса. В отчёте записать два исхода: «обмен через Go прошёл в диагностическом варианте» и «текущий контракт клиента короткую проверку не прошёл». Сценарий с рабочим контекстом оставить до решения владельца об изменении клиента.
- Перед диагностическим POST измерить размер полного сериализованного тела в UTF-8 с добавленным полем. Если размер больше 16 КиБ, завершить прогон до отправки этого запроса. В отчёте указать, что контроль пропущен по пределу размера, а причина HTTP 400 и совместимость продолжения через Go остаются открытыми.

## Что записать и когда закрывать F2.9

Зафиксировать дату, модель и версию из доступных метаданных, исход каждой проверки, HTTP-статусы, длительность, использование токенов и состояние квот до и после. Для `reasoning_content` записать только наличие поля и результат контроля. Если пришёл `429`, записать доступный `Retry-After` и остановить запуск. Если `429` не было, отметить это отдельно. Локальные тесты уже подтверждают, что `rate_limit` завершает задание, а повтор ошибки сервера выполняется внутри агентного цикла. Порог нагрузки по малой выборке не оценивается. [Проверки клиента](../../tests/llm-failures.test.ts) · [Проверка очереди](../../tests/chat-queue-agent-loop.test.ts)

Для решения о переходе к F5.6 нужны полный успешный обмен через выбранный доступ с пригодным контрактом клиента и решение владельца о применимости условий Go к целевому использованию. При отрицательном или неизвестном результате зафиксировать конкретный пробел и вернуть выбор владельцу. Веха F4 может идти параллельно. [Зависимость F5.6](../roadmap.md#перед-f56)
