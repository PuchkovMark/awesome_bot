## Проблема или цель

Основной модели нужен контролируемый доступ к инструментам конкретной платформы и к видимым сведениям об участниках своей беседы. Исполняемый реестр нужен также [задаче 036](036-universal-subagents.md).

## Ожидаемое поведение

Перед каждым вызовом модели харнес определяет разрешённые инструменты по платформе и возможностям адаптера. Участники доступны через три операции: получить сведения о человеке, найти по разрешённому признаку и вывести ограниченный список. Каждая операция сама проверяет область чата и права. Для полноценной проверки выдачи нужны данные реестра F5.1 и профильные правила видимости. Инструментальный обмен с Go уже подтверждён в F2.9.

## Критерии приёмки

- Реестр. На двух искусственных платформах проверить общие и платформенные инструменты, отсутствие нужной возможности и изменение выданного набора к следующему шагу. Попытка вызвать инструмент вне текущего списка даёт контролируемую ошибку и ноль исполнений.
- Цикл. Подмена модели запрашивает выданный читающий инструмент, получает результат с тем же tool_call_id и формирует один итоговый ответ. Неверные аргументы, попытка подменить чат, смена поколения и исчерпание лимитов не приводят к неразрешённому действию. Результат инструмента остаётся недоверенными данными.
- Участники. Отдельно проверить все три операции на двух беседах, совпадающих именах и закрытом поле. Поиск по скрытому признаку не выдаёт совпадения, из которого можно вывести закрытый факт. Обычная роль администратора не открывает личные поля.
- Проверить жёсткий потолок выдачи, запрос сверх него и неполный снимок состава. По результату понятно, когда список неполон. Модель не может расширить выдачу сменой параметров или выбором другой платформы.

## Что явно не входит

Создание субагентов, поиск по истории F6.3, веб-поиск и добавление второго боевого адаптера. Прохождение проверок реестра отдельно не закрывает приёмку трёх инструментов.
