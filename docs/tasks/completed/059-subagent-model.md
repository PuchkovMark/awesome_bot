## Проблема или цель

Сейчас помощник при вызове `delegate` получает клиент основной модели. Владелец выбрал `claude-haiku-5-5` для делегированных подзадач и сжатия переписки. Сжатие описано в плане 056.

## Ожидаемое поведение

Основная модель отвечает участнику и решает, когда вызвать помощника. Каждый помощник выполняет свою подзадачу на `claude-haiku-5-5`, включая продолжение после чтения инструментом и разрешённый повтор попытки. Итог делегирования получает основная модель, которая формирует один ответ участнику.

## Критерии приёмки

- В обычном диалоге без делегирования проверить, что запрос получает только модель из `LLM_MODEL`. В составном запросе проверить по фактическим обращениям к провайдеру, что оба помощника используют `claude-haiku-5-5`, в том числе после возврата инструмента, а итог формирует основная модель.
- При временном сбое Haiku проверить адресата повтора. При недоступности помощника основная модель получает явный исход и может завершить ответ по доступным данным. Расход каждой попытки и резерв финального ответа учитываются по действующим правилам.
- На синтетическом составном вопросе проверить обращение к Haiku через OpenCode Go, чтение разрешённым инструментом и достоверность результата, переданного основной модели. Записать использованные модели в отчёте оценки.

## Что явно не входит

Построение сводок относится к задаче 056. Основную модель диалога задаёт существующая настройка `LLM_MODEL`.
