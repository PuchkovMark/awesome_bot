## Проблема или цель

При утрате рабочей БД оператору нужна пригодная для восстановления копия с сохранением границ доступа и более поздних удалений.

## Ожидаемое поведение

Раз в сутки создаётся копия рабочей БД. В отдельной папке постоянно хранится один резервный файл — самый свежий из успешно проверенных. До окончания проверки новой копии предыдущая пригодная копия остаётся доступной в пределах срока хранения. Восстановление можно проверить на отдельной БД до допуска приложения к данным. Предельный возраст копии — 30 суток.

Рабочую БД переключает вручную владелец сервера или назначенный им оператор. Время восстановления и простоя сначала измеряется на пробном запуске.

## Критерии приёмки

- На тестовой БД с двумя беседами создать копию штатным способом и восстановить отдельно. После открытия приложением сверить настройки, доступную историю и принадлежность данных каждой беседе.
- После создания копии удалить личные данные, очистить историю и сбросить одно подключение. При восстановлении старая история и удалённые данные не возвращаются в выдачу. При недостатке сведений для сверки защищённые данные остаются закрыты. Проверить сохранность второй беседы.
- Воспроизвести сбой создания и отдельно попытку восстановления из непригодной копии. Оператор различает сбой и успешную проверку, результат прерванной операции не выдаётся за пригодную копию.
- На управляемом времени выполнить два суточных запуска с изменением данных между ними. В папке остаётся один резервный файл с последними данными. Прервать следующую замену и проверить, что предыдущий файл восстанавливается. При достижении предельных 30 суток с момента снимка просроченная копия удаляется. В README описать создание копии и воспроизводимую проверку восстановления.
