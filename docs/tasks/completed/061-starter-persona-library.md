## Проблема или цель

Каталог из шести персонажей уже готов. Источник — `src/services/settings/personalityService.ts` ветки `main` в коммите `bbc6b69`. Задача охватывает подключение всех шести исходных карточек к ответам и выбору персонажа в беседе и личке.

## Ожидаемое поведение

В списке доступны Алекс, Макс, Сократ, Виктор, Никон и Чипсик. По умолчанию отвечает Макс (`max`). Это относится к новым и существующим беседам и личным диалогам без явного выбора. В беседе персонажа для всех выбирает администратор бота или владелец Пенька, в личке — сам пользователь. Явный выбор действует только в соответствующем чате и сохраняется после перезапуска.

## Критерии приёмки

- Сверить состав и полное содержимое всех шести карточек с исходником. Для каждой проверить идентификатор, имя, описание, пример реплики, текст характера (`systemPrompt`) и обе группы параметров (`settings`, `influences`). Текст характера используется по правилам [слоя персонажа](../../specs/personas.md#версии-и-недоверенное-описание).
- Задать вопрос до первого выбора в беседе и в личке. По ответу и версии в трассировке подтвердить, что применён Макс. Повторить после обновления для существующего чата без выбора и для чата с ранее выбранным персонажем. Во втором случае применяется сохранённая версия.
- Администратор бота выбирает для беседы Виктора, а один участник выбирает для своей лички Сократа. После перезапуска в беседе оба участника получают ответы Виктора, в личке первого отвечает Сократ, в личке второго без выбора — Макс. Проверить смену владельцем и отказ в смене для участника и администратора VK без роли администратора бота.
- Для каждого персонажа проверить на модели манеру по исходной карточке. Например, на нейтральном вопросе Макс допускает лёгкую иронию, а на болезненную тему отвечает серьёзно. В трассировке видна фактически применённая версия. После появления новой редакции карточки чат с явным выбором продолжает использовать выбранную версию.
- Для готового персонажа проверить приоритет системных правил. Роль пользователя ограничивает изменяющие действия, сведения другой беседы и чужие закрытые поля недоступны, а при отсутствии факта бот сообщает о неполноте знаний. Сопоставить результаты проверок харнеса и оценочного прогона на модели.

## Что явно не входит

Создание персонажа по собственному описанию и его предпросмотр отложены в [бэклог](../../roadmap.md#пользовательские-персонажи). Расширение списка и перенос пользовательских данных старого бота сюда не входят.
