## Проблема или цель

В Test Bot четыре подтверждённых человека, индивидуальный предел для беседы владелец не задавал. По действующему правилу группа получила 4 × 15 000 = 60 000 токенов за 24 часа. При первом запуске после поиска по истории бот уже сообщил о нехватке бюджета. Владелец предложил увеличить базовый запас для небольших бесед. [Наблюдение в VK](../../README.md#личная-проверка-в-vk)

## Ожидаемое поведение

За скользящие 24 часа у беседы по умолчанию есть 500 000 токенов плюс 300 000 за каждые полные 20 подтверждённых людей. Первая прибавка действует с 20-го человека, вторая — с 40-го. До первого подтверждённого состава действует базовый предел. При неполных сведениях используется последний подтверждённый состав этой беседы.

## Критерии приёмки

1. Для новой беседы до получения состава и для существующей Test Bot с четырьмя людьми отчёт владельца «Показать расход» показывает общий предел 500 000. Допуск обращения использует тот же предел. Обращение, для которого оставшихся из 60 000 токенов раньше не хватало, проходит при достаточном остатке нового бюджета.
2. Для 19, 20, 39 и 40 человек общий предел равен соответственно 500 000, 800 000, 800 000 и 1 100 000. Аккаунт сообщества VK в число людей не входит.
3. При подтверждённых переходах 19 → 20 → 19 предел меняется со следующей проверки. Неполный снимок между ними сохраняет последнее подтверждённое значение. Учтённые расходы и резервы сохраняются при пересчёте, обновлении действующей установки и перезапуске.
4. Явно заданный владельцем предел продолжает действовать при изменении состава. Сброс этой настройки возвращает предел по текущей численности с учётом уже потраченных токенов. Для другой беседы расчёт ведётся отдельно.

## Что явно не входит

Размер контекста модели, бюджет личного диалога, отдельные квоты инициативы и правила учёта вызовов модели.
