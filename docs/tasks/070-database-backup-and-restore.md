## Проблема или цель

При утрате рабочей БД оператору нужна пригодная для восстановления копия с сохранением границ доступа и более поздних удалений.

## Ожидаемое поведение

Копии создаются и выводятся из хранения по согласованному расписанию. Восстановление можно проверить на отдельной БД до допуска приложения к данным. Предельный возраст копии — 30 суток.

## Критерии приёмки

- На тестовой БД с двумя беседами создать копию штатным способом и восстановить отдельно. После открытия приложением сверить настройки, доступную историю и принадлежность данных каждой беседе.
- После создания копии удалить личные данные, очистить историю и сбросить одно подключение. При восстановлении старая история и удалённые данные не возвращаются в выдачу. При недостатке сведений для сверки защищённые данные остаются закрыты. Проверить сохранность второй беседы.
- Воспроизвести сбой создания и отдельно попытку восстановления из непригодной копии. Оператор различает сбой и успешную проверку, результат прерванной операции не выдаётся за пригодную копию.
- На управляемом времени проверить согласованную периодичность и удаление копий по сроку, включая предельные 30 суток. В README описать создание копии и воспроизводимую проверку восстановления.
