## Подход и ключевые решения

### Граница ядра

В [ядре](../../src/core/index.ts) уже есть авторизация и жизненный цикл подключения; агентного цикла пока нет. Предлагается отдельно создаваемый компонент с внедряемым [LlmClient](../../src/llm/types.ts). Он получает готовые системные инструкции, историю user/assistant, maxOutputTokens, непрозрачную сессию и сигнал отмены. Параметры ограничений задаёт доверенный вызывающий компонент. Импорт и создание не вызывают модель, не читают окружение и не запускают работу.

Провайдер, HTTP, ключи, chatId, адаптер, хранилище и выбор версий не входят в эту границу. Подготовка контекста остаётся F2.5, очереди — F2.3. Вызывающая граница отвечает за актуальную область подключения и отмену старого задания; цикл не повышает старое поколение и не обещает сам проверить права или состояние беседы.

Для первой версии не принимаются описания инструментов, история tool и сообщения assistant с вызовами. Такой вход отклоняется до обращения к клиенту; дополнительные поля не могут включить инструментальный режим. tools клиенту не выдаются. Запрошенный подменой вызов завершается безопасным отказом без разбора аргументов и исполнения. Это осознанное ограничение первой версии из дорожной карты; полноценный инструментальный цикл этим планом не реализуется.

Конфигурация фиксируется при создании, вход — при запуске. Исходные объекты не меняются. Для каждой попытки используется независимое представление одного снимка: подмена клиента не может изменить историю следующей попытки. Не добавляются сообщения «продолжи», тексты ошибок или частичный ответ, не смешиваются данные параллельных запусков.

### Результаты запуска

Результат отдельно передаёт исход и безопасную сводку выполнения. Только complete содержит законченный ответ для дальнейшей отправки; отправитель в цикл не входит.

| Исход клиента или выполнения | Поведение цикла |
| --- | --- |
| complete с корректным непустым текстом | Возврат исходного текста без trim и переписывания; успех последней разрешённой попытки остаётся успехом |
| incomplete | Отдельный незавершённый исход с помеченным частичным текстом для вызывающего компонента; сам не публикуется и не продолжается автоматически |
| refused / empty | Отдельные конечные исходы без повторного обращения и без выдуманного ответа |
| tool_calls, в том числе с текстом | Неподдерживаемый инструментальный исход; сопутствующий текст и аргументы не становятся ответом, инструкции не исполняются |
| Безопасная ошибка клиента | Конечная фиксированная категория либо ограниченный повтор по правилам ниже; message клиента не копируется вслепую |
| Отказ Promise или неверная форма результата подмены | Фиксированная ошибка границы клиента без исходной диагностики; без повторов |
| Отмена / исчерпание общего времени | Отдельный конечный исход, прекращающий ожидание и будущие обращения |
| Исчерпание числа попыток перед разрешённым повтором | Исход лимита шагов с безопасной категорией последней ошибки; не успешный ответ |

Несмотря на TypeScript-контракт, возвращённая форма проверяется во время исполнения и проецируется в разрешённые поля. Неизвестный вариант или пустой complete не проходит как успех. Не возвращаются raw-объекты, reasoning_content и произвольная диагностическая строка клиента. Исходы не превращаются автоматически в тексты участникам: это обязанность будущей интеграции.

### Шаги, время и ограниченные повторы

Одна попытка — один фактически начатый вызов complete, включая повтор и синхронный сбой подмены. На этой стадии без инструментов это и есть шаг цикла. Предел maxSteps по умолчанию сохраняет уже заданные спецификацией 6; доверенная конфигурация может явно задать положительный конечный предел. Каждая попытка расходует его один раз, отдельного неограниченного счётчика повторов нет. Проверка ввода и отмена до первого вызова не расходуют шаг. Достижение числа шагов само по себе не отбрасывает готовый результат: лимит срабатывает при необходимости следующего обращения.

Предлагается явная политика повторов: по умолчанию они выключены; включённая доверенным компонентом политика допускает только rate_limit и server. Повтор использует тот же снимок запроса после ограниченной отменяемой паузы, не меняет модель/провайдера и не обнуляет счётчик шагов. При выключенной политике возвращается исходная безопасная категория. Сетевые ошибки, таймаут отдельного клиента, отмена, постоянные ошибки и неподдерживаемые ответы не повторяются автоматически. Отказ неизвестной подмены тоже не считается доказанным временным сбоем.

Даже server не гарантирует, что предыдущая обработка не была оплачена. Поэтому включение повторов — явный выбор вызывающей границы; гарантии идемпотентности или отсутствия повторных списаний нет. Клиент F2.1 по-прежнему делает одну HTTP-попытку. Сервисные ответы и параметры Retry-After не домысливаются: текущий нейтральный контракт их не содержит.

Общий конечный срок охватывает все вызовы и паузы и не продлевается с каждой попыткой. Его завершение отличается от ошибки timeout отдельного клиента. Отмена и общий срок прекращают ожидание даже при подмене, игнорирующей сигнал; сигнал передаётся клиенту, поздний ответ не доставляется повторно и не запускает следующий шаг. Освобождаются собственные таймеры и слушатели. Уже отправленный внешнему сервису запрос отменой не откатывается. Значения срока и паузы, сигнатуры и средства управляемого времени определяются планом реализации; новых чисел здесь нет.

### Сводка выполнения и границы диагностики

Возвращаются число начатых попыток, конечный исход, длительность и расход для будущего учёта. Для input/output независимо сохраняются сумма известных значений и число попыток с неизвестным расходом. При любом неизвестном слагаемом сумма известных токенов не выдаётся за полный расход. Неожиданный отказ, отменённый незавершённый вызов и ошибка без usage оставляют расход этой попытки неизвестным; нулевое число попыток отличается от неизвестного расхода состоявшейся попытки. Некорректные счётчики и переполнение не превращаются в достоверные суммы.

Сводка не содержит текстов, аргументов инструментов, сессии, ключей или исходных ошибок. Она не является долговечной трассировкой: запись и привязка к доверенной области запроса остаются F2.6 и вызывающей границе. Цикл не пишет запросы, ответы или диагностические подробности даже через debug. Отдельный механизм логирования ради этого компонента не вводится.

## Альтернативы и причина выбора

- Немедленно включить инструменты означало бы добавить реестр, авторизацию и непроверенную совместимость reasoning_content. Это расширяет утверждённый объём; первая версия явно отклоняет такие вызовы.
- Универсальные автоматические повторы для всех ошибок создают повторную оплату при неизвестном результате и маскируют постоянные сбои. Выбран явный узкий допуск и общий предел.
- Автоматически продолжать incomplete отдельным сообщением меняло бы историю и могло выдавать противоречивое продолжение. Частичный результат остаётся отдельным исходом для дальнейшего решения.
- Подключить HTTP-клиент и хранилище внутри цикла связало бы ядро с инфраструктурой и живым доступом. Внедрение нейтрального клиента даёт проверяемый каркас независимо от F2.9.

## Изменения спецификаций

После реализации и успешного review [агентный цикл](../specs/agent-loop.md) опишет реализованный режим без инструментов отдельно от целевого полного цикла: исходы, конечные попытки, общую длительность и явный допуск повторов. [Архитектура](../specs/architecture.md) уточнит фактического владельца повторов, внедрение клиента и отсутствие инфраструктурных зависимостей. [Контекст](../specs/context.md) уточнит неизменяемую границу уже подготовленного запроса; сборщик останется будущим.

[Безопасность](../specs/security.md) и [правила логов](../specs/commands-and-limits.md) при необходимости сошлются на отсутствие инструментальных разрешений и безопасную сводку. Готовность записи трассировок, отправителя или очереди не заявляется. Требования evals не меняются: подмена проверяет код, реальная модель — качество. Сейчас спецификации не переписываются под ещё не реализованное поведение.

## Влияние на контракты и данные

Появятся нейтральные контракт запуска и исходов в ядре, явная фабрика с клиентом и ограничениями, сводка выполнения. Точные имена, поля и размещение определит план реализации. Контракт F2.1, транспорт Go, конфигурация окружения, общий каталог и API хранения не меняются. БД, миграции, долговечное состояние, фоновые задания и новые зависимости не нужны: отдельный вызов сейчас не обещает продолжения после перезапуска процесса.

Документы 012 остаются активными. Готовность кода на подменах может пройти review и синхронизацию, но до результата F2.9 или отдельного решения человека об изменении зависимости нельзя объявить выполненными F2.2 и задачу 012 или переносить их в completed. Готовность каркаса будет зафиксирована явно без утверждения живого доступа.

## Риски

- Внедрённая подмена может вернуть неверную форму, изменить вход или зависнуть. Нужны проверки формы, изолированных снимков, игнорирования отмены и поздних отказов без unhandled rejection.
- Несколько владельцев повторов создают лавину обращений. На этой стадии циклом управляет только ядро, а вызов F2.1 однопопыточный; будущая очередь должна сохранить общий предел задания.
- Неполная статистика может выглядеть как точный расход. Известные и неизвестные слагаемые показываются раздельно; сводка не даёт финансовой гарантии.
- Смена подключения или отзыв прав не проверяются самим циклом; нельзя выдавать его наличие за готовность сквозной авторизации или отмены заданий.
- Риск reasoning_content и применимость условий Go остаются в F2.9. Проверка на подменах не доказывает реальный инструментальный цикл и не снимает юридических вопросов.

## Допущения

Только подготовленная текстовая история user/assistant, без описаний и исполнения инструментов; один снимок на запуск; один владелец ограниченных повторов; никаких живых вызовов. Проверяются все исходы F2.1, лимиты и их границы, отмена при вызове и паузе, неизвестный usage, изоляция параллельных запусков, отсутствие утечек и побочных эффектов при импорте/создании. Сохраняются сборка, типы, линтер, платформенные границы и ESM; README отражает текущий объём.

## Открытые вопросы

Блокирующих вопросов для утверждения подхода нет. На согласование вынесены: повторы по умолчанию выключены, явное включение только для rate_limit/server, одна попытка как один шаг, отдельный незавершённый результат и безопасная сводка с неизвестным расходом. Числа нового общего срока и паузы остаются плану реализации.

F2.9 отложена человеком, но условие завершения F2.2 не отменено. Подтверждение провайдера, реальные измерения и юридическое раскрытие остаются открытыми вне этого плана; отсутствие этих результатов не блокирует проектирование и реализацию каркаса на подменах.
