## Подход и ключевые решения

Предлагается служебная команда «приостановленные беседы» в личке сообщества VK. Владелец видит идентификатор каждого подключения VK в состоянии `uncertain`, последнюю установленную причину паузы и команды выбора для этой строки. При пустом результате бот пишет «Приостановленных бесед нет». Если весь список превышает размер сообщения VK, выдача продолжается отдельными частями с целыми строками. Команды привязаны к конкретным беседам и остаются однозначными при изменении порядка списка.

Пример строки для подключения после перезапуска приложения:

> Беседа vk:2000000123. После запуска приложения непрерывность приёма не подтверждена.
> «Продолжить vk:2000000123 17/4» — сохранить поколение 17 и имеющуюся историю. Сообщения за время паузы могут отсутствовать.
> «Начать заново vk:2000000123 17/4» — удалить данные прежнего подключения и начать настройку с чистого состояния.

Здесь 17 — поколение, 4 — ревизия на момент просмотра. Обе команды требуют явного выбора владельца. Просмотр, повторная доставка обзора и восстановление связи с VK сами по себе сохраняют паузу. После решения бот сообщает исход для выбранной беседы. Если состояние изменилось, предлагает обновить список. Продолжение допускает обычную обработку с учётом сохранённых режима, включения и прочих действующих ограничений.

## Влияние на контракты и данные

Использовать существующий личный административный путь. Адаптер проверяет, что отправитель и адресат личного диалога соответствуют настроенному `BOT_OWNER_ID`. Харнес повторно проверяет полномочие владельца для обзора и изменения. Служебный запрос работает при паузе целевого подключения и выключенном обычном боте. Межчатовый список доступен только через этот узкий путь. Для формирования ответа достаточно технических полей подключения, без чтения текстов, вызова модели и публикации в целевую группу.

В SQLite уже есть состояние, поколение и ревизия. Добавить долговечную причину актуальной паузы. Переход в `uncertain` и запись причины составляют одно изменение. Различать установленные источником обстоятельства, например запуск приложения, разрыв наблюдения или первое обнаружение беседы. Если для старой записи причина неизвестна, сообщать «Причина прежней паузы не сохранена». Повторная проверка после перезапуска не должна приписывать ранее приостановленной беседе новую причину без наблюдаемого события для этой беседы.

Для выбора из обзора передавать тройку «чат, поколение, ревизия». В одной транзакции проверить состояние `uncertain` и точное совпадение тройки с показанной владельцу, затем применить существующую семантику `continue` или `new`. Сейчас локальный `resolve-chat` получает подтверждение состояния в момент запуска команды. Для решения по прежнему списку требуется проверка именно показанной версии. Новая операция служит также основой для будущего кабинета F9.6–F9.7. Эксплуатационный CLI остаётся отдельным доверенным путём оператора.

## Альтернативы и причина выбора

Дополнительная CLI-команда была бы доступна при остановленном приёме VK, но требовала бы доступа к хосту. Личка использует уже работающую проверку владельца и позволяет принять решение из VK после восстановления опроса. Веб-кабинет сможет использовать тот же контракт позднее. Рассылка уведомления по каждой беседе при разрыве создала бы серию сообщений сразу после перезапуска. Запрашиваемый обзор даёт владельцу весь список за одно обращение.

## Риски и приёмка

- На отдельной SQLite и с подменой VK создать десять приостановленных бесед и одну активную. Владелец видит ровно десять идентификаторов, причины и последствия обоих решений. Отдельно проверить пустой список, многочастную выдачу, прежнюю запись без причины и запрос от участника, локального администратора или из группы.
- Для одной беседы выбрать продолжение и проверить сохранность истории и поколения. Для второй выбрать новое подключение и проверить очистку данных прежнего поколения. Остальные восемь сохраняют паузу, активная беседа продолжает работать. Пока нет решения, обычные сообщения приостановленной беседы не журналируются и не доходят до модели.
- Повтор команды VK, одновременный выбор разных действий по одной строке и ответ на старую строку после новой паузы должны применить максимум одно решение к показанной версии. Отдельно проверить сбой доставки ответа владельцу после успешного изменения: повтор не очищает данные ещё раз.
- Проверять долговечность отдельно от политики старта VK. После повторного открытия БД принятые решения сохранены. Полный перезапуск приёма может снова перевести активные подключения в паузу по правилам F3.1. Тогда новый обзор отражает текущую причину и ревизию, а старый выбор недействителен.

## Допущения и открытые вопросы

Владелец утвердил вывод в личке сообщества, выбор копированием команды из строки и явную команду «Начать заново» после показанного предупреждения об очистке. Наблюдатель VK должен получать новые события, чтобы владелец мог воспользоваться личкой. Зависимость F3.4 выполнена.
