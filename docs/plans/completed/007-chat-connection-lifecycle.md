## Подход и ключевые решения

Каждое подключение получает неповторяемое поколение. Запрос фиксирует подтверждённую личность, беседу и поколение; отдельно учитывается ревизия принятых наблюдений. Перезапуск сохраняет состояние. Ни запрос участника, ни административный запрос владельца не переводятся на новое поколение автоматически. Актуальность проверяется при чтении и изменении данных, права — по правилам F1.6a.

Сведения о состоянии поступают от отдельного доверенного нейтрального источника. Событие участия служит поводом для сверки, но без доказательства свежести само не создаёт и не удаляет подключение. Ответ сверки относится к ожидаемой области и ревизии: применение одного ответа делает пересекающуюся проверку устаревшей. Локальная ревизия описывает порядок принятых состояний, а не порядок событий VK. Время получения, необязательный eventId и непроверенный кеш не доказывают свежесть. Неизвестное и частичный состав не заменяются подтверждённым отсутствием.

Возможности реального источника проверяются отдельной F1.8 **до реализации F1.6b**, а не после неё перед адаптером. Исследование устанавливает доступность сведений, их полноту, нужные права и возможность различить новое добавление и старое событие. Если часть гарантий недостижима, контракт пересматривается, а человек выбирает политику недостаточных сведений до зависимой реализации. Тестовая подмена не доказывает выполнимость контракта VK.

После удаления все данные и состояние конкретной беседы удаляются. Для защиты от цикла «подключения нет → подключение → снова нет» сохраняется общий монотонный счётчик БД, без связей с чатами, людьми и событиями. Он не хранит их идентификаторы, хеши или историю соответствий. Отсутствие связей должно проверяться по схеме. Повторное подключение требует нового подтверждения; старый ответ сверки не может его создать. Изменение другой беседы может потребовать повторной проверки отсутствующего подключения, не меняя её данных.

Защита охватывает все публичные операции хранения, включая журнал, настройки и назначения. Переход выполняется постепенно с работающей сборкой; итоговый публичный API не сохраняет входов только с `chatId`. Передача роли или поколения моделью не допускается. Инфраструктурное обслуживание отделено от запросов. Подключение и настройки разделены: первое сообщение можно записать после подтверждения подключения, до создания настроек.

Подтверждённый выход прекращает `explicit`; `creator/inviter` при выходе сохраняются. Передача создателя меняет только `creator`, остальные основания независимы. Подтверждённая передача неизвестному преемнику прекращает прежнее основание без назначения выдуманного человека; просто неизвестный создатель не доказывает передачу. Отзыв владельца сильнее любых автоматических сведений, возвращение не возобновляет явное назначение.

Удаление локальных данных выполняется целиком либо откатывается; другие беседы и общие ресурсы сохраняются. Старые запросы и результаты незавершённых вычислений не применяются к новому подключению. Очередь и отправитель обязаны подключить эту проверку в F2.3/F3.x; атомарность уже начатой внешней отправки с БД не гарантируется. Будущие сущности обязаны расширять охват очистки, но не создаются ради этой задачи.

Боевых данных нет. Поддержка существующих тестовых БД ограничена сохранением миграций 1–4 с checksum, применением новой миграции к заполненной тестовой БД и минимальным подтверждением перенесённой области перед запросом. Отдельная система восстановления или сложной активации старых данных не создаётся. Источник не объявляется знающим пропущенный цикл удаления/приглашения только по факту обновления БД.

## Альтернативы и причина выбора

- Один `chatId` и предварительный допуск оставляют возможность воздействовать на новое подключение старым запросом; область проверяется непосредственно при операции.
- Хранение записи об удалённой беседе противоречит полному удалению; общий счётчик сохраняет защиту без персонального следа.
- Сохранение старого публичного API оставляет обход; он удаляется после перевода потребителей.
- Источник с неподтверждёнными гарантиями опасен для интеграции; исследование VK вынесено перед реализацией механизма.

## Влияние на контракты и данные

Нужны новые нейтральные контракты области и наблюдений, новая миграция и изменение публичных операций хранения и создания контекстов авторизации. Техническая форма, переход потребителей и проверки определены в плане реализации. [ChannelAdapter](../../../src/contracts/adapter.ts) пока не предоставляет требуемую сверку; существование интерфейса не означает поддержку VK. SDK в ядро и инструменты не добавляются.

## Риски

Главный риск — невозможность получить достаточные доказательства у VK; он разбирается в F1.8 до реализации. Механизм не знает недоставленных событий. Политика неполноты не выбирается агентом по примеру из обсуждения.

Забытый публичный вход или таблица оставят обход либо неполную очистку. Отдельные проверки охватывают API и все таблицы с FTS; смысловое ревью дополнительно ищет устаревшие требования. Общий счётчик может вызывать лишнюю сверку, но не затрагивает данные других чатов.

## Допущения

Один процесс; синтетические данные и подмены без VK/LLM в тестах реализации. Числовые TTL и периоды синхронизации не вводятся. Очередь, отправитель, режимы, восстановление F4.1, профильные сценарии, текст согласия и бэкапы F9.3 остаются за границами. Проверки одного процесса не объявляются межпроцессными гонками.

## Открытые вопросы

Три технических выбора утверждены пользователем: общий счётчик, обязательная область публичных операций и минимальная сохранность тестовой БД. Их повторного согласования не требуется.

Зависимость F1.8 снята принятием ограниченного результата исследования и политики паузы с явным решением владельца. Недоказанные свойства VK не считаются подтверждёнными; проверка живого источника остаётся F3.x. Срок бэкапов и текст согласия не выбираются этой фичей.

## Уточнение по результатам исследования — принято 2026-11-21

Пользователь принял политику: неоднозначное подключение переводится в uncertain, данные сохраняются, журнал и обычные запросы не допускаются, новые назначения запрещены. Владелец явно подтверждает продолжение либо новое подключение со сбросом через отдельный доверенный вход; обычный контекст модели такого права не получает. Это не enabled: false и не silent. Наблюдение с недостаточной доказательностью не считается подтверждением поколения; выход из uncertain по обычной сверке не допускается. Принятое решение снимает зависимость ожидания политики; исследование с ограниченной доказательной базой не объявляет гарантии VK подтверждёнными. Реализация 007 разрешена с этим уточнением.
