## Подход и ключевые решения

Приветствие включается администратором бота отдельно для каждой беседы, по умолчанию настройка выключена. Изменение действует на последующие входы. Служебное вступление при подключении самого бота продолжает жить по правилам F3.6.

Основание для приветствия — подтверждённый новый вход человека в текущем поколении беседы. Для однозначного входа по ссылке достаточно свежего события с идентификаторами. Для приглашения или неопределённого события нужна связь с конкретным человеком и последующее подтверждение его присутствия полным актуальным составом. Исходный состав и перечень людей после разрыва связи сами по себе не дают повода для отправки. Дубли и устаревшие события не создают нового входа. Подтверждённый выход и новое вступление позволяют отличить возвращение от повтора.

Первое подтверждение открывает окно на 30 секунд по UTC. Последующие подтверждения в той же беседе до окончания окна включаются в него, сохраняя первоначальное время отправки. Событие ровно на границе открывает следующее окно. При отправке учитываются только участники, которые всё ещё присутствуют. Для одного человека действуют согласованные тексты первого входа и возвращения, для двух и более — один общий текст. При недоступном имени опускается обращение по имени.

Базовые формулировки зафиксированы в задаче. Для настроенной беседы используются выбранный шаблон и персонаж, доступные правила и только разрешённые для публичного приветствия поля профиля этой беседы. Базовый текст работает без профиля и дополнительных настроек. Если анкету уже можно пройти, допустима одна строка приглашения. Для группы, где есть вернувшийся с сохранённым профилем, публикуется общее приветствие без этой строки, чтобы не приглашать его повторно.

Перед отправкой проверяются актуальность подключения, настройка приветствия, право публикации и исходящий лимит. Включённое приветствие разрешено в normal и active. При молчаливом режиме, паузе или тихих часах бот пропускает публикацию. После снятия запрета пропущенные приветствия не рассылаются.

## Альтернативы и причина выбора

Немедленная отправка каждому создаёт серию сообщений при массовом входе. Фиксированное окно даёт одну публикацию и ограничивает ожидание первого участника. Сравнение двух списков без события не позволяет отличить вступление от восстановления наблюдения.

## Влияние на контракты и данные

Реестр передаёт подтверждение входа в рамках чата и поколения. Настройка, незавершённое окно и результат попытки отправки сохраняются в БД. Повтор обработки после перезапуска не дублирует доставленное приветствие. При неизвестном результате отправки повтор допустим только с защитой от дубля. Сброс поколения отменяет прежние публикации. Персональные сведения учитываются в выгрузке и очистке F5.8.

## Проверка и риски

На подмене VK проверить первый снимок существующей беседы, вход по ссылке, приглашение с полным и неполным составом, возвращение и повтор события после перезапуска. С контрольными часами проверить входы на 0, 29 и 30 секундах. Первые два дают одно общее приветствие, третий получает отдельное окно. Проверить выход до отправки, отключение приветствий внутри окна, смену поколения и потерю подтверждения отправки. В двух беседах проверить изоляцию настроек. Проверить закрытый факт, отсутствие профиля и отсутствие доступной анкеты.

## Изменения спецификаций

После приёмки обновить правила знакомства, этикета, команд, хранения и событий участия. Описать отличие пользовательского приветствия от служебного вступления и условия добавления строки об анкете.

## Подтверждение владельца

2026-11-23 владелец утвердил план, включая пропуск приветствия при ограничениях, варианты без имени «Привет! Добро пожаловать в беседу!» и «С возвращением!», а также общее приветствие без приглашения к анкете для смешанной группы. Открытых продуктовых вопросов нет.
