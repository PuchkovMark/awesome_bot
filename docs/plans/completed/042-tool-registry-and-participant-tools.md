## Подход и ключевые решения

**Допуск и исполнение.** Единый реестр связывает уникальное имя, описание, схему аргументов и обработчик существующего контракта `ToolDefinition`. Перед каждой попыткой модели харнес определяет платформу по доверенному ключу беседы и выдаёт только схемы инструментов, доступных на ней при подтверждённых возможностях адаптера. Исполнитель сверяет имя со списком именно этой попытки, проверяет актуальность допуска и валидирует аргументы, включая запрет лишних полей. Чат, поколение и инициатора передаёт харнес. Инструмент самостоятельно проверяет область, действующие права и видимость при чтении. Для изменяющих инструментов сохраняется дополнительная проверка роли харнесом. Диагностика фиксирует операцию и код исхода без аргументов и содержимого профилей.

**Продолжение диалога.** Каждому принятому вызову соответствует отдельный результат с исходным `tool_call_id`. Отказ в вызове возвращает безопасную ошибку. Строки в результатах остаются недоверенными данными. При повторе запроса к провайдеру используются уже полученные и всё ещё допустимые результаты. На каждом продолжении действуют общий срок, отмена, предел шагов, проверка актуальности источников и резерв F4.6 на всю попытку. F4.3 списывается один раз за обращение. В беседу попадает только конечный ответ после проверки актуальности использованных данных.

| Операция | Предложение для первой версии |
| --- | --- |
| Получить карточку | Использовать подтверждённого автора сообщения или цитаты либо участника, однозначно выбранного из результатов в текущей области. Вернуть доступное имя и только сведения, разрешённые для аудитории ответа. |
| Найти по признаку | Искать по видимым имени, фамилии и выбранному участником обращению. Из профильных признаков предложен явно указанный публичный интерес. Поиск по интересу доступен после определения его источника и видимости в F5.3 и применения правил F5.8. |
| Вывести список | Читать известный состав текущей беседы из F5.1. Возвращать подтверждённых присутствующих в стабильном порядке по отображаемому имени, при совпадении — по локальному ключу. Указывать отдельно ограничение выдачи и неполноту сведений о составе. |

При двух участниках с именем «Саша Иванов» бот просит ответить на сообщение нужного человека или упомянуть его. До уточнения карточка конкретного Саши не раскрывается. Для сопоставления внутри харнеса используются подтверждённое авторство и область поколения по правилам F2.11. Пользователь видит имя и фамилию либо выбранное обращение. [Различение авторов](035-chat-author-labels.md) · [Правила обращения](041-participant-address-preferences.md)

Предлагаемый размер поиска и списка — 5 человек по умолчанию, максимум 10 разных участников суммарно во всех результатах инструментов за обращение, включая карточки. Положительный запрос сверх остатка сокращается с явной отметкой. Повтор уже показанного участника не расходует место второй раз. После исчерпания остатка запрос нового человека возвращает признак ограничения. Поиск сначала ограничивает доступные записи и поля, затем ищет и сортирует. Закрытое поле не влияет на совпадение, порядок, подсказку или количество. При неполном составе пустая выборка означает «среди известных участников совпадений нет».

## Альтернативы и причина выбора

Полный состав в каждом промпте расходовал бы токены даже для обычного приветствия. Вызов по запросу ограничивает объём и позволяет проверить видимость в момент чтения. Выбор первого тёзки по порядку быстрее на один обмен, но может раскрыть карточку другого человека. Подтверждённая цитата или упоминание разрешают совпадение независимо от порядка выдачи.

## Изменения спецификаций

После приёмки в правилах инструментов и агентного цикла описать отбор на каждом запросе, проверку вызова и продолжение с результатом. В документах об участниках, профилях и безопасности закрепить порядок выборки, признаки неполноты и проверку видимости до поиска и публикации. ## Влияние на контракты и данные

Схемы модели описывают только пользовательские параметры. Для результата выборки нужны участники и отдельные признаки ограничения размера и неполного состава. Публичные инструменты читают реестр и разрешённые поля профиля в исходном поколении. Отдельная копия профиля для инструментов не требуется. Список выданных схем и счётчик показанных участников относятся к текущему обращению. При выключенном профилировании применяются правила F5.8 для базовых данных участия. ## Риски и приёмка

- На двух искусственных платформах проверить общий и платформенный инструменты, отсутствие возможности и её отзыв между шагами. Вызов вне списка текущего запроса возвращает ошибку, число исполнений равно нулю.
- Подмена модели вызывает разрешённый инструмент и завершает один ответ после результата с тем же идентификатором. Отдельно проверить лишний параметр чата, неверный тип, отмену, исчерпание бюджета и смену поколения. Если видимость отозвана во время подготовки ответа, устаревшие сведения не уходят ни в продолжение, ни в публикацию.
- Для каждой из трёх операций использовать две беседы, полных тёзок и закрытый факт. Проверить запрос обычного участника и администратора. При изменении только закрытого факта наблюдаемый результат публичного поиска должен совпадать.
- На неполном снимке и группе из 12 известных участников проверить запрос на 20, повтор поиска с другими параметрами и карточку одиннадцатого человека. Предел за обращение сохраняется, обе причины неполноты различимы.
- Проверка реестра на синтетическом инструменте даст отдельный результат для [задачи о субагентах](../../tasks/completed/036-universal-subagents.md). Полная приёмка F5.6 требует также трёх операций на данных F5.1 с действующими правилами профилей и F5.8.
