## Подход и ключевые решения

- Приём состоит из Bots Long Poll сообщества и преобразования нового входящего сообщения в `IncomingMessage`. `vk-io` используется для вызовов API сообщества. Кандидат для проверки — `vk-io@4.10.1`. Приёмник явно наблюдает потерю позиции и перезапуск подписки. У рассмотренного приёмника SDK обновление позиции при ошибке и перезапуски происходят внутри цикла. Для соблюдения политики F1.6b предлагается держать цикл Bots Long Poll на стороне адаптера и использовать SDK для получения сервера. Тесты подменяют источник ответов Long Poll и API. [Релиз SDK](https://github.com/negezor/vk-io/releases/tag/vk-io%404.10.1) · [Транспорт SDK](https://github.com/negezor/vk-io/blob/cc2bbd7/packages/vk-io/src/updates/transports/polling.ts#L110-L210)
- В обычный путь входят новые входящие сообщения. Исходящие сообщения, правки и записи с `action` отделяются при разборе события. Корректный `peer_id` определяет `chatId` и тип чата по спецификации проекта, `from_id` даёт `userId`, а `date` преобразуется во время UTC в миллисекундах. Для `messageId` и `replyToMessageId` предложен единый ключ `conversation_message_id` в пределах чата. Родитель связывается только при достоверной принадлежности тому же чату. `isReplyToBot` требует подтверждённого `from_id` родителя и совпадения с id подключённого сообщества. При отсутствующем или недоступном родителе флаг остаётся `false`; надёжная ссылка на родителя сохраняется отдельно, если её можно установить. Формат ключа проверяется на событиях лички, беседы, reply и повторной доставки до закрепления. [Схема сообщения VK](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/messages/objects.json#L66) · [Контекст сообщения SDK](https://github.com/negezor/vk-io/blob/cc2bbd7/packages/vk-io/src/structures/contexts/message.ts#L52-L106)
- Адаптер снимает только полное платформенное упоминание подключённого сообщества, подтверждённое форматом VK. Другие упоминания и обычное обращение по имени остаются в тексте. Для вложений передаётся минимальный дескриптор вида; недоступный вид получает `unknown`. Некорректное обязательное поле отклоняет событие с безопасной категорией причины. Диагностика ограничивается категориями и счётчиками.
- Имя поступает из доступных платформенных сведений. При недоступности `authorName` предлагается оставлять пустой строкой. `isBot` и `isAdmin` принимают `true` или `false` при установленном источнике значения. При неполных или противоречивых сведениях используется `unknown`. Положительный id и отсутствие признака сами по себе не доказывают, что автор является человеком; правила классификации и достаточность сигналов сверяются на тестовых событиях. Платформенные сведения используются отдельно от ролей харнеса.
- Доверенная входная связка фиксирует область подключения через F1.6b до асинхронной обработки. После обогащения событие допускается в роутер только в исходной актуальной области. При разрыве наблюдения приёмник прекращает обычную передачу для затронутых подключений до применения политики F1.6b. Успешный повторный запрос и свежий `ts` сами по себе не доказывают непрерывность. Для неопределённого подключения используется действующий механизм паузы и решения владельца. Служебные события будут подсоединены в F3.3, точка входа приложения — в F3.4.
- Локальная приёмка проверяет преобразование событий и штатную связку с роутером и SQLite на подменах. Отдельные сценарии проверяют одинаковые id в двух чатах, повторную доставку, сохранение reply, молчание при `isBot: unknown`, потерю позиции и отклонение старого события после смены поколения. Предварительная проверка доступа и фактических событий проводится в согласованном тестовом сообществе в объёме действующей спецификации. Её результаты ограничивают, какие сведения могут считаться подтверждёнными в реальном источнике. [Правила источника жизненного цикла](../../specs/channels.md#источник-жизненного-цикла)

## Альтернативы и причина выбора

- Готовая подписка `vk-io` уменьшает объём кода, но рассмотренная версия обрабатывает потерю позиции внутри цикла. Явная граница приёма позволяет привязать прекращение допуска к наблюдаемому изменению подписки и проверить этот переход на подмене. [Цикл `vk-io`](https://github.com/negezor/vk-io/blob/cc2bbd7/packages/vk-io/src/updates/transports/polling.ts#L110-L210)
- Применение общего `id` при отсутствии локального номера создало бы два пространства ключей в одном чате. Единый проверенный ключ нужен, чтобы один и тот же reply указывал на исходную запись, а повторная доставка учитывалась как дубль.
- При недоступном имени пустое значение сохраняет возможность принять сообщение с подтверждённым идентификатором автора. Для признаков, которые влияют на маршрутизацию и права, используется явно предусмотренное состояние `unknown`.

## Изменения спецификаций

После приёмки описать в [каналах](../../specs/channels.md) фактическую границу транспорта, источники полей, устойчивый ключ reply и условия паузы. Обновить README сведениями о подтверждённых правах и настройках приёма, а результаты натурной проверки связать с [отчётом о возможностях VK](../../research/vk-lifecycle-capabilities.md). Сквозная проверка ответов через интерфейс VK относится к F3.5.

## Влияние на контракты и данные

Используются существующие `EventHandler`, `IncomingMessage`, `ConnectionScope` и штатный роутер. Приёмная часть использует операции `platform` и `start` контракта адаптера. Для фиксации области требуется внутренняя граница композиции, а поля `IncomingMessage` и схема SQLite остаются прежними. Выбранный формат id понадобится F3.2 для согласования отправленных частей с reply. При натурной проверке сохраняются только безопасные сведения об условиях, доступных полях и кодах ошибок.

## Риски

- Форма событий и набор доступных сведений могут различаться по настройкам токена, беседы и SDK. Страница VK про Bots Long Poll при подготовке плана не открылась. Доступные схема и исходники подтверждают форму известных полей и поведение SDK; условия доставки и прав проверяются в тестовом сообществе. [Схема VK](https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/messages/objects.json#L66) · [Отчёт об ограничениях](../../research/vk-lifecycle-capabilities.md)
- Пропуск удаления и повторного добавления может сделать обычное событие неоднозначным. Состояние F1.6b определяет допустимость записи, а проверка на старом поколении защищает от задержанного локального запроса.
- Если VK не предоставляет стабильный `conversation_message_id` для подлежащих приёму событий, потребуется подтвердить единое представление ключа до реализации преобразования и зафиксировать решение в плане.

## Допущения

- Проверка транспорта использует одно согласованное тестовое сообщество, синтетические сообщения и тестовые беседы. Реальная модель участвует в последующей ручной проверке F3.5.
- Условия штатной остановки приложения и полная сборка относятся к F3.4. Локальные проверки приёма используют управляемую подмену транспорта и действующий интерфейс жизненного цикла.
