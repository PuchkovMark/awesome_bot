## Подход и ключевые решения

Основная модель ведёт диалог, решает, кому поручить подзадачу, и готовит итоговый ответ. Для каждого вызова через `delegate` харнес передаёт помощнику клиент `claude-haiku-5-5`. Клиент закреплён за ветвью на всё обращение, в том числе при чтении инструментом, продолжении с его результатом и разрешённом повторе.

| Вызов | Откуда берётся модель |
| --- | --- |
| Прямой ответ, выбор подзадач, итог по результатам помощников | Действующая настройка `LLM_MODEL` |
| Оба помощника, включая последовательную передачу результата первой ветви второй | Общая со сводками настройка `LLM_AUX_MODEL`, по умолчанию `claude-haiku-5-5` |

Имя `LLM_AUX_MODEL` предложено для конфигурации установки. При отсутствии параметра существующая установка получает согласованный Haiku. Явно пустое или некорректное значение обрабатывается как ошибка конфигурации. В приложении достаточно создать два клиента через существующую фабрику OpenCode Go. Фабрика фиксирует модель при создании клиента, а контекст, инструменты и ссылку на поколение задаёт харнес для конкретного обращения. Сейчас обе роли получают один клиент. [Создание клиентов в приложении](../../../src/app/service.ts) · [Выдача клиента помощнику](../../../src/app/model-tools.ts)

Второй вызов после инструмента — следующий логический шаг помощника. Повтор запроса после допустимой серверной ошибки — ещё одна попытка прежнего шага. Сейчас ветвь делает одну попытку за шаг. Для согласованного сценария повтора применить политику цикла для ошибки `server`, включая настройку числа попыток и общий срок. Повтор использует тот же запрос к Haiku и уже прочитанный результат инструмента. Каждая отправка требует свежей проверки источников, отдельного резерва F4.6 и сохранения остатка для финального ответа основной модели. Исчерпание срока, попыток или бюджета даёт основной модели явный исход ветви. [Цикл помощника](../../../src/core/agent-loop/delegation.ts) · [Учёт попыток](../../../src/core/chat-queue/delegated-attempts.ts)

## Альтернативы и причина выбора

Замена `LLM_MODEL` переключила бы также обычный диалог. Выбор модели по тексту системной инструкции зависел бы от формулировки промпта. Передача нужного клиента при создании ветви привязывает выбор к роли вызова, которую определяет сам харнес. Общая настройка со сжатием позволяет оператору задать выбранную модель в одном месте.

## Влияние на контракты и данные

Меняются конфигурация приложения и внутренняя передача клиента в `delegate`. Для теста можно подставить отдельные клиенты обеих ролей. Используются текущие контракт `LlmClient`, авторизация инструментов чтения, пределы 2560/640 для ветви и один допуск F4.3 на исходное обращение. Отчёт оценки фиксирует модель каждой фактической попытки и связывает её с основной ветвью или помощником. Изменений схемы БД для 059 не требуется. ## Риски и приёмка

- **Случайная отправка другой модели.** На подмене HTTP проверить поле `model` у прямого ответа и всего составного обращения. Для двух помощников проверить первый запрос и продолжение после чтения. Завершить ветви в обратном порядке и проверить, что основная модель получает оба результата и выпускает один ответ.
- **Повторное списание или выполнение инструмента.** Вернуть серверную ошибку на продолжении помощника. Следующая допустимая попытка идёт в Haiku с тем же результатом чтения, под отдельным ключом расхода. Проверить отключённый повтор, исчезновение источника и исчерпание бюджета перед отправкой. Даже при недоступности Haiku обычное обращение может получить прямой ответ основной модели.
- **Формально успешный вызов с пустым результатом.** В прежней оценке обе ветви вернули пустой видимый текст. На синтетическом составном вопросе проверить содержательный ответ Haiku с подтверждаемой ссылкой и хотя бы одно продолжение после разрешённого чтения. Записать имена обеих моделей, исходы, фактический расход и время. Оценка через Go проверяет также доступ по ключу установки.
