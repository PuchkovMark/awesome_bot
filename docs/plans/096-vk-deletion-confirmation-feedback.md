## Подход и ключевые решения

Бот принимает команду подтверждения в проверенной личке автора. Ответ зависит от того, удалось ли связать код с собственным запросом автора в действующем подключении.

- **Свой просроченный или использованный код.** Бот объясняет, что этим кодом уже нельзя подтвердить удаление, и даёт две готовые команды с ID из запроса. Например, `/статус-удаления vk:2000000041` проверяет статус, а `/удалить-мои-данные vk:2000000041` запрашивает новый код. Проверка статуса идёт первой, чтобы после повторного ввода использованного кода автор мог узнать результат первой операции.
- **Неизвестный код или код другого человека.** В обоих случаях текст одинаковый. Например, «По этому коду подтвердить удаление не удалось. Отправьте в нужной беседе `/статус-удаления`, чтобы проверить статус, или `/удалить-мои-данные`, чтобы получить новый код. Статус и код придут в вашу личку». Так автор сам выбирает беседу. Если привязку своего запроса к действующему поколению уже нельзя подтвердить, подходит та же общая подсказка.
- **Новый запрос.** Код выдаётся, когда автор сам отправляет команду запроса. Только отдельное своевременное подтверждение скрывает его данные в выбранной беседе. Повторное предъявление использованного кода ведёт к подсказке.

## Альтернативы и причина выбора

Универсальный ответ с командами без ID потребовал бы от автора просроченного запроса снова выбирать беседу. В личке команда без ID относится к самой личке. Подстановка адреса из собственного запроса позволяет сразу скопировать нужную команду. Подстановка адреса последней беседы автора при неизвестном коде могла бы направить его к другому набору данных.

## Изменения спецификаций

В справочнике команд описать оба вида подсказки и место отправки команд. В правилах приватности закрепить одинаковый ответ для чужого и неизвестного кода. [Команды личных данных](../specs/commands-and-limits.md#личные-данные-f58) · [Выгрузка и удаление](../specs/privacy.md#выгрузка-и-удаление)

Меняется текст служебного ответа и появляется ответ при неизвестном коде допустимого формата. ## Риски

Приёмка сравнит ответы одному получателю на неизвестный и чужой коды, включая отсутствие чужих идентификаторов. Для автора с данными в двух беседах проверит отказ ровно через 15 минут, запрос по готовой команде для первой беседы, успешное подтверждение нового кода и повтор этого подтверждения. После ошибки данные обеих бесед должны быть доступны, после успеха скрываются только данные автора в первой. [Критерии приёмки](../tasks/096-vk-deletion-confirmation-feedback.md#критерии-приёмки)

## Допущения

Подсказка приходит обычным служебным ответом при доступной личной доставке VK. Для нового кода подходит существующая команда запроса, которую участник уже может отправить из нужной беседы. [Управление личным запросом из беседы](../tasks/completed/083-vk-command-timing-and-help.md)
