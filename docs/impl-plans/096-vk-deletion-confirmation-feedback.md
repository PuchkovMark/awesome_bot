## Упорядоченные шаги

### 1. Дать автору готовые команды для его беседы

- **Цель.** После отказа подтвердить собственный код дать в личке две команды с ID из запроса. Первой показать `/статус-удаления`, второй — `/удалить-мои-данные`.
- **Модули.** В ветке подтверждения в `src/app/personal-data.ts` использовать результат существующих `deletionScope(sender, code)` и `confirmDeletion`. Подставлять ID только при совпадении поколения и действующем допуске к этой беседе, проверять допуск также перед отправкой. Успешное подтверждение по-прежнему проходит через транзакцию в `src/storage/personal-deletion.ts`. [Обработчик](../../src/app/personal-data.ts) · [Поиск собственного запроса](../../src/storage/personal-data-store.ts)
- **Тесты.** В `tests/application-personal-data.test.ts` подготовить две группы с данными одного автора через существующий стенд с временной SQLite и подменами VK и модели. Получить код для первой группы, предъявить его ровно через 15 минут и проверить обе строки в личном ответе. Отправить скопированную команду статуса, затем команду запроса нового кода. До подтверждения нового кода записи доступны в обеих группах. Подтвердить новый код до истечения срока и повторить его отдельным сообщением. Проверить видимость записей в обеих группах, одну подтверждённую операцию и возможность запросить её статус по подсказке после повтора. [Стенд приложения](../../tests/helpers/application-response-fixture.ts) · [Проверки срока и однократности](../../tests/storage-personal-data.test.ts)
- **Готово, когда** проходят `npm run build` и `npm test -- tests/application-personal-data.test.ts tests/storage-personal-data.test.ts`. Скопированные из личного ответа команды выбирают исходную группу, а успешное подтверждение скрывает данные автора только в ней.

### 2. Дать одинаковый ответ на чужой и неизвестный коды

- **Цель.** Если по коду нельзя определить собственный запрос в действующем поколении, объяснить автору, как запросить статус или новый код из нужной беседы.
- **Модули.** В `src/app/personal-data.ts` использовать общую подсказку для отсутствующей привязки, сменившегося поколения и недоступной целевой области. Отправлять её через существующий `replyPrivateControl` проверенному отправителю, пока его входящее актуально. Для ответа достаточно поиска по автору и коду. Личный текст содержит команды, выбор беседы остаётся за автором. [Доставка в личку](../../src/channels/vk/channel.ts) · [Проверки области](../../src/core/lifecycle/service.ts)
- **Тесты.** В `tests/application-personal-data.test.ts` отправить из одной лички неизвестный код допустимого формата и действующий код другого человека. Сравнить ответы целиком и проверить адресата, отсутствие кода, ID и статуса чужой беседы. Сверить число заявок и подтверждений и видимость данных обоих участников. Дополнительно воспроизвести недоступность прежней области собственного запроса и проверить ту же подсказку. Для проверки доставки учитывать именно ответ на команду, поскольку первое обращение может сопровождаться отдельным уведомлением о профиле.
- **Готово, когда** проходят `npm run build` и `npm test -- tests/application-personal-data.test.ts tests/storage-personal-data.test.ts`. Оба отправленных кода дают одному получателю один и тот же текст. Каждый запрос нового кода по-прежнему требует отдельной команды автора.
