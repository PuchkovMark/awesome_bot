## Границы и технические допущения

План реализации ожидает утверждения. Каждый шаг заканчивается отдельным коммитом с зелёной сборкой и соответствующими тестами; зависимые потребители переводятся после появления рабочих новых операций. До шага интеграции новые модули проверяются через публичные тестовые сборки, обычный путь очереди сохраняется. В финале временная совместимость удаляется. Код не начинается до утверждения этого документа.

Используются Node.js и npm проекта без установки зависимостей. [build](../../package.json) уже включает lint, проверки каталога/контекста, typecheck и сборку ESM. Базовые проверки каждого шага — `npm run build` и адресный `npm test -- <пути тестов>`; при изменении общих типов, хранения, очереди и публикации — также полный `npm test`. Новые пути ниже явно помечены; перечисленные существующие пути проверены. Внешние клиенты и отправитель подменяются, F2.9 не проводится этим планом.

Предлагаются технические параметры сборщика, передаваемые доверенной сборкой и недоступные тексту участника или модели:

| Настройка | Предложенное значение по умолчанию / правило |
| --- | --- |
| inputBudgetTokens | 8000 оценочных единиц входа, в пределах ранее заданного ориентира |
| maxOutputTokens | 1024, отдельный выходной резерв |
| modelContextTokens | Обязательное явное значение инфраструктуры; inputBudgetTokens + maxOutputTokens не больше него; возможность реальной модели проверяется F2.9 |
| environmentReserveTokens | 1024, резерв динамического доверенного окружения и его обрамления |
| historyPageSize | 32 записи |
| maxHistoryMessages | 128 включённых записей, включая отдельно цитируемый источник, без текущего сообщения |
| maxScannedMessages | 256 просмотренных записей, включая отбрасываемые; ограничивает работу независимо от окна |
| historyTextCodePoints | 2048 на проекцию одной необязательной исторической записи |
| replyTextCodePoints | 1024 на цитируемую выдержку, дополнительно ограничивается остатком бюджета |
| preparationTimeoutMs | 2000 мс в пределах общего срока обработчика |
| postPreparationMarginMs | 1000 мс минимального дополнительного запаса после подготовки и цикла |

Это предлагаемые настройки реализации, не новые продуктовые лимиты. Проверять положительные безопасные целые, верхние технические границы, historyPageSize ≤ maxScannedMessages, maxHistoryMessages ≤ maxScannedMessages и непротиворечивость бюджетов. Не объявлять значение modelContextTokens характеристикой Go без проверки.

Предложенная оценка ввода: длина сериализованных текстов в UTF-8 байтах, плюс 32 оценочные единицы на сообщение и 128 на запрос. Один байт считается одной оценочной единицей токена — намеренно осторожная оценка для русского и смешанного Unicode. Экранирование, даты, авторы, заглушки и маркеры входят в расчёт. Это не точный токенизатор и не математическая гарантия для неизвестного протокола провайдера; параметры запаса и реальная вместимость проверяются F2.9.

Сначала проверяется обязательный минимум: выбранный статичный промпт, фиксированные разделители, минимальное обрамление сообщения и резерв окружения. Если минимум больше inputBudgetTokens — static_budget_too_small. Если минимум помещается, но полное текущее сообщение с автором и метками не помещается в остаток — current_message_too_large. Реальное окружение должно укладываться в резерв; переполнение доверенных служебных данных — внутренняя ошибка подготовки, без обвинения пользователя и без усечения системных правил. Неиспользованная часть резерва окружения не отдаётся истории в v1: одинаковые настройки дают устойчивую границу проверки текущего сообщения. Перед возвратом проверяется оценка всего фактически сериализованного запроса.

Очередь сохраняет действующие сроки F2.3. Композиция проверяет handlerTimeoutMs ≥ preparationTimeoutMs + фактический timeoutMs цикла + postPreparationMarginMs; одновременно остаётся прежняя проверка F2.3 handlerTimeoutMs ≥ timeoutMs цикла + handlerMarginMs. С текущими defaults 130000 ≥ 2000 + 120000 + 1000. Подготовка не начинает отсчёт общего срока заново; на каждом ожидании действует сигнал задания, а при подготовке — ещё и её ограниченный срок.

## Упорядоченные шаги

### 1. Узкие контракты, бюджет и начальная проверка

- Цель: ввести проверяемый результат подготовки, неизменяемые метаданные и конфигурацию без включения нового пути в существующую очередь.
- Модули и файлы: новые `src/core/context/types.ts`, `config.ts`, `budget.ts`, `startup.ts`, `index.ts` внутри нового каталога `src/core/context/`; существующие [типы цикла](../../src/core/agent-loop/types.ts) использовать как целевую форму, транспортный LlmClient не расширять.
- Действия: определить готовый результат с system/messages и метаданными; отказ с доверенными причинами missing_system_prompt, static_budget_too_small, current_message_too_large, internal_error; отдельно отмену и недоступность исходной записи. Типы не допускают отправить отказ в LlmClient или выдать его за AgentLoopResult. Начальный валидатор принимает только точную выбранную версию и конфигурацию, не читает каталог. Нулевое/отсутствующее значение версии не заменяется fallback; содержимое каталога не создаётся и не редактируется разработкой сборщика.
- Тесты: новые `tests/context-contracts.typecheck.ts`, `context-config.test.ts`, `context-budget.test.ts`, `context-startup.test.ts`. Параметры и зависимости, границы статичного минимума и текущего сообщения, учёт экранирования/Unicode/ролей, отсутствие версии и startup-ошибки. Проверить точную границу по предложенному оценщику, не заявляя точности по токенизатору провайдера.
- Условие готовности: build и новые тесты проходят; текущие тесты цикла не меняют поведения. Валидатор возвращает безопасные причины без текста промпта/исключения, конфигурация фиксируется снимком.

- Действия: добавить nullable attachment_count с проверкой неотрицательного безопасного целого. В MessageInput это необязательный минимальный признак, в чтении неизвестность явна; старые строки получают null. Роутер передаёт длину проверенного массива IncomingMessage.attachments, без reference/URL/описаний. Признак пишется в ту же запись и транзакцию приёма; дубликат не переписывает исходную запись и не создаёт новое задание. Другие писатели могут не задавать число. chats.systemPrompt остаётся физически и в текущем техническом API; миграции 1–8 и их контрольные суммы не меняются.
- Тесты: новая `tests/storage-context-migration.test.ts`; расширить [миграции](../../tests/storage-migrations.test.ts), [журнал](../../tests/storage-messages.test.ts), [валидацию](../../tests/storage-validation.test.ts), [приём](../../tests/router-admission.test.ts), [идемпотентность очереди](../../tests/queue-admission.test.ts), [FTS](../../tests/storage-fts.test.ts), [охват очистки](../../tests/lifecycle-cleanup-coverage.test.ts). Проверить пустую БД и upgrade базы до версии 8 с данными/FTS/выбранной версией/заданиями, null/0/1/несколько/неверные числа, дубликат и откат целой постановки. Если имеющихся индексов недостаточно, добавить индекс следующей новой миграцией; миграцию 9, уже зафиксированную на шаге 2, не менять.

### 4. Сериализация лички, беседы и окружения

- Цель: сформировать честный, устойчивый по формату ввод с отдельными доверенными инструкциями и человеческими данными.
- Модули и файлы: новые `src/core/context/format.ts`, `environment.ts`; новые тесты `tests/context-format.test.ts`, `context-environment.test.ts`, `context-untrusted.test.ts`; использовать [нейтральные возможности](../../src/contracts/capabilities.ts) и [тип сообщения](../../src/contracts/adapter.ts), без SDK.
- Действия: system начинается точным текстом выбранной версии, после фиксированного разделителя — доверенное окружение; идентификаторы области, sessionId и авторизационные данные не сериализуются. Возможности проецируются из конечной схемы, неизвестное помечается неизвестным; часы внедряются, дата UTC отображается с IANA-таймзоной чата. Не добавлять title, произвольный текст настройки или имена в доверенное окружение.
- Формат: личка сохраняет user/assistant и добавляет авторство как данные; беседа — один блок user с экранированными полями автора/времени/текста/признака бота и явно выделенным текущим вопросом. Человеческий текст не создаёт роли system или разрешённые инструменты. Для подтверждённого одного вложения без текста — нейтральная заглушка недоступного содержимого; для старой неизвестной записи — честная отметка отсутствия текста без утверждения о вложении. Будущие слои отсутствуют в текстах и отмечены в метаданных.
- Тесты: русский, emoji, переносы, управляющие символы, кавычки и попытки закрыть блок; слова system/owner и инструкции о чужой беседе в имени/тексте; обе искусственные платформы, unknown, active в личке → normal, все причины обычного обращения. Проверить предупреждение о новых сообщениях, время около смены даты и таймзону независимо от процесса. Динамические поля не меняют статичный префикс; budget считает фактическое экранирование.
- Условие готовности: build и новые тесты проходят; сериализатор не выполняет I/O, не выдумывает профили, не меняет выбранную общую версию и не использует устаревший промпт.

### 5. Сборщик снимка: бюджет, окно и reply

- Цель: получить рабочую подготовку из реальных узких читателей и чистых функций предыдущих шагов.
- Модули и файлы: новые `src/core/context/builder.ts`, `metrics.ts`; ранее добавленные types/config/budget/startup/index. Новые `tests/context-builder.test.ts`, `context-reply.test.ts`, `context-snapshot.test.ts`, `context-isolation.test.ts`; существующие тестовые помощники хранения/области используются без сетевых вызовов.
- Алгоритм: проверить сигнал/область/исходную запись, один раз прочитать настройки и выбранную общую версию; проверить обязательный минимум и полное текущее сообщение. Затем добавить доступный reply с ограниченной выдержкой и явным маркером, затем обычное окно от новых к старым. Учитывать общий бюджет и число записей; на первой не вмещающейся старой записи остановить обычное окно, не искать произвольные более старые короткие записи. После страниц возвращать управление event loop и проверять отмену/время; не держать транзакцию между await.
- Reply не дублируется в истории; текущая запись исключена из окна и включена один раз. Цитата недоступна/усечена/не помещается — разные метаданные, но без раскрытия чужой области. Маркер отсутствующей цитаты заранее учитывается в обрамлении, не вытесняет текущее сообщение. Исходное сообщение не обрезается и не подменяется ссылкой на новое поколение.
- Результат: глубоко зафиксировать готовые строки и метаданные ref/cutoff/включённые id/размеры/признаки усечения/отсутствующие будущие слои. Метаданные не содержат полный текст. Перед возвратом перепроверить область, текущую разрешённость обработки и фактический полный бюджет. Не создавать вызов модели или запись журнала. Счётчики причин без полного ввода/ошибки; missing_system_prompt и static_budget_too_small различимы.
- Тесты: все бюджетные границы из шага 1 на реальных сериализованных форматах, длинный reply/история/автор, точное отсутствие дубликатов, пустые будущие слои, старое поле заполнено вредоносным текстом и не применяется. Пауза между чтениями с переключением версии, удалением/повторным подключением/uncertain/отменой; согласованность метаданных с текстом и ограничение числа/объёма выдач. Никаких fallback и частичных ready.
- Условие готовности: build, новые тесты и тесты границ проходят; сборщик применим в тестовой сборке к storage и не импортирует полное хранилище. Проверка стадии не заявляет качество ответов живой модели.

### 6. Различимые результаты подготовки в очереди

- Цель: передать маршрут и отказы подготовки без вызова F2.2 и без вымышленных ответов клиента.
- Модули и файлы: [типы очереди](../../src/core/chat-queue/types.ts), [сервис](../../src/core/chat-queue/service.ts), [адаптер цикла](../../src/core/chat-queue/agent-loop-adapter.ts), [валидация](../../src/core/chat-queue/validation.ts), при необходимости [valid хранения](../../src/storage/queue-store.ts). Новый `src/core/prepare-context.ts` — инфраструктурная композиция вне каталога сборщика; передаёт только узкие зависимости и внедряемую функцию сессии [HMAC](../../src/llm/session.ts).
- Действия: QueueHandlerInput дополняется сохранённым route и синхронным доверенным isCurrent, связанным с реальной работой, поколением, владением, сроком и текущим разрешением обычного пути. На границе до loop.run guard вызывается снова; проверка не заменяется периодическим pump. Callback не выдаёт запись или права модели. Маршрут с null остаётся пригодным для общего пользовательского обработчика очереди, но композиция сборщика без достоверного маршрута не вызывает модель.
- Результаты: добавить отдельное поле preparationFailure в QueueCompletion; result остаётся только AgentLoopResult. Prepare адаптера переводится на явный discriminated union, затем переводятся все существующие тестовые prepare. После перевода старый возврат голого ввода больше не принимается типами. В БД остаются существующие коды failed/interrupted/message_missing/deadline_exceeded; причины подготовки не требуют таблицы текстов и не меняют LlmClient. При отмене/утрате актуальности нет уведомления; неизвестные/невалидные формы не считаются успешной подготовкой.

### 7. Общий период и согласованные уведомления переполнения

Идемпотентное подтверждение сверяет фактическую сохранённую строку и не переклассифицирует обычное сообщение. Ошибка отправки не возвращает резерв и не порождает автоповтор.
