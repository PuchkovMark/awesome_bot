## Упорядоченные шаги

Каждый шаг заканчивается успешной сборкой `npm run build` и перечисленными тестами. В локальных проверках используются подмены Go и VK.

### 1. Передать помощникам настроенный клиент Haiku

Переиспользовать общую со сводками настройку `LLM_AUX_MODEL` и клиент из композиции приложения. Если 059 реализуется первой, добавить параметр в `src/config/types.ts`, обработку в `src/config/application.ts` и пример в `.env.example`. Значение по умолчанию — `claude-haiku-5-5`. В `src/app/service.ts` передать вспомогательный клиент в `src/app/model-tools.ts` для `createJobDelegation`. Основной цикл и публикация по итогам работы помощников продолжают использовать основную модель. В стендах внедрять оба клиента явно.

В новом `tests/application-subagent-model.test.ts` проверить через транспорт поле `model` для прямого ответа, двух независимых ветвей в обратном порядке завершения и финального ответа. Проверить последовательную передачу результата другой ветви. Команда — `npm test -- tests/config.test.ts tests/application-subagent-model.test.ts tests/delegation.test.ts`. Шаг готов, когда смена основной модели не переключает помощника, а прямой ответ делает один запрос по адресу основной модели.

### 2. Различить повтор попытки и продолжение после инструмента

В `src/core/agent-loop/delegation.ts` и `src/core/chat-queue/delegated-attempts.ts` применить переданные настройки серверных повторов общего цикла. Сохранить запрос и результат чтения для того же логического шага. Для каждой фактической отправки проверить источники, общий срок и лимит попыток, зарезервировать расход и защитить финальный ответ. После отмены или исчерпания попыток вернуть основной модели явный исход.

Расширить `tests/delegation.test.ts`, `tests/delegation-budget.test.ts` и прикладной тест шага 1. Подмена возвращает запрос разрешённого инструмента, затем серверную ошибку и успешный ответ. Проверить чтение ровно один раз, повтор на Haiku с тем же результатом, отдельный учёт попыток и одну публикацию. Проверить отключённые повторы, отзыв источника в паузе, исчерпанную квоту и недоступный клиент. Команда — `npm test -- tests/delegation.test.ts tests/delegation-budget.test.ts tests/application-subagent-model.test.ts tests/application-token-budget.test.ts`. Шаг готов, когда соблюдаются ограничения 2560/640, а одна ветвь не расходует резерв финальной попытки.

### 3. Проверить качество делегирования

Адаптировать `tests/delegation-go-comparison.test.ts` и его стенд к двум фактическим клиентам. Записывать роль, ID использованной модели, результат, расход и время каждой попытки. Запустить локальную проверку формирования отчёта с подменами и `npm test -- tests/application-subagent-model.test.ts tests/delegation-budget.test.ts`. Затем по правилам проекта провести отдельно согласованный прогон Go на синтетическом составном вопросе с разрешённым чтением. Сверить результат с источником и сравнить с прямым ответом. Шаг готов при подтверждённом содержательном результате помощника и одном достоверном финальном ответе. [Предыдущее сравнение](../research/delegation-go-validation.md)
