## Упорядоченные шаги

### 1. Сохранить исход подтверждения и условие срока в SQLite

- **Цель.** После перезапуска отличать достоверный отказ VK от ещё не начатой отправки и от потери квитанции. Сейчас `settle` при отказе возвращает часть в состояние `ready`. [Хранилище напоминаний](../../../src/storage/reminder-store.ts)
- **Изменения.** Добавить миграцию восстановления подтверждения и зарегистрировать её в `src/storage/migrations/index.ts`. Для части подтверждения хранить признак достоверного отказа, для ожидающего задания — исходное условие срока и отметку о групповой подсказке. В `src/app/reminders.ts` использовать результат действующего разбора при назначении и при завершении уточнения. Для относительного срока сохранять число минут, для календарного — назначенные день, время и пояс с учётом выбранного момента. Текст поручения уже есть в личной записи. В хранилище обновлять исход вместе с соответствующей частью, при начале новой попытки снимать прежний отказ. При завершении или отмене очищать данные восстановления вместе с текстом. [Миграция 60](../../../src/storage/migrations/060-reminder-confirmation-recovery.ts) · [Расчёт срока](../../../src/core/reminders/time.ts) · [Сроки хранения](../../specs/privacy.md#личные-напоминания)
- **Совместимость.** Старая запись сохраняет номер и срок. Старое `ready` само по себе не доказывает отказ. В `src/storage/restore-work.ts` учесть, что при сверке снимка столбцы задания и частей сейчас копируются по позиции. При разных версиях схемы переносить доступные поля по именам. Использовать известные состояния и квитанции из актуальной БД.
- **Проверка.** В `tests/storage-reminders.test.ts` проверить отказ, неопределённый исход, повторное открытие БД и очистку. В `tests/storage-migrations.test.ts` проверить обновление старого ожидающего задания, а в `tests/storage-database-restore.test.ts` — сверку снимка со старой схемой. Обновить ожидания версий в тестах обновления и собранного приложения.

  ```sh
  npm run build
  npm test -- tests/storage-reminders.test.ts tests/storage-migrations.test.ts tests/storage-participant-upgrade.test.ts tests/storage-dist.test.ts tests/storage-database-restore.test.ts tests/application-reminders.test.ts
  ```

- **Готово, когда** сборка и проверки проходят, после открытия БД видны прежний номер, срок и подтверждённые части, а неопределённое старое состояние допускает только проверку статуса.

### 2. Дать автору подсказку и восстановление по номеру

- **Цель.** После сбоя вести автора из беседы в «Мои напоминания». В личке показывать отдельно назначенный срок и доставку подтверждения.
- **Изменения.** В `src/core/reminders/commands.ts` распознавать `Повтори подтверждение #12` и `Проверь напоминание #12` в личке. В `src/app/reminders.ts` дополнить строку списка состоянием и подходящей командой. При отказе или неизвестном исходе первой отправки дать в исходной беседе одну нейтральную подсказку «Проверить напоминание можно в личке по команде „Мои напоминания“». Связать её с исходным событием и проверить действующее поколение перед публикацией. При закрытой личке до назначения действует прежняя инструкция разрешить сообщения. [Распознавание команд](../../../src/core/reminders/commands.ts) · [Обработка и отправка](../../../src/app/reminders.ts)
- **Доставка.** При повторе проверить автора, поколение лички, право записи и состояние задания. После достоверного отказа повторную отправку запускает личная команда автора. Обработчик использует сохранённый `send_id` недоставленной части и пропускает уже подтверждённые части. Повтор исходного события VK не запускает эту команду.
- **Сверка.** Проверка по номеру читает квитанцию через `reminderDelivery().confirm`. Даже если следующая часть готова к отправке, проверка не вызывает `publish`. Сообщать об успехе после сверки всех частей. При недостающей квитанции показать исходный срок и «Доставка подтверждения неизвестна». Перед записью результата повторно проверить поколение, ключ части и состояние задания. Сверка не должна удерживать задание от плановой доставки при наступлении срока. Если отправка самого напоминания уже началась или задание завершилось, показать фактическое состояние. [Операции адаптера](../../../src/channels/vk/administration-delivery.ts)
- **Проверка.** В `tests/helpers/application-reminders-fixture.ts` добавить однократный отказ VK до публикации. Для потери ответа после публикации и временно скрытой квитанции использовать `lost`, `hide` и `reveal`. В `tests/application-reminders.test.ts` проверить список, обе команды, подтверждение из нескольких частей и повтор исходного события. Отдельно посчитать запросы на чтение, попытки отправки подтверждения и фактически опубликованные сообщения. Успешное первичное подтверждение обходится без групповой подсказки.

  ```sh
  npm run build
  npm test -- tests/application-reminders.test.ts tests/storage-reminders.test.ts tests/vk-outbound.test.ts
  ```

- **Готово, когда** сборка и проверки проходят. Автор может получить пропущенное подтверждение по исходному номеру. Проверка уже опубликованного сообщения меняет статус при появлении достоверной квитанции и сохраняет число отправок подтверждения.

### 3. Связать повтор той же просьбы с существующим заданием

- **Цель.** Если в 12:00 UTC Ира попросила напомнить через минуту, а в 12:00:20 повторила просьбу после сбоя подтверждения, сохранить одно задание на 12:01.
- **Изменения.** В `src/storage/reminder-store.ts` сначала проверять сохранённую привязку события VK в `personal_reminder_inputs`. Для нового сообщения искать среди ожидающих заданий с неустановленным подтверждением в личном поколении автора. Сравнивать поручение и условие срока из шага 1. При единственном точном совпадении записать привязку нового события к прежнему номеру в той же транзакции, где проверено совпадение. Вернуть в `src/app/reminders.ts` результат, позволяющий отличить найденное задание от нового. При нескольких кандидатах или недостатке данных старой версии предложить доступные номера в личке. Повтор события не должен создавать задание или ещё одну групповую подсказку. [Сохранение входного события](../../../src/storage/reminder-store.ts) · [Повтор служебной команды](../../../src/core/message-router/service.ts)
- **Проверка.** В `tests/storage-reminders.test.ts` проверить конкурирующие обращения, неоднозначность, старую запись и две одинаковые по тексту просьбы на разные сроки. В `tests/application-reminders.test.ts` использовать `send` для нового сообщения и `repeat` для прежнего события. Для отказа и потери ответа перезапустить приложение с той же БД, продолжить прежние подключения и перевести часы на 12:01. Повторить с календарным сроком и проверить совпадение дня, времени и пояса.

  ```sh
  npm run build
  npm test -- tests/storage-reminders.test.ts tests/application-reminders.test.ts tests/reminder-time.test.ts
  ```

- **Готово, когда** сборка и проверки проходят. При обоих видах сбоя в БД один номер, а в 12:01 автор получает ровно одно напоминание. Просьба «через 5 минут взять билет» создаёт отдельное задание с собственным сроком.

### 4. Создавать второе задание по явной команде в личке

- **Цель.** Дать автору возможность осознанно получить второе напоминание с тем же поручением на тот же будущий срок.
- **Изменения.** В `src/core/reminders/commands.ts` и `src/app/reminders.ts` добавить личную команду `Создать ещё одно #12`. В списке подписать её как создание копии на тот же срок. В `src/storage/reminder-store.ts` в одной транзакции проверить автора, поколение, ожидающее состояние и будущий срок, создать задание с новым номером и собственными ключами отправки, затем связать событие команды с копией. Копировать сохранённые поручение, `due_at` и пояс. Для повтора события использовать существующую ветвь `replayOnly`. На границе срока предложить новую просьбу с новым сроком, для чужого номера дать обычный ответ «Напоминание не найдено».
- **Проверка.** В стенде `tests/helpers/application-reminders-fixture.ts` адресовать чтение сообщений парой из `peer_id` и `conversation_message_id`, чтобы воспроизвести одинаковые локальные номера в двух беседах. В исходящих сообщениях обеих групп проверить полный текст подсказки. В личках проверить получателя каждого подтверждения и напоминания.
