## Упорядоченные шаги

### 1. Распознать вопрос в собственной фразе автора

- **Цель** — провести явный вопрос по существующему маршруту `ordinary` с причиной `name`, в том числе без слов «ты» и «подскажи».
- **Модули и файлы** — в `src/core/message-router/name-address.ts` расширить `directlyAddressesName`. Использовать действующую нормализацию регистра и «ё/е» и сопоставление целого слова. Искать имя и признаки вопроса в авторском тексте за пределами цитат. Учитывать роль имени до его исключения из фразы. Например, в «где встречаемся завтра» вопросительное слово относится к совместному действию, а в «куда ушёл Пенёк» имя обозначает действующее лицо. По отдельности имя, вопросительное слово и знак вопроса недостаточны. При неоднозначном разборе сохранять молчание в нормальной беседе.
- **Тесты** — в `tests/message-router-policy.test.ts` покрыть таблицу утверждённого плана, включая имя в середине, «Пенек» в конце и строчную реплику без пунктуации. Добавить второй пример с другим глаголом, например «Пенёк, во сколько выходим?». Сопоставить с «Где Пенёк?», «Куда ушёл Пенёк?», «Почему Пенёк молчит?», именем только в цитате и вопросом без имени. Прогнать существующие примеры просьб, приветствий и зова по имени. Через `routeMessage` проверить прямой маршрут в `normal` и `active`, молчание в `silent` и при неподтверждённом отправителе. Проверки режима и reply выполняет `src/core/message-router/routing.ts`.

  ```sh
  npm run build
  npm test -- tests/message-router-policy.test.ts tests/router-admission.test.ts
  ```

- **Условие готовности** — сборка и тесты проходят. Перестановка имени, его написание и пунктуация сохраняют решение для одного и того же явного вопроса. Вопрос о самом Пеньке в нормальном режиме остаётся без ответа.

### 2. Проверить журнал, ответ VK и повтор события

- **Цель** — подтвердить через приложение, что участник получает ровно один ответ в исходной беседе и на нужную реплику.
- **Модули и файлы** — добавить новый `tests/application-name-address.test.ts` на стенде `tests/helpers/application-response-fixture.ts` с подменами VK и модели. Использовать включённую беседу в `normal`, подтверждённого человека, доступную квоту и отсутствие активной анкеты. В `tests/router-admission.test.ts` проверить новый вопрос через `router.receive` и штатную очередь SQLite. Эта проверка покажет исход `duplicate` непосредственно на границе приёма.
- **Положительные сценарии** — подать «Пенёк, где встречаемся завтра?» и варианты написания и положения имени из плана фичи отдельными событиями. Для каждого дождаться публикации, сверить одну строку автора по чату и номеру VK, один вызов модели и один отправленный ответ. У ответа проверить `peer_id` и номер исходной реплики в `reply_message`. Повторить исходное событие через `replay` с той же парой диалога и номера. Дождаться записи следующей нейтральной реплики в этой беседе и сверить прежние количества входов, вызовов модели и ответов по проверяемому событию.
- **Отрицательные сценарии** — подать обсуждение Пенька, имя только внутри цитаты и прямой вопрос в reply другому участнику. Для последнего сначала отправить и записать сообщение этого участника, чтобы подмена VK подтвердила автора цитируемой реплики. После приёма проверить запись каждого входа, отсутствие вызова модели и отправки ответа. На уровне роутера различить подтверждённый чужой reply и неизвестного адресата. Для платформенного упоминания и reply самому боту проверить прежние положительные маршруты.
- **Пересылки** — в `tests/vk-inbound-normalization.test.ts` передать событие с нейтральной подписью автора и обращением к Пеньку внутри `fwd_messages`. Проверить, что в поле `text` для роутера попадает только подпись. Если участник задал явный вопрос в самой подписи, его собственный текст проходит обычную проверку адресации.

  ```sh
  npm run build
  npm test -- tests/application-name-address.test.ts tests/router-admission.test.ts tests/message-router-policy.test.ts tests/vk-inbound-normalization.test.ts tests/application-autonomous-replies.test.ts tests/application-questionnaire-routing.test.ts
  ```

- **Условие готовности** — сборка и тесты проходят. У допущенного вопроса одна публикация после двух доставок события. Каждый из трёх отрицательных сценариев оставляет только вход в журнале.

Повтор каждого события не создал второй вход или ответ. В приёме очереди проверен результат `duplicate`.
