## Упорядоченные шаги

Каждый шаг реализации завершается успешными `npm run build` и указанным прогоном Vitest. Входные события проходят через приложение с подменами VK и модели. Для проверок хранения используются временные базы SQLite. При изменении схемы проверить как пустую БД, так и обновление предыдущей версии. Новые миграции регистрируются в `src/storage/migrations/index.ts`. В пользовательских подсказках команда появляется на том шаге, где её уже можно выполнить. [Правила проверки](../../project.md#проверка-и-документация)

### 1. Исправить выбор беседы для личных данных и подсказку профиля

- **Цель.** В групповом обработчике сохранить явно введённый ID. Для `/мои-данные`, `/отключить-профиль`, `/удалить-мои-данные` и `/статус-удаления` сравнивать его с источником до чтения данных или создания операции. При несовпадении вернуть строку с командой и введённым ID для лички. Для отдельной команды `/профиль` при недоставке личного списка подставлять ID исходной беседы.
- **Модули.** `src/app/personal-data.ts`, `src/app/profile-commands.ts`, передача сообщения в `src/app/service.ts`. При широком удалении пояснить участнику область действия в существующем запросе подтверждения.
- **Проверки.** Завести одного участника в двух беседах. Отправить в первой все четыре команды с ID второй, затем без ID и с ID первой. Скопировать предложенную строку в личку, проверить адресата и права. Отдельно воспроизвести закрытую личку при `/профиль`. Запуск — `npm test -- tests/application-personal-data.test.ts tests/application-profile-commands.test.ts`.
- **Готово, когда** неверно адресованный запрос даёт только подсказку. В обеих беседах сохранены профили, выдача и удаление не начаты. По скопированной команде автор получает данные нужной беседы.

### 2. Распознавать команды до разбора ответа на анкету

- **Цель.** Применить одни правила к имени команды и подкоманды в обработчиках первого личного обращения, маршрутизации и исполнения. Нормализовать регистр и разделительные пробелы, сохранить дословно аргументы и текст ответов. Подсказку для неизвестной адресованной команды выдавать после распознавания действующих команд, включая прямые команды владельца, и до передачи текста модели.
- **Модули.** `src/app/questionnaire-commands.ts`, `src/app/service.ts`, `src/core/message-router/command-boundary.ts`, `src/core/message-router/service.ts` и `src/core/message-router/routing.ts`. Применить действующие проверки автора, пересылки, адресации и режима. Для служебного ввода использовать нейтральную запись в журнале.
- **Проверки.** В беседе и личке начинать каждый пример с активной попытки. Проверить `/Анкета пауза`, `/анкета   пауза`, опечатку `/анкета паузза`, неизвестную команду, а также команду при первом уведомлении и после него. Сверить состояние попытки, число вызовов модели и содержимое сохранённых ответов. Запуск — `npm test -- tests/application-questionnaire-commands.test.ts tests/application-questionnaire-routing.test.ts tests/router-command-boundary.test.ts tests/application-lifecycle.test.ts`.
- **Готово, когда** оба варианта паузы приостанавливают заполнение, а при опечатке автор получает подсказку и продолжает с того же шага. Обычная реплика двух участников обрабатывается по прежним правилам адресации.

### 3. Показывать анкету по факту заполнения

- **Цель.** После проверки беседы, поколения, участия и прав различать готовую анкету и отсутствие завершённой попытки. Автор по `/анкета` начинает заполнение, после паузы возобновляет его, а во время доставки, ожидания ответа или разбора получает текущее состояние. По завершении та же команда показывает его анкету. Просмотр по `/анкета показать` и `/анкета показать @участник` до завершения возвращает «Анкета не заполнена», после завершения выводит актуальные публичные пары по порядку вопросов. При пустой выдаче показать заголовок и «Нет публичных ответов».
- **Модули.** В `src/storage/questionnaire-view-store.ts`, `src/storage/profile-fact-selection.ts` и `src/storage/profile-fact-reader.ts` убрать проверку старого переключателя из просмотра и карточек. В `src/app/profile-list-text.ts` убрать прежнюю подпись о закрытой анкете. Сохранить ограничения полей и повторную проверку перед каждой частью выдачи. В `src/app/questionnaire-commands.ts`, `src/core/questionnaire/answer.ts`, `src/core/chat-queue/types.ts` и `src/core/message-router/publication-service.ts` убрать вопрос о доступе, ожидание 15 минут и команды `/анкета открыть` и `/анкета закрыть`. Ответы на устаревшие вопросы распознавать по прежним квитанциям. В справку не включать `/анкета доступ`.
- **Совместимость.** Сейчас у `questionnaire_presentations` внешний ключ на `questionnaire_access`. В новой миграции `src/storage/migrations/050-questionnaire-completion.ts` перенести привязку представления к завершённой попытке с сохранением идентификатора исходного ответа, ранее выданного согласия, отказа и доставленных частей. Идентификаторы прежних вопросов о доступе использовать только для отбрасывания поздних ответов. Согласовать `src/storage/questionnaire-progress-store.ts`, `src/storage/questionnaire-access-store.ts`, `src/storage/questionnaire-presentation-store.ts`, `src/storage/personal-export.ts` и `src/storage/questionnaire-profile-restore.ts`. Новый вопрос о представлении отправлять после подтверждения доставки завершения. Исключить повтор старого вопроса о просмотре после рестарта и восстановления.
- **Проверки.** Для себя и второго участника пройти все строки [таблицы состояний](../../plans/completed/080-vk-command-usability.md#анкета-глазами-участника). На старой БД проверить открытые, закрытые и ожидающие анкеты, скрытое поле, все пропуски, чужую беседу и отозванное право между частями отправки. Сверить согласие на представление и запрет повторной публикации. Запуск — `npm test -- tests/application-questionnaire-access.test.ts tests/application-questionnaire-routing.test.ts tests/storage-questionnaire-profile.test.ts tests/application-context-cards.test.ts tests/storage-migrations.test.ts tests/lifecycle-cleanup-coverage.test.ts tests/storage-database-restore.test.ts`.
- **Готово, когда** участник сразу видит готовую анкету своей беседы по запросу. Личные и отдельно скрытые поля не выдаются группе. Старый ответ «Разрешить» или «Закрыть» не меняет данные. Публикация представления требует отдельного согласия.

### 4. Дать автору исправить ответ или заполнить пропуск в беседе

- **Цель.** По `/анкета изменить` вернуть нумерованные вопросы закреплённой редакции без прежних ответов. Принять номер и новый текст только в прямом ответе автора на доставленный список в той же беседе. При нескольких частях связать номер с соответствующей частью. Срок списка — 24 часа с доставки. Команда до завершения возвращает «Анкета не заполнена».
- **Модули.** Добавить обработку в `src/app/questionnaire-commands.ts` и доставку с квитанцией через `src/channels/vk/channel.ts`. Для привязки списка и защиты от повторов предусмотреть новые `src/storage/questionnaire-management-store.ts` и `src/storage/migrations/051-questionnaire-answer-edits.ts`. Использовать правила из `src/storage/profile-command-store.ts` и `src/storage/profile-fact-store.ts`. Для пропуска создать факт и связь с позицией, для существующего ответа обновить действующее значение с сохранением видимости. В одной транзакции проверить попытку, зафиксировать событие и правку. Учесть эти правки и новые позиции при сверке копии в `src/storage/questionnaire-profile-restore.ts`.
- **Проверки.** Исправить город ответом `2 Казань`, затем дополнить пропуск. Проверить историческую редакцию, повтор одного события, неверный номер, ответ другого участника, пересылку, истечение срока и перезапуск. Второй аккаунт видит актуальное публичное значение. Для проверки через приложение добавить новый `tests/application-questionnaire-management.test.ts`. Запуск — `npm test -- tests/application-questionnaire-management.test.ts tests/storage-questionnaire-profile.test.ts tests/application-profile-commands.test.ts tests/storage-migrations.test.ts tests/lifecycle-cleanup-coverage.test.ts tests/storage-database-restore.test.ts`.
- **Готово, когда** автор с закрытой личкой исправляет одно поле в беседе. Остальные ответы и индивидуальные ограничения сохраняются. Номер из просроченного списка даёт подсказку открыть свежий.

### 5. Удалять только свою анкету с подтверждением в той же беседе

- **Цель.** По `/анкета удалить` отправлять в исходную беседу запрос с вариантами «Удалить» и «Оставить». Принимать прямой ответ автора в течение 15 минут после подтверждённой доставки, сверяя сообщение запроса, автора, беседу, поколение и попытку. Без завершённой анкеты вернуть «Анкета не заполнена». В случае удаления предложить новое заполнение по текущей редакции.
- **Модули.** Расширить `src/app/questionnaire-commands.ts` и хранилище управления анкетой из шага 4. Новая миграция `src/storage/migrations/052-questionnaire-removal.ts` хранит запрос, исход и сведения об удалённой попытке без текста ответов. В одной транзакции принять подтверждение, удалить попытку, исходные факты анкеты и их правки, привязки списков и решения о представлении. Удаления одной строки попытки недостаточно, поскольку связанные строки в `profile_facts` имеют собственный жизненный цикл. Перед отложенной выдачей сверять идентификатор попытки, в том числе в `src/storage/questionnaire-progress-store.ts`.
- **Восстановление.** В `src/storage/questionnaire-profile-restore.ts` и `src/storage/personal-data-restore.ts` сверять снимок с доверенной текущей БД по попытке. Учитывать отдельное удаление, новое заполнение и последующие правки. При восстановлении закрывать прежние незавершённые запросы. Учесть очистку новых записей при полном удалении данных автора и сбросе поколения.
- **Проверки.** Проверить отказ, истечение срока, сбой доставки, рестарт, два конкурирующих подтверждения и ответ на старый запрос после нового заполнения. Восстановить копию, сделанную до удаления. Отдельно пройти с закрытой личкой весь путь от первого `/анкета` до повторного старта и проверить адрес каждого исходящего сообщения. Запуск — `npm test -- tests/application-questionnaire-management.test.ts tests/application-questionnaire-access.test.ts tests/storage-database-restore.test.ts tests/storage-personal-data.test.ts tests/lifecycle-cleanup.test.ts tests/lifecycle-cleanup-coverage.test.ts tests/storage-migrations.test.ts`.
- **Готово, когда** после удаления просмотр возвращает «Анкета не заполнена», старое подтверждение не удаляет новую анкету, прежние ответы не появляются из копии. Остальные данные профиля, сообщения VK и данные соседней беседы сохраняются.

- **Проверки.** Собрать проект через `npm run build` и выполнить полный `npm test`, поскольку изменения затрагивают общую маршрутизацию, миграции, очистку и восстановление.
