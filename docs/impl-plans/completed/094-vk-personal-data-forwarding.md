## Упорядоченные шаги

### 1. Обработать собственную команду с пересылкой на обоих входах

- **Цель.** Когда автор написал команду и приложил пересылку, ответить в исходном диалоге «Отправьте команду отдельным сообщением без пересылки». Завершить обработку до обращения к личным данным.
- **Изменения.** В `src/app/personal-data.ts` использовать общий разбор собственной подписи в `groupPersonalCommand` и `createPersonalCommands`. Существующее выражение `personalRequest` распознаёт четыре команды и необязательный ID беседы. Выбрать один из трёх исходов — обычная команда, служебная подсказка или отсутствие личной команды. В `src/app/service.ts` передавать `hasForwarded` из группового сообщения при вызове `personal`. Распознанная в группе подсказка проходит существующий допуск `profile.self.manage`. Личный вход уже получает признак пересылки от VK. [Групповой и личный входы](../../../src/app/service.ts) · [Обработчик](../../../src/app/personal-data.ts)
- **Отправка.** Для подсказки в группе использовать `replyGroupControl` с областью исходной беседы, в личке — `replyPrivateControl` для подтверждённого автора этого диалога. Проверить актуальность входа и допуск к отправке в исходном диалоге. Ветка подсказки должна завершиться до выбора целевого чата по аргументу, вызова `privacy.hasData`, выдачи статуса и операций с данными. Обычная команда проходит действующие проверки прав и адресации. [Служебные ответы VK](../../../src/channels/vk/channel.ts)
- **Тесты.** В новом `tests/personal-data-forwarding.unit.test.ts` проверить обработчик с подменой зависимостей. Для собственной команды с пересылкой должны вызываться только нужные операции ответа. Проверить ноль вызовов `privacy.hasData`, `status`, `beginExport`, `export`, `disable` и `requestDeletion`. В `tests/application-personal-data.test.ts` прогнать исходный случай отключения в беседе и в личке с ID беседы, используя существующий флаг пересылки в `submit`. Сравнить текст, адресата ответа и отсутствие отметки об отключении.

  ```sh
  npm run build
  npm test -- tests/personal-data-forwarding.unit.test.ts tests/application-personal-data.test.ts tests/router-command-boundary.test.ts
  ```

- **Готово, когда** сборка и проверки проходят. Оба входа дают одну и ту же подсказку в диалоге отправителя. Выбор целевой беседы и операции с профилем начинаются только при допустимой отдельной команде.

### 2. Проверить четыре команды, пересланный текст и изоляцию бесед

- **Цель.** Убедиться через штатный вход VK, что подсказка исчерпывает результат собственной команды с пересылкой и что отдельно отправленная команда по-прежнему работает.
- **Стенд.** В `tests/helpers/application-response-fixture.ts` дать `submit` возможность передать реальный текст внутри подмены `fwd_messages`. Сохранить существующие вызовы с булевым флагом и возможность указать локальный номер события. В `tests/application-personal-data.test.ts` подготовить доступную личку автора и его записи в двух беседах A и B через `connectGroup`. Перед командами дождаться готовности диалогов и запомнить состояние данных и отправок. [Подмена VK](../../../tests/helpers/application-response-fixture.ts)
- **Собственная команда.** Для `/мои-данные`, `/отключить-профиль`, `/удалить-мои-данные` и `/статус-удаления` проверить беседу A и личку с ID A. После команды с пересылкой сверить новые исходящие сообщения по `peer_id` и полному тексту. Проверить ноль загрузок и отправок файла, отсутствие новых строк в `personal_exports` и `personal_deletions`, сохранность отметок `personal_profile_choices.disabled_at` в A и B. Также проверить вариант с ID беседы B в команде из A. Автор видит ту же подсказку в A.
- **Текст только в пересылке.** Передать пересланное сообщение с командой и пустой либо нейтральной собственной подписью. В обеих точках входа проверить отсутствие служебной подсказки и операций с данными после завершения обработки. Обычный ответ бота на собственные слова автора учитывать отдельно. В `tests/vk-inbound-normalization.test.ts` закрепить, что в тексте для разбора остаётся подпись и передаётся `hasForwarded`. [Нормализация](../../../src/channels/vk/normalize.ts)
- **Контроль.** Тем же автором отправить обычную `/отключить-профиль` в A. Проверить отметку и семь суток на выгрузку от времени этой команды, подтверждение только в личке автора, действующий профиль и прежние данные в B. Для штатной выгрузки и удаления использовать существующие проверки получателя файла и личной доставки кода. [Сквозные проверки](../../../tests/application-personal-data.test.ts)

  ```sh
  npm run build
  npm test -- tests/application-personal-data.test.ts tests/vk-inbound-normalization.test.ts tests/vk-inbound-integration.test.ts tests/storage-personal-data.test.ts
  ```

- **Готово, когда** сборка и тесты проходят. Для каждой из четырёх команд проверены оба диалога, видимый ответ и состояние данных. Семидневный срок в A начинается с отдельной команды автора.

## Результаты приёмки

Основа ветки — `2689d59`. Реализация сохранена в `7afb39b`, сквозные проверки — в `bf62df4`. VK, модель и загрузка файла заменены подменами. Использованы временные базы SQLite и управляемое время. [Сквозные проверки](../../../tests/application-personal-data.test.ts)

- На исходной ревизии оба регрессионных теста упали. Групповая подпись с `/отключить-профиль` отключила профиль и дала ответ в личку 41 «Профилирование в vk:2000000041 отключено. Личная выгрузка профиля доступна до 2026-11-30T12:00:00.000Z.». Эквивалентная подпись в личке ушла в модель и получила «Синтетический ответ».
- После правки четыре команды с пересылкой дали ровно «Отправьте команду отдельным сообщением без пересылки» в исходной беседе или личке. Указание ID соседней беседы в подписи из группы дало ту же подсказку в группе. В обеих беседах профили оставались доступны. Число строк выгрузок, запросов удаления и отключений оставалось нулевым. Загрузок и отправок файлов не было.
- Проверка обработчика дала ноль вызовов `hasData`, `status`, `beginExport`, `export`, `disable` и `requestDeletion`. Для события, утратившего актуальность, отправок подсказки не было. [Юнит-тесты](../../../tests/personal-data-forwarding.unit.test.ts)
- Когда команда была только в переданной реплике с пустой или нейтральной подписью, в журнале осталась собственная подпись. Служебных ответов и операций с данными не было. Обычная реакция на подпись в личке продолжила работать. [Нормализация VK](../../../tests/vk-inbound-normalization.test.ts)
- Отдельная `/отключить-профиль` в A создала единственную отметку `disabled_at` в `2026-11-23T12:00:01.000Z`. Профиль в B остался доступен. Подтверждение автору пришло в личку 41 со сроком выгрузки `2026-11-30T12:00:01.000Z`.
- `npm run build` и `git diff --check` прошли. На шагах 1 и 2 прошли 17 и 75 тестов соответственно. В итоговом наборе из шести файлов прошли все 80 тестов. Запуски `npm test` использовали `--maxWorkers=1`, `--testTimeout=15000` и временный каталог под `/dev/shm`. Ревью прошло без замечаний.
