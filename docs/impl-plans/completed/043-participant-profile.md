## Упорядоченные шаги

Каждый шаг завершать указанными целевыми тестами и успешной сборкой `npm run build`. Для разработки использовать временную SQLite с синтетическими данными. Шаги хранения и выбора факта можно проверять до реализации 040. Для сквозной приёмки нужны действующие проверки допуска, личной выгрузки и удаления F5.8. Инструменты 042 могут подключиться к готовому чтению позднее.

### 1. Сохранить происхождение и порядок изменений

Расширить типы в `src/storage/participant-types.ts`. Добавить следующую свободную миграцию в `src/storage/migrations/` и зарегистрировать её в `index.ts`. Сохранить таблицы и связи F1.5. Для новых изменений учитывать исходное время UTC, устойчивый ключ события, тип изменения и его область. Для снятия интереса хранить, к какому увлечению оно относится. Ограничения видимости должны действовать и при замене значения. Включить новые записи в очистку поколения.

Расширить `tests/storage-participant-upgrade.test.ts` и `tests/lifecycle-cleanup-coverage.test.ts`. После обновления и повторного открытия заполненной БД старые значения, метки и отсутствующие ссылки на источник сохранены. Миграция не присваивает им задним числом согласие, публичность или доказанное время исходного события. Сброс поколения очищает его профильные данные, соседняя беседа сохраняется.

### 2. Выбрать действующий факт и применить отзыв интереса

В новом `src/storage/profile-fact-store.ts` выполнять изменение атомарно в действующей области подключения. Для однозначного поля сравнивать источник, затем время исходного изменения. При совпадении обоих использовать стабильный порядок исходных событий, чтобы результат воспроизводился при повторной доставке в другом порядке. Для каждого интереса отдельно учитывать последнее действующее решение человека. Надёжность и происхождение сохранять независимо. Повтор одной операции не создаёт второго факта и не отменяет позднейшее решение.

В новом `tests/storage-profile-facts.test.ts` проверить перестановку записей от человека, администратора и бота, равное время событий, поздний дубль, две группы, личку и тёзок. Контрольная цепочка — шахматы, бег, отказ от шахмат, перезапуск, повтор первого события, новый вывод бота о шахматах. После цепочки действует только бег. Более позднее собственное добавление возвращает шахматы.

### 3. Подключить проверки записи и жизненного цикла профиля

В `src/storage/scoped-storage.ts` и новом хранилище фактов применять доверенные чат, поколение и личность. Получать основание для метки источника из проверенного события и полномочий. Для записи из переписки сопоставлять исходное сообщение с моментом доставки уведомления. Проверять допуск 040 при фиксации, включая отказ, поступивший после начала обработки. Включить факты, ограничения и отзывы в личную выгрузку и очистку 040 с учётом правил обработки чужих источников. До появления сервиса 040 пользоваться подменой допуска только в тестах.

В новом `tests/profile-personal-data.test.ts` проверить старое сообщение, обработанное после уведомления, допустимую запись после доставки, подмену авторства через текст и отключение между подготовкой и записью. Закрытый профиль сразу недоступен для обычного чтения. Проверенный автор может получить свою выгрузку в установленный семисуточный срок. При явном удалении, истечении срока и смене поколения старые операции не восстанавливают профиль. Для приёмки повторить эти проверки с сервисом 040 и временной БД.

### 4. Предоставить проверяемые данные для инструментов участников

Предоставить в `src/storage/scoped-types.ts` и `src/storage/scoped-storage.ts` чтение действующих значений для заданной аудитории и проверку актуальности прочитанного. Сначала определить действующее состояние поля вместе с ограничением человека, затем формировать публичную выборку. Публичный поиск интересов допускает только собственное действующее утверждение с видимостью `chat`. Обновление скрытого поля сохраняет ограничение. При исправлении, отзыве, удалении или смене области повторная проверка прежнего результата должна обнаружить изменение.

В новом `tests/profile-public-read.test.ts` сравнить доступные значения и число совпадений для отсутствующего, снятого, выведенного ботом, скрытого и имеющего неизвестную видимость интереса. Повторить для администратора. Проверить ранее публичные шахматы после скрытия и между чтением и использованием, а также неизменность выдачи другой группы. Строка, похожая на команду, остаётся значением поля. Готовность — потребитель 042 может получить разрешённое совпадение и отклонить устаревшее, не читая закрытые версии самостоятельно.

### 5. Выполнить приёмку, ревью и синхронизацию

Пройти критерии задачи на временной SQLite через штатные операции хранения и допуска. Выполнить `npm run build`, `npm test` и `npm run test:queue-load`. Провести `review`, устранить замечания и повторить проверку. После успешного ревью выполнить `sync-specs` для профилей, хранения, инструментов и приватности. Обновить дорожную карту и журнал решений.

Записать результаты и даты завершения. Конечные пути — `docs/tasks/completed/043-participant-profile.md`, `docs/plans/completed/043-participant-profile.md` и `docs/impl-plans/completed/043-participant-profile.md`. Проверить внутренние и входящие ссылки после переноса. [Правила хранения](../../project.md#хранение-активных-и-выполненных-задач)

## Результаты приёмки

Ревью завершено без открытых замечаний по плану 043. Реализация зафиксирована в ветке `plan-043-participant-profile` до коммита `bb45cde`.

- Прошли `npm run build`, 1141 обычных тестов и 10 нагрузочных тестов очереди.
- Миграция 29 сохранила контрольные суммы и заполненные строки без выдуманного времени, источника или доступа. Две группы, личка и два тёзки сохранили независимые факты после перезапуска.
- Проверены приоритет источников, равное время, поздний повтор, собственное исправление и устойчивый отзыв шахмат при сохранении бега. Ссылку на недоступную реплику личная выгрузка не показывает.
- Временная SQLite использовала штатный F5.8. Проверены доставка уведомления, смена версии, отключение во время обработки, семисуточная выгрузка, подтверждённое удаление и полный сброс поколения.
- Публичные тесты подтвердили отсутствие совпадений для закрытого, неизвестного, снятого и выведенного ботом интереса. Скрытие блокирует старую публичную версию. Повторная проверка выявляет изменение доступа и области. Интерфейс проверен для будущего потребителя F5.6.

В общей рабочей копии прошла сборка после переноса 043 и 45 целевых тестов. Полный прогон общей копии выявил ошибки после параллельных изменений агентного цикла и добавления миграции 30. В частности, часть тестов запустила прежнюю сборку с новой схемой. Полный набор плана 043 прошёл в отдельной ветке с миграцией 29.
