## Упорядоченные шаги

Каждый шаг завершать сборкой и затронутыми тестами. VK и модель подменять.

### 1. Различить просмотр раздела и вопрос по его содержанию

В обработке паспорта и маршруте входящих сообщений (`src/app/chat-passport.ts`, `src/app/service.ts`) распознавать однозначную адресованную просьбу показать раздел. Использовать чтение текущего раздела 051 с проверкой прав. Сохранить поведение команд просмотра и редактора. Для обычных вопросов выделить платформенно-независимый отбор кандидатов в новом модуле `src/core/context/passport.ts`. Основание для отбора — собственный текст текущего обращения. Отдельный вызов модели для классификации не требуется.

В `tests/application-chat-passport.test.ts` проверить команду, адресованную просьбу, пустой раздел, повтор события и такую же фразу в чужой цитате. Для «Можно сюда кинуть рекламу?» ожидать кандидата «правила», для вопроса о местном выражении — «глоссарий», для «Как дела?» — пустой набор. Критерий готовности: явный просмотр возвращает содержимое из БД с нулём вызовов модели, фраза о рекламе остаётся обычным вопросом.

### 2. Добавить подходящие разделы в пределах бюджета

Через `src/storage/chat-passport-store.ts` получить согласованный снимок текущего подключения. Подключить его к подготовке обычного контекста и окончательной сборке запроса с карточками и инструментами. Разделы передавать в недоверенном пользовательском JSON. Неиспользованные разделы исключать целиком, пустое поле опускать. Для каждого кандидата штатной оценкой измерять прибавку к полному сериализованному входу. Соблюдать сразу три предела: 10 % входного бюджета с округлением вниз, 1024 оценочных токена и свободное место после карточек, схем инструментов и резерва ответа. Порядок среди подходящих разделов — правила, глоссарий, тема, традиции, важные события.

В `tests/context-budget.test.ts` проверить точную границу и превышение на единицу, кириллицу, экранирование, два подходящих раздела разной длины. Сравнить контрольный запрос «Как дела?» с запросом при пустом паспорте. Критерий готовности: нулевая прибавка для обычной реплики без признаков связи с паспортом, сохранность текущего сообщения, цитаты, истории, карточек и схем. Специализированный запрос движка анкеты сохраняет собственный состав.

### 3. Проверять ревизии до модели и публикации

В `src/core/chat-queue/agent-loop-adapter.ts` и пути публикации связать фактически отправленные разделы с их ревизиями и поколением. При смене редакции до первого вызова пересобрать ввод в пределах срока задания. На продолжениях пересчитать свободный объём; для публикации учитывать использованные разделы всей цепочки, включая те, что перестали помещаться в последнем запросе. Проверять актуальность перед повторным вызовом и отправкой каждой части. Диагностика хранит сведения о составе и размере без текста паспорта.

В новом интеграционном тесте по образцу `tests/application-context-cards.test.ts` задержать модель и доставку. Проверить правку, очистку, сброс поколения и изменение пропущенного раздела. Критерий готовности: устаревший ответ удерживается, изменение неиспользованного раздела допускает доставку, продолжение инструментального обмена укладывается в бюджет.

### 4. Сквозная приёмка, ревью и синхронизация

Через штатный вход VK на подменах проверить две беседы с разными определениями слова «маяк», личку, вопрос о рекламе, прямой просмотр и нейтральное приветствие. В оценках проверить инструкцию из глоссария о выдаче прав: текст остаётся данными, разрешения и результат проверки полномочий сохраняются. Выполнить `npm run build`, `npm test`, `npm run test:queue-load` и `npm run eval:local -- --out <новый файл JSON>`. Зафиксировать число вызовов модели и состав запросов для контрольных сценариев.

Пройти `review`, исправить замечания и повторить проверки. После успешного ревью выполнить `sync-specs` для контекста, знания о беседе и оценок. Обновить дорожную карту и решения, проставить даты завершения.
