# Агентный цикл

## Реализованная граница клиента

F2.1 предоставляет [нейтральный клиент](architecture.md#клиент-модели-f21) с complete/incomplete/refused/empty/tool_calls/error. Только complete обозначает законченный текст; сопутствующий текст tool_calls не финальный ответ. Будущий цикл проверяет список разрешённых инструментов и разбирает аргументы перед исполнением, связывает результаты с идентификаторами вызовов и владеет ограниченными повторами с общим сроком. Сам клиент аргументы не разбирает, инструменты не исполняет и запросы не повторяет. F2.2 завершена после F2.9. Текстовый цикл имеет один логический шаг. Подтверждённое через Go транспортное продолжение используется как основание для F5.6, где появляется исполняемый реестр. [Валидация провайдера](../research/go-model-validation.md#натурная-проверка-2026-11-23)

## Реализованный текстовый цикл F2.2

[createAgentLoop](../../src/core/agent-loop/service.ts) явно получает LlmClient и доверенные опции, возвращает run(input). Клиент, конфигурация и подготовленный текстовый вход фиксируются снимками; каждая попытка получает независимую копию. Нет импорта HTTP-клиента, чтения окружения/БД, самостоятельной сборки контекста, выбора версии или отправки сообщений. Импорт и создание не запускают работу или таймеры. Вход допускает только system, историю user/assistant, maxOutputTokens, sessionId и signal; инструментальные и произвольные поля отклоняются до обращения.

Лимиты разделены: maxSteps по умолчанию 6 — логические шаги, maxAttemptsPerStep по умолчанию 2 — попытки одного шага, включая первую. Первая версия без инструментов выполняет один логический шаг, поэтому повтор server увеличивает попытки, но не шаги; искусственных следующих шагов нет. При подключённом реестре следующий шаг получает результаты инструментов с исходными tool_call_id. Повтор продолжения использует сохранённые результаты. Итог содержит steps, attempts и attemptsPerStep; до первой отправки все они нулевые/пустые.

Автоповтор по умолчанию только server; retryServerErrors = false отключает его. Rate_limit — отдельный конечный исход: очередь F2.3 завершает задание без перепланирования. Каждый повтор проходит [общий допуск F9.1](#ожидание-места-и-восстановление-f91). Завершение при `rate_limit` проверено подменами. Все натурные запросы F2.9 дали HTTP 200. Сеть, timeout клиента, постоянные ошибки, отмена, неверные результаты и неожиданный отказ клиента не повторяются. Успех последней попытки остаётся успехом; если следующий server-повтор невозможен из-за предела, возвращается attempt_limit с фиксированным lastErrorCode = server. Повтор использует тот же запрос; сообщения ошибок или «продолжи» не добавляются. Это не гарантия отсутствия повторной оплаты.

Общий timeoutMs по умолчанию 120000 мс охватывает подготовку, попытки и паузы; retryDelayMs по умолчанию 1000 мс. Предел попыток/шагов — положительное безопасное целое, срок и пауза — положительные целые не больше 2147483647 мс. Срок не продлевается при повторе, длительность измеряется монотонными часами. Предварительная отмена исключает попытку; отмена и deadline прекращают ожидание даже при игнорировании сигнала клиентом. Поздний результат/отказ не создаёт второй доставки и не меняет сводку; собственные таймеры и слушатели освобождаются. Timeout отдельного клиента остаётся error/timeout, общий срок — deadline_exceeded.

Результаты: complete с буквальным text, incomplete с отдельным partialText, refused, empty, rate_limit, llm_wait_timeout, llm_provider_paused, tools_not_supported, cancelled, deadline_exceeded, attempt_limit и error с фиксированными code/message. Неверный ввод даёт invalid_input без обращения; неверная форма, синхронный throw или отказ Promise клиента — client_failure без исходных message/stack/cause. Пустой complete не считается успехом. В текстовом режиме без реестра запросы инструментов завершаются tools_not_supported; их аргументы и reasoning_content не читаются ради разрешения действий. Неполный текст сам не публикуется и не продолжается.

Сводка возвращает длительность, шаги/попытки и независимые input/output: knownTokens, unknownAttempts, overflowed. Ошибка или незавершённая отменённая попытка без usage остаётся неизвестным расходом, а не нулём. Корректный явный ноль учитывается; отсутствие обращений означает достоверный ноль. Переполнение knownTokens помечается null и overflowed, сумма известных значений при наличии неизвестных не считается полным расходом. Снимок результата и сводки неизменяемый. В сводке нет текстов, сессии и секретов; цикл ничего не логирует, включая debug. Долговечная трассировка реализована F2.6.

Политику и пределы повторов в проде выбирает владелец бота; точка сборки F3.4 передаст инфраструктурную конфигурацию. Эти настройки не входят во ввод модели/участников и не изменяются обычным администратором беседы. Команды изменения политики сейчас не реализованы. Очередь не должна создавать независимый второй цикл server-повторов.

Связка createAgentLoopQueue создаёт цикл из одного снимка фактических настроек и проверяет, что срок обработчика очереди не меньше общего срока цикла с положительным запасом. Очередь хранит только конечный код, без текста ответа; полный исход передаётся политике F2.4 после проверки finish, а связывание с реальным отправителем остаётся будущей интеграции.

## Ожидание места и восстановление F9.1

При занятых местах вызов для ответа ждёт до настроенной границы или оставшегося срока задания. При освобождении места харнес проверяет срок, отмену, поколение и источники, выполняет штатный допуск F4.3 и F4.6 и запускает отправку синхронно после резерва. Время ожидания измеряется до получения места. При отказе до отправки попытка не учитывается, оформленный для неё резерв снимается. Поздний подтверждённый usage завершившегося вызова сверяется с резервом даже после завершения задания.

HTTP 429 завершает задание без перепланирования и ставит общую паузу до срока из `Retry-After` или на начальную задержку. Пауза также начинается после серии 5xx в заданном окне. Для отдельной ошибки `server` действует прежний ограниченный повтор. По истечении паузы допускается один актуальный вызов. При подтверждённом успехе он открывает допуск. При 429 или 5xx расчётная задержка удваивается до настроенного предела с соблюдением более долгого срока провайдера. Сетевой сбой или отмена до отправки освобождают право на проверку. [Настройки и уведомления](commands-and-limits.md#параллелизм-модели-f91) · [Пауза в SQLite](storage.md#пауза-провайдера-f91)

## Допуск по токен-бюджету F4.6

Перед фактическим вызовом клиента харнес проверяет актуальность задания и источников и резервирует оценку полного входа и передаваемый клиенту `maxOutputTokens`. В оценку входят системный текст, сообщения и выданные описания инструментов при наличии. Общий остаток и остаток инициативы проверяются по назначению попытки. Точное совпадение допускается. Токен-резерв и первое списание F4.3 оформляются в одной транзакции. Отказ любого ограничения сохраняет оба ресурса. У каждой попытки провайдера свой ключ, включая повтор запроса. F4.3 использует один допуск на обращение.

Полученный usage заменяет соответствующий резерв фактической величиной независимо для входа и выхода. Подтверждённый ноль учитывается. При доказанной отмене до вызова освобождаются резерв и первое списание F4.3. После возможного вызова неизвестная часть удерживается до сверки либо выхода из исходного окна. Поздний usage уточняет запись попытки, завершённая трассировка сохраняет исход. Если фактический расход превышает прогноз, учитывается вся подтверждённая сумма, а доступный остаток ограничивается нулём. [Окно списания](commands-and-limits.md#бюджет-расходов) · [Хранение попыток](storage.md#токен-бюджет-f46)

Фоновая попытка F5.7 имеет назначение `profile_update`. Харнес атомарно проверяет прямые задачи, общий остаток и фоновую долю. Допуск порции использует общий учёт usage. Попытка проходит вне обычных заданий и не списывает квоту F4.3. [Условия запуска](profiles.md#автообновление-из-переписки-f57)

## Самостоятельные реплики F4.7

Перед вызовом Haiku харнес проверяет действующее подключение, настройки, раскрытие, видимость источников и [остатки бюджета](commands-and-limits.md#бюджет-расходов). Оценка занимает фоновое место F9.1 с приоритетом обычных заданий. От запроса до решения допускается до 45 секунд в пределах срока исходного ожидания. Резерв выхода составляет 384 токена с учётом возможных внутренних рассуждений модели.

Харнес принимает только законченные «ответить» и «промолчать». Для «промолчать», ошибки, отказа, тайм-аута, лишнего текста и вызова инструмента результатом становится тишина. Оценка использует собственный резерв и не занимает квоту пользовательского ответа, исходящее место или индикатор набора. Подтверждённый расход учитывается при любом решении.

При своевременном «ответить» харнес передаёт исходное сообщение основной модели по обычному заданию. Свободная инициатива получает назначение `initiative` и проходит проверки отдельной квоты F4.3 и обоих остатков F4.6. При отзыве допуска доступный расход сохраняется, публикация подавляется.

Перед первой попыткой отправки харнес атомарно резервирует одну самостоятельную реплику F4.3 и одно исходящее место F4.5. Подтверждения частей обновляют ту же публикацию. Достоверный отказ всей публикации освобождает оба резерва. Подтверждённая часть либо неизвестная попытка сохраняет учёт. Запрет, ошибка или истечение срока инициативы дают молчание.

Трассировка фиксирует режим, вид повода, причину удержания, попытку модели и результат доставки. Текст источника хранится в журнале по общим правилам. [Этикет и интервалы](chat-etiquette.md#самоограничение-и-принятие-решения) · [Хранение инициативы](storage.md#самостоятельные-реплики-f47)

Молчаливый режим не публикует обычные ответы или уведомления этой таблицы; выключенный бот также молчит по обычному пути. Сохранённый active в личке имеет эффективный normal и использует его колонку. Unknown отправителя блокирует обычный ответ и уведомление независимо от исхода. Служебные результаты авторизованных команд относятся к отдельному пути, а не к ответу модели по этой таблице.

Для подготовки F2.5 отсутствие выбранного общего системного промпта считается внутренней ошибкой конфигурации этой таблицы: модель не вызывается, запасного промпта нет; normal/личка допускает ограниченное нейтральное уведомление, active молчит. Предусмотрены отдельный безопасный счётчик и начальная проверка конфигурации. Слишком большое текущее сообщение и слишком малый бюджет различаются без вызова модели и без молчаливого усечения; строки утверждены человеком в [задаче 015](../tasks/completed/015-context-builder.md). Недостаточный бюджет имеет отдельную причину и безопасный счётчик для владельца, проверяется при запуске. Обе новые причины используют общий долговечный период уведомлений F2.4, а не отдельные периоды по причине.

«Уведомление» — допустимый вид реакции, не безусловная отправка. Оно короткое, нейтральное, без raw-ошибок, внутренних кодов, деталей модели/провайдера и частичного текста. Не чаще одного уведомления на чат за настраиваемый период, общий для причин; только reply к исходному сообщению. Успешные уведомления помечаются в журнале как служебные и не попадают в контекст, включая выборки истории/поиска для контекста. Если отправка reply невозможна, обычное сообщение вместо него не подразумевается. Число периода определяется планом реализации, не этой спецификацией.

При локальном исчерпании квоты используется текст «Сейчас слишком много запросов. Попробуй чуть позже.» Трассировка содержит `quota_exhausted` как исход и идентификатор строки публикации, ноль попыток и отсутствие вызова модели. Ограничение провайдера после вызова проходит по правилам `rate_limit`. При исчерпании лимита самостоятельной реплики применяется молчание. [Лимиты F4.3](commands-and-limits.md#лимиты-и-защита)

F4.4 проверяет доступность источников перед каждой попыткой отправки, в том числе после ожидания лимитера VK, и при записи подтверждённой части. Потеря источника прекращает дальнейшую отправку без служебного уведомления. Ранее доставленные части остаются в VK. Публикация частей сохраняет уже подтверждённые записи. Отказ остатка отражается как `failed`, неоднозначная доставка или изменение текста VK — как `unknown`. При наличии записанных частей неполный исход получает причину `partial_delivery`. Сбой записи подтверждения учитывается отдельно. [Журнал](storage.md#операции-журнала)

[Сценарий молчания при ошибке в active](evals.md#ошибка-в-активном-режиме-не-даёт-сообщения) проверяет локальную связку роутера, очереди, цикла и подмены порта. Тесты отдельного цикла или одной таблицы не доказывают готовность живого отправителя.

F4.5 занимает исходящее место при первом фактическом допуске к `messages.send`, после технического лимитера и проверки актуальности источников. Для короткого отказа F4.3/F4.5/F4.6 исходящее место и общий период уведомлений проверяются и занимаются одной транзакцией. Отказ на пороге относится только к своему всплеску. Публикация при исчерпанном пределе фиксируется как `response_rate`, текст модели и нейтральное уведомление по этой причине не выдаются.

## Целевое поведение полного цикла

Модель вызывается с системным промптом, [контекстом](context.md) и списком [инструментов](tools.md).

Перед каждым вызовом модели харнес формирует список инструментов по [правилам отбора и проверки вызова](tools.md#отбор-и-проверка-вызова). Если модель запрашивает инструмент, харнес сначала проверяет его наличие в выданном списке, затем выполняет разрешённый вызов, возвращает результат модели и вызывает её снова. Недопустимый вызов отклоняется с ошибкой и логируется по тем же правилам реестра. Безопасные независимые разрешённые инструменты допустимо выполнять параллельно в одном шаге.

Цикл завершается при текстовом ответе модели или достижении лимита шагов (по умолчанию 6). При исчерпании лимита возвращается отдельный исход; его публикация или молчание определяется таблицей интеграции выше. В активном режиме ошибка не даёт сообщения.

Ошибка отдельного инструмента возвращается модели текстом в результате вызова, не прерывая цикл; модель может переформулировать вызов. Ошибки LLM и отправки обрабатываются согласно [архитектуре](architecture.md).

Источники событий харнеса и правила учёта описаны в [метриках F9.2](#метрики-обращений-f92).

## Метрики обращений F9.2

Роутер считает адресованное обращение после первой записи входящего сообщения в журнал. Переполнение, отказ в квоте и подавление служебного уведомления сохраняют учёт обращения. Очередь относит ожидание и обработку к периоду первого приёма. Истёкшее в очереди задание даёт замер ожидания до своего срока. При восстановлении прерванного задания сохраняются известные замеры.

Первый фактический вызов на логическом шаге считает шаг и попытку. Повтор того же шага добавляет попытку, а продолжение после инструмента открывает новый шаг. Харнес фиксирует ошибки отправленных вызовов в периоде попытки. Вызов `delegate` относится к основной модели, запуск и завершение уникальной ветви, её попытки и чтение относятся к субагентам. Повтор уже выполненного вызова использует сохранённый результат. Разбор анкеты и явный пересказ учитываются по маршруту основного ответа.

Попытки, ошибки и подтверждённый расход Haiku отражаются отдельными сериями `gate_name` и `gate_initiative`. Вызовы основной модели идут в серии соответствующего ответа. [Сводка по беседе](commands-and-limits.md#историческая-сводка-по-беседе-f92)

Обращение и результат доставки относятся ко времени приёма. Подтверждение всех частей обычного ответа даёт один успех. При подтверждении части записывается частичная доставка. При неопределённом исходе без подтверждённых частей записывается неизвестная доставка. Отказ по F4.3 учитывается по решению очереди. Самостоятельная реплика увеличивает счётчик доставленных реплик после подтверждения всех частей. Её фактические попытки входят в расход инициативы. [Хранение метрик](storage.md#хранение-метрик-f92)

## Трассировка ответа

F2.6 трассирует все начатые задания: запись создаётся при старте, закрывается исходом; незакрытые при восстановлении очереди помечаются прерванными. Для задания и поколения подключения существует одна трассировка. Подготовка ответа не доказывает его внешнюю доставку.

В записи находятся фактически использованные слои контекста с идентификаторами и размерами без полного текста, точная версия промпта, имя использованной модели, версия применённого персонажа, сводка шагов и попыток, исход, расход токенов и длительность. Неизвестный расход не становится нулём. Сохраняются режим, вид реакции, решение о публикации и сработавшая строка таблицы; для самостоятельных реплик — сработавший повод. Отсутствующие слои и инструменты не выдумываются.

При допуске основного вызова харнес записывает точную ссылку в `context.persona.version` и число сериализованных байтов блока в `context.persona.bytes`. Если вызов не получил допуск, в трассировке остаётся метка отсутствующего слоя. Записи прежнего формата читаются штатно. [Слой персонажа](context.md#персонаж-в-контексте-f71)

Для задания из беседы VK трассировка содержит проверенную версию раскрытия и итог допуска, если проверка выполнялась. Эти поля не содержат текста раскрытия или сообщений. Ранее сохранённые записи читаются без этого поля.

Результаты инструментов сохраняются только структурированными признаками (имя, исход, размер, длительность), без аргументов и текстов. Полные тексты контекста, сообщений и ответа, секреты, сессия модели и raw-ошибки не копируются. Размер и срок ограничены [настройками трассировки](storage.md#хранение-трассировок-f26); превышение размера полной формы ведёт к явно обозначенной минимальной форме без молчаливого усечения обязательных полей. Трассировка не является источником метрик: счётчики и учёт расхода работают независимо от её наличия и очистки.

Перед публикацией трассировка сохраняется. При сбое выполняется попытка минимальной записи; при её отказе ответ модели не публикуется. Отдельная причина и безопасный счётчик отражают этот сбой; повторного вызова модели нет. Нейтральное уведомление в normal/личке подчиняется общему долговечному периоду и запретам публикации; active молчит. Это служебное уведомление допускается и при отсутствии сохранённой трассировки, не запускает повторную цепочку записи или генерации. Если недоступны проверки области или резервирование периода, уведомление не отправляется. Правило блокировки ответа пересматривается после первых недель эксплуатации.

Трассировка хранится в [БД](storage.md), имеет ограниченный срок, короче сообщений, и удаляется также вместе с исходным сообщением или беседой по [privacy](privacy.md). В выгрузку данных человека она не входит. Статус F2.6 отмечен в [дорожной карте](../roadmap.md#веха-2-ядро-без-платформы).

Команда [«почему ты так ответил»](commands-and-limits.md#объяснение-ответа-и-расход) выбирает последнюю завершённую неистёкшую трассировку обычного ответа со статусом `delivered` в указанной области. Служебные уведомления и недоставленные целиком ответы пропускаются. Сводка показывает известные повод, режим, время завершения в UTC и названия групп использованных источников. Названия берутся из фиксированного набора, содержимое источников в сводку не входит. [Правила доступа](security.md#доступ-к-трассировкам-f26)

Роль и права проверяются харнесом и инструментами по [security](security.md); текст запроса не может разрешить изменяющее действие. Платные проверки поведения при смене промптов, персонажей или модели выполняются по [правилам оценочных тестов](evals.md).

В таблице публикации версии 1 используются `complete`, `unusable_response` для incomplete/refused/empty, `unsuccessful` для ошибок, ограничений провайдера, дедлайна и failed, `queue_full`, `quota_exhausted`, `token_budget_exhausted`, `current_message_too_large`, `static_budget_too_small`, `trace_write_failed` и `silent_outcome`. `invalid_route` означает отсутствие разрешённого маршрута. Группа уведомлений с одинаковым текстом сохраняет различие исходов. `pending_checks` обозначает незавершённую проверку, `allowed` — разрешение с ещё неподтверждённой доставкой. `delivered`, `failed` и `unknown` отражают записанный результат порта. После сбоя подтверждения `allowed` сохраняет смысл разрешения и исключает автоматический повтор.

## Делегирование в пользовательском обращении

Основная модель выбирает до двух подзадач. Независимые вызовы могут выполняться параллельно. Зависимая ветвь может сослаться на завершённый результат. Харнес передаёт выбранные материалы и разрешённые инструменты чтения. Каждая попытка помощника ограничена 2560 оценочными токенами входа и 640 токенами выхода. Пустой или неподтверждённый результат отмечается как неполный. Итоговый ответ публикует основной маршрут.

Ветвь использует вспомогательный клиент из [конфигурации приложения](architecture.md#клиент-модели-f21) до завершения. Продолжение после чтения занимает новый логический шаг. При разрешённом повторе после `server` харнес отправляет тот же запрос с уже полученным результатом чтения. Каждая попытка проходит проверку срока, актуальности задания и видимости источников перед отправкой.

Общий срок и лимит шагов действуют для всего задания. Для каждой отправки помощника харнес сохраняет основной модели последний шаг и резерв токенов для завершения. F4.3 учитывает исходное обращение один раз, F4.6 учитывает каждую фактическую попытку. При исчерпании попыток или бюджета ветвь возвращает `limit`, при недоступности модели — `unavailable`. Отмена задания или отзыв использованных данных останавливают работу по ним. [Сравнение на Go](../research/delegation-go-validation.md#две-модели-в-задаче-059)
