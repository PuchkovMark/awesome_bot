# Профили участников

В правилах управления «администратор» означает администратора бота, назначенного по [правилам безопасности](security.md#роли-и-проверки), а не администратора беседы VK.

## Границы профиля

Профиль привязан к конкретной беседе. Данные между беседами не переходят; общим остаётся только идентификатор человека. Связь с участником и сущности фактов — в [хранилище](storage.md).

В личке действует отдельный профиль только этого диалога. Анкета, заполненная в личке, относится только к личке; анкеты бесед через личку не проходят. Данные профиля и ответы не переносятся между чатами.

## Факты и видимость

У каждого факта есть источник: рассказал сам человек, бот вывел из переписки или добавил администратор. Указывается признак надёжности. У каждого поля есть видимость. Новое поле по умолчанию видно всем участникам текущей беседы (`chat`). Человек может явно ограничить видимость отдельных полей, в том числе оставить сведения только боту (`bot`). Явное ограничение имеет приоритет над значением по умолчанию. Между беседами сведения не передаются.

Человек может посмотреть и исправить данные о себе, скрыть поля и удалить всё о себе. Выведенные ботом факты можно отклонить. Автообновление из переписки сохраняет источник и возможность отклонения.

Видимость должна учитываться при выдаче сведений через [инструменты](tools.md), включении [карточек в контекст](context.md), [приветствии и представлении](onboarding.md). Персонаж не отменяет ограничения доступа к данным.

## Представление фактов в модели

Модель F1.5 связывает профиль с участием конкретного чата, а факт — с этим профилем. Значение — обычная Unicode-строка, ключ поля непустой и пока не ограничен продуктовым справочником. История может содержать несколько фактов по ключу. Действующее состояние определяется правилами F5.3. Даты создания/изменения записи задаются явно и не являются отметками согласия или актуальности факта. Физические поля и связи находятся в [хранилище](storage.md#физическая-модель-участников-и-профилей).

Обязательный источник — `self` (сообщил сам человек), `inferred` (вывод из переписки), `admin` (добавлено администратором). Необязательные сведения об авторе, сообщении и примечании источника допускают `null`; недоступное исходное сообщение или участник не подменяются выдуманными данными. Метка не доказывает личность автора и его полномочия; текст источника остаётся недоверенным.

Надёжность сохраняется как явная метка `unknown/unverified/confirmed`: оценка не предоставлена, сведения отмечены неподтверждёнными или запись помечена подтверждённой. `confirmed` не доказывает истинность. Источник не назначает надёжность автоматически; слова самого человека или администратора не получают приоритета над выводом одним ограничением БД.

Видимость сохраняется как `unknown/bot/chat`: намерение не определено, использование ботом без разрешения публичного раскрытия либо намерение использования в текущей беседе. На уровне схемы F1.5 метки обязательны и не имеют SQL-default; `unknown` также задаётся явно. При создании новых записей по умолчанию применяется `chat` с учётом решения участника. Это правило не переопределяет явно заданные ограничения и не превращает сохранённый `unknown` в разрешение выдачи. `bot` не разрешает публикацию через ответ, `chat` не предоставляет доступ автоматически, не заменяет согласие и не допускает перенос в другой чат.

Публичное чтение F5.3 применяет ограничения и проверяет действующий допуск. [Личные команды F5.4](#личный-список-и-правки-f54) используют отдельный доступ автора.

## Действующие факты и интересы F5.3

При записи из переписки харнес связывает изменение с подтверждённым человеком, доступной репликой и текущим поколением чата. Участник меняет свои факты и видимость. Администратор бота может добавить факт подтверждённому участнику беседы. Вывод, полученный из сообщения участника, имеет источник `inferred`. Допуск F5.8 проверяется в транзакции по времени исходной реплики и действующему состоянию профиля. [Приватность](privacy.md#согласие-и-внешний-провайдер)

Для однозначного поля действует факт самого участника, при его отсутствии — факт администратора, затем вывод бота. При равном источнике побеждает более новое исходное событие. Повтор события сохраняет прежнюю запись. Надёжность сохраняется независимо от приоритета. Для каждого интереса решение учитывается отдельно. Отказ участника удерживает интерес снятым до его нового собственного утверждения. При столкновении утверждения и отказа в одном исходном событии действует отказ.

Публичный читатель сначала определяет действующее состояние, затем применяет видимость. Новый факт получает `chat` по умолчанию. Последнее явное ограничение участника переживает замену значения. Закрытые метки прежних записей ограничивают публичную выдачу до явного выбора владельца профиля. Старые факты без проверенного происхождения сохраняются для собственных данных. Публичный читатель выбирает только факты с подтверждённым допуском. [Поиск по интересам](tools.md#инструменты-участников) · [Хранение](storage.md#события-фактов-профиля-f53)

## Факты для карточки в контексте F5.5

Харнес читает действующие факты с видимостью `chat` в области ответа. Для лички используется профиль только этого диалога. Форму обращения выбирают по правилам F5.2 для той же аудитории.

Карточка использует до двух фактов. Приоритет от источника к источнику идёт от собственных утверждений к сведениям администратора и затем к выводам бота. Внутри источника выбирается более свежее исходное событие. Для равенства сохраняется устойчивый порядок по ключу события и номеру записи. [Отбор участников и бюджет](context.md#карточки-активных-участников-f55)

## Личный список и правки F5.4

При действующем допуске F5.8 владелец профиля видит действующие факты выбранного чата, включая закрытые. В личке указываются выбранный чат, номер, значение, источник и действующая видимость каждой позиции. Пустой профиль получает короткий ответ.

Исправление создаёт утверждение участника с сохранением ограничения видимости. При замене интереса прежнее значение перестаёт действовать, а остальные интересы сохраняются. Если новый интерес уже действует, правка отклоняется. Когда для нового значения сохраняется более строгое прежнее ограничение, применяется оно.

Скрытие устанавливает видимость `bot` для выбранной позиции. Публичная карточка и поиск сразу учитывают ограничение. Подготовленный ответ по утратившей актуальность выдаче не публикуется.

Отклонение снимает действующий вывод бота. Оно относится к конкретному выводу и не возвращает более ранние выводы по той же позиции. Для утверждения самого человека или администратора бот поясняет допустимое действие. [Команды](commands-and-limits.md#команды-профиля-f54) · [Привязки](storage.md#привязки-личного-профиля-f54)

## Предпочтение в обращении F5.2

Явный выбор формы принадлежит автору и текущему поколению чата. Включённый бот принимает выбор после [допуска профиля F5.8](privacy.md#согласие-и-внешний-провайдер). Источник выбора — собственное сообщение участника. Разговорное упоминание прозвища и другие профильные факты сами по себе выбор не меняют.

В группе применяется только значение с видимостью `chat`. По умолчанию новый выбор в группе получает эту видимость, выбор в личке получает `bot` и доступен только в личном диалоге автора. Замена формы и сброс сохраняют установленную видимость. `unknown` закрывает использование формы. Скрытие в беседе, сброс и потеря допуска возвращают [базовое обращение](participants.md#имена-и-обращения). [Хранение](storage.md#выбранные-обращения-f52) · [Команды](commands-and-limits.md#предпочтения-в-обращении-f52)

## Анкета и согласие

Правила этого и следующих разделов задают продуктовые требования; модель F1.5 сама по себе не реализует сбор, выдачу или согласие.

Анкета добровольна; любое поле можно пропустить. Профиль может создаваться из ответов по [правилам знакомства](onboarding.md).

Сбор персональных данных требует согласия и проверки соответствия законодательству. Решение о правовом основании, форме согласия и допустимом составе данных принимает человек; эта спецификация не разрешает эти вопросы за него.

## Открытые вопросы

- Какие предметные поля и сложные значения нужны; кто назначает метки и как исполнять ограничения видимости при формировании ответа, включая «только боту»?
- Приоритет источников подтверждён; определить техническую обработку отклонённых выводов и давности в соответствующем плане.
- Каковы права администратора на добавление фактов и изменение видимости, без отмены прав самого человека?

## Жизненный цикл данных

Согласие, версионный текст согласия, выгрузка, удаление всех данных человека в беседе, сроки хранения и правила при выходе регулируются [privacy](privacy.md). Немедленное скрытие профиля при выходе и удаление после льготного срока подтверждены человеком; число определяется в плане, срок очистки бэкапов ещё не выбран. Способ пересборки связанных сообщений, саммари, памяти и копий при удалении ещё не выбран.

Проверки прав определены в [security](security.md). Текст факта и его источника остаётся недоверенными данными при включении в контекст.

## Согласованные правила профилей

**Подтверждено человеком 2026-11-21**, с уточнениями F5.8 о сроке копий и уведомлении. Подтверждение требований не означает готовности реализации.

- **Приоритет источников:** сам человек → администратор → вывод бота. Факт нижестоящего источника не перезаписывает вышестоящий; при равном источнике побеждает более новый. Устаревшие факты помечаются и теряют вес со временем, молчаливо не удаляются. Выводы бота видны человеку и могут быть отклонены. Алгоритм веса и числа давности определяются планом.
- **«Только боту»:** поле влияет на тон и выбор слов, но не цитируется и не пересказывается другим участникам прямо или косвенно, включая ответ на вопрос о человеке. Администратор его не видит. В приветствия и представления не попадает. Требование проверяется оценочными сценариями.
- **Уведомление.** Для профиля действует допуск F5.8 по доставленной версии. Участник может отключить профилирование. Публичное представление требует отдельного согласия.
- **Выход:** профиль немедленно скрывается от бота, затем удаляется после льготного срока, число определяется в плане. Предельный срок копии составляет 30 суток; человек должен получать честную информацию о состоянии удаления. Административные правила выхода этим не меняются.
- **Выгрузка.** Автор получает JSON в личке по правилам обработки совместных записей и источников. [Приватность](privacy.md)
- **Приветствие и анкета:** применяются подтверждённые [настройки](onboarding.md#настройки-приветствия-и-анкеты).

[Подтверждение](../decisions.md#подтверждение-режимов-и-правил-данных) заменяет прежний статус предложения. Хранилище F5.3 применяет выбор и публичную видимость. Использование закрытых фактов для тона и автоматическое извлечение относятся к последующим фичам.
