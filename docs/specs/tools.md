# Инструменты модели

## Реестр и выполнение

Единый реестр содержит схему каждого инструмента (имя, понятное модели описание, параметры) и функцию выполнения с контекстом запроса, прежде всего `chatId`. Описание явно объясняет, когда инструмент вызывать и когда нет.

Контракт инструмента также содержит доступность по платформам и требуемые [возможности адаптера](channels.md#возможности-платформы). По умолчанию инструмент доступен для всех платформ; это не отменяет проверки требуемых возможностей.

## Чтение, изменение и авторизация

Общий `ToolDefinition<Parameters, Result>` из [контрактов](../../src/contracts/index.ts) содержит `name`, `description`, `parameters`, `access: read | write`, необязательные `platforms` и `requiredCapabilities`, асинхронную функцию `execute(parameters, context): Promise<Result>`.

`parameters` — JSON-представление корневой объектной схемы с `type: object`. Рекурсивные JSON-типы допускают примитивы, объекты и массивы, исключают функции и `undefined`. Они не валидируют keywords JSON Schema, корректность чисел, входные данные или соответствие произвольной схемы обобщённому типу параметров. Runtime-валидатор и преобразование в API модели вводятся будущими фичами.

`platforms` допускает `all` или readonly-список имён платформ: отсутствие объявления означает `all`, явный пустой список — ни одной платформы. `requiredCapabilities` — отдельный список имён из [словаря адаптера](channels.md#возможности-платформы); отсутствие означает отсутствие требований. Это описательная семантика для будущего механизма отбора F5.6, не работающий реестр в F1.3.

`ToolContext` передаётся харнесом отдельно от параметров модели и содержит текущие `chatId`, `platform`, вызывающего `userId`, платформенные сведения `isAdmin`, общий `adapter` и необязательный непрозрачный `authorization`. Контекст не назначает роль и не разрешает обращение к чужим чатам. Проверка соответствия области контекста и адаптера, назначение роли и авторизация реализуются харнесом и инструментами согласно [безопасности](security.md).

Нейтральная операция может вызывать общий метод `context.adapter`, не импортируя платформенные типы. Проверки F1.3 демонстрируют получение имени на двух искусственных платформах; продуктовые инструменты участников и фактический исполнитель не реализованы.

Читающие инструменты получают сведения, изменяющие меняют настройки или данные либо выполняют действие: например, удаляют данные, редактируют паспорт или персонажа. Эта классификация независима от доступности по платформам.

Каждый инструмент сам проверяет права вызывающего, область чата и видимость данных. Для изменяющего действия харнес дополнительно проверяет роль человека, от имени которого выполняется запрос, по [матрице безопасности](security.md#матрица-действий-и-минимальных-ролей). Роль вычисляется харнесом по конфигу владельца и сохранённым назначениям; подтверждённые данные платформы дают только исходные сведения для оснований; модель и текст сообщения не могут её назначить.

Выдача инструмента модели и наличие платформенной возможности не заменяют проверку прав. Текст в параметрах и результатах остаётся недоверенными данными по [правилам контекста](security.md#недоверенный-текст). История и инструменты участников относятся к читающим; новые изменяющие инструменты не добавляются одним перечислением примеров.

Правила изоляции и подстановки `chatId` определены в [архитектуре](architecture.md). Модель не получает возможности выбирать другой чат. Вызовы и ошибки обрабатывает [агентный цикл](agent-loop.md).

В F1.6a [toolAuthorization](../../src/tools/authorization.ts) сверяет инициатора, чат, платформу и адаптер с `authorization`; отсутствие контекста или несовпадение даёт отказ. Контекст `kind: owner` в этот путь модели не допускается. Помощник проверяет область, но не разрешает запись: инструмент при исполнении вызывает защищённую атомарную операцию сервиса. Сервис проверяет происхождение контекста, исходную область подключения и текущие права независимо от предварительного допуска. Контекст авторизации содержит `ConnectionScope`; инструмент передаёт её в хранилище, не выбирая новое поколение по chatId. Устаревшая область или `uncertain` отклоняет чтение и изменение. Прямой вызов и снятие прав после допуска проверены тестовым инструментом с реальной SQLite-записью; продуктовый реестр остаётся F5.6.

## Категории инструментов

| Категория | Определение |
| --- | --- |
| Нейтральные | Работают через общее хранилище без платформенной реализации; подавляющее большинство инструментов |
| Платформенные | Имеют смысл только в одной платформе и доступны только для неё |
| Нейтральные по смыслу, с разной реализацией | Для модели это один инструмент с общим контрактом; конкретную реализацию выполняет адаптер текущей платформы |

Если смысл операции общий, предпочитается третий вариант вместо отдельных платформенных инструментов. Категория не разрешает импорт платформенных SDK или типов в `tools`: платформенная реализация остаётся в адаптере.

## Отбор и проверка вызова

Перед каждым запросом к модели, включая повторные вызовы агентного цикла, харнес:

1. Определяет платформу по префиксу составного `chatId` из контекста запроса.
2. Отбирает инструменты, доступные для этой платформы.
3. Сопоставляет требуемые возможности каждого инструмента с объявленными возможностями адаптера. Если необходимая возможность отсутствует, инструмент исключается.
4. Передаёт модели только получившийся список инструментов.

Решение принимает харнес; модель не может выбрать платформу, изменить возможности адаптера или повлиять на правила отбора.

При запросе инструмента вне списка, выданного для соответствующего вызова модели, харнес отклоняет вызов с ошибкой, не выполняет инструмент и логирует попытку. Ошибка возвращается в цикл согласно [правилам ошибок инструментов](agent-loop.md); ограничения безопасного логирования остаются в силе.

## Первые инструменты

| Инструмент | Параметры и поведение |
| --- | --- |
| Поиск по истории | Необязательный текстовый запрос, начало и конец периода, необязательный автор, лимит; FTS5 и фильтры |
| Получение сообщений за период | Даты и лимит |

Оба инструмента имеют жёсткий потолок выдачи в коде: около 40 сообщений либо ограничение по токенам. Модель не может превысить потолок. Ответ поиска всегда содержит число найденных и показанных сообщений, подсказку сузить период или запрос. Правило о шуме — в [контексте](context.md).

Инструменты принимают даты ISO с часовым поясом. Преобразование «вчера» в диапазон дат выполняет модель, поэтому системный промпт обязательно содержит текущую дату и таймзону.

## Расширение

Напоминания, модерация, веб-поиск и другие последующие инструменты добавляются тем же способом, без изменения агентного цикла.

## Инструменты участников

| Инструмент | Назначение |
| --- | --- |
| Кто такой участник | Получить сведения об участнике в текущей беседе |
| Найти участников по признаку | Найти участников по доступным признакам в текущей беседе |
| Список участников | Получить ограниченную выборку участников текущей беседы |

Для всех трёх `chatId` подставляет харнес, модель не может выбирать или менять беседу. Выдача учитывает [видимость и права человека](profiles.md), а состав реестра — [синхронизацию участников](participants.md).

В коде задаётся жёсткий потолок выдачи, недоступный для повышения моделью; результат содержит подсказку о неполноте. Неполный состав из-за прав VK или ограничения выдачи не представляется полным списком. Численные потолки новых инструментов пока не определены.
