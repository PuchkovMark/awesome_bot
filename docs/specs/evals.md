# Оценочные тесты поведения

## Назначение

Мок-модель проверяет код и контракты. Оценочные тесты на реальной модели проверяют качество поведения при смене системных промптов, персонажей или модели. Они дополняют обычные тесты, а не заменяют их.

Изменение промптов, персонажей или модели требует прогона применимых оценочных сценариев. Начальные наборы формируются по мере появления поведения в соответствующих вехах; каркас предусмотрен в F2.8.

## Формат набора и результатов

Набор — список сценариев. Каждый содержит входные сообщения, состояние беседы (участники, профили, журнал), ожидаемое поведение и проверяемые критерии прохождения. Критерии описывают наличие факта, отсутствие чужих данных, отказ или вызов нужного инструмента; формулировка «ответ хороший» не подходит.

Запуск выполняется вручную по отдельной команде, вне обычного прогона тестов: вызовы реальной модели платные. Конкретная команда пока не выбрана. Результаты сохраняются для сравнения версий промптов, персонажей и модели; место, формат и сроки хранения требуют плана с учётом [privacy](privacy.md).

## Стартовые категории

Целевой объём — **20–30 сценариев**. Ниже перечислены категории; отдельно задан сценарий молчания при ошибке в активном режиме. Остальные конкретные сценарии наполняются по мере реализации.

| Категория | Где появляется соответствующее поведение |
| --- | --- |
| Вопросы о прошлом, «что было вчера?» | F6.3–F6.5 |
| Вопросы об участниках, «кто такой Вася?» | F5.5–F5.6 |
| Поиск участников | F5.6 |
| Пустой и ограниченный журнал | F2.5, F6.3 |
| Честность о неполноте | F2.5, F6.6 |
| Соблюдение персонажа | F7.1–F7.5 |
| Обход правил через персонажа | F7.6 |
| Внедрение инструкций через сообщения и профили | F2.7, F5.3, F5.5; проверки имён, анкет и паспорта расширяются в вехах 5, 6 и 8 |
| Данные другой беседы | F5.6, F6.3 |
| Прохождение анкеты | F8.2–F8.3 |
| Приветствие новичка | F8.4–F8.6 |
| Большой поток сообщений | F4.5 |
| Парные сценарии «должен вступить» / «должен промолчать» в активном режиме | F2.4, F4.3, F4.5–F4.7; правила без модели, случаев обязательного молчания больше |
| Нераскрытие полей «только боту» | F5.5–F5.6, F8.4–F8.6; правило подтверждено человеком |
| Отказ в изменяющих действиях без прав | F1.6, F5.4, F6.1, F7.3, F8.7 |

F2.8 создаёт каркас и начальный набор для уже доступного поведения, остальные категории наполняются в своих вехах. Цель 20–30 не требует преждевременной реализации будущих функций. Внедрение через имя, анкету, персонажа и паспорт дополнительно проверяется по [security](security.md).

Для активного режима строятся пары на одном поводе: без препятствий ожидается вступление, при добавлении запрета — молчание. Отрицательные случаи должны преобладать: чужой reply-диалог, иной адресат, отсутствие реакции на прошлую реплику бота, чувствительная тема, другой бот, флуд, тихие часы, пауза, лимиты и бюджет, личка. Проверяются отсутствие модельного привратника в текущей воронке и фиксация повода в трассировке. Числовые пороги берутся из будущей конфигурации сценария, здесь не выбираются. Правила без модели дополнительно проверяются обычными тестами; реальные LLM-прогоны нужны для качества полученного ответа и непротиворечия системным ограничениям.

Подтверждённое правило «только боту» требует оценочных пар, которые проверяют отсутствие прямого и косвенного раскрытия другим участникам, администратору, в приветствии и представлении. Это действующий критерий будущей реализации; сценарии наполняются по мере появления профилей и приветствий.

## Ошибка в активном режиме не даёт сообщения

Сценарий active-error-silence закрепляет правило: в активном режиме ошибка не даёт сообщения. Обычное обращение проверено локальной связкой F2.4 с подменами клиента и порта: server исчерпывает попытки, исход attempt_limit не порождает сообщения. Самостоятельный повод остаётся будущей F4.7, реальный отправитель — F3.x. За согласованную [таблицу реакций](agent-loop.md#публикация-исхода-и-молчание) отвечает F2.4; изменения строк утверждает человек.

| Условие | Проверка |
| --- | --- |
| Включён active; есть вход, для которого разрешено обращение к модели | Проверить обычное обращение к боту и самостоятельный повод как варианты одного сценария |
| Подмена клиента возвращает server до исчерпания разрешённых попыток шага | Итог — техническая ошибка/лимит попыток, без выдачи за complete |
| Путь публикации получил неуспешный исход | Число исходящих сообщений равно нулю; нет ни служебной фразы об ошибке, ни частичного текста под видом ответа |
| Диагностика | Доступны только безопасный исход и счётчики шагов/попыток; в диагностике нет полного контекста, исходной ошибки и секретов |

Отказ воспроизводится управляемой подменой; платный запрос и намеренное исчерпание квоты не нужны для проверки этой ветви. При появлении пути публикации сценарий проверяется на всей связке с отправителем. Тест одного нейтрального цикла без отправителя не считается проверкой молчания активного режима. Качество реальных ответов по-прежнему проверяется отдельными оценочными прогонами.

## Обращение по имени и обязательное молчание F2.4

Локальные парные проверки: «Пенек помоги с задачей» / «Пенёк сегодня молчит», «Подскажи пожалуйста Пенёк как это сделать» / «Мы обсуждали бота Пенек». В normal первая фраза каждой пары даёт обращение, вторая не запускает модель; свободное упоминание не исполняет будущую F4.7. Положение имени, е/ё, регистр и обычная пунктуация не ограничивают положительные примеры. Unknown отправителя, silent, выключение и невалидная область требуют молчания; active в личке имеет normal.

Для всех строк таблицы публикации проверяются вид реакции, общий период разных причин, reply-источник, отметка в журнале и отсутствие уведомления в контекстном читателе/FTS. Ошибка, partialText и текст инструментов не выдаются за законченный ответ; неизвестный исход молчит. Эти проверки не требуют платной модели и не заменяют натурные оценочные прогоны качества.

## Локальная проверка подготовки F2.5

Подменный клиент проверяет фактический запрос всей цепочки роутер → очередь → контекст → цикл: границу записи, reply вне окна, отсутствие notice, неизменный снимок server-повтора после смены версии. Проверены русский/Unicode, недоверенная разметка, две искусственные платформы, неизвестные возможности, дата в таймзоне чата, отдельные отказы переполнения и единый период уведомлений. Отмена, поддельная область и реальное переподключение не передают старую работу модели. Эти структурные проверки пройдены, натурные оценки качества остаются будущими.
